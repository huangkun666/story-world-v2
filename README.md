# Story World v2

> Agent 知识处理与状态推演引擎

[![CI](https://github.com/huangkun666/story-world-v2/actions/workflows/ci.yml/badge.svg)](https://github.com/huangkun666/story-world-v2/actions/workflows/ci.yml)

[![版本](https://img.shields.io/github/manifest-json/v/huangkun666/story-world-v2?label=version)](manifest.json)
[![许可](https://img.shields.io/badge/license-MIT-green)](LICENSE)

Story World v2 将非结构化资料组织为实体、关系、规则和事件，结合任务计划、状态更新、知识检索和因果追踪，支持具有持续状态的多轮交互。项目提供 SillyTavern 集成，社区已有数百人使用。

模型负责提出变化，程序负责校验、记账和保存；当前状态、历史证据与来源资料分别管理。用户可以查看实体与任务、追踪事件来路，并通过快照和完整导出恢复数据。

## 版本与能力范围

| 入口 | 内容与状态 |
|---|---|
| 公开 main | 可安装的宿主集成；结构化抽取、计划与事件管理、名称/关键词检索、可选向量召回、因果追踪、快照与导入导出。包含抽取块大小、中止抽取和任务诊断。 |
| GitHub Releases | 历史打包版本；与 main 的能力可能不同，安装前查看发布说明。公开版本及构建读数见 [STATE.md §1](STATE.md)。 |
| 本地研发版，尚未公开发布 | Dexie/IndexedDB 正式记忆账、Orama 与 Graphology 组合检索、逐任务检查点、分支与固定版本检索、二维/三维图谱等。下文单独说明，下载公开 main 不会得到这些模块。 |

公开代码中的界面入口仍沿用实际名称；使用指南列出对应按钮，安装目录为 `story-world-v2`。

## 工程亮点

### 知识加工与来源核验

读取宿主场景配置与来源条目，将资料抽取为结构化实体、属性、关系和规则。抽取请求按来源规模分块并控制并发，保留可核验的来源依据；对结构、引用和可用结果进行检查。

公开 main 支持调整抽取块大小、停止后续请求以及查看任务诊断。来源正文只读，改变来源选择不会自动重做已有状态。抽取质量取决于原文和模型，缺少证据的字段保持空缺，不用默认值补成事实。

### 计划驱动的状态更新

程序维护实体及进行中的任务计划、事件和条件。每轮汇集当前状态、已记录的对话事实和相关历史，组装模型输入；模型提出结构化变化，程序校验后写入状态账本。

非法提议按当前校验规则处理，可用内容继续保留；全部不可用或结算失败时报告错误，不增加轮次。模型不直接修改正式数据，历史事实也不会仅因出现在检索结果里就作为本轮新事件再次执行。

### 公开版本的检索链路

当前公开代码使用统一的历史检索接口，分别服务模型输入和对话上下文：

1. **构造查询**：根据当前对话、实体名称与别名及任务相关内容构造查询。
2. **读取历史**：从当前状态与已归档记录中读取候选，保留事件标识、轮次、时间原文和来源。
3. **名称与关键词匹配**：合并候选并去重；关键词候选按不同词命中数、再按新旧选择，最终按时间顺序组织。
4. **可选向量召回**：显式开启并配置 Embedding 通道后，将历史增量向量化；近期全文窗口与窗口外历史分别处理。向量索引与聊天及历史范围绑定。
5. **控制上下文预算**：按配置选择完整记录，保留已知时间与出处。模型输入和界面展示使用不同预算，显示多少不决定完整数据保存多少。
6. **异步结果保护**：查询变化立即使旧结果失效；新向量结果尚未准备好或失败时，使用当前查询的名称、关键词候选。迟到结果只有在聊天、状态与完整查询仍匹配时才可使用。
7. **历史隔离**：恢复旧快照时，后来产生的分支历史不得混入；缺少历史校验的旧数据按现有保护策略隔离。

对应实现：[历史检索](src/ledger-recall.js)、[向量记录](src/ledger-vector.js)、[增量编排](src/embed-orchestration.js)、[异步运行时](web/embed-runtime.js)、[历史范围校验](src/vector-history.js)。

### 因果追踪与状态保护

事件记录来源、参与方及关联变化；因果链视图支持追踪前因和后续影响。用户控制的实体始终受保护，其他实体可使用界面中的「禁止模拟」控制项；当前对话已记录的行动也有本轮保护。

程序检查明确的结构与写入边界，生成提示词约束模型的间接叙述。这些措施不等于模型永远不会误解原文或编造描述。

### 快照、导出与故障处理

状态变化与参数调整分开管理；快照可恢复历史状态，整聊天导出保留聊天与插件数据。快照只恢复插件状态，不回退聊天正文，不能替代完整导出。

调试台记录本插件的任务阶段、进度、耗时和错误。抽取失败按 HTTP、超时、网络、空响应、截断、JSON 和来源校验等原因区分；停止操作不保证服务端撤销已发出的请求或免除费用。

## 本地研发进展

以下能力已在本地开发并有相应技术验证，**尚未进入公开 main，不能当作公开安装包的现有功能**。技术检查、真实模型样本、真实宿主与用户验收分别记录，不以自动化结果代替用户验收。

### 逐任务的图关联 RAG

```text
当前状态中的计划、事件和条件
  → 生成任务，逐任务构造查询与明确引用
  → 固定场景 / 分支 / 数据版本及检索参数
  → 优先保留明确引用
  → Orama 中文全文与向量混合召回
  → Graphology BFS 扩展因果、所属和参与方关联
  → 从同一正式版本回取完整原文记录
  → 去重合并，按整条记录控制上下文预算
  → 模型提出变化，校验后事务提交
```

查询逐项保存检查点，恢复时复用已完成结果；向量以通道身份和内容哈希缓存，同版索引可复用。向量失败可回退全文；索引构建失败时仍可回取明确引用，并如实标记能力受限。

### 正式记忆账与可恢复执行

Dexie/IndexedDB 作为唯一可写事实存储，全文、向量与关系图作为可重建索引。资料版本、原文、正式快照、操作记录、模型原响应与 usage 分开保存。

执行过程按准备、检索、输入打包、生成、校验和提交分阶段记录；通过操作标识去重及预期版本校验保护事务提交。已收到的响应可在本地继续处理；未知请求不自动重发，取消与迟到响应按正式操作状态处理。

### 当前状态与历史证据分离

当前状态从固定正式版本读取，历史通过检索获得，两类上下文独立计预算。信息根据参与方与已记录的知情依据投影，明确区分计划、持续及结束状态，避免把过去发生的事或尚未生效的计划当作当前事实。

研发版另包含版本快照、分支恢复，以及 G6、Three.js 与 ELK Worker 的图谱集成。图谱交互、内存和部分显示问题仍待用户实测，不能据此承诺所有设备流畅或全部问题已解决。

## 安装

公开版本依赖 SillyTavern 宿主。当前公开说明对应已验证的宿主版本；环境与兼容性边界见 [使用指南](docs/community-guide.md)。模型与 Embedding 服务可按配置使用本地或远端接口。

在宿主的「扩展 → 安装扩展」中填写：

```text
https://github.com/huangkun666/story-world-v2
```

也可以手动安装：

```bash
cd <你的SillyTavern>/public/scripts/extensions/third-party
git clone https://github.com/huangkun666/story-world-v2.git story-world-v2
```

Git 安装需要宿主所在机器具备 Git。ZIP 安装应把解压目录改为 `story-world-v2`，不要保留 `-main` 后缀；模板使用固定目录读取。Git 安装可通过宿主更新，ZIP 需手动替换文件。更新后硬刷新页面，并核对窗口中的版本与构建显示。

## 第一次使用

1. 从宿主输入区的扩展菜单打开「观棋窗口」。
2. 在「设置 → 模型通道」填写插件自己的服务地址、凭据及模型。此配置与宿主聊天模型独立；连通测试会发送真实请求。
3. 在「设置 → 抽象来源」选择资料，查看实际将提交的正文；宿主中的角色卡、世界书是本项目的资料入口，原文只读。
4. 点击「开始新世界」完成场景初始化。已有状态时先完整导出；确认提示后再操作，不把尽力保存的自保快照当作唯一备份。
5. 点击「推进一轮」手动更新状态，或在「参数」中开启「插件总闸 · 自动推进」。总闸默认关闭。
6. 需要语义检索时单独配置并开启「记忆通道」。Embedding 会产生额外请求与费用。

初始化抽取与普通单轮更新的超时、输出设置作用范围不同，详情见 [使用指南](docs/community-guide.md)与[故障排查](docs/community-faq.md)。进行中的保存、导入或初始化操作结束前，不要切换聊天或从多个标签页同时写同一状态。

## 已知限制

- 主生成、资料抽取和 Embedding 的调用与成本分别计算；提高并发或缩小分块不保证更快、更便宜。
- 长资料抽取和状态更新依赖模型及服务能力。单次来源覆盖不等于语义准确率，自动化判据不等于用户验收。
- 原始资料与运行时状态各有职责；原文不会被插件改写，来源改变也不等于已有状态自动重建。
- 对话事实提取依赖当前版本约定的标签输入；没有标签时不会靠词表猜测整个正文中的行为。
- 完整导出可能包含私人聊天、资料与配置；分享前检查并脱敏。报告问题先保留现场，不以清空数据替代排查。
- 公开版本的快照只恢复插件状态，不撤销宿主聊天。兼容性按实际宿主与浏览器验证范围说明，不承诺未经验证的设备。
- 本地研发版的图谱性能、内存和部分交互仍未通过用户实测；源码检查或本机隔离验证不代表全平台真机验收。

<a id="它没做什么诚实交代"></a>
<a id="它做什么三句话"></a>

程序以明确结构和来源为依据，不把缺失信息补成事实，不用固定语义词表判断资料类型，不把自由文本属性换算成未经定义的分数。模型生成质量与确定性写入检查分别评估。

## 运行测试与自检

公开安装包无需用户执行 npm 安装或构建。在插件目录中运行：

```bash
node --test                 # 全量测试（本版：2310 / 2310）
node demo/smoke-demo.js     # 合成冒烟：50 轮曲线 + 断言（终态 8351 字节 · PASS · 警告 0）
node scripts/audit-docs.mjs # 开发工作区文档与索引检查，内部也会运行测试
```

前两条是零模型调用的技术检查。上面的机器核对镜像对应公开版本记录，权威读数见 [STATE.md §1](STATE.md)。实际运行失败必须保留并报告，不把记录中的读数当作本次执行结果。

公开仓库是开发项目子树的独立导出件；文档索引包含开发工作区的信息，公开干净检出上的索引检查可能与开发工作区不同。公开 CI 执行全量测试和合成冒烟。真实模型质量、真实资料、宿主安装、设备性能与用户验收另行验证。

