## 2. 四条不可违——甲的规矩（违了必出事故，且都出过）

**① 只提取不创作。** 无从合成、无从润色、无从补全。块间合并取"信息量最大的那块"，**绝不合成一句**——合并=摘要=创作。
**② 编译一次，此后以账本为准，永不回查原文。** 运行期没有任何"按需读原文"的通道（用户已拍；`recalledText` 那条路已作废）。
**③ 一个值一格现值 + 一张发票。** 就地覆盖，没有历史堆栈；**因挂在事件/编年上**（那本来就是记历史的地方）。
**④ 空就是空。** 抽不出来不写、不猜、不兜底（`buildScaleAnchor` 空表 ⇒ 键不出现）。

★ 这四条有个**共同的下游判据**，可当自检问题用：**"这个值，换一本书还成立吗？"**——
四条守的是"值来自这本书"，破一条就是把模型的话当书的话。

## 3. 七条泛用律——从 leg60 的七条硬事实里提出来的

每条格式：**律（可搬去任何一本书）→ 本书实例（读数照抄）→ 判据形态（怎么机械判）**。

**律 1 · 取料面律：生效集合 ≠ 磁盘集合。**
书的"作者意图"写在**壳**里（作者亲笔的目录），不写在条目顺序里；而"禁用"在 ST 生态常常是**仓储**，不是废弃。
- 实例：三国 827 条里禁用 **563 条 / 850,282 字**，被壳点名过的 **554 条 / 835,647 字**；引擎旧看到 **18.9%**，大荒 87.6%。
- 判据：**按声明取料**（恒注入壳声明的目录必读 + "自成一套"的壳声明的料必读）；零词表。

**律 2 · 尺与量分离律：档位表是"尺子"，逐人数值是"量出来的"。**
一把尺子（`T0级_天下无双 = 勇武100`）可以照抄；一个量（"关羽 = 99"）**必须来自某人说过这句话**。
- 实例：书里 **37 人有明写数值 / 43 处**（`演义战力体系` 写 `吕布（勇武100 / 统御75）`）；账上 **37/37 全中、漏 0**。
- ★ 同一条律的**反面**也是律：三国明写「反数据化：禁止出现数值化的能力设定」⇒ **尺子进叙述就是违作者铁律**。
  ⇒ **律 2 的完整形**：**尺可以进包，量只有书里说了才落账，且落账的形态要随书的禁词纪律变**。

**律 3 · 契约漏登记律（最会伪装的一条）：形状层漏登记 ⇒ 生产端一律白干，而判据全绿。**
- 实例：`bookEntities.fields`（leg25 e 加了提示词与净化层、**契约层忘了登记**）⇒ 用户新账 **323 条**违约；
  `source.type` 缺 `'seed'`（7 条）· `seedFrom`（7 条）· `meta.seedRoots`（1 条）——**起根从 leg40 就在写**。
- 判据：**生产端每加一个键，契约表同步**；且**只落标量**（`compileSummary` 只写 16 个标量，判据锁"键在契约表 + 必须是标量"）。
- ★ 这条律的判据形态值得单独记：**"契约不是校验器，是清单"**——校验器只管你登记过的形状，登记漏了它永远绿。

**律 4 · 方言律（提任何判据前先答"换一本书会怎样"）。**
- 实例（反过拟合实测）：`（YYYY年）` 块头——**三国 127 个 / 大荒 0 / re0 0 / 实教 0 / 综漫 0 / Eldoria 0**。
  ⇒ 任何以 `阶级（年）` 为判据的机制都是**方言机制**（leg60 §4.4 被用户当场抓）。
- 判据形态：**形态判据**（有没有壳 / 题名前后缀频次 / 互相成族）**不是词表**；且判据要报"跨 N 本书的命中数"，n=1 不许当结论。

**律 5 · 出处闸律：名号有全书级出处校验，属性没有——这是错的。**
- 实例（交接 §3-G）：属性字段**没有出处闸**，抽查 6 条全对，但 323 条不能保证。
- 判据：**值必须能在本书原文里找到**（`evidence` 是原文字串，既有治法：`applySeedRoots` 同款验伪）。
- ★ 附律（交接 §3-D）：`<user>` 与 `丕` 是**活实体**——它们**真的在原文里**，全书级校验抓不住 ⇒
  **出处闸管不出"这名字是不是个人"**，要另加**名号形态闸**（含 `<>{}` 的丢；单字名单独判——`宛`/`郿` 是合法古地名，**不许一刀切长度**）。

**律 6 · 进度律：世界有时间轴，账本只有轮次（`tick`）。**
- 实例：书的料**按世界进度分段**（三国 28 个年份块 / 大荒 7 个境界阶段块 / 实教按学期），而账上**没有"世界进度"这个量** ⇒ 分段料选不了。
- ★ 两个来源的**性质完全不同**，别混：大荒 `stat_data.世界.时间` **在**（可读一次落账）；三国 `stat_data` **根本不存在**（MVU 没跑起来）⇒ **三国这局"时间对齐"无源可对**。
- 判据：**进度是"账上的一个量"，不是"引擎的一个参数"**（加"年份/剧本方向"两参 = 方言律的反例）。

**律 7 · 尺子摆出来才有人用律：抽出来的东西没人消费 = 没抽。**
- 实例：`rules`/`society`/`techOrMagic`/`historyNotes` **只出现在 `render.js`**；`pack.setting` 只带 `tension+env`
  ⇒ 模型**一个字看不到**这本书的尺子（真账 85 实体里 `实力` 0 条）。leg60 才让"刻度"进包（A-8 冻结层的**唯一窄口**）。
- ★ 本棒实测：契约里 `rules` 的形状是 `['法则1（原文）']`（`src/abstract.js:63`）——**一条平铺的法则串**，
  ⇒ 书的"判定原则"**连形状都没有**（不是"没抽到"，是**没有地方放**）。这条把 §4-C 从"漏抽"改判为"契约缺一格"。

## 4. 四个失效形状——"全绿但没接线"的五种变体，和两类假测量

这是本仓最贵的知识，leg60 §4 的五个错与 leg60 出数档 §4 的三处，**抽象成形状**就能当检查表用：

| 形状 | 一句话机理 | 已发生的实例（都修了） | 当场可用的探测问句 |
|---|---|---|---|
| **① 机制在、线断了** | 纯函数写好了、判据锁着它，**接线处丢了** | 别名通道：`sanitizeCanon` 只收 `{name,kind}` 把 `aliases` 静默丢；`titleRoster` 塞进 `catalog` 而 `web/index.js` 读**顶层** | "这个函数，生产路径上**谁调它**？grep 得到吗？" |
| **② 判据锁了机制、没锁接线** | 测试**直接喂函数**手工对象 ⇒ 机制永远绿 | `roster-merge.test.js` 全程喂 `dedupeRoster` | "这条判据走的是生产入口，还是我手搓的对象？" |
| **③ 空绿（新分支没人跑）** | 只加渲染、没加判据 ⇒ 那条分支一次没执行 | 设定页两栏（补"真渲染一次"后当场抓出 markdown 星号写进了 HTML） | "这条分支，**哪条判据真的走过它**？" |
| **④ 兜底掩盖"从没给过"** | `X ?? 默认` 让"没人给 X"看着像"X 就是默认" | `cfg.limitsTicks ?? 500`（真源从不注入，印的是渲染层自己抄的数） | "这个值是**现算**的，还是**写死**的？" |
| **⑤ 契约漏登记**（律 3） | 见 §3 律 3 | 344 条违约 | "生产端写的每个键，契约表里有吗？" |

**两类假测量（说"没有"之前必须先过这两问）：**

- **空测量（查错了那一份）**：leg60 曾断言"书里没写人物数值"——**只查了合订文本**（恰恰不含 366 条人物档案 52.6 万字）+ **正则方向写反**（书里是"档位在前、人名在后"）⇒ 算出"共现 0 处"这个**自己造出来的假象**。真相反：37 人明写数值、账上 37/37。
  ★ **问句："我查的这一份，是不是那一份？"**
- **空测量（聚合体 ≠ 明细）**：leg59c 的"卡内置书 ∪ 具名书 = 232,020"是空测量（去重放在了"滤禁用"之后）。
  ★ **问句："我量的这个数，和我说的那句话，是同一个东西吗？"**
- **过拟合（律 4 的反面）**：把"这本书的字段名"当机制。
  ★ **问句："换一本书会怎样？给实测，不给推理。"**
- **覆盖率的假成绩**：报"132 条实力"而不给分母（实际 39%，且 95 条是错位的官职）。
  ★ **问句："分母是多少？有值的那些，值**是**什么？"**

## 5. 五张机制卡——leg61 的三件正事 + 两条必带的纪律

每卡固定五格：**是什么 · 判据在哪一层 · 泛用性判定 · 上游依赖（缺了就先别做）· 代价与预期**。
★ 五卡都遵守：**零新引擎参数 · 零词表判语义 · 没有材料的书零扰动**（宁可不发调用，不许猜）。

### 卡 1 · 归属边（势力树）【用户已拍「还是得要」】

- **现状**：势力→势力 parent **0 / 57** · `branches` **0** ⇒ 用户截图里 9 个"曹/魏"**全是平级兄弟**；根因 = leg24 片1「停抄书」不再抽 `parent`，而大荒那条"照书办"标签通道（`<X帝麾下_Y>`）**三国没有**。
- **★ 判据在哪一层（本卡最重要的一句）**：**丙**。书里**写着**势力树，而且是**逐年的**——
  `<势力>阶级（YYYY年）` 块 **112 个 / 39 个势力 / 28 个年份（159…290）**，块内 `首领/谋士/武将` + **子单位**（`青州兵：兵力 约30万 · 性质 曹操核心武装`）；
  另有 **成员→势力+官职 399 条 / 158 人**（`皇甫嵩[朝廷讨伐军]：左中郎将，统北军主力`）。
  ⇒ **隶属关系有原文出处，不用编**（与 v1 那条"势力成员标签"同一族材料）。
- **泛用性判定**：**求"归树"这个动作泛用；`阶级（年）` 这个形式是方言**（律 4 实测其余 5 本 **0**）。
  口径因此定死：**只按"这一条正文提到了某在册势力名"切块，不认 `阶级`/年份/格式**。
- **上游依赖**：**无**（本卡可以立刻做——它只要"书文 + 势力清单"）。
- **代价与预期**：**一次归树调用**（输入=势力清单+各自相关原文段；输出 `{child,parent,evidence}`，**evidence 必须是原文字串**）+ 纯函数验伪（两端在册 · 自指/成环弃 · 证据对不上丢）。
  三国预期 **确定边 10–20 条** + **18 条未定**（同一子单位在不同处属于不同父 ⇒ **不硬选**，落"未定"登记、面板可见）。
- **★ 不许做的一格**：`曹操军` vs `曹魏军/大魏/魏朝廷/曹家`（同一组织不同时期）——**书里从没写过这句话**；
  要合并 = **身份归一**，**需用户明确授权"允许按常识合并"并标「（推）」**。

### 卡 2 · 世界进度（分段料的钥匙）

- **现状**：书的料**按世界进度分段**，账上只有 `tick` ⇒ 不只挡势力树，**年份史 / 人口 / 格局 / 双模式规则集全都对不上**（这就是 leg60 出数档 §5.4 那条"编译期判不出这局走哪条线"的同一条病）。
- **★ 判据在哪一层**：**乙**（账上多一个量）+ **甲**（一条可选来源）。
- **泛用性判定**：**泛用**——只要"一个世界有比轮次更粗的时间轴"就成立；**方言的部分是"那个量叫什么"**：
  大荒叫 `stat_data.世界.时间`（**在**，可读一次落账）；三国**没有**（MVU 没跑起来 ⇒ **无源可对**）。
- **三条来源（都不引入方言参数；可并用，建议按此序）**：
  **(a) 账上派生**（纯函数、零 token、可判据锁）：三国的年份史与事件台词里本来写"建安三年"⇒ 读得出来；
  **(b) 玩家在开局描述里写**（复用已有 textarea `playerDesc`，**不加新控件**）；
  **(c) 变量真有就读一次落账**（大荒那样；**不是每轮读**——守"编译一次、以账本为准"）。
- **★ 别做**：给引擎加"年份/剧本方向"两个参数（那是这本书的字段名 = 方言机制，用户已抓过一次）；也别做"每轮读变量"（违 §2 律②）。
- **上游依赖**：卡 1 **依赖它**吗？——**不依赖**（卡 1 走"提到在册势力名"这条与时间无关的切法）。
  ⇒ **所以先做卡 1**；卡 2 一旦落地，卡 1 的边可以**再按进度分层**（收益是"逐年势力树"，不是"能不能做树"）。

### 卡 3 · `实力` 栏的分类错位【用户最在意的一栏】

- **★ 先量清分母（这是上一棒的教训）**：`实力` **132/340 = 39%**，成分 = **书里真值 37 条**（照抄 ✓）+ **官职/爵位 95 条**（**错位，该进 `身份`**）+ **真档位标签 0 条**。`身份` 261/340。
- **★ 判据在哪一层**：**丙**（哪一栏收什么）+ **甲**（提示词口径）+ **乙**（契约里这两栏的关系）。
- **泛用性判定**：**泛用**，且可写成一句可判等的口径：
  **「紧贴名号的"职/爵/号"→ `身份`；`实力` 只收原文紧贴名号的档位或数值原话；不许用刻度算数（律 2：尺子不许当代数）。」**
- **★ 三选一（需用户拍）**：
  **甲（建议）**：按上面那句口径收口 ⇒ 95 条归位（`身份` 261→~340）、`实力` 落到 **37**（**诚实**）；
  **乙**：允许"模型按刻度提议的数值"落账，但**必须带「（推）」标记、与原文值分栏显示**（= 把 leg25 c 那条"手拍值让编的看起来像算的"按新形式部分接回来，**需明确授权**）；
  **丙（附）**：把 `实力` 从每轮实体表撤掉或加纪律——**依据是书明令"反数据化"**（`pack.js:240` 表头含 `实力`、`:433` 逐行填 ⇒ 模型有把数字写进叙述、违作者铁律的风险）。
- **上游依赖**：**无**。★ 但**不是独立的一件事**——见卡 4：只做卡 3，模型仍然"不知道怎么判"。
- **代价**：一次提示词口径改写 + 归位迁移（载入期一次性 · 幂等 · 不可变，与 `settle.migrateLegacyAttrs`／`slimLegacyCompile` **同一治法**）。

### 卡 4 · 判定原则（"没有实力怎么判胜负"的答案）【与卡 3 同批做，别拆开】

- **★ 现状是"没地方放"，不是"没抽到"**（本棒实测，见 §3 律 7）：书里明写
  「**生死决斗结果判定时必须作为唯一底层逻辑参考**」+ `战例优先 / 平手传递 / 回合数参考 / 状态因素`，
