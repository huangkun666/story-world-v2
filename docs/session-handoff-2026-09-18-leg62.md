## 1. 硬事实（本棒实测，都指得出出处）

1. **两遍抽取的账（真机 · 详见 §2.2）**：同一批块、同一模型，"只报名号"去重 **1022** 个 vs "七样一起问" **364** 个；
   两臂输出总量相近（71k vs 78k 字符）⇒ 差的是**每个名号的输出成本**（~57 vs ~188 字符），**不是输出装不下**。
2. **`所属` 是"抽出来了却一个都没落地"的字段**（真账三本账）：名册带 `所属` **233 / 482 / 141** 条，实体账上 **0 / 0 / 0**
   （`pushEntity` 的落账名单里从来没有它；它只在中途被 `verifyClaimedParent` 用了一次，看着"有人用"）。
3. **旧属性白名单只认七个键**（`所属/身份/定位/实力/性质/倾向/规模`）。三国前 2 块抽到 **34 种键，旧口径只留下 2 种**：
   被丢的 32 种是 `籍贯/出身/本姓/生卒/体型/脸型/眼睛/发色/发型/发饰/皮肤/妆容/手部/肩部/腰部/腿部…`——**全是书里写着的**。
4. **势力树没有纯函数判据**（跨书实测，见 §4.3）：`<势力>阶级（年）` 三国 116 / 大荒 0；`<X帝麾下_Y>` 大荒 18 / 三国 0；
   **"父名与子名同段共现"三国 91 / 大荒 217 处全是噪声**（"诸葛亮是琅琊诸葛氏的人""两军交战"，甚至"万法阁叛徒 ⇒ 万法阁∈天机阁"）。
   ⇒ 只认**名字包含**（三国 5 组 / 大荒 3 组），其余交给模型那一遍。
5. **档位重复的真因不是模型乱写**（用户新账·大荒）：书里本来就有**四张表挂在同一个坐标上**——
   境界表（`T4 金丹境 (妖:小妖境…)`）· 品阶表（`地阶(T4-T6)`）· 宗门职阶（`外门/内门/真传/长老`）· 数值基准（`战力基准 T1=100~T9=1e9`）。
   块间再抽一遍只是**放大**了它。实测 103 条档位里**同名 0 组**（精确去重一条都拦不住）。
6. **编译耗时被两个真 bug 放大**（见 §4.4）：超时后先重试（又等满 600 秒）再拆半 ⇒ 大荒 22 次调用/1909 秒；
   大书块尺寸 60000 在 600 秒网关限下**必然超时** ⇒ 级联拆半 ⇒ 三国 7 块跑 >2.5 小时未收尾。
7. **串栏规模已量准**（大荒 1620 个属性项）：两栏值**完全相同** 5 处（0.3%）、一栏值是另一栏子串 64 处（4%，含 `身份⊃所属` 正常嵌套）。
   ★**出处闸管不了它**（那句话确实在原文里）。
8. **"没有档位"是多数情况**（7 本书实测）：有尺的只有大荒（103 档/65 维）与三国（27 档/9 维）；
   Eldoria / Global / 实教 / 综漫的档位记号与 `range` 字样**全是 0**；re0 书里有 96 处记号但**没有账本**。

## 3. 待办（按优先级）

### ★★★ A. 设定面重构：给"刻度"一个通用的数据结构（**用户当场点名，本棒未做**）

#### 3.1 证据（用户给的实教截图，逐条对照）

| 面板显示 | 它真的是什么 |
|---|---|
| **力量谱系（5 档）**：`S~E级 / A班 / B班 / C班 / D班` | **不是力量谱系**——是**班级分配制度**（`A班=精英最高资源保障`、`D班=底层资源最少多隐藏实力`） |
| **维度与刻度（14 项）**：`学力/智力/判断力/体育/团队` | 真正的基础**属性**（5 项，同一把 `S~E级` 尺） |
| `身体 / 思考 / 社会 / 贡献 / 综合` | **合成分**（由基础属性派生的另一层） |
| `S系统评分 / S点数` | **不是维度，是公式**：`学力/智力/判断力/体育/团队5项S~E级`、`CP班级点数+PP个人点数` |

⇒ 三处错位，**同一个根**：**值没有"它是什么类"的字段**。
`powerScale` 只有 `{level, note}` ⇒ 制度规则与强度刻度挤一个框；`dims` 只有 `{name, range}` ⇒ 属性/派生/公式平铺一张表。

#### 3.2 通用结构（提案 · 待用户拍）

1. **`powerScale` → 每条带 `axis`**（这把尺叫什么，**照抄书里的表头**：`班级评定`/`S系统评分`/`境界`…）
   与 `usage`（`评级` / `分配` / `换算` 三选一，**枚举**，判据可锁）；
2. **`dims` → 每条带 `kind`**（`属性` / `派生` / `公式` 三选一，**枚举**）；
3. **★值不进这张表**：`S~E级` 是**刻度**；某人"学力 B"是**账上那一格**。表只描述坐标系 ⇒ 这是"维护成本"的真正来源；
4. **分组靠机械判据，不靠读一遍书**（本棒想出来的那条）：**用 `实力` 的取值去反查它在哪把尺上**——
   某角色的 `实力` 值能在哪把尺的档位表里找到，那把尺就是**实际在用**的轴；匹配不上的尺就是**没人用的表**
   （如实教的班级分配规则，它压根不是用来填 `实力` 的）。通用 · 可判等 · 零词表，且顺带产出**覆盖率**（哪把尺被用过几次）。
5. **显示分组**：面板与每轮包的 `刻度` 块都按 `axis`/`kind` 分栏 —— `力量谱系` 那一栏再也不会把"D班"和"T4 金丹境"摆在一起。

#### 3.3 落地顺序（建议）

先做**只读试算**（拿实教 + 大荒的设定跑分组，列出"哪些条目会被判成 `分配`/`公式`、哪些尺被 `实力` 用过"）⇒ 用户看分组对不对 ⇒ 再动代码与契约。

### ★★ B. "没有档位"的分支（本棒只查清，未做）

现在 `buildScaleAnchor` 的判据是"没档位没维度 ⇒ 返回 null ⇒ **键不出现**"。看着像"零扰动"，实际是**沉默**：
书没给尺子时模型收到的是**什么都没有** ⇒ 它自己编一把（三国那次编出 `声誉十级`）。
**要三支**：① 有尺 ⇒ 照现在；② **没有尺 ⇒ 明确告知"本书没有成文刻度"**（让模型用书自己的写法，而不是造一把）；③ 半有尺（只有零散区间，如 re0）⇒ 只进区间那半。
判据是形态判据、已实测：Eldoria/综漫/实教/Global 四本都是 0，一次都不会误判成"有尺"。

### ★★ C. 串栏（模型把体质写进定位｜同族病）

量过：**少数但不是零**（完全同值 5/1620 · 子串 64/1620）。**出处闸管不了它**。
治法只能是"给每一栏一句同类性约束"（`定位` 只收处境/职责、`体质` 只收体质），并且**要判据能验**——
但注意 §4.1：**别用某一本书的示例词去写这个约束**。

### ★ D. 名册归一（势力名的"同一实体不同叫法"仍不稳）

模型两次跑出来的势力名不同（上次 `曹魏军/蜀汉南征军`，这次 `曹魏/蜀汉`）⇒ 势力树在半数叫法上仍会飘。
`dedupeRoster` 按"名字 ∪ 别名"归一，别名靠模型交（三国 53 条 / 大荒 39 条）——**覆盖率不够**。

## 4. 我（leg61）犯过的五个错——下一任别重犯

1. **★同一族的错，犯了三次：拿一本书的观察当判据**（用户三次追问才逼出来）
   ① 止损判据写"累计已有法则与档位"⇒ 第一次调用就命中、**整遍一块没跑**；② 改看 `canon.powerScale.length > 0`
   ⇒ 判的是"键在不在"（净化层**预置空数组**）**同样恒真**；③ 档位归一的轴名最先用 `境/期/阶` 这种**中文词表**判、
   合并用"长度差 ≤25%"和"短注就合"（24 字阈值**照大荒那份表反推**）⇒ 全是过拟合，**已被用户当场质问后全部撤掉**。
   **教训：判据里出现"我在这本书里看到的词或数字"就是过拟合。撤完之后要补一条"换一套记号照样成立"的锁。**
2. **★死代码（最隐蔽的一处）**：`dedupeRules` 里用 `for (const [k,i] of idx)` / `idx.forEach` **遍历 Map 一次都不迭代**
   ⇒ 前缀合并整段是死代码，而判据当时是绿的（因为我先写的测试用别的路径过了）。**教训：新增分支要有"它真的被执行过"的证据。**
3. **★夹具造假（判据是对的、夹具是假的）**：两遍抽取的测试里，mock 自己造了 `名号0` 这种**书里根本没有的名字**，
   于是 40 个名号被全书级出处校验**正确地**丢掉。**教训：报"抽取失败"之前先问"我的输入合法吗"。**
4. **★把"我提的方案"当成"用户的批复"**：甲类边折叠这件事，我在文档里写的落点与最终实现不一致（我以为要"保留子势力独立"，
   实际是"折进 branches"——后者才符合用户原话"部门给当成势力了"）。**教训：写方案时把"它会改变什么"逐条列出来，别只写意图。**
5. **★设计上的越界（用户最后直接砍掉）**：我提议"给每个实体每轮带 4 个属性"，量出来是 **+29.8%~38.9% 包体积**
   （三国整包 20,988 字符 ⇒ +8,160），还提了"在场过滤/按需带列"的整套机制。
   用户答复：**「不要管这个，现在只做粗粒度，维护这些成本很大」**。
   **教训：先报体积代价再谈方案；"细粒度属性"这条线本棒已明确砍掉，别自己捡回来。**
