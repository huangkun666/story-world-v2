## 1. leg110：修「点事件链总撞『环防·至此为止』」

### 1.1 病（两处叠在一起）

**第一处（引擎层，真 bug）：归档时"重指大事纪"改完不查重。**

`src/settle.js` 的归档函数里，有两个循环把"指向已归档事件的指针"改指到那个大事纪上。它们**改完就完事、不看这个 id 是不是已经在了**。于是**两件不同的事各自引用同一件旧事**时，重指之后变成**同一个 id 出现两次**。真账实测：

```
m_20 的来路 = ["m_10", "ev_1_1", "m_10"]      ← m_10 出现两遍，还多一条冗余的 ev_1_1
m_30 的来路 = ["m_20", "m_20"]                ← 也是两遍
```

**第二处（链展开层）：把"走过"当成了"成环"。**

`src/chain.js` 展开大事纪节点时，用的是**整条事件链累积的"已走过"集合**当防环集合。而那个集合里装的是"这条链上走过的事件"——于是大事纪引用到一个**早就走过的事件**时，就被判成"引用成环"、剪断，面板打出「**账不可信处的如实标注**」。**账是可信的，是那里判错了。**

### 1.2 影响面（先量再动）

- 真账 **75 个可点节点里 14 个（19%）** 撞这条误报：`ev_25_3` … `ev_36_3` 那一整片 + `m_20` / `m_30`
- ★那一片正好是**最长的那条因果链**（第 25–36 轮"死煞狂潮"那条）⇒ 用户觉得"**总是**"撞上，是因为他点的大多是有内容的链
- **真账里真互指 0 处** ⇒ 面板打的"环防"**全部是误报**

### 1.3 三处改（引擎层 ×2 + 渲染层 ×1，**契约层不动**）

| 改哪 | 怎么改 |
|---|---|
| `src/settle.js` | 新增 `normalizeMilestoneLinks`：大事纪的 `links.up`/`links.down` **去重** + 去掉"已被某个大事纪包含"的冗余直指 |
| `src/chain.js` | 大事纪节点的防环集合**只装"大事纪自己那条路径"**（从一个空集起步、不继承事件链的集合）⇒ **真环照样拦、误报消失**；同批：同一 id 在 parents 里只渲染一次（重复引用**跳过、不剪断**） |
| `src/render.js` | 那句措辞改成如实（不再说"账不可信"） |

### 1.4 ★两处自证

1. **先证红**：两条新判据在改前**真的红**（第一条靶心正是 `m_20` 里重复的 `m_10`）
2. **真环用例（`A-15③` 人工互指）改后原样通过** ⇒ 证明消掉的只是误报、**没把环防拆掉**

### 1.5 ★★本笔自己踩的三个坑（留档，都值得记）

1. **归一的位置放错两次**：第一版放在分段循环里 ⇒ 只有"本轮真有事件归档"才跑；挪出循环后**仍被 `if (!bySeg.size) return` 挡住** ⇒ **必须放在那个提前 return 之前**。不挪对的话，"旧账自愈"就是一句空话（旧账不必等到有事件归档就会被用户点到）。
2. **去冗余那段写成一句链式过滤 ⇒ 自反**：元素会被自己判成"包含它的大事纪"（那个集合里就有它自己的 id）⇒ 改成两步走：**先认出"来路里哪些真的是大事纪"，再问谁被它们包含**。
3. **判据里持有了过期引用**：归档函数每轮**重建**大事纪对象 ⇒ 断言必须**现取** `w.m('m_20')`，不能提前存一个变量。

### 1.6 ★旧账自愈（不用跑迁移脚本）

归一跑在归档函数的**最前面**，而那个函数**每 tick 都跑** ⇒ 用户下一轮推进时，旧账里写脏的那两个大事纪就被就地修好。**不需要导出/导入、不需要一次性脚本。**

## 2. leg111：归档事件保住来路

### 2.1 病

归档那一段只做两件事：

```js
m.titles.push(ev.title);   // 只留标题
m.ids.push(ev.id);         // 只留号
```

**事件对象整个从账上移除**——它的**来路（`source.ref`）、位置、波及名单一起消失**。后果分两层：

| 丢的是哪一类因果 | 改前现状 |
|---|---|
| **跨段**（第 5 轮的事 → 第 12 轮的事） | ✔ 保住了——记在大事纪的 `links.up` 里（所以面板上"第 1–10 轮 → 第 11–20 轮"还看得见） |
| **段内**（同一个大事纪里"哪件事引发了哪件事"） | ✖ **全丢**——真账 4 个纪共 **63 条**已归档事件全无来路 |

### 2.2 治法（四处：契约层 + 引擎层 + 链展开 + 渲染层）

**口径照用户原话：「和其他没进的事件一样」** ⇒ 存**事件契约那五格**，形状完全同形，渲染层不必分两套。

| 层 | 改哪 | 做什么 |
|---|---|---|
| **契约层** | `src/schemas/ssot.schema.js` | 大事纪新增**可选**格 `rows`（大事纪是 `additional:false` ⇒ **必须登记**，否则违约）。每项：`id / title / source / position / ripples` |
| **引擎层** | `src/settle.js` | 归档时把这五格原样 push 进 `m.rows`。★**按 id 去重**——大事纪是**逐 tick 增量长**的（同一纪会分多轮被推进事件），重复 push 会涨出假条目 |
| **链展开** | `src/chain.js` | 新增 `archivedEventMap(world)` 索引：上溯时**先查 `rows`**（归档事件与热池事件走同一条路、能继续往上走）；下沿时**把归档的引用方也算进来**（改前只扫热池 ⇒ 一条事归档后下游就看不见了）；★**点一件已归档的事也能当链的起点**（改前落到"大事纪为根"、逐事件来路一条都没有） |
| **渲染层** | `src/render.js` | 新增 `cvEventState`：归档的事件**如实标「已归大事纪」**（不谎报"未了结"——归档的前提是整链结清，它一定平息了）；新增 `cvMsEntries`：纪内条目改成**标题 + 逐条链入口**（见 §2.4） |

### 2.3 ★先证红

把留档那段拆掉 ⇒ 两条新判据**当场全红**，且第二条的报错正是用户看到的现象：`milestone:m_10`（走进大事纪就没了）。

### 2.4 ★同批修掉的第二处病（违反本仓 A-3）

链视图"展开这一纪的条目"原来印的是**内部号**：`escapeHtml(n.ids.join(' · '))` ⇒ 玩家看到 `ev_11_2 · ev_12_1`。
本仓 A-3 明写「**代号绝不入玩家视线**」。而**编年·账目层那处是对的**（标题 + 逐条挂「链」按钮）⇒ **两处口径分叉**。
⇒ 链视图照账目层改齐；旧账没有 `rows` 时退回"`ids` + `titles` 同位取名"，**没标题就如实印号并注明**。

### 2.5 ★★旧账修不回来（如实登记，不是漏做）

本笔**之前**归档的那 63 条事件，事件对象已从热账删除，而**卷库只存编年行、不存事件本体** ⇒ **没有回填来源**。
⇒ 行为**退回原样、不编来路**。用户已知悉：**从现在起新归档的事件**来路齐全；**已归档的老事件**还是只剩标题。
