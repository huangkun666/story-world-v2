## 0. 一句话

**世界书只有一个，消费者有四个；"生效集合"不是一个数。**
- **聊天 LLM 那一侧有两层注入器**：ST 原生（13 条恒注入 + 254 条带触发词）
  ★**加上 ST-Prompt-Template 的 `getwi`——它"完全绕过酒馆内置的世界书处理逻辑，无条件激活"**
  ⇒ 那 **563 条 `disable=true` 的条目（847,565 字符 = 全书的 81.2%）照样被拉进聊天上下文**（实测被点名 **556 条 / 838,678 字符**）。
  ⇒ **这就是"为什么聊天模型能够知道历史"的机械答案**（原句是用户问的）。
- **引擎那一侧只有一个窗口**：`composeInitSource` 先按 `disable` 做**减法**，
  五件套再**只读头 30000 字符** ⇒ **2.9% 的全书 / 12.9% 的自己那段 src / 4.5% 的启用条目**。
- ⇒ 两边**用的是同一个 `disable`**（不是"ST 过滤了我们没过滤"）；
  真正的差别是**书里的真内容不在启用集里**，而**只有聊天那侧拿得到**。
