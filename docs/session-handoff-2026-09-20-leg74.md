## 1. 硬事实（本棒实测）

### 1.1 ★★★先把"三层"分清（这是本棒最该记住的一件事）

用户的问话是「**我不是说不要文风禁令了吗？**」——**他说得对，但那条令只落在了一层上**。
本棒逐层查清了现场（`pack.js:592-612` / `render.js:1828-1885` / `measure-leg64-rule-kinds.md:27`）：

| 层 | 文风禁令 在本棒之前怎么了 | 证据 |
|---|---|---|
| **每轮包**（模型看到的） | ★**一条都没进过**（leg64 起只取 `判断依据`+`世界观设定`） | `pack.js` 的 `ruleAnchorCore` 只取 `判据` 那一堆；`RULE_CLASSES_PACK` 只两项 |
| **账本** `canon.rules` | ⚠ **一直留着**，还带 `ruleKinds` 标注 | leg64 当时的拍板是"其余三类**一条都不删**，全留账给面板"（`pack.js:603` 旧注释） |
| **面板** | ⚠ **专门开一段**「文风禁令（N 条）—— 只留在这里给作者看，不进每轮包」 | `render.js` 按 `RULE_CLASSES` 逐类分段渲染 |

★★**所以这是一个"口径落错层"的历史遗留**：leg64 记录的是
> 「分类后哪几类进包？ → **只进「判断依据」**（不选"判据+文风禁令"…）」（`docs/measure-leg64-rule-kinds.md:27`）

——**问的是"进包"**，答的也是"进包"，于是"不进包但留账给面板"成了当时合理的落地。
而用户这次的意图是**更根本的那一层**：这一类**根本不该被抽出来记账**。
★**教训**：用户说"不要 X"时，要问清是**哪一层**不要（进包 / 入账 / 上屏）——
本棒是先量清三层、把差异摆给用户看，再按他拍的那层动手（**没有**擅自扩大处理面）。

### 1.2 ★★★为什么**不能**改成"让提示词别抽这一类"（本设计的关键，别改回去）

看起来最直接的办法是把 `文风禁令` 从提示词词表里删掉。**那样会更糟**，原因是数据结构决定的：

```
rules:  ['法则原文甲', '法则原文乙', ...]        ← 未分类的**纯字符串数组**
判据:   ['判断依据',   '世界观设定', ...]        ← 类别按位对齐，挂在另一列
```

- 词表一旦删掉这一类，模型遇到写法规矩时**必须**塞进剩下四类之一
  ⇒ 多半进「其他」或「世界观设定」⇒ **再也认不出来、清不掉了**，而「世界观设定」**是进包的**
  ⇒ 写法规矩会**混进每轮包**（比现在坏得多）。
- ⇒ 定稿口径：**类别词保留**（它成了**丢弃标记**，不再是展示类别），模型**照标**，
  **记账边界确定性丢弃**。丢弃凭**模型的标注**，**不靠关键词猜内容**
  （本仓明禁过拟合——猜错会误删真法则）。

★代码里这条口径写在 `abstract-tier.js` 的 `RULE_CLASS_STYLE` 与 `pruneStyleRules` 两处头注，
★判据里也锁了（`RULE_CLASS_GUIDE` 必须明写"不会进账本"+"优先不要交"）。

### 1.3 三个入口 + **唯一实现**

```
abstract-tier.js  pruneStyleRules(rules, ruleKinds) → { rules, ruleKinds, dropped }   ← 唯一实现（叶子模块）
      ↑                         ↑                                ↑
sanitizeCanon 收账时     mergeCanonChunks 并集后        settle.migrateStyleRulesFromCanon 载入期清旧账
（新账根本不带它）        （重抽/补抽的必经之路）          （老账早抽进来了，只能在这里摘）
```

★**摘除的两步**（`pruneStyleRules` 内部，判据锁着）：
① 摘掉"标注为文风禁令"的条目（**先删类别键**）② 清掉"值仍是文风禁令"的**陈旧键**
（键指向的原文已不在账上）。
★★**顺序是设计的一部分**：删键必须**先于** `keyByPrefix` 重挂类别——否则"互为前缀的近义长版"
会从被摘的短版那里**继承**到 `文风禁令` ⇒ 账上出现"标着已废弃类别"的法则（§2.5 演练④咬的就是它）。

### 1.4 旧账清理：`migrateStyleRulesFromCanon(ssot)`

**为什么必须在载入期清**：那些条目**早在 leg64 就抽进老账了**，只改抽取侧 ⇒ 老账里那一类会一直躺在面板上
（用户看到的正是它）。

| 纪律 | 怎么落的（判据逐条锁着） |
|---|---|
| **幂等** | 账上没有这一类 ⇒ **原对象返回**（`===` 判等）⇒ 每次载入不会改账一个字节 |
| **不可变** | 返回新 ssot，**绝不就地改**（判据实测原对象的 `rules` 一字未动） |
| **不许无声消失** | 摘掉的原话进 `meta.styleRulesPurged`（照 `legacyAttrsPurged` 的先例）+ 时点 `styleRulesPurgedAt` |
| **老账零扰动** | leg64 **之前**的账**根本没有 `ruleKinds`** ⇒ 一条都认不出来 ⇒ **原样返回**（不猜、不重抽） |
| **两列不许劈叉** | 摘原文**同时**摘类别键；摘空了就把 `ruleKinds` **整格删掉**（不留 `{}`、更不留 `undefined`） |

★**接线位置**：`web/index.js` 的 `loadWorld` 里，紧接 `migrateLegacyAttrs`（leg24 片4）与
`slimLegacyCompile`（leg60）之后——**第三处旧账清理，同一位置同一治法**。

### 1.5 ★★本棒自查发现的一个洞（已修，如实留档）

`loadWorld` 那个"账本变了就写盘"的条件原本是：

```js
if (changed || loc.inherited > 0 || migrated !== hot || pieceSync.renamed || …) {
    writeHotMeta(…);  const flushed = await flushHotMeta();   // 名册入账/旧账清理不该只活在页面内存
```

★`migrated !== hot` 只是 **`slimLegacyCompile`** 那一次的比较，**没带上本棒的清理**
⇒ 如果**只**发生了文风禁令清理，就**不写盘**：内存里干净了（面板是对的），
但**盘上那份老账照旧带着写法规矩**（导出/换机/看账都还能看到）——
而**紧接着那行注释写的正是"旧账清理不该只活在页面内存"**。
⇒ 已修：条件里补 `|| migrated1 !== migrated`（两次比较**各算各的**，不许合并）。
★判据：`leg74 真接线：载入期的清理必须进落盘条件`（含反向自证）。

### 1.6 `PANEL_BUILD` **升位** → `leg74-style-rules-purged`

照 leg62/63 那条老纪律（**玩家可见面真的变了就升位**）——本棒真的改了两处玩家会读到的东西：
① 设定页法则栏那段说明过去写「书里写下的规则条条都在这里，**一条不删**」+
   「**文风禁令**、变量指令与格言留在本页给作者看」⇒ **这两句在 leg74 之后是假的**；
② 会少掉「文风禁令（N 条）」整段。
★本仓最忌"面板印一个不再为真的数/话" ⇒ 两处文案都按**现算的事实**重写（"不在此列"）。
★与 leg71/leg72/leg73 的"不升位"不矛盾：那三棒是**纯结构搬迁、可见面逐字节没变**。
★起名合 `/^leg\d+-/`，不含那七个禁词。

## 4. 我（leg74）犯过的错 —— 下一棒别重犯

1. **★★在 `import` 花括号里写了一行注释 ⇒ 弄坏了两条结构锁。**
   `abstract.js` 那个 tier 模块 import 有**多行**，我顺手在 `pruneStyleRules,` 后面加了 `// …` 注释。
   而本仓"import 集合**不多不少**"那几条判据是**按逗号切大括号内容**来取符号名的
   ⇒ 注释把**下一个符号名**染成了 `// ★leg74：…\n RULE_CLASSES` ⇒ `module-layout.test.js` 两条当场红。
   ★**纪律：`import { … }` 的花括号里一律不写注释**（要写就写在 import 语句**上方**）。
   ★这个坑很隐蔽：**语法完全合法、`node --check` 全绿**，只有那几条"解析 import 集合"的判据会红。

2. **★★★演练"没咬住"有两种可能，必须先分清是哪种（本棒最值钱的一条）。**
   演练③第一版报"没咬住"。**那可能是判据瞎了，也可能是我的变异根本不是缺陷**——
   我没有直接去改判据，而是先写了个探针（`leg74-diag-bite3.mjs`）把两种变异的**产物**打出来：
   变异③（只删第一处删键）⇒ **孤儿键 0、残留 0**（第二道"陈旧键清扫"兜住了它）⇒ **它不是缺陷**，
   判据保持绿是**对的**；变异③′（两处都删）⇒ **孤儿键 1** ⇒ 那才是该被咬住的形态。
   ⇒ 换成③′ 后当场咬住。
   ★**纪律：演练报"没咬住"时，先证"这个变异到底有没有产生缺陷"，再决定改判据还是改变异**
     （leg71 那次是"把被测的那条锁自己摘了"⇒ 假"没咬住"；本棒这次是"变异等价"⇒ 真"不该咬住"）。

3. **★★判据拿"全文正则"判"某个条件里有没有某一项" ⇒ 假绿；反向自证又打错了行 ⇒ 假红。**
   §1.5 那条判据我第一版写的是"全文里有没有 `migrated1 !== migrated`"——
   而**上一行的日志**（`if (migrated1 !== migrated) console.info(…)`）里就有它
   ⇒ **日志那一行替条件作证**（假绿：条件里真删掉它，判据也照样绿）。
   我的反向自证更直接：`code.replace('migrated1 !== migrated || ', '')` **先打中的是日志那一行**，
   于是"删掉之后仍能匹配"⇒ 报**假红**，我一度以为判据写坏了。
   ★**纪律：判"某一行的条件里有没有 X"要先用唯一标识定位那一行，再在那一行上判**；
     反向自证要改的也必须是**那一行**（全文 replace 会先打中别处的同名串）。

4. **★★受控对照第一版做错了两次，结论差点被带偏。**
   ① 我在**产物**上做字符串回退——那只覆盖"我以为改了的"那几处，**其余差异看不见**；
   ② 我只抹了**一种**构建号 HTML 形态，另一种（`构建 <b>…</b>`）留在产物里，
      于是"净差异"里混进了构建号，我第一次以为"差异不止那几句"。
   ⇒ 定稿做法：**真造一份旧版源码**（反向还原 + 每条断言命中一次）+ **两种形态都抹** + **口径自证**
     （旧产物在旧口径下必须回到基线）。
   ★**纪律：受控对照要"造出对照组"，不要在对照组缺席时用字面量拼一个**。

5. **★端到端探针直接 `includes(原文)` 没考虑 HTML 转义 ⇒ 假红。**
   用户第一条原话里有 `<content>`，而面板走 `escapeHtml` 会画成 `&lt;content&gt;`
   ⇒ 我那条断言当场红。**那是判据写错，不是代码错**。
   ★**纪律：凡是"某段文字有没有画到面板上"的判据，一律按**转义后**的形态核对**。

6. **★我用 `{ ruleKinds: undefined }` 表达"这一格清空了" ⇒ 留下了一个自有键。**
   本仓判"这一格在不在"用的是 `in` / `Object.keys`（leg64 的零迁移锁就是这么写的），
   而 `{ x: undefined }` **会让 `'ruleKinds' in canon` 为真** ⇒ 违反"空着就是空着"。
   已修：显式 `delete nextCanon.ruleKinds`，并**补了一条判据**（"全都是文风禁令 ⇒ 这一格必须整个消失"）。
   ★**纪律：表达"键不存在"只有 `delete` 一种写法**，别用 `undefined` 占位。
