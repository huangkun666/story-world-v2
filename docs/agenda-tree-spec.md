## 0. 人话版：这会怎么样

现在的世界有个盲区：**盘算只会"推进"，不会"出生"**。势力们把手头的事办完（满步结算）之后，就只能没谋划地干动——K7 真跑里那 17 条"行动↔盘算不一致"警告就是这个盲区的现场录音。这个细案给世界装上**盘算树**：模型在世界步里可以**提议新盘算**（必须带来源：从事件、父盘算、或世界处境里生——无源之物不存在），引擎负责裁判出生——验明正身、挂父链（大树生小树，深链合法）、按 GC 上限把关（每轮至多俩新、在飞至多十五、顶层至多五）、检出依赖环自动拆（环里分量最低的让路，断链转"伺机而动"，编年留痕）。盘算从此有完整的一生：**诞生挂因 → 委派落痕 → 推进留痕 → 终结产果**——而终结不再只唱"达成"一种结局：撑到满步但被打崩的按**败露**结清，带着未竟事业和未了子盘的按**变形**移交后事（顺带把两笔执行债清了：满步败露/变形分支、memory.promises/blocked 写入路径）。你看到的世界：势力打完一仗会开始谋划下一仗——而不是干站着等下一轮点名。

## 3. 设计

### 3.1 世界步新增 `newAgendas`（契约层，拍板点 T1）

- **形状**（与 actions 同哲学——模型只提议，引擎裁决）：
  `{ entity: 提议方（必须存在的实体）, goal, stage?, visibility: 'known'|'concealed', maxSteps: int 1..8（缺省 4，引擎钳制）, source: { type: 'event'|'parent'|'state', ref? }, note? }`
- **语义校验**（check-step，A-1）：
  - `entity` ∈ 实体池；`visibility` 枚举；`maxSteps` 钳制 [1,8]；
  - `source.event` → ref 必须是已存在**未决**事件；`source.parent` → ref 必须是已存在**在飞**盘算且 ≠ 自身；`source.state` → 无 ref。「无源之物不存在」（§4.2 同哲学延伸）。
- **落账形状**（schema 扩展）：`{ id: a_<tick>_<n>, owner, goal, stage, visibility, maxSteps, progress: 0, memory: { promises: [], done: [], blocked: [], turnsAlive: 0 }, parentId? }`——与既有 agenda 同形状 + 可选 `parentId`（契约零新类型）。

### 3.2 出生裁判（引擎，拍板点 T2）

- **落点**：结算管线内 gate 之后、裁定之前（与门控同序同哲学）。
- **静默滤除（A-2）**：静默方提议的 newAgendas → 滤除（计入 `silentDropped.newAgendas`，双面无痕）；被点名应答方（lifted）可以提议。
- **GC 上限（A-3，沿用已暂定数字，报批联动）**：
  - 每 tick 新生 ≤2；在飞全局 ≤15；**顶层（无父盘算）≤5**；
  - 超限 → 拒建该条 + 警告（"盘算大厦顶"），世界其余照常——超限不新建（§4.3 存原文语义之一）。
- **挂因留痕（§4.4①/②）**：
  - `source.state` → 编年"由处境而生：<goal>"；
  - `source.event` → 编年"因事而生：由「<事件>」而生"；
  - `source.parent` → 编年"委派：<父>拆大给小——<goal>" + 父 `memory.promises` 写入子 id（A-5 前半，清 promises 写入债）。

### 3.3 树与环（引擎，ANCHOR §4.1 落地）

- **深链合法**：parentId 链不限层深（"依赖最多一层"限制不做——真实政治如此）；
- **环检测**：每次创建时从新节点沿父链 DFS 上溯，触到自己即环（确定性）；
- **自动拆（A-4）**：成环不拒绝整件事——环内各节点按分量排序，**最低分量方**与其父的边断开（分量相等按 `progress` 浅者先让），该盘算转"伺机而动"（独立、无父）+ `memory.blocked` 记"拆环让路"（清 blocked 写入债）+ 编年"拆环：<低分量方>让路转伺机"（§4.1 留痕）；
- **兑现落痕（§4.4② 小兑现大）**：子盘算满步达成 → 其父 `memory.done` 记"兑现：<子 goal>" + 编年。

### 3.4 满步强制结算三态（引擎，拍板点 T3；清执行债"满步败露/变形分支"）

满步（progress ≥ maxSteps）时引擎裁决结局（**模型无直接终结通道**——advances 只推进，closed/变形/败露全归引擎，§3④）：

| 态 | 判据（提案） | 编年 |
|---|---|---|
| **达成** | 近 2 tick 对 owner 无负向 δ（stateChanges/影响通道负增量累计 < 0.05） | 现有"达成（终结产果）" |
| **败露** | 近 2 tick 负向 δ 累计 ≥ 0.05（被打崩的谋算不唱凯歌） | "败露：功败垂成（<goal>）" |
| **变形** | 存在在飞子盘算 → 原盘算终结，各子断父链转独立（事业移交诸子） | "变形：事业移交诸子（<子数> 项断链转独立）" |

- 三种终止都终结产果（§4.4④：死盘算变成世界的后果，不是删除）；变形/拆环会改变 parentId（树在结算中演化）。

### 3.5 演化上下文与 prompt（契约层）

- pack：在飞盘算含 `parentId`（树形是"谋划的结构"，可见；**分量数字不可见原则 P3 不动**）；
- prompts：六铁律补"**可提议新盘算，必须带来源（event/parent/state）——无源之物不存在**" + 内嵌 JSON 模板增 `newAgendas` 示例（延续显式模板约束）。

### 3.6 双流（渲染层）

- 观棋格局行保持平面计数（在飞盘算数与顶层数并示）；树信息由编年自然承载（委派/拆环/变形/兑现各有措辞）；
- 注入侧不新增分支——静默方新盘算由 gate 保证双面无痕，渲染不重复过滤。
