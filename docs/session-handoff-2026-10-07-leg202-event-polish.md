## 最终行为

- `src/event-provenance.js` 区分生产来源 chat/world/setting/unknown 与记录类别 result/state/maintenance。聊天的关键词、向量、冷热卷和最终格式化统一排除聊天结果与维护记录，过滤发生在条数及字符预算之前。世界召回保持原行为；未知来源仍可选入并单列统计。
- 世界产生的新后果即使因指向聊天事件，也仍属于 world。原编年中确定的 `事件「世界结果」——沿「聊天标题」而来` 格式在聊天投影中改为引用事件编号，后果正文保留，原账不改。只对能按事件 ID 核对的格式处理，不按相似度删文字。
- 普通行动不再自动成为事件，只登记当轮已行动者。旧协议变化形成已完成结果，承诺形成未决事项；值未变不新增变更事件。旧账中的既有事件不迁移、不删除、不自动关闭。
- v3 明确结果与关联的多条变化/承诺共用一个事件。未解析参与者保留名字，不伪造实体。完成或归档事实仍可产生新的世界后果；盘算因须仍在办，收场仍只能做一次。
- `turnFacts.events` 提供简洁结果，`actedIds` / `changedFields` 分别提供行动与字段保护。其他世界包栏目保留事件引用，省去本轮结果的重复正文；既有总预算规则保持。
- `meta.chatConsumption` 将聊天、稳定消息 ID、swipe/版本、内容指纹、消费轮次、结果事件及变更字段随世界同笔保存。相同正文的不同消息各自消费；已消费消息的手动补推只推进世界，传空 dialogue；用户和系统消息不作为助手标签。
- 编辑、删除、swipe 切换已消费消息时阻止自动覆盖，并指向受影响轮之前的快照。`previewConsumptionRecovery` 只预览可恢复输入，原文缺失会明确标记，不自动重放或替换历史。
- 异步提交核对聊天作用域、世界版本和输入版本；失败不发布候选世界或消费记录。保存期间输入改变时，再次核对并在作用域仍一致、候选尚未被别人替换时回存原账。迟到结果不能写进另一聊天或回档后的世界。
- 消息消费、事件来源和完整世界输入组成的读数只进入已有复制报告，没有新增诊断页面。

首轮对照 `real-model-comparison/` 中的受控变化写了合法字段表之外的「通行许可」，因此未落字段；只用于普通动作路径观察，不能作为重要结果验收。第二轮改用合法「身份」字段并重新跑两组对照，前一轮证据保留。

模型虽设置 temperature=0，每臂仍只是一轮样本，内容具有随机差异。世界事件条数减少不能直接解释为质量提高或遗漏减少；输入组成统计也没有测量内部注意力。学校新实现中第三方确认许可并提出合作，大荒中第三方借许可留下追踪印记，属于仍在生成的新后果；是否长期少重复、多线均衡，须更多固定输入和长跑样本。

结构泛用性脚本已对本机真实世界书目录运行；它统计的是既有机制的结构依据，不能单凭该表宣称新事件机制的语义质量。新增规则依据协议、记录来源与事件 ID，未引入世界类型词表。

## 剩余现场边界

- 官方 ST、TT、手机的真实保存后重新载入尚未操作。契约夹具验证了宿主调用形状、失败重试和回滚，没有证明实际磁盘或 IPC 写入。宿主超时后才完成的已发保存无法可靠取消，仍需现场复验。
- 旧世界没有历史消息消费身份，不能事后猜出哪些消息已被消费。本次不按标题或正文推断历史。升级时直接对仍停在末条旧助手消息的聊天推进，可能首次登记该旧消息；应在副本或快照前核对后再继续，新记录产生后才有持久防重依据。
- 冷卷先写、热账后提交的既有顺序，可能在热账失败或作用域切换后留下未挂接的冷卷。热账不会发布迟到候选，孤卷整理没有扩进本次范围。
- 很大的世界账会在守卫边界序列化核对版本；本次优先正确性，未增加消息硬配额。

后续现场验证应使用世界副本和可恢复快照，至少覆盖：自动处理后手动推进、刷新后再推进、失败重试、编辑/swipe/删除、切聊天、同轮回档，以及 TT 的额外消息 ID 完整保存。模型长跑和宿主发布分别记录授权与实测。本次没有替用户发布。
