## 2. 交付：一栏新东西 ＋ 两处实测抓出来的真缺陷

### 2.1 那一栏是什么

| | |
|---|---|
| **名字** | `相关往事`（人话："系统按你这一轮正在动的事，替你把旧账翻出来的那几行"） |
| **谁发起** | ★**引擎**，在 `buildEvolutionPack` 里——**模型还没开口** |
| **为什么必须这样** | 模型一开口，这一轮的输出就已经在生成中 ⇒ **它没法在说话之前先问一句** ⇒ **"本轮到位"这条要求在结构上就排除了任何模型发起的取回**（那条现成的"点名取线 ⇒ 下一轮给"通道因此**不合格**，与它"150 轮 0 次"是两件事） |
| **查询怎么来** | `buildQuery(ssot,{picks})`（上场实体**真名** ＋ 未决事件标题）＋ **在飞盘算的目标原话** ⇒ 交给检索层的 `按真名取` ＋ `按词` |
| **取哪几行** | ★**从最旧的那一端取**（见 §2.2 的②） |
| **成本** | **零额外模型调用**（检索层是同步的）；引擎侧单轮耗时实测 **峰 15ms**（红线 200ms） |

**三条口径**：**只取原文**（`briefLineText` 只去固定前后缀，不改写）· **不重复"最近的事"**（按**行身份**排重）·
**有空才挂键**（取不到 ⇒ 键不出现，旧世界逐字节回到今天）。

## 2.4 ★★ 第二件：**全史索引**（`故事线` 不再只说得出最近 500 轮）

**病（实测数，不是推演）**：`LINES_TOP = 40`，而干净合成世界**每 500 轮立出 24.4～40.6 条线**
⇒ **一屏只装得下约 500 轮**。一万轮时账上 **488～812 条线**，模型只看得见 **40 条（5%～8%）**；
而它是**按"收口轮次"从新到旧**截的 ⇒ **第 3,000 轮立的那条线，在模型眼里从来没有存在过**。

★★**更刺眼的是**：`linesOf()` 一直返回 `{lines, total}`，而**生产三处都只用 `lines`**——
`total`（账上真有几条）**算得出来却被丢掉**，只在测试里被读过 ⇒ **模型拿到的是一张残缺、却不说破的地图**。

**改了三处（一处一个尺子，必须同源）**：

| 处 | 改成什么 |
|---|---|
| `src/lines.js` | 新增 `pickLinesForPack(world,{top})`：**相关优先，其余照旧**（两组各自内部仍按收口轮次新→旧）。相关性**只用账上真有的结构**（这条线里有没有未收口的事/谋划，或哪件事波及到"正在动的人"），不猜、不模糊匹配。★**纯从账算**（不依赖 `picks`/`moveFact`）⇒ 出包侧与校验侧算得出同一份 |
| `src/pack.js` | `故事线` 改用 `pickLinesForPack`；**被截时挂 `故事线说明`**（"账上一共 N 条线，这里只摆得下 M 条……**没摆出来的不是没有**"）；没截时不挂（旧输出逐字节不变） |
| `src/check-step.js` | 点名校验改成认**账上真有的全部线**（原来是"截前 40 条"） |

★★**第三处非改不可，否则会当场拒掉整步**：栏里现在是"相关优先"的 40 条，而校验若还按"收口轮次截前 40 条"，
模型点了它**明明看见**的一条老线会被判"没有这一条线" ⇒ **整轮白跑**（不是丢一条提议）。
★口径**没松**：仍然只收账上真算得出来的根 id，**编的照样不认**。
★同一处 `buildLineDetails`（"线的经过"）也跟着改成全史，否则"点了名却取不到经过"。

**判据 4 条**：**I1** 老的但相关的线进得来（并用一条前置断言证明"老的尺子进不来"）· **I2** 截了必须说出共几条 ·
**I3** 一条相关线都没有时**逐字等于今天**（旧世界零漂移）· **I4** 没截时不挂空话。
