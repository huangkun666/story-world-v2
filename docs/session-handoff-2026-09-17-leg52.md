## 2. ★★ 新发现：**「一个数两把尺子」在设定页与信息带还活着**（leg52 修）

**现场读数（同一份真账 × 同一份真源，同一时刻）**：

| 面 | 读哪一本账 | 画出的「天时」 |
|---|---|---|
| 参数页 | 真源（`cfg.paramEnv`） | **大灾** |
| **设定档案页** | **镜像**（`paramsOf`） | **未定** |
| **观棋信息带** | **镜像**（`paramsOf`） | **未定** |

**根因**（`src/render.js`）：`renderSettingHtml` 与 `renderInfoBandHtml` 的**签名里没有 `paramEnv`**，直接 `paramsOf(world)`；
而 `renderAll` 调 `renderSettingHtml(world)` 时**连 `config` 都没传**（同一个函数里参数页是**传了**的）。

⇒ `param-hub.js` 的口径是「**"这一格该显示什么值"只在 `displayEnv` 一处裁决**」，
leg48 把**参数页**治好了（它自己的注释写着"本仓『一个数两把尺子』的老病在这里发作过**九轮**"），
**但只治了一个面**——设定页与信息带至今读的是"下一次落账才追上"的镜像。
玩家在参数页选了天时=大灾，切到设定页/关掉面板再看就是「未定」：**这就是"改了回默认"的观感层残留**。

**修法与它的边界**：
- 新增 `paramEnvOverride(env)` / `resolveEnv(world, envOverride)`（`render.js`）——**只挑 `isPlayerInputKey` 的键**
  （与 `param-hub.displayEnv` **同一把尺子**）；因变量绝不接受覆盖（`param-store.js` 明写真源无权管辖它们）。
- `renderInfoBandHtml` / `renderSettingHtml` 收 `{ config }`；`renderBoardHtml` 把 `opts.config` 透传给信息带；
  `renderAll` 给设定页补上 `config`。
- ★**接线面不用改**：`web/index.js` 的 `renderCfg()` **总是**注入 `paramHub.displayEnv(w)`（`:1706`），
  两处 `renderAll` 都走它（`:271` 的 `cfgForRender` 与 `:1920` 的 `renderCfg()`）⇒ 真源一路到底。
  新判据 `leg52·G` 把这条**接线**也锁住（防下一棒新加一处忘带 `config` 的 `renderAll`）。

★**顺带修掉一个真洞**：`src/params.js` 的 `PARAM_ROWS` 原来把 `envOverride` 当**整份替换**
（`const cur = envOverride ?? paramsOf(world)`）⇒ 真源里**混进一个因变量**就会把"世界刚写下的结果"顶掉。
**leg52 之前咬不到**，是因为 `render.js` 传进来的那份已经过 `isPlayerInputKey` 过滤（上游挡住了）。
本棒把过滤**同时**下沉到 `params.js`（判据用 `PARAM_NATURE`，不 import `param-store`——那会让这层叶子反向依赖）
⇒ 两处一致是**一道锁**，不是一个补丁。判据 `leg52·E` 当场抓红过这一格，留档。
