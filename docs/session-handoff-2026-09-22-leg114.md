## 1. 病：那个读数是个"永远刚好"的数

### 1.1 人话版

这个插件每轮要给**世界模型**递一份"料"（往事、名册、各方谋划、处境、设定…）。这份料有个**上限**，超了就按固定次序裁掉一些段落。
上限原来是写死在源码里的 **30000**（估法：字符数 ÷ 3）。

你说「**30000token 预算也太少了，我一般玩聊天 rp 每轮 5,6 万都正常**」——**这是你对自己模型的实测，比两个星期前那个数字更有依据。**
所以本笔把它做成**面板上可填的一格**。

### 1.2 ★★但细案漏了一格（这是本笔最值钱的发现）

细案里我推荐的"丙案"是：**先给你看读数，你按读数填**。可是真去核那个读数时发现——
账上每轮记的 `packTokens`，是在 `trimPack` **裁完之后**才量的（`pack.js` 先裁、后量）。后果：

- 包**没撑满**时：读数如实，一切正常；
- 包**撑满**时：它被裁到"刚好装进上限"⇒ 读数**恒等于上限附近**，你从账上**只会看到"30000，刚好合适"**。

⇒ **你嫌它小，恰恰是因为它在裁；而账上那个数看不出来。** 所以本笔同批补记一格 **`packTokensBeforeTrim`（裁之前有多大）**：
两个数一比，"裁掉了多少"当场看得见，该填多少也就有了依据（面板那行会直接说"填到 X 以上"）。

### 2.1 ★它是"尺"，不是"闸"（本笔最要紧的一条区分）

| | `每轮递线`/`每轮事件` 那几个 | **包预算（本笔）** |
|---|---|---|
| 它是什么 | **闸**：限制**模型能做什么**，超了**拒**（还静默拦） | **尺**：限制**引擎给模型看多少**，**不拦任何东西** |
| 静默吗 | 是（`sanitize-step.js` 静默截断） | 否（裁了什么**如实写进** `pack.trimmed`） |

⇒ 所以它**不属**铁律 2 那个"数字先报批"（那条管"限制模型/影响世界"的判据值）；它只动**容量**。
**但它的真风险另有一条：看到更多 ⇒ 模型行为会变** ⇒ 这就是**出厂值本笔不抬**的理由。

### 2.2 ★为什么必须住进 `limits.js`（不能就地改 `pack.js`）

这个数有**三处**读它（`pack.js` 的 `buildEvolutionPack` 与 `trimPack` 的形参缺省、`smoke.js` 的冒烟断言）。
就地改一处 = **立刻两把尺子**（包按 A 裁、冒烟按 B 断言）。⇒ 先收成**一份**，再从 `resolveLimits` 分发。

★**依赖方向是安全的**（实测）：`limits.js` 是**零 import 的"叶子里的根"**（`THREADS_TOP` 那些值是它**自己定义**的）
⇒ `pack.js → limits.js` 这条边**没有回路**。
★**本笔勘正一句旧话**：`pack.js` 里那句"`limits.js` 要引用本文件的 `THREADS_TOP` ⇒ 反向 import 会成循环依赖"
是 **leg40b 的旧话**——那时 limits.js 还 import 别人；今天它零 import，**那句话已不成立**（照实改了注，**没动** `threads` 那一行的行为）。

### 2.3 ★不设条数上限、也不新增任何"提案态数字"

`LIMIT_GEARS['包预算'] = [30000, 60000]` —— **只有两档，因为只数得出两个有出处**的值
（30000 = 出厂定案；60000 = ★**你自己那句"每轮 5,6 万都正常"**）。
★**没加第三档**：再往上（12 万之类）**没有任何实测出处**，写进去就是"能开多大开多大"（本表纪律：不许有无出处的档位）。
它现在只是**建议值**（leg54 起白名单已撤，填别的照收）⇒ 两档够用。

## 4. ★★本笔踩的坑（都值得记）

### 4.1 ★`settle.js` 那处建包**原来没递 `lim`** ⇒ 账上读数与真包不一致（旧病，本笔必须治）

全仓有**两处**建包：`tick.js:259`（**真发出去的那一份**，递了 `lim`）与 `settle.js`（**记账用的那一份**，**没递**）。
⇒ 记账那一份一直按**出厂** `每轮递线` 建，而真包按**账上设的**建 ⇒ **同一个 tick 两个尺寸**。

★**为什么本笔非治不可**（不是顺手改）：玩家把预算调大之后，记账那一处仍按出厂 30000 裁
⇒ **面板读数会谎报"被裁了"**（而真包根本没裁）。⇒ 对齐它。**对没设过任何上限的账：`resolveLimits` 给的就是出厂值 ⇒ 逐字节回到今天。**

### 4.2 ★★环基线那 4 条环**全是幻影**（本笔最该带走的一条）

我加了 `pack.js → limits.js` 这条**合法**的边之后，环判据当场红了一条
`settle.js → pack.js → limits.js → settle.js`。查下去发现**病不在那个 import**：

- 检测器的正则 `/from\s+'(\.[^']+)'/g` **扫全文，包括注释**；
- `limits.js:15` 是 leg40b 留档的一句注释，它**引用了当年写错的那一行**（原文里就带着 `from './settle.js'`）
  ⇒ 被算成一条 `limits.js → settle.js` 的边；
- 把注释去掉后实测：`limits.js` 出边**零条**，整个 `src/` 的 import 图**零环**。

⇒ **四条"基线环"全是注释造成的幻影**（不只这一条）。治法：让 `importGraph` **用上本文件早就有的那把尺**
（`stripComments`，它自带"字符串里的 `//` 不是注释"的反向自证）——**不新造第二个剥离器**，基线清空。
★这条判据的实质因此**变强**：从"没有新环"变成"**真的零环**"。

### 4.3 ★`trimPack` 在"裁无可裁"时会把包**裁得更大**（+50 est）

实测：一个 3031 est 的包，预算给 2400 ⇒ 裁完 **3081 est**（**变大了**），且如实留了 `budgetOverrun` 痕迹。
机理：剪枝序全部用尽仍越界时，它把 `budgetOverrun` 记进 `trimmed`，而 **`trimmed` 自己也要占几十 token**，
且那一格是在**最后一步**才挂上去的（`pack.js` 的 `if (cut.length) pack.trimmed = cut;` 排在越界检查**之后**）。
⇒ **"裁过"这件事本身把包撑大了一点。**

★**这不在本笔范围内**（它是既有行为、且它**如实报了** `budgetOverrun`，不是静默），**本笔没改它**。
但本笔的面板读数**必须**处理它——否则会印出"**裁掉了 −50**"这种荒唐话，或者更坏：把它当成"没裁"（**那是假话**）。
⇒ 读数写了**三支**：没裁 / 真裁小了 / **裁无可裁**（第三支如实说"这一格填得比这份料的最小可能还小"）。
**下一任若要治它**：把越界检查挪到 `pack.trimmed` 挂好之后，或者让 `trimmed` 不进包（改成非枚举）。

*  **看着刚好合适**。⇒ **一个永远"刚好"的读数，等于没有读数。** 补记"裁之前有多大"才让那一格可用。*
*★**第二值钱的一条**：**判据也会骗人，而且骗得比代码更久**——*
*  环基线那 4 条"既有环"**全是注释造成的幻影**，而它一直绿着、还写着"本棒没有引入新环"的保证。*
*  修它的那一步**不是改判据，是让判据用上文件里早就有的那把尺**。*
*★**第三值钱的一条**：**"改了一处，另一处没跟着改"是同一个病的两种长相**——*
*  本笔逮到 `settle.js` 那处建包没递 `lim`：它一直按**出厂**值量、而真包按**账上**的值建。*
*  这与"一个数两把尺子"是同一个病，只是它藏得更深（两处都在跑、都不报错）。*
