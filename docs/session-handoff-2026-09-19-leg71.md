   ★**纪律（已是第二次）：凡"判断某个东西在不在"的判据，一律跑在剥注释后的源码上**，并附**剥离器自证**
   （`test/module-layout.test.js` 的 `stripComments`；`test/adopt-scale-draft.test.js` 那份是同款）。
2. **★★★我把"被测的那条锁"自己摘掉了 ⇒ 报了一次假"没咬住"。**
   第④段演练要咬"模块数基线"，而那条断言**住在用例名含 `丙案⑤` 的那条用例里**
   （模块数基线与环基线写在同一条判据），我的摘锁清单写的却是 `丙案⑤|丙案⑥|丙案⑦`
   ⇒ **第二跑把被测条摘了 ⇒ 全绿 ⇒ 报"没咬住"**，而全量跑的红才是真相。
   ★**纪律：摘锁清单里绝不许有"本段要咬的那条"；摘之前先确认目标断言住在哪个用例里**
   （本棒为此连查四次才定位——`leg71-diag-4b/4c/4d.mjs` 的读数口径留档在探针头注）。
3. **★对照必须"只差被测那一件事"。** 第一版渲染哈希对照拿 **HEAD（leg69）** 比现在，
   差异里**混着 leg70 的 UI 改动** ⇒ 那个"不同"证明不了丙案（见 §1.5 第 1 条）。
   ★**纪律：做"改动前 vs 改动后"的对照，先问一句"这两棵树之间只差我要测的那件事吗"**；
   不是就得**造**一棵只差那一件事的树（本棒用 `git worktree` + 把其余文件换成当前版）。
4. **★规范化（正则替换）很容易"抹多"。** 我第一版抹构建号的正则把产物里**同一句话里的普通词**也抹了
   （3 处只该抹 1 处）⇒ 抹多 = **放过了真差异**。
   ★**纪律：规范化只许用"精确串 + 先断言出现次数"**，不许用宽泛正则（这与 leg69 §4.5"掩码把要找的代码一起抹了"同源）。
5. **★夹具没覆盖 = 判据说的话没有意义。** golden 终态 **刻度 0 / 法则 0** ⇒ 第一版"渲染产物不变"**根本没走到**搬走的代码。
   ★**纪律：写"产物不变/行为不变"这类判据前，先加一条"覆盖自检"**（产物里必须出现被测那族的记号，缺一个就报错）。
6. **★工具脚本自己会咬到自己：** 我第一版搬迁脚本用**模板字面量**写注释，而注释里含反引号 ⇒ **脚本当场语法错**；
   另一版用 PowerShell `git archive | tar -x` 喂二进制 ⇒ `bad header checksum` 刷了一屏。
   ★**纪律：写"改文件/搬代码"的脚本时，一律字符串拼接 + 不用 shell 管道搬二进制**（这两条已写进探针头注）。

### 5.4 ★坑：`--test-skip-pattern` 是**正则**且支持 `|`，但"摘哪条"要先查清楚

- ★**它不会把跳过的条数记进 `ℹ skipped`**（那条恒 0）⇒ **只能靠 `ℹ tests N` 对不上总数来判断**（leg70 §5.4）；
- ★★**最大的坑不是语法，是"摘错条"**：本棒把"被测的那条"自己摘了，于是得到一次**假"没咬住"**（§4.2）。
