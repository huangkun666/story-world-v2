## 4. ★★★ 本笔最值钱的三条

### ① **"搬一张卡"的真形状：处理器与存储一个字都不用动**

**为什么能不动**（三处，缺一条这条结论就不成立）：

| 那条链 | 它住在哪 | 为什么搬家不影响它 |
|---|---|---|
| 四枚注入开关 | `web/action-router.js` 的 `route()` **早退**（① `data-inject-switch`） | 它是**绑在面板窗口上的 click 委托**（`win.addEventListener('click', …)`）——参数页就在同一个窗口里 |
| 「一轮最多递多少条行动」 | `web/model-channel.js` 的 `bindSettingsForm`（`data-settings` 那一支） | 同上（`input`/`change` 委托也绑在**面板窗口**上，`getWin: () => document.getElementById(WINDOW_ID)`） |
| 开关按下后的**原地改字** | `web/index.js` 的 `sw2ToggleInject` | 它查的是 `document.querySelectorAll('[data-inject-switch="键"]')`——**全文档按属性查**，与在哪一页无关 |

⇒ ★**教训（省下一整轮返工的那种）**：动手搬之前**先把接线读一遍**（"谁在监听、监听的根是谁"），
比搬完再修便宜得多。**本笔因此只改了 `web/index.js` 的两个字符串**。

★★**唯一必须跟着改的那一处**：状态条那句「（⚠ 这一格没在眼前更新——切走再切回**设置页**就是新状态）」
——搬了家不改它，它就会**指着一个没有那一格的地方**（本仓"面板指路必须指到真有的地方"那条纪律）。

### ② **分组口径必须落在真源，不许渲染层自己再判一遍**

病（存量）：`limits.js` 里"哪几个是闸、哪几个是尺"**只写在注释里**——
`LIMIT_DEFAULTS` 的 `包预算` 那条写着"★尺：只裁料、不拦事"、`往事轮数` 那条写着"与 `包预算` 同族（都是尺）"。
**注释是散文，机器读不到** ⇒ 渲染层要分组，就只能自己再判一遍（那就是**第二份真相**，迟早分叉）。

⇒ 定稿：落成 **`LIMIT_META[k].kind`**（唯一真源）＋ `LIMIT_KIND_NOTE`（两句人话）。
判据照它验（`LIMIT_KEYS` 逐个必须有 `kind`），渲染层照它分组。

### ③ **渲染层按表序走，不写"先 filter 闸、再 filter 尺"**

```js
let capKind = null;
const capKnobs = limitRows.map((r) => {           // ★按 limitRows 的表序走
    const kind = LIMIT_META[r.key]?.kind || '';
    if (kind === capKind) return limitKnob(r);
    capKind = kind;
    return 组头(kind) + limitKnob(r);
}).join('');
```

**理由**：filter 那种写法**一旦条件写错，会把某一格从页面上整个抹掉**——
而判据只数得出"少了一个框"，**指不出是谁**（本仓 leg103 §G 那条："数组里没有的词等于不存在"）。
按表序走最坏只是**组头位置怪**，框一个都不会丢。

## 5. ★ 我栽的一跤（如实登记）

写那条"分组"判据时**第一版就红了**，红的原因不是代码、是**尺子**：

| 第几版 | 我写的 | 咬到了什么 |
|---|---|---|
| 第一版 | `cap.indexOf('<b>闸</b>')` 当"闸那一组的起点" | **上面那句结论**（「**闸**填小了会拦下…；**尺**一个东西都不拦…」）里**也有**这两个字 ⇒ 命中的是结论句 ⇒ 切出来的两段里**一个框都没有** |
| 定稿 | 锚用**整行结构** `'<div class="sw2-row sw2-limit-group"><b>闸</b>'` | 咬的是"**那一组真的从哪开始**" |

★**这是本仓的老毛病第 N 次**（leg142 §5 连着两次"词面代替语义"）：
**尺子错的时候，看起来永远像行错**。写判据先问一句"我要咬的是**哪一层**"。

★★**同一天第二次差点栽进同一个坑（这次在写的时候就抓住了，留档）**：
组头那句说明我第一版写成「尺 —— 一个东西都不拦，**只管「看多少 / 看多久」**」——
而卡片顶上那句结论**已经有**「尺一个东西都不拦，只管「看多少 / 看多久」」（**同一句话印两遍**，
正是用户这次说"字太多了"要治的那类）⇒ 改成各七个字的短标签（**照展示页的组头写法**）。
★**改短之后判据也跟着出问题了**：那条断言原本只找"那句话在不在"，而短标签
（`一个东西都不拦`）**是结论句的子串** ⇒ **组头整个删掉它照样绿**（假绿）。
⇒ 定稿把锚**连着组头那一行**一起咬：`'<div class="sw2-row sw2-limit-group"><b>尺</b><em>一个东西都不拦</em>'`，
并**先证红**（把 `<em>` 清空 ⇒ 当场红）。
★**两条教训合起来是一句话**：**判据的锚要咬"结构里的位置"，不是"页面上有没有这几个字"**。
