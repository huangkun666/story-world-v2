## 4. ★★★ 本笔最值钱的六条

### ① **"只在发版时才跑的闸"等于没跑过——发布流程自 leg122/leg124 起就是断的**

**病（本仓自己立的闸，自己没跑）**：`publish-release.mjs` 会把子树导成**独立根树**，再在**导出件里**
跑判据、冒烟、文档守门（"社区装到的那份就是我测过的那份"）。而这条流程**自 leg107 之后一次没跑过**，
期间 leg122 和 leg124 各往里塞了一处**只在导出件里才发作**的东西：

- **leg122**：用户令「`kb/` 不要进 git」⇒ 它被 `.gitignore` 挡住 ⇒ **进不了发布树**。
  可知识索引的**指纹**是按"盘上有哪些卡片源文件"算的 ⇒ 工作区 `d033988e`、导出件 `0a62e514`
  （**差 11 份**，与 `kb/` 十页 ＋ `kb-index.json` 的数目**逐一对得上**）⇒ 导出件的 R10 **恒红**。
- **leg124**：把 `published.commit` / `.date` 改成**现读 git**。导出件**不在任何 git 仓库里**
  ⇒ 读成 `null`，盘上是字符串 ⇒ 逐字节比对**恒红**。★这**违反了 leg106 自己立的规矩**
  （"一切'问本机'的结果不进这个文件"）。

**为什么没人发现**：这两条**只在导出件里发作**。而仓里那三道闸（判据、冒烟、文档守门）
**在工作区里全绿**——本笔实测：`--dry-run` 之前，`node --test` 1390 全绿、冒烟 PASS、守门 PASS。
★**"闸装在导出件里"这件事本身没有价值，除非有人真跑它。**

**代价**：发布仓**默默停在 `leg105-deadpager` 约 40 棒**（点 release 下载的人拿到的是那一版）。

**治法**：`build-kb.mjs` 的哈希基只取"进得了发布树"的源文件（`NON_SHIPPED`）；
`audit-docs.mjs` 的那两格改常数（**值一个字节没变**）。
★**给下一任的一句话**：**改完发布流程，必须真跑一次 `--dry-run`** ——
它是唯一会发现这类病的装置，而它跑一次只要几分钟。

### ② **未提交的工作会挡住一切下游动作**

`publish-release.mjs` 导出的**是 `HEAD`**，且第 ① 步就要求工作区干净。而本笔开工时
**leg129–leg145 十七棒的改动全在工作区里**（115 改 ＋ 33 新增），HEAD 停在 **leg128**。
⇒ 照现状直接跑，推上去的是 **leg128**，不是 leg145 —— **而且脚本不会报错**（它忠实导出了 HEAD）。
★**"我以为推了最新版"与"真的推了最新版"之间，隔着一次 `git status`。**

### ③ **gitignored 的东西会从哈希里悄悄漏掉**

任何"**按目录现取、再哈希**"的机制，都要先问一句：**这些文件进得了发布树吗？**
`kb/` 的例子说明：**被 gitignore 的目录在开发机上是"存在"的，在发布件里是"不存在"的** ——
于是同一个提交、同一份脚本，**两处算出两个指纹**。而守门只看指纹 ⇒ 一边绿一边红。

### ④ **"看起来像失职的"，先查是不是有人裁定过**

用户问「**tag怎么不动**」。第一反应是"漏了/忘了"。**真相是**：leg100 发预览版时打了
`v1.0.0-preview.1`，leg103 他当场裁「**tag/release 甲/乙/丙 取丙〔不动〕**」，
并写明「★**若下一任要改这个口径，先问用户**」—— 所以 `publish-release.mjs` 第 ⑤ 步
**写死"不带 tag"**，跑完还打一行"★本脚本不动 tag"。
★**这是设计，不是事故。** 而他随后拍了新口径：**tag 只跟 release 走**（不是每次推送都打），
做法是「**另打一个新的，旧的一律不碰**」——★**tag 不可变**：已经下载过 `preview.1` 的人
手里是另一份内容，挪它等于让同一个名字指两份东西。

### ⑤ **一个面板的"异常"状态行，本该只说自己的事**

**病**：`web/index.js` 挂的是**全局** `window` 钩子（`error` ＋ `unhandledrejection`）
⇒ 页面上**任何人的**未捕获异常都写进本插件的状态条。实测那一回：
**SillyTavern 自带的 TTS 扩展**（`public/scripts/extensions/tts/system.js`）里有一段
**只在手机/平板上跑**的 iOS 变通 —— `if (isMobile())` 之后，**你点页面第一下**它就
`new SpeechSynthesisUtterance(' . ')` 去"唤醒"语音引擎，**裸构造、没做能力检测**
（同文件那五处 `'speechSynthesis' in window` 守卫管的是别处）。
在不实现 Web Speech 合成的手机浏览器 / 内嵌 WebView 上 ⇒ ReferenceError。
★**而本插件一行语音代码都没有**（全仓 `speechSynthesis` **零命中**，实测）。
⇒ 玩家的面板上印着别人的错、还挂着 `⚠`，**真正的自家异常被淹在里面**。

**治法**：分流口 `reportWinError` 住在 `status-bar.js`（状态条那行字只有一处写手）——
**自己的 ⇒ 状态条＋控制台；别人的 ⇒ 只进控制台**（★别人的也留痕：**"看不到"比"看错"更坏**）。
判别按**插件根目录**、**从 `import.meta.url` 现算**（写死 `story-world-v2` 就是第二份"安装契约"真相）；
★**拿不到出处时保守当自己的**（宁可多报一句，也不许把自己的错吞掉）。

### ⑥ **"发布点"这个读数天生落后一笔，这是设计使然**

它记的是"**哪一笔把这一版送上线**"，而"把它改成新值"这件事本身**又要再提交、再推一次**
才到得了远端 ⇒ 永远有一笔纯记账提交压在它上面。
★**别为了"追上 tip"反复重推**——那只会再造出一笔记账提交，永远追不上。
★同批**把结构上的一处错改对了**：`published.tagCommit` 原先接的是 `PUBLISHED_COMMIT_REF` ——
在"tag 与 main 是同一笔"的年代那样写没问题，可**tag 只跟 release 走**之后两者**本来就会越差越远**
⇒ 再接着写就是生成物**谎报"tag 指着 main 的尖端"**。已拆出独立常数。
