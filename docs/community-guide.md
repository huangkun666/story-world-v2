# 社区使用指南

本指南介绍 Story World v2 的资料接入、结构化抽取、状态更新、知识检索与数据恢复。SillyTavern（简称 ST）是当前公开版本的宿主；宿主中的角色卡与世界书是资料入口。插件通过独立的推演模型通道维护运行状态，与宿主聊天模型分开配置。界面入口沿用实际产品名称。

> **安装来源与能力范围**：公开 main 已包含可调抽取块大小、中止抽取和任务诊断；旧 Release 与 main 可能不同，版本及构建读数见 [STATE.md §1](../STATE.md)。Dexie/IndexedDB 正式记忆账、逐任务图检索及新图谱仍属于本地研发版，未随本次文案更新发布。请以实际窗口显示和对应版本的代码为准。

## 安装与更新

推荐在 ST 的扩展管理器中用仓库地址安装：

1. 打开 ST 的扩展管理器，选择从 URL 安装扩展。
2. 填入本项目的 GitHub 仓库地址：<https://github.com/huangkun666/story-world-v2>。
3. 安装完成后，在扩展列表中确认目录名为 `story-world-v2`，然后刷新 ST 页面。

也可以在 ST 扩展目录中用 Git 克隆仓库。若你熟悉命令行，可参考项目 [README 的安装说明](../README.md#安装)。使用 ZIP 安装时，解压目录也必须叫 `story-world-v2`；ST 按固定目录名读取面板模板。ZIP 目录通常带有 `-main` 后缀，需要先改名。

用扩展管理器安装的 Git 克隆可通过 ST 的更新功能更新。ZIP 没有 Git 元数据，不能用 Git 更新；需要手动下载新 ZIP 并替换插件文件。更新后对 ST 页面做硬刷新（通常是 Ctrl+Shift+R），再打开插件窗口查看版本和构建号。只有面板显示的新值才能说明浏览器载入了新文件；浏览器缓存可能仍保留旧页面。

如果你从 GitHub Releases 下载，请先看发布页版本。**当前 1.1.2 在 main，Release 仍停在 1.1.0**；两者不是同一份代码。

当前公开版本记录的宿主验证范围为 SillyTavern **1.15.0**，其他版本尚未逐一验证。请在社区反馈中附上 ST 版本和浏览器信息。

## 第一次初始化

### 1. 看清两条模型通道

在「设置」页的「模型通道」中填写服务地址、密钥和推演模型。这条通道供插件抽取设定、推进场景使用。它和 ST 正在使用的聊天模型是两回事：你可以填同一个模型服务，也可以为场景推进单独选择模型。修改这里不会替你更改 ST 的聊天模型设置。

填写后可用页面上的获取模型或测试连通操作检查配置。测试连通会向你配置的服务发送真实请求；只有在你愿意产生一次模型请求时再点。模型输出上限、单轮超时和「同时问几块」也在模型通道相关设置中；并发请求越多，对服务的同时压力越大。注意，单轮输出上限和单轮超时是普通场景推进请求的设置，不控制初始化抽取；不要用调高它们来修抽取失败。测试连通成功也不代表正式抽取所用的 JSON 参数一定被服务接受。

**抽取设置：**「抽取每块字符数」设置每块来源正文的字符目标，默认 30,000。它按正文字符数计算，不是 token 数；只接受正整数，且不能超过程序可准确表示的整数范围。完整原文行不会被截断；单行超过目标时会独立保留，并在任务记录中提示超长。此项只影响「开始新世界」和「只重抽设定」，不改变「只抽刻度」——刻度仍对整份来源调用一次。块设得更小可能增加模型请求和总耗时，不保证更快。

### 2. 检查抽象来源

进入「设置」页的「抽象来源」。这里列出插件读到的场景配置内容和来源资料条目。场景配置的描述、情景、性格、开场白分别列出；来源资料按来源分组。你可以搜索题名或正文、按来源筛选，并选择默认来源或自选来源。

每条来源可使用自动清理、读取全文或选择多个原文片段。页面上的预览用于查看实际会交给抽取任务的内容。原文是只读的；选择一个被禁用的来源资料条目，不会替你开启原始条目。若来源原文后来变化，旧选段需要重新选择。这里的选择影响后续抽象和查书，不会让已有场景自动重抽。

资料的组织方式各不相同。抽取结果可能很丰富，也可能只得到少量设定；插件会保留没有依据的空白，不会为了填满页面而猜测。来源选择可以缩小参与抽取的材料。来源资料仍由 ST 和聊天模型照常使用，插件只读它，不会修改原文。

### 3. 创建场景

在观棋窗口顶部选择「开始新世界」。首次初始化会读取当前聊天所用的场景配置及资料条目，并通过你配置的**推演模型通道**抽取设定、名号和起始内容。抽取期间看状态栏进度；耗时取决于来源规模、块大小、并发和模型服务响应。若抽取时间很长或状态没有推进，记录停在哪一块和已等待多久，再查看调试台的任务记录；不要连续重试。

如果当前已经有场景，「开始新世界」会提示即将替换当前场景，并尝试在初始化前拍一份「换掉前自保」快照；这次快照保存是尽力而为，不保证一定成功。确认前先用「导出整聊天」备份重要数据，之后到「快照」页回读确认该快照确实存在。抽象任务可在窗口操作区点「中止抽象」；窄屏先点窗口顶部「操作」展开操作区。没有抽象任务时该按钮不可用。「开始新世界」「只重抽设定」「只抽刻度」共用一项任务，同一时间只能运行一项；中止或失败后可以再次开始，原场景和有效缓存会保留。中止不会保证已发出的请求在服务端取消或不计费。初始化、载入或导入保存尚未结束时不要切换聊天，也尽量避免多个标签页同时操作同一场景。

### 4. 用户控制实体与保护

用户控制的实体始终受保护，面板不能把它改成允许推演模型模拟。其他实体可以在「角色与势力」页面打开实体资料，在资料行使用「禁止模拟」开关，阻止推演模型代写该实体；再次点击可恢复模拟。实体保护设置会保存到当前场景。

本轮聊天正文中实际行动过的实体也会在这轮受到保护。保护不增加模型请求次数。程序能拦截对受保护实体的直接动作和字段修改，但模型仍可能在其他实体的标题或描述里写出间接情节；不要把保护理解成对所有叙述的绝对保证。

## 日常推进

在窗口顶部点「推进一轮」可手动推进，不要求先开启自动推进。若在「参数」页开启「插件总闸 · 自动推进」，插件会在收到 对话回复后自动推进。总闸关闭时，聊天仍照常进行，手动推进仍可用。

每轮由推演模型提出变化，程序检查并把可用内容写入状态账本。推演模型通道和聊天模型通道分别配置；调整其中一条不会自动改变另一条。你可以在「观棋」「编年」「角色与势力」「设定」等页面查看当前状态和事件。实体、组织或设定缺少来源依据时可能留空，这不等于来源原文明确写了“没有”。

「禁止模拟」只限制推演模型对指定实体的直接模拟，不会让实体从场景中删除，也不会增加额外模型调用。若一轮全部提议都无法使用，页面会报告失败且场景轮次不增加；根据状态信息检查原因后再决定是否重试。

## 保存、导出与回退

插件的状态账本保存在当前聊天的插件数据中。升级、换设备或准备尝试大幅调整前，可在「设置」页使用「导出整聊天」保存包含聊天和状态账本的文件，并妥善保管。文件可能含私人聊天正文、场景设定和实体信息；分享前请检查内容并移除隐私。使用「导入恢复」会用文件中的聊天和状态账本替换当前状态；它不会先替你拍快照。导入前如需退路，先到「快照」页点「拍一份快照」，并确认快照列表里能读到它。导入或保存尚未结束时不要切换聊天，也避免多个标签页同时改同一个场景。

「快照」页保存状态账本的历史状态，可选择一份恢复。快照**只恢复状态账本，不恢复或删除聊天对话**；恢复旧场景后，对话仍可能比状态账本前进了几轮。快照不是聊天备份，也不能替代整聊天导出。快照有保留数量限制，旧快照可能被新快照替代；不要把它当作长期归档。参数修改不会触发场景快照。

开始新场景会尝试拍当前场景的自保快照，但这是尽力而为，不是成功保证；导入恢复不会自动拍。请以快照页实际读回结果为准。若发现状态账本不对，先导出当前整聊天以保留现场，再寻求排查；不要立刻重新初始化来遮盖问题。切换聊天时，旧载入任务会被阻止写入新聊天；这项保护不代表所有载入问题都已解决。清空或重置快照会影响当前聊天的快照库，不是通用修复手段。操作前先导出重要数据，并确认清楚按钮会影响哪份内容。

## 遇到问题时

先记录操作前后的现象，别急着清账、删除存档或重置快照。检查「设置 → 调试」中的记录和可复制/下载的调试报告；报告可能含环境和错误信息，公开前请先检查并脱敏。需要进一步排查时，请按[常见问题](community-faq.md)中的反馈模板提供资料，并遮掉密钥与私人正文。
