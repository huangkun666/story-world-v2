# 抢先测试使用指南

本文对应 `codex/preview-2026-10-23` 测试分支，扩展清单版本保持 1.1.2。安装与切换前先看 [README](../README.md)。

## 安装前保存数据

已有世界先在插件“设置 → 存储”完整导出备份，并妥善保存酒馆聊天和原始资料。不要双装正式版与测试版。代码、ZIP 和 Git 仓库不包含当前浏览器的世界数据库；同一访问地址下换代码通常仍会读取原本地数据，所以测试前也需要备份。

初次试用建议使用单独聊天和可公开的少量资料，先熟悉创建、导出和导入操作。

## 配置与选择资料

1. 在插件“设置 → 模型通道”填写本插件使用的 API 地址、密钥与模型。它与酒馆主聊天模型的配置分开。
2. 打开“设置 → 抽象来源”，检查当前可读的世界书条目与角色卡内容，选择本次使用的资料。可以检查可用来源及正文；源资料只读。
3. 在“参数 → 抽象与字段”核对进包目标字符、并发、输出上限与超时。目标字符用于按完整条目合包；大条目仍完整发送，不应把它当作模型必能容纳的保证。“不限”也受实际模型与服务商能力约束。

修改设置用于后续调用；不要以为已在飞的请求会跟着改变。

## 建立世界

点“开始新世界”，保持在原聊天等待任务进度。

1. **前置：字段、设定与地点。** 程序调用模型读取资料，并统一字段与地点。
2. **确认字段。** 出现字段窗口后检查候选名称、适用对象和说明，按需选择或编辑，再点“确认字段并继续”。非法名称会提示错误并保留草稿。关闭窗口后可从继续入口重新打开。
3. **每包 A/B。** A 处理属性与关系，B 处理经历与计划。成功部分会保存；此时不要重复点“开始新世界”。
4. **统一与整理。** 统一实体身份，并在需要时整理相关候选；这些仍可能产生模型调用。
5. **保存与玩家初始化。** 等待世界正式保存完成。玩家按当前玩家信息初始化；如出现重名报错，先核对角色信息再继续。查看实体与玩家是否符合预期，再开始推进。

原文未明述的位置可以留空；不需要为了建世界编造地点。当前创建链路不是旧版“先采用设定候选，再补齐必填位置”的流程。

## 中断、失败与继续

看到失败时先读具体阶段与原因，可在“设置 → 调试”查看记录。输出不完整、字段格式错误、鉴权失败和限流要分别处理，不要连续重复新建。

需要重试时，用“继续抽象”接续原任务，已成功部分与确认字段会保留；未完成请求按当前设置处理。对于断网、超时或关闭页面造成的“结果未确认”，认真阅读确认提示：手动重试可能再次计费。程序不会自动补发这些未知请求。

“开始新世界”会重新读取当前资料并产生新的模型调用，不是“继续”的同义词。停止任务后，已发送请求仍可能由服务商完成和计费。请待任务结束并保存后再刷新或更新扩展。

新建成功后，大块请求与中间过程会清理；原文、确认字段、正式成果与世界历史继续保存。失败和未完成任务保留恢复与调试信息。

## 日常使用与备份

在观棋窗口查看近况，在实体页检查人物与势力，在世界图谱查看地图、关系和事件来路。根据需要开启聊天注入与标签相关设置，并检查其说明；模型仍可能生成不合适的内容，观察面板与正文是否一致。

世界推进失败时查看调试记录，确认原因后再手动推进；不要把错误状态当作已成功落账。

定期在“设置 → 存储”完整导出。迁移设备、浏览器或访问地址后，在新环境导入备份。快照恢复会建立分支，原历史保留；它不回退聊天。清除网站数据或浏览器存储可能使未备份世界丢失。

遇到问题请按 [FAQ 反馈模板](community-faq.md#如何反馈) 提供最小信息，并先检查附件里的私人资料。
