## 2. ★★ 第一笔（leg101 · `589a44c`）：两条滚动条打架

**起因**：用户贴面板实机截图 + 「**窗口太小了，最重要的说书都没位置了**」（他当时正在准备发帖，这张图要发出去）。

**病（两处，都在 `web/style.css`，都是 leg99 那一笔留下的）**：

| # | 病 | 机理 |
|---|---|---|
| ① | **内外两条滚动条打架** | leg99 把"滚动"从外壳**下放到两栏**（`.sw2-merged-main/-side{overflow-y:auto}`），但**外壳那条 `overflow:auto` 没撤** ⇒ 两栏在内部滚、外壳也在滚，**外壳滚到哪内容就被裁到哪**（截图底部那句被切一半） |
| ② | **`calc(88vh - 190px)` 里那个 190px 不够** | 它是按"页头一行 ＋ 信息带"估的，而外壳里实打实还有**状态条 ＋ 页签行 ＋ 页内边距** ⇒ grid 比外壳真剩下的高度**更高** —— **这正是①那个打架的机理** |

**修法（三处，全在样式；产品行为一个字节未改）**：
① `.sw2-window` → `height:88vh` + `display:flex` + `flex-direction:column` + **`overflow:hidden`**；
② `.sw2-view.sw2-active` → 合并成一条：`display:block;flex:1 1 auto;min-height:0;overflow:auto`；
③ `.sw2-merged-grid` → `calc(88vh - 190px)` **改 `100%`**。

★★**为什么改结构而不是把 190 调大**：**没有浏览器就量不出那个数的真值**（leg89 §5.5 那条自律）
⇒ 调常数等于**再猜一次**；改成让 flex 分配高度 ⇒ **页签多一行少一行都不再算错**。

**同批**：`PANEL_BUILD` → `leg101-fitwindow` · `CSS_VERSION` → `20260922-leg101-fitwindow`（真动了样式）。
**读数**：1078/1078 · fail 0 · 冒烟 8231 字节逐字节未变。

### 2.1 ★★★ 顺手抓到一条**"空绿"判据**（本仓"空绿"家族的新成员）

`test/panorama.test.js` 那条 leg99 的样式判据里，取规则的 `ruleOf` 是这么写的：

```js
const m = new RegExp(`\\${sel}\\{([^}]*)\\}`).exec(css.replace(/\s*\n\s*/g, ''));
```

**两个病，都不出声**：
1. **转义只加一个反斜杠** ⇒ 拼出来是 `\.sw2-merged-main\{…\}`：**选择器里那个 `.` 成了通配符**；
2. ★**更要命**：**本仓 CSS 注释里大量写「选择器{…}」这种字面引用**（如 `` `.sw2-merged-grid{height:100%}` ``）
   ⇒ 正则会**优先命中注释**，取回来的 `body` 是**注释片段**——**读数直接撒谎**。
   本笔实测：真规则在 9459，它命中的是 **4134 的注释**；
3. 取不到时返回 `''`，而下面断言**全是"body 里必须有 X"** ⇒ **一条都没命中时照样绿**。

★**它是怎么被发现的**：leg101 那条 `height:100%` 恰好让"第一条命中"从注释换成了真规则
⇒ 两条**本来就在空转**的断言**当场红了**，才暴露。**不是我去看它，是它自己顶出来的。**

**定稿**：`先剥掉注释` ＋ `按字面转义` ＋ **`空 body 当场红`**。
★这一笔的取证装置：`leg101-ruleof-probe.mjs`、`leg101-verify-ruleof.mjs`。

## 3. ★★★ 第二笔（leg102 · `1fa4a6d`）：窗口本身没变大

**起因**：leg101 推完之后，用户回「**老样子没变大**」。

### 3.1 ★★ 用户给的两行读数把病定死了（**这就是"要读数不要猜"的样子**）

用户在 Console 里跑了我给的一行，回了两条：

```
[ "style.css", "style.css?v=20260922-leg101-fitwindow" ]     ← 新样式表**已加载**
'790.24px | hidden'                                          ← leg101 **完全生效**
```

⇒ ★★★**leg101 治的那条是真的好了，但用户要的那件事我上一笔根本没做到。** 真正的病：

| # | 病 | 说明 |
|---|---|---|
| ① | **宽度写死 `1120px`** | 1080p 上只占 **58%** —— 用户截图里**两侧的空白**就是这么来的 |
| ② | **`88vh` 相对旧 `max-height:88%` 只差一点点** | ⇒ 等于没变 |

⇒ **"太小"是宽高两头都小**，而 leg101 只改了第三件事（滚动条）。
★★**这是本棒最该带走的一条**：我上一笔**自己认定**了病因（滚动条打架），**没先问用户要读数**——
如果我第一次就让他量那两行，就没有第二笔。

### 3.2 修法（用户令「**占满整个屏幕吧**」⇒ 按这句话定口径，不再拍数）

```css
.sw2-window{ width:100%; height:calc(100vh - 40px); display:flex; flex-direction:column; overflow:hidden; }
```

- **宽度** `1120px` → `100%`（遮罩有 `padding:20px` ⇒ 实际 = 视口宽 − 40px，两侧各留 20px 边）
- **高度** `88vh` → `calc(100vh - 40px)`（同上，那 40px 就是遮罩的留边）
- ★**用 vh/百分比而不是更大的常数**：窗口多大**由视口决定**，不必替别人的屏幕猜一个数
- ★`.sw2-view.sw2-active` 与 `.sw2-merged-grid` **一个字没改** —— 它们吃 flex 分出来的余高，
  **窗口一变大自动跟着变大**（这是 leg101 改结构的红利）

**同批**：`PANEL_BUILD` → `leg102-fullscreen` · `CSS_VERSION` → `20260922-leg102-fullscreen`。
**判据**：1078/1078 · fail 0 · 冒烟 8231；并在 `panorama.test.js` **补两条尺寸口径断言**
（宽度不许写死 / 高度要按视口算）——★leg101 只钉了 `display:flex`+`overflow:hidden`，**没钉尺寸**，
所以"窗口本身没变大"这件事判据是**看不见**的。

## 8. ★★★ 留给下一任的重头戏：`recalled` 该拆（用户三问，逐问被我核过）

> ★这一节是**本棒与用户最长的一段讨论**，也是**唯一一条用户明确点名要拆的机制**。
> 用户三问：①「注入世界书干嘛？不用注入世界书，只有初始化的时候才需要世界书啊」
> ②「为啥要检索，这插件不是世界的唯一权威吗？」③「**设定已经在插件里了还要查世界书干嘛？？**」

### 8.1 先纠正一个读法（我第一遍就写歪了，被用户顶回来）

**`injectWorldBookRecall` 的注入面是"世界模型"，不是聊天 LLM。**（`src/tick.js:157-173`）

```
runTick → injectWorldBookRecall → 检索命中的书原文片段
       → world.meta.recalledText → pack.js:969 的 pack.recalled 键
       → 随包递给「世界模型」（玩家在设置页填的那条通道）
```

⇒ **它没有往你的对话里塞任何东西**。用户抱怨的"账与世界书不一致"来自 **ST 自己往聊天 LLM 塞书**，
不是这条。★**措辞错了会把下一任带歪**——这是本棒踩过的一脚。

### 8.2 但用户的判断**是对的**，理由比"要不要注入"深一层

**设定确实在插件里**（`frozen` 冻结层，`ssot.schema.js:24`："世界书提取产物（书指纹不变不重抽），引擎只读"），
**「设定」页就是照它逐字段画的**（`render.js:1716`「A-6：展示与 setting.frozen 逐字段一致」）。
**但每轮给世界模型的包里，设定只截了最省的那一截**（`pack.js:926-939`）：

| 设定页上有 | 每轮进包吗 |
|---|---|
| 刻度表（全部） | **只有几张当锚**进（`刻度`），其余只留**表名+规模**（`刻度目录`、**不带档位内容**） |
| 法则（全部） | **只有"判据"那一类**进（`RULE_CLASSES_PACK`） |
| 书内名号（`bookEntities`） | **只有 name+kind** 进 |
| 原始 canon 正文 | **不进**（`pack.js:367` 明写 A-8「冻结层不入包」） |

★★**最能说明问题的是：插件自己在「设定」页上就把这件事印出来了**——
`render.js:1875` 写的是「**这一类每轮进模型的包**」／「**只留在这里给作者看，不进每轮包**」。

### 8.3 ★★★ 而"目录 + 点名"那套**已经是正解**（用户指出的，我核完确认他对）

用户第三问的落点：『不是还有目录吗？模型想要哪个概念就直接根据目录去找啊』——**这条机制真的存在**：

- **刻度**：`刻度`（最常用的几张，常驻）∪ `刻度目录`（**只列还没进包的那些**）= 全集；
  模型点名 ⇒ `check-step.js:409-423` **校验表名** ⇒ 写进 `meta.scaleRequests` ⇒
  ★**同一轮出包时整张表的档位就在包里**（`刻度补`）。
  写账那一步很讲究：**只在整步没错时写** · 写的是**核过的表名**（编的名字进不了账）·
  **每轮被新值覆盖**（没点名就覆盖成空数组）⇒ **天然一次性、不跨轮囤积**。
- **法则**：`RULE_CLASSES_PACK` 那一类**每轮全进**。
- 提示词第 15 条（`prompts.js:305-313`）把它讲得很清楚：表名照抄、一轮 ≤6 张、递给你之后**不会每轮挂着**。

⇒ ★★**分界不是"类别"，是"那个类别有没有结构化到可以被点名"**：

| | 形状 | 怎么办 |
|---|---|---|
| 刻度 | **成表、有名字** | **目录 + 点名**（从**账上**取）★正解 |
| 法则 | 成句、数量有限 | 全部进包 |
| **散在叙述里的细节** | **不成表、没名字** | ★**现在只能回头查书 ← 病灶** |

⇒ 它可能照着书里一句话往账上记一件与账上已有事实矛盾的事，**于是分歧从"书 vs 账"蔓延成"账内部就不一致"**。
**那比"聊天 LLM 和面板不一致"更脏，因为它污染真源。**

**但拆的顺序不能反**（反了不是干净地拆掉，是拆出个窟窿）：

2. **同批改提示词 `prompts.js:301-303`**——它现在明写：

   > · …**别自己编设定**：书里没有的细节，就不写；**recalled 里没有，说明这一轮没检索到**
   ⇒ **拆掉注入却留着这三句，就是叫模型照一栏不存在的输入办事**；且这三句是"别自己编设定"那条红线的**承重墙**。
   按本仓纪律还要**同批升 `MAIN_PROMPT_V`**。
