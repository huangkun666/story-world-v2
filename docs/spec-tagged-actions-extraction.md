## 2. 标签规范（★这一节就是注入给聊天模型的那段原文）

### 2.1 分块结构

★**全部标签必须包在一个 ` ```tags ` 块里**（leg93 用户裁示「就甲吧」，见 §2.4）：

```tags
【时长】三天
【场景：忘川渡口】
【行动】薛铁衣｜迎战｜黄坤
【行动】孟婆｜探查｜灵脉

【时长】一炷香
【场景：孟婆庄】
【行动】黄坤｜搜刮｜阴阳玉
```

| 标签 | 含义 | 出现次数 |
|---|---|---|
| `【时长】` | **从这里起又过了多久**（散文写法：三天／半晌／一炷香／半月）。★**累加**，不表时刻 | 每块**至多一条**，块头按需 |
| `【场景：X】` | 从这里起**这一场戏在哪儿**（X 用世界账上的地名） | 每块**至多一条**，块头按需 |
| `【行动】` | 一条**已经发生**的角色行动 | 每块若干条，一行一条 |

### 2.2 行动那一条的四格

```
【行动】主语｜动词｜对象
```

| 格 | 必填 | 口径 |
|---|---|---|
| 主语 | ★**必填** | **做出这个动作的人**。必须是名册上的名号（或用别名） |
| 动词 | 可省 | 这个动作**是什么**（两三个字：迎战／盘问／搜刮／传讯／探查…） |
| 对象 | 可省 | 动作针对的**人或物**（名册上的名号；也可以是没有实体的人/物） |
| **地点** | ★**不写在行动里** | 一律由**上面最近的 `【场景：X】`**继承（零成本兜底） |

### 2.3 五条硬规定（写进注入原文）

1. **只标签"已经写出来的行动"**——旁白、景物、心理描写**不标**。
2. **在块外、没有 `【场景：…】` 的行动，地点算空**（不是"在上一处"，也不是"在别处"）。
3. **没出手的人不标**（只是被提到、只是在场、只是说话，不构成行动）。
4. **主角照样标**（他做了什么就写什么）——★插件**不会**拿这条去替他做决定，只是记下来。
5. **一行一条**，共用全角竖线 `｜`；**块以外**的正文**照常自由写**（想怎么写就怎么写、想怎么引用标签记号都行——块外一律当正文）。
6. ★★★**全部标签包在那一个 ` ```tags ` 块里**（leg93 加，见 §2.4）；**一个标签占一整行**（行首不许缩进、不许有 `-` `*` `1.` 这类列表符号，行尾不许再跟别的标签）。

★**为什么是这几格**：标签的作用是让插件能把"名号"对成账上的 id（§3.3），并知道这一场戏在哪儿、过了多久。**标签不是账，是给插件读的路标**——正文仍归模型自由写。

### 2.4 ★★★ 标签块（边界）——leg93 用户裁示「就甲吧」

**用户之问（原话）**：「**正文里有【…】呢？不能包裹在一个标签里吗？**」

**逐字喂真提取器实测**（装置 `F:/deepseek/tmp/leg93-brackets-in-prose.mjs`）——两处**真会出事**的：

| 正文里长这样 | 实测后果 |
|---|---|
| 一句**以 `【行动】` 开头**的叙述（解说格式/举例子/被引用） | 被当成**一条真行动**（名字 = 整句话），落进 `unresolved`/`notNoted` |
| 一句**以 `【时长】` 开头**的叙述 | `elapsed` **收下一整句话**（实测「这个词表示时间流逝。」） |

★**第二条更重**：`elapsed` 是"账外的料"，**引擎一个字都不校验**（`pack.js:964`），它**原样进世界模型的 prompt**（`prompts.js:222`）。

**根因（一句话）**：认不认得出标签**全看 `【` 在不在行首**——正文与标签**共用同一个语法空间**，中间没有边界。

**修法（甲案）**：给标签一个**专属边界**——` ```tags ` 围栏块；`extractTags` **只扫块里**（`shellRange`）。

| 情形 | 行为 |
|---|---|
| 有块 | **只扫块内**；块外的 `【…】` 一律当正文（病①②从根上消失，不是"加检查拦住"） |
| **没块** | ★★**退回逐行扫全篇**（`mode:'all'`）——**老账、老聊天逐字节不变** |
| 块没闭合 | 吃到正文末尾，标签**照样读出来**（`closed:false` 如实标出） |
| 围栏行不干净（` ```tags ` 后面还跟字） | **不算开块** ⇒ 退回逐行扫 |

★★**为什么必须留"没块就退回"这条降级**：模型漏写围栏时，"**整轮零标签**"比"少认几条"严重得多。
★**代价面（已登记，不许藏）**：模型的标签若写在块外 ⇒ **就是不认**。这一面由注入规范那条硬要求兜
（`web/inject.js` 的 `tagSpecText()`，判据在 `test/tag-extract.test.js` 的 leg93㉔/㉔d）——**规范判据与提取器判据是一对，缺一不可**。

★**外层包裹（代码块/`<tags>`）过去"有没有用"**：过去**没用**——旧实现是逐行扫全篇，包裹行只是被判"其它一律不看"，
`【` 在不在行首才是唯一判据。⇒ **甲案正是把"包裹"从一个无意义的壳变成真正的边界**。

## 3. 提取：正则与归一口径

### 3.1 正则（四族）

| 族 | 匹配 | 说明 |
|---|---|---|
| 时长 | `/【时长】\s*([^\n【]+)/g` | 全部命中**按出现序收集**（累加，见 §4） |
| 场景 | `/【场景[:：]\s*([^】\n]+)\s*】/g` | ★**冒号全角半角都收**（`：`/`:`）——模型两个都会写 |
| 行动 | `/【行动】\s*([^\n【]+)/g` | 行尾即止；下一行是标签则截断 |
| 切格 | `split('｜')`（**全角**） | ★**半角 `\|` 不认**：它是 Markdown 表格与代码块里最常见的字符，认它必然误切 |

★**为什么用全角 `｜`**：正文是散文，全角竖线在中文写作里几乎不出现 ⇒ 正则切不坏；半角会跟 Markdown、表格、对话引号打架。

### 3.2 时空继承

★★**先定扫描范围**（leg93 · §2.4）：`shellRange(text)` 找到 ` ```tags ` 块 ⇒ **只扫块内**；块不在 ⇒ 扫全篇（老行为）。

逐行扫（**不是先按块切**——块切法在"模型漏写块头"时会整块丢）：
- 遇到 `【时长】` ⇒ 收进时长序列。
- 遇到 `【场景：X】` ⇒ 更新"当前场景"。
- 遇到 `【行动】` ⇒ 该行动的**地点 = 当前场景**（没有就是空）。

★**为什么"逐行"而不是"先切块"**：块切法在模型漏写块头时会把**整块**丢掉；
逐行扫的下限是"**只丢那一行**"，与"丢了什么要能被看见"这条口径一致。

### 3.3 名字 → id 归一（三档，逐档兜底）

| 档 | 对什么 | 命中即 |
|---|---|---|
| ① | `context.playerId` 的那个实体（名号或别名） | 这条走**主角槽**（§3.5） |
| ② | `ssot.entities[]` 的 `name` | `actorId = e.id` |
| ③ | `ssot.entities[].aliases`（**大小写与全半角不敏感**） | `actorId = e.id`（★实测过"小娥 ≠ 白小娥"，别名不归一必然漏人） |

**都不中** ⇒ 这条`action`**不进包**，进 `unresolved[]`（名字 + 条数），**面板与状态条如实报数**。
★**标签绝不新建实体**——入局归世界模型提议（`prompts.js` 第 11 条：`source.type="entity"` + 每轮至多一个 + 引擎复核）。标签直接造人会绕过全部闸门。

**对象格**：同样三档归一；不中 ⇒ `targetId = null`，**原文照留**在 `targetText`（不丢那句话）。
**场景格**：在地点表里归一；不中 ⇒ 原样留文本、标 `locationDerived: false`。

### 3.4 动词 —— ★**不做词表归一**（本节 2026-09-20 更正）

**先记清楚旧口径为什么有词表**：老路要读**玩家打的自由中文**，没有结构 ⇒ `extract.js:12-26` 拿 13 条正则硬猜"这一句是什么动作"，命中第一条就归一成规范动词（"我去看看" → `探查`）。它有两个天性：**表外的动作不存在**、**信息被降级**（"拔剑冲阵"被写成"迎战"）。

**核过全仓，动词在引擎里只干四件事**：

| 用处 | 位置 | 形态 |
|---|---|---|
| 判"这一轮有没有动作" | `tick.js:151` `move.verb ? move : null` | ★**唯一真正吃归一的判据**（空 ⇒ 整条事实被丢） |
| 判"玩家这轮活跃吗" | `settle.js:1183` `if (playerId && moveFact?.verb)` | 真值判断 |
| 拼【你的行迹】那一行 | `streams.js:75` | **原样转文本** |
| 拼上场选择器提示词 | `entity-lookup.js:99` | **原样转文本**（注释自己写着"照原样转发"） |

⇒ 动词**从不被判对错、从不与白名单比对**。

**标签口径下的定稿**：

- ★**动词原样保留、逐字转发**——**不设受控表、不做归一**。标签本身已是结构，"是什么动作"由模型直接写出来，插件不需要猜。
- ⇒ **"动词不在表里"这个问题在新设计里不存在**（没有表可对）。§3.4 原来那句"沿用那张表当起点"**已作废**——留着只会让下一任以为动词要过表。
- 动词**缺失**（两格写法）⇒ `verb = null`，**这条仍然进包**（"某人做了一件事、说不清是什么"也是事实）。
- ★**连带改一处判据**：`tick.js:151` 的 `move.verb ? move : null` **不能再用**——它的尺子是"词表命中"，标签口径下没有词表。新尺子 = **标签在 ⇒ 有动作**。

### 3.5 主角槽（★承重墙）

标签主语 = 玩家棋子 ⇒ 这条**绝不进 `turnFacts.actions`**，走 `playerMove`：

- `pack.js:939` 的 `playerMove` ⇒ `streams.js:74` 渲染成【你的行迹】递进主调用。
- ★**为什么必须分开**：玩家进 `actions[]` ⇒ `check-step.js:170` **拒整步**、世界当场不动（红线 1 代码化）。**记下来可以，替你决定不行。**
- ★`playerMove` 是**单事实形状**（`extract.js` 契约 v1）。多条主角行动 ⇒ **取第一条 + 如实报"本轮含 3 条主角行动，入账 1 条"**，不合并成一句假话。（放宽形状 = 已登记未裁决，§10.2）

## 4. 时间：读它干什么用（★本设计最该记住的一节）

| 问题 | 回答 |
|---|---|
| 引擎解析它吗 | ★**不解析**。"三天"与"一炷香"在插件看来是同一串字——**一个单元测试都不许断言它等于 72 小时**（那正是"编数"红线） |
| 那它喂给谁 | ★**喂给下一轮的世界模型**。它现在只知道"过了一轮"，不知道一轮里过了三天还是一炷香 |
| 它真在干活吗 | 在：世界模型据此判断**哪些旧线按现实早该有下文**（`prompts.js` 第 9、14 条要的"因果接得上"）、谁会带着新动静露面、这一轮该不该直接**跳到下一件要紧事**——全部走**现成机制**（`agendaAdvances` + 起新线），不新造任何东西 |
| 累加怎么表达 | 各段散文**并列**递过去（`"三天；一炷香"`），**不做算术**。"本轮共过多久"这句话归模型自己读 |
| 落包的哪 | `turnFacts.elapsed`（新键，缀在 pack **末尾**，§5.1） |
| 账上留痕吗 | ★**不回写 step**（`worldStepSchema` 顶层 `additional:false`，`world-step.schema.js:8`）。只在 `stage` 与注入读数里留"本轮时长：三天；一炷香"给人和面板看 |

★**一句话**：**时间不是账，是上下文。账按轮走，故事按时间走；硬把两者对齐只能靠编数。**

### 14.7 ★★★ 两处**设计错了**的地方（用户当场指出，已改）

用户原话：**「有些人还没加进名册的不会忽略吧，只是不造这个人是吗」** → **「为啥要丢掉呢就算不在名册上也给插件模型看到啊？？120个角色上顶没必要啊，我真服了」**

#### 错误一：不在名册上的人，**连行动一起丢了**（我把"不造人"错做成"整条丢"）

- **原设计写的**（§3.3）：主语三档都不中 ⇒ "不进包、不新建实体，只进 `unresolved` 如实报数"。
- **实际后果**：`unresolved` 里**只有名字和条数**，世界模型**不知道他干了什么**。
  ⇒ 若剧情里新冒出一个重要人物、模型给他标了一堆行动，**这些行动全部消失**，
  而且**"这个人该不该入局"永远拿不到证据**（证据被丢了）。这是"丢料"，比"多占几行 token"坏得多。
- **现在的形状**：新增 `turnFacts.notNoted`（`[{name, did:[…]}]`）——**名字 + 他做过的事**都递下去，
  但**明确标成"不在名册上、没写进账"**。入不入局仍由世界模型走现成的 `newEntities` 通道提议、引擎复核
  （★**仍然绝不凭空造人**——这一点没错，错的是"顺手把行动也扔了"）。
- **提示词同步**（`prompts.js` 第 8 条）：新增一条边界，讲清"这些人不占'不要再演一遍'那条禁令
  （他们本来就不在账上）"、"情节真需要就用第 11 条那条通道让他出场、别为了消化名字而造人"。

#### 错误二：注入的名册**按条数封顶 120**（自己制造"认不出"）

- **原设计写的**：`ROSTER_CAP = 120`，理由是"防炸包"。
- **为什么是错的**：这张表是**让模型写对名字**的必需料——**砍掉的那部分，模型写了也认不出**，
  于是"不在名册"里有一大批**是插件自己砍出来的**。要省 token 该省别处，不该省这张表
  （一项就是"名号（也叫 别称）"，很轻）。
- **现在**：`ROSTER_CAP = Infinity`（不封顶；`cap` 形参保留，仅测试可自设）。

★**教训（写给下一任）**：**"归不上"这类读数的第一反应必须是"我是不是把料砍了/扔了"，而不是"模型写错了"。**
两处错误的同一种形状：**为了让包小一点/代码干净一点，把"证据"处理掉了**——而证据是这个世界
唯一能自我修正的东西（`docs/session-handoff-2026-09-20-leg86.md` §0 那条纪律的另一面）。
