## 0. 人话版：这会怎么样

你在 SillyTavern 里得到一个「观棋窗口」面板：每轮对话后世界自动跑一步，窗口实时刷新——顶部一句话说清现在什么局势；下面一条动态流讲刚刚发生了什么（最新一条最醒目，暗处的谋划用暗红色标出）；旁边列着各方位置与动作；再往下是一行各方盘算总览。另有五个页签：**编年**（完整史卷）、**大事纪·旧卷**（长世界自动归档的纪要与旧卷）、**角色与势力**（所有角色势力的全量表）、**设定**（世界设定的档案——力量谱系、法则、史略，随时翻，重抽也在这页）、**设置**（模型、你的开档描述、旧卷管理）。全程插件本地存储（热账随聊天、旧卷入本地库），除模型调用外数据不出本机；演算失败世界原样不动，面板报错可重试。另外本阶段一并把**实体生灭**补上：对话里冒出来反复出现的角色可以入局（凭依据，不许凭空造），被打崩≠死、覆灭才算死，久不活跃的实体自动转背景（不删除，被事件点名自动复归）——"死了还在动"的 OOC 从此不可能。

## 2. 范围限制（本棒不做，防漂移）

- **方向相悖报警**（K5 减项）：候补不变，薄裁定不产胜负之魂不动；
- **兑现通道细则**（玩家尝试兑现机制）：触发不变（兑现通道设计拍板），本阶段只立接线不立机制；
- **未决点 1 深化**（条件句/多意图样本）：触发=提取调用增强时；
- **里程碑模型润色**：T3-D1 定案的结构摘要够用，润色延后（YAGNI + 成本）；
- **v1 编辑面全系**：撤销/健康体检/数据编辑器不搬（v2 设置面窄）；v1 子树零触碰（范式搬经验，代码不搬）；
- **多聊天共享世界**：每聊天一个独立世界（metadata 键隔离），不做跨聊天迁移；
- **NPC 深度模拟**：性格/关系网络/独立记忆不做（未设计项，不随本阶段发明）；
- **移动端/窄屏优化**：宿主为 ST 桌面页面，本阶段不承诺响应式；面板 min-width 保底；
- **SSE/WebSocket/独立服务器**：ANCHOR §3⑦ 已裁，不回归。

## 3. 设计

### 3.1 总体架构（T-U1）

- **形态**：ST 插件（`manifest.json` + 浏览器侧 `index.js` + `settings.html` 挂载面板 + `style.css`），v1 范式实证过（modal 窗口/页签/工具栏/saveSettings/扩展菜单、`.sd_` 类冲突限窗纪律、缓存破坏版本号）；**命名空间 `sw2_` 全隔离**（与 v1 共页共存，v1 经验：弹窗 z-index、双插件 css 覆盖、winEl 限窗、全局错误网——全部沿用为工程纪律）；
- **引擎进浏览器**：v2 引擎（纯 ESM、零依赖）原样跑在 ST 页面侧（fetch 浏览器原生）；唯一的 Node 依赖点 `st-preset.js`（读文件）浏览器侧由**设置页配置**替代（extension_settings），Node 侧 CLI/env 路径保持不变（K30 适配层）；
- **存储**（对话已认可"存插件里就行"）：热账 SSOT 随聊天（chat metadata，每聊天一份）；旧卷入 IndexedDB（chatId 键）；设置进 extension_settings；导出=下载 JSON，导入=读回——除模型调用外数据不出本机；
- **数据流单向**：引擎产物（ssot/streams/chronicle/milestones）→ 渲染纯函数 → DOM；UI 不发明状态、不存第二本账（A-2）。

**视觉纪律**（T-U2）：金色只给"最新一轮"；暗处=收敛暗红；数字降噪（影响力 88 无小数、世情带值为 0.44 原值）；无"走向预测"任何表述（已裁）；技术细节一律折叠/悬停。

### 3.3 异步化与可靠性（T-U7）

- **触发**：回合完成即推进（ANCHOR §3②）——ST 对话完成事件（事件源绑定）→ 异步 tick → 结算后刷新面板；手动「推进」按钮补推；
- **状态**：演算中（状态条 + 按钮 loading + 防重入锁）；失败=世界如实不动（引擎不变式）+ 状态条报错 + 重试；
- **超时/字数上限**（提案报批）：主调用超时 120s（AbortController）+ max_tokens 4096（transport 层参数化，编排层）——队列"主调用超时/max_tokens"设计缺口隨本阶段闭合；
- 多 tick 并发防护：世界锁 + 串行队列（同一世界一次一个 tick）。

### 3.4 世界书接入与抽象管线执行器（K31，A-7）

- v2 侧补"书→canon"LLM 抽取执行器（v1 director.js 在 v1，不搬代码只搬口径）：书源读取（角色卡描述默认 / 世界信息合订 / 粘贴）→ 指纹（K26 复用）→ 命中不重抽 / 书变自动失效 / force 绕过 → 小调用抽取（prompt 铁律：只提取不创作、无数量约束取全、原文措辞不润色；张力三件 + 环境量初值抽取段并入，T2 拍板）→ 净化（形状合法为止）→ 落 `context.setting`（frozen 五件套 + dynamic 初值）；
- 成本：初始化/书变/force 三时机调用（成本纪律，与 tick 数解耦）；
- 失败软着陆：抽取失败 → 世界不初始化阻塞、状态条报错可重试（沿用 v1 AbortController + 软着陆经验）。

### 3.5 玩家描述解析接线（K32，A-8，T-U8）

- 输入物（T7-1 已拍 a）：开档描述段 playerDesc——设置页 textarea 持有，**不落 SSOT**（溯源走日志/快照）；PLAYER_DESC_LIMIT=2000 提案截断；
- 调用点：开档/初始化流程（设定池就绪且含 playerId 即触发）→ 一次小调用（解析器注入式，输出四字段全可选 [0,1]）→ `injectPlayerAttrs`（v1.1 已就位，只接线）；失败/无依据 → 定案默认 #6-9（零阻塞）；
- 手填优先不变；force（「重新抽取设定」）联动重解析（T7-3）。

### 3.6 冷档轮转（K35，A-9，T-U6）

- 阈值（提案报批）：编年热卷超 **500 tick 或 5MB**（报批二批 §二 延续项）→ 前置段剥离入 IndexedDB 卷（每卷独立键：chatId + 卷序）；
- 断链防线：事件已归档机制（K20）先于编年轮转——冷档切的是编年文本段，**里程碑与因果指针留在热态**（红线 2 代码化）；
- 阅卷：按卷加载并用编年视图渲染（加载态）；导出=整聊天下载 JSON，导入=读回验签（SHA-256 摘要）；
- 设置页展示当前体积/阈值/卷清单。

### 3.7 实体治理（K37，A-10..A-12，T-U5；对话已确认"生灭要有、GC 可以"）

**状态契约（契约层）**：ssot 实体增可选 `status: "active" | "retired" | "dead"`（缺省 active，零扰动旧世界）；全库过滤面三点统一：pack（演化上下文）/ 点名列拆（门控例外）/ gate 静默判定——retired/dead 一律剔除，"死了还在动 = OOC"代码化。

**生（三通道）**：
1. 初始化：世界书名录（抽象管线抽取段产实体清单，出处=书内条目，只提取不创作）；
2. 运行时：模型提议 `newEntities`（契约新组）——带源 `{type: book|event|dialogueFact, ref}`；校验：无源拒 / 静默方拒 / 玩家拒 / 同 tick 重复拒 / 单轮 ≤1（提案）/ 席位 ≤32（提案）；落账 + 编年「XX 入局」；
3. **对话依据册**（新轻量记账户，编排/契约）：落子提取的对象双名单命中记录顺带记账（meta 内、随背景化清理）——"白小娥反复被点名"成为可溯源的 dialogueFact 依据（活档样本已证：对象名单真实记录小娥/云松子）。

**灭（覆灭裁定，推荐 A）**：模型提议 `entityFates: [{entity, verdict:"dead", source:{type:event|agenda, ref}, reason}]`（与 agendaCancels 同构，模型只有提议权）→ 引擎复核：ref 必须真实落账 + 指向歼灭性事件/终结 + 目标无在飞盘算子树 → 落 status=dead + 编年「覆灭」；**打崩 ≠ 灭**（attrs 归零仍为合法客体，K7 案例回归断言）；dead 为终局不复归；玩家不可灭。

**背景化 GC（定期，对话认可）**：条件 = 无在飞盘算 + 无未决事件/链引用 + 影响力 <0.05（提案）+ 连续 20 轮（提案）未活跃 → status=retired（名录/指针全保留）；**复归**=被落账事件点名（点名列命中）自动升回 active（一条确定性规则，不发明状态机）；触发时机：每 20 轮（提案）扫描 + 超 32 强制（按活力优先级，低者先退）；席位计数只算 active。

**数字提案清单（铁律 2，随 K37 曲线 + 报批批次）**：ENTITY_BIRTH_PER_TICK=1 · ENTITY_IDLE_RETIRE_TICKS=20 · RETIRE_WEIGHT_FLOOR=0.05 · ENTITY_GC_SCAN_TICKS=20 · POOL_CAP=32（原案）· 依据册保留窗口（待定，随曲线）。
