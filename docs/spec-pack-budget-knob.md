> **状态**：✔ **已办结（leg114 · 2026-09-22）**——用户拍板**按细案 §7 标的那几条倾向走**
> （丙案"先给读数、你按读数填" · 出厂值**不抬** · 照抄 `callMaxTokens` 的范围与措辞），
> 并另定两条：**读数同批补记"裁之前有多大"**（细案 §2.4 丙案漏了一格，见下）· **30000 搬进 `limits.js` 当唯一的家**。

## 1. 用户的话与它指的是什么

> 「**30000token 预算也太少了，我一般玩聊天 rp 每轮 5,6 万都正常**」
> 「**以后模型的能力肯定越来越强，我认为可以做个调整的入口，让用户根据自家模型的能力动态调节**」

### 1.1 ★先把两个数分清楚（它们量的不是一回事）

| | 是什么 | 现在的值 |
|---|---|---|
| 用户说的 **5–6 万** | 玩家 RP 那一路（**聊天模型**）整条上下文 | 聊天侧的事，与下面无关 |
| **30,000** | **世界步**（另一个模型调用）**输入**里那个包的上限 | `pack.js:20` `EVOLUTION_BUDGET_TOKENS` |
| 输出上限 | 世界步**回复**的长度 | **16,384**（`transport-http.js:21`，leg19 用户拍板 4096→16384） |

**30,000 的来历**：`pack.js:20` 原话——「用户 **2026-09-09** 定案（"现在的大模型绝对有这个能力"）」。
⇒ **那是两个星期前按当时的模型拍的数**。用户说它偏小，**这是用户对自己模型的实测，比这个旧数字更有依据**。

### 1.2 ★这个数和你刚撤掉的那个数**性质不一样**（这点必须先说清）

| | `entityUpdates 每轮 ≤3`（leg112 已撤） | 包预算（本笔） |
|---|---|---|
| 它是什么 | **闸**：限制**模型能做什么**，超了**整步拒** | **尺**：限制**引擎给模型看多少**，**不拦任何东西** |
| 静默吗 | 是（`sanitize-step.js` 静默截断） | 否（裁了什么如实写进 `pack.trimmed`） |
| 数字性质 | **提案态**、没量过、却当了家 | 出厂值有定案记录，且**本笔不改变出厂值** |

⇒ **本笔不属于铁律 2 那个"数字先报批"**（那条管的是"限制模型/影响世界的判据值"）。本笔只动**容量**。
**但它的真风险另有一条**：**看到更多 ⇒ 模型行为会变**（所以要和"先量再动"配套，见 §5）。

## 2. 设计

### 2.1 一句话

**把这个数从"写死在源码里的常量"改成"面板上可调、账上留痕、出厂值不变的容量旋钮"。**

### 2.2 ★不新造机制——本仓已有两个现成样板，各取一半

| 样板 | 在哪 | 本笔借它什么 |
|---|---|---|
| **`limits.js`（尺度上限的唯一真源 + 可调档位）** | `src/limits.js` | ★**"一个数只有一把尺"**：值住在 `limits.js`，由它 `resolveLimits(world)` 解析，各处（包/结算/面板）**都从这里取** |
| **`callMaxTokens`（调用参数：面板 input，自己填）** | `render.js:2074` | ★**"自己填、插件不替你探测"** 的交互与措辞口径（范围 1024–131072，步进 1024） |

`limits.js` 的立表口径（原话）：

> 「**一个数两把尺子**是本仓老病……这些上限原先散在两处 ⇒ 参数化时必须先收成**一份**，否则"面板上写着 6、引擎按 3 跑"。」
> 「**默认逐字不变**：出厂值就是参数化之前那几个数 ⇒ 未设档位时行为与参数化之前**逐字节相同**。」
> 「**账上要看得见**：这些值不进账的话，"玩家把上限调低了"与"引擎坏了"在读数上**一模一样**，没法归因。」

**三条纪律本笔逐条照抄。**

### 2.3 为什么必须走 `limits.js`（不能就地改 `pack.js`）

`EVOLUTION_BUDGET_TOKENS` 现在有**三个**读它的地方：

| 读它的地方 | 干什么 |
|---|---|
| `pack.js:987` | `buildEvolutionPack` 结尾**强制**整包预算（`trimPack(pack, EVOLUTION_BUDGET_TOKENS)`） |
| `pack.js:1012` | `trimPack` 的**形参缺省值** |
| `smoke.js:6/87` | 冒烟断言（`assertSmoke({ budgetTokens = EVOLUTION_BUDGET_TOKENS })`） |

⇒ 就地改一处 = **立刻变成两把尺子**（包按 A 裁、冒烟按 B 断言）。⇒ **必须先收进 `limits.js`，再从那里分发。**

### 2.4 "自动"档怎么算（★口径留用户拍，本细案只给候选）

用户的原意是"跟着自家模型的能力走"。三条候选：

| 档 | 算法 | 好处 | 坏处 |
|---|---|---|---|
| **甲** | **不自动**：就是个数，你自己填 | 零猜测、行为可复现 | 用户得自己知道该填多少 |
| **乙** | 按面板已填的**模型上下文窗口**取一个比例（比如 30%） | "模型强了就自动宽" | **比例是个新提案数字**（铁律 2）⇒ 得先出曲线 |
| **丙** | **保留包预算自动填的"读数"**：面板上显示"上一轮包实际用了多少 / 上限多少"，让你按读数自己定 | 不新增算法，但**给了你判断依据**（这正是你现在缺的） | 仍要你手动填 |

★**本细案的倾向：丙**（先给读数，再让你填）——它**不新增任何提案态数字**，且直接回答"我该填多少"。
**甲是底线**（哪怕只做甲也比今天强）。**乙要等你先拍那个比例，并且要先出曲线。**

### 2.5 落点（四层）

| 层 | 落点 | 做什么 |
|---|---|---|
| **参数真源（引擎层）** | `src/limits.js` | 新增出厂值（照抄现名与值：`30000`）+ `LIMIT_DEFAULTS` 加一格 + `resolveLimits` 解析它。★**本文件只导出常量与纯函数、不 import 任何 `src/` 模块**（`limits.js:13` 写死的依赖方向，踩过循环依赖 + TDZ，别破） |
| **取用处（引擎层）** | `src/pack.js` | `buildEvolutionPack` 与 `trimPack` 的预算**改为从 `lim` 进来**（形参缺省仍是出厂值 ⇒ **旧调用方零扰动**）。★本文件**不反向 import `limits.js`**（既有先例：`pack.js` 的 `THREADS_TOP` 就是这么处理的，理由写在 `pack.js:960`） |
| **渲染层** | `src/render.js` | 参数页新增一行：数字 input（照 `callMaxTokens` 的措辞口径）+ **"上一轮实际用了多少"的读数**（§2.4 丙） |
| **接线层** | `web/index.js` | ★**余量只剩 1 行**（`STATE.md` §1）⇒ 若真要在这里加东西，**先搬一族出去**（照 leg112 §4.1 那把尺：`web/book-rebaseline.js` 就是那么搬的） |

★**参数存哪**：照 `limits.js` 既有口径落 `context.setting.dynamic.env`（与"天时/张力推手/插件总闸"**同一处、同一写通道** `set-param`）——**不新开一套存储**。

## 3. 出厂值：★**不变（30000）**

按 `limits.js` 那条纪律：「**默认逐字不变**……未设档位时行为与参数化之前**逐字节相同**」。
⇒ 本笔**不改出厂值**。用户嫌小 ⇒ **由用户自己在面板上填**（这正是本笔要做的入口）。

**诚实交代这两件事的区别**：
- "**给入口**"= 让用户能调（本笔）；
- "**抬出厂值**"= 改所有人的默认行为 ⇒ 那要单独出曲线（因为**看到更多 ⇒ 模型行为会变**）。

⇒ 本笔只做前者。**后者等 §5 的曲线出来再拍。**

## 5. 判据（每条真跑）

| # | 判据 | 为什么必须有 |
|---|---|---|
| K1 | ★**一个数一把尺**：`pack.js` 与 `smoke.js` 读到的预算**同源**（改成同一条链） | `limits.js:4` 那条老病（leg32/leg33 踩过） |
| K2 | **默认逐字不变**：账上没设 ⇒ 包与今天**逐字节相同**、`trimPack` 行为不变 | `limits.js:7` 的既有纪律 |
| K3 | **账上留痕**：设了值 ⇒ 值真的落 `context.setting.dynamic.env`，且**面板读数与引擎实读一致** | "玩家调低了"与"引擎坏了"必须能分开 |
| K4 | **越界拒绝**：填负数/非数/超大 ⇒ 照既有 `normalizeParam` 口径归一或拒，**不许悄悄当成默认值** | 本仓"空着就是空着"（§2.2 红线 2） |
| K5 | **面板读数如实**：显示"上一轮实际用了多少"时，**取的是真值**（不是再算一遍） | 两把尺子是本仓老病 |
| K6 | **冒烟**：`node demo/smoke-demo.js` 的终态 SSOT 字节数**逐字节不变**（出厂值没动） | 本笔是"给入口"，不该动行为 |
| K7 | **改了预算会真裁**：把预算调到 1000 ⇒ 包被裁且 `trimmed` 如实记名 | "预算已强制"不许是空话 |

## 6. 本笔**不做**的

1. **不改出厂值**（§3）；
2. **不做自动探测模型能力**（`render.js:2074` 已有原话："**自己填，插件不替你探测**"）；
3. **不让模型自己决定要多大的包**——那会变成"给名单不给资格"那类空转（`limits.js` 那条纪律：参数是**旋钮**，不是模型的行为开关）；
4. **不做"按需扩容"**（那属检索层，见配套细案）。
