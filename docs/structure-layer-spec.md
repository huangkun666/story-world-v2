## 0. 人话版：这会怎么样

世界书本来就是**带结构**的百科：条目里写着「势力名/所在天/统辖/辖属/核心机构/统治者」，有的条目甚至用标签直接标了「谁的麾下」。我们要做的不是让模型"再猜一遍谁归谁管"，而是**先把这本书的体例读出来**（它用哪些字段、哪些标签表达结构），再让模型**按书的体例去填一张关系表**。这张表落进账本后：势力和它的上级、它的统治者、它的所在、它的下属机构都各有一条**有原文依据**的边；书里明写的标"读到的"，模型推断的标"推的"等你确认；书里没写的，引擎绝不自己编。

结果就是你期望的那样：**天庭不再散成一地部门**——它能被指认成一个顶点（或一个架构层），部门挂在它下面；「蟠桃园」不再当地名，而是"上界势力，辖属瑶池"。

**你不需要懂结构**（leg22 用户质询后修订）：书里写着的**自动读**，能从名号算出来的**自动算**（`天庭百官` → "百官是编制，上级是天庭"），实在拿不准的**按后果分级自动处理**——低/中后果直接生效并可一键改判，高后果（折叠/合并）默认执行但显著标注 + 一键撤销 + 留痕。**面板不是编辑器，是异常处理器**：正常情况你一眼都不用看。

## 1. 背景与实证（数据说话）

**源是富结构的**（`大荒-姬元真` 世界书，235 条）：

- **书的字段体例**：行首字段名 **1265 种**；结构类字段实测出现：`势力名` 17 · `所在天` 15 · `势力所在地` 14 · `势力定位` 14 · `架构总述` 5 · `统治者` 5 · `核心机构` 4 · `统辖` 1 · `辖属` 1。
- **书的类型标签**：235 条中 **76 条**正文首行带 `<类型_名字>` 标签，其中 `上界势力` 15 条、`幽冥势力` 3 条，另有 **12 条把隶属直接写进标签**（`<太素帝麾下_X>` `<织命帝麾下_X>` `<渡虚帝麾下_X>` `<沉星帝麾下_X>` `<噬天帝麾下_X>`）。
- **书里明写的原文样例**：
  - `<上界势力_天庭百官>` / `所在天: 第十二重天·朝天殿（行政司法中枢）` / `统辖: 人帝姬元真，日常由瑶池主全权代理`
  - `<上界势力_蟠桃园>` / `辖属: 瑶池（瑶池主代人帝管辖）`
  - `[真界·人帝天庭六重天总览]` / `统治者: 人帝（古帝境·T15）` / `核心机构: 仙籍司、洗凡池、万卷阁`
  - **书里没有"天庭"这个独立势力条目**——顶是架构条目（六重天/下三天/上三天）+ 统治者（人帝·角色）+ 天层（第十至十五重天）；「天庭」是合称。
- **我们丢掉了什么**（导出 (6) 实账对照）：

| 书里怎么写的 | (6) 里成了什么 | 丢了 |
|---|---|---|
| `<上界势力_蟠桃园>` … `辖属: 瑶池` | kind=**location** | 类别判错 + 辖属边整条 |
| `<上界势力_天庭百官>` … `统辖: 人帝姬元真` | **不在册** | 整个势力 + 两条边 |
| 瑶池（蟠桃园的上级） | kind=**location** | 上级非 faction → 折叠永不可能 |
| `统治者: 人帝` / `核心机构: 仙籍司、万卷阁` | 人帝=character ✓ / 万卷阁=location / 仙籍司=faction | 架构层无落点 |

- **量化病征**（(6) 872 名册 / 635 实体）：势力→势力 parent **3%（3/112）**、角色→势力 71%、地名 234 个而位置集仍只有 `["未明"]`、实体无位置 **88.3%**、四维全默认 36%、`hardPower 0.5` 是最大桶（均值回潮）、别名子串对 88 组（48 个短名独立入账）。
- **机制性结论**：结构性信息**在源里**，被三层吃掉——①**契约只有一条边**（`parent`，且须指向 faction；书里的 `统辖` 指向人 → K49 校验主动弃）②**类别靠猜**（书有 `<上界势力_X>` 标签却不用）③**逐名号局部提问抽不出全局结构**（3% 即证）。

**结论：「字段表＋类型标签」路线只有 1 本满血、1 本换形态可用——"适用于大多数世界书"不成立。** 四条推论：
1. **字段词表不能当契约**：大荒 `统治者:`／三国 `首领（X）：`／别的书可能 `掌门/宗主/负责人` → 词表只作**种子**，role 判定靠"**种子词表 + 值形态 + 位置**"三合一泛化。
2. **结构来源必须分四档**（§2.2）：`tag` > `field` > `sentence`（散文层级句，三国/re0 走这条）> `player`（玩家手填/确认）。
3. **宏型巨书必须过滤**：Global 765 种假标签——脚手架黑名单是**硬要求**，否则体例轮被淹没。
4. **产品判断（leg22 修订）**：既然"书有可读结构"是少数，**主入口必须是全自动**——书读到的（tag/field/sentence）+ 确定性算出来的（**名号形态学**、**传递闭包**）覆盖大部分；模型推断与运行期候选按**后果分级**处理（§2.5）；**`player` 只是纠正与兜底，不是主入口**。小白路径＝零操作下世界也长得对。

## 2. 设计

### 2.1 体例轮（K61，编排层；**确定性，零 LLM**）

先读"这本书怎么表达结构"，产出 **bookStyle**（全部逐字来自书，带出现次数与样例）：

```
bookStyle: {
  fields:   [{ label: '统辖', count: 1, samples: ['统辖: 人帝姬元真，日常由瑶池主全权代理'], role: 'hierarchy' }],
  tags:     [{ prefix: '上界势力', count: 15, samples: ['<上界势力_天庭百官>'], carries: 'type' },
             { prefix: '太素帝麾下', count: 2, carries: 'allegiance:<上级名>' }],
  relWords: ['统辖','辖属','管辖','麾下','归附','门下','所属','分支'],   // 书里表达上下级的词表
  coordWords: ['重天','洲','域','界','驻地'],                          // 坐标层级词（若书有）
  powerHints: ['T\d+', '境界', '力量等级', '战力基准'],                 // 书自带的阶标注（喂 K50 词档版）
}
```

- **字段名/标签前缀/词表全部用确定性扫描**（行首 `字段:` 正则 + `<...>` 首行标签 + 词表匹配）；**role 判定＝种子词表 + 值形态（值是人名/势力名/地名）+ 位置（条目头部）三合一**——词表是种子不是契约（`首领（曹操）：` 与 `统治者: 人帝` 同 role）；未识别字段不猜、只登记。**零 LLM、逐字节可复现**（A-2）。
- **产出三态分级**（判据与具体字段名无关）：`rich`（有结构字段或类型标签）／`medium`／`thin`（只有散文层级句）／`none`（都没有）——三态决定骨架轮走哪条路（§2.3）。
- **泛化信号（不依赖字段名）**：条目头部 `标签:值` 密度 · 明确层级词命中（收紧词表 + 值形态判断，排除裸"归/界/山"类宽词）· 类型标签数（过黑名单后）· 坐标词命中。
- **脚手架黑名单（硬要求）**：`writing_style / control_scope / narrative / expression / aesthetics / prompt_discipline / dynamics / Chain_of_Thought / think / Analysis / UpdateVariable / actions_info / %_…` + 频次下界 + 头部位置约束——防宏型巨书（Global 21MB / 765 种假标签）淹没体例轮。
- **`unknownStructCandidates`**：未识别但形态像结构字段的标签（如三国的 `首领（X）：`）单列，供玩家一键认领为结构字段。
- **名号形态学（同一轮内，确定性、零 LLM、可解释）**：从**名号本身的形态**算结构线索——①**编制/机构字**（百官/阎罗/军/营/卫/司/监/局/部/院/曹/署）→ 该名号是 `body`（编制，不独立入池）②**势力字**（宗/门/派/教/盟/阁/宫/殿/家/族/国/朝）→ `actor` ③**地界字**（洲/山/海/泽/域/渊/狱/界/城/谷/池/森/原）→ `place/domain` ④**包含关系**（`天庭百官` ⊃ `天庭`、`昆仑道宫` ⊃ `昆仑`、`大虞皇朝` ⊃ `大虞`）→ 候选 `superior` 边 ⑤**"X帝麾下"/"X门下"式前缀** → `superior` 边。**每条线索都带解释**（"因'百官'判为编制；因名号含'天庭'判上级为天庭"），玩家可一键改判——**这是小白路径的主力**（人看名单时会做的事，引擎做）。
- 字段 role 的 LLM 归类**登记不做**（触发＝实机发现"种子+值形态"覆盖不足）。

### 2.2 契约：边表（K62，契约层）

**结构不塞进实体字段，单独一张边表**（实体保持薄；一条事实只有一处存）：

```
canon.structure: {
  nodes: [{ name, typeTag?, role: 'actor'|'body'|'place'|'domain'|'office', src: 'tag'|'field'|'sentence'|'player'|'inferred' }],
  edges: [{ from, to, rel: 'superior'|'ruler'|'seat'|'organ'|'agent', src: 'tag'|'field'|'sentence'|'player'|'inferred', evidence, at? }],
  apex:  ['人帝天庭六重天总览', ...],
}
```

- **来源四类（按"离书多远"分，`src` 取值）**：
  - **读到的**：`tag`（书标签，如 `<太素帝麾下_X>`）> `field`（字段明述，如 `辖属: 瑶池`）> `sentence`（散文层级句，带原句；三国/re0 走这条）
  - **算出来的（确定性、零 LLM）**：`name`（名号形态学，§2.1）· `derive`（**传递闭包**：书里 `A→B`、`B→C` ⇒ `A→C`，是推导不是编造）
  - **推断的（低置信，候选池）**：`inferred`（模型推断，带依据）· `runtime`（**运行期长出来的候选边**：盘算归属/事件波及/对话里的隶属断言——与"对话事实"同级，不自动改账）
  - **人定的**：`player`（纠正/兜底，**权威最高**——人比书与模型都权威）
- **引擎认「读到的 + 算出来的 + 人定的」；「推断的」进候选池**，按后果分级处理（§2.5）。"引擎只守诚实底线"因此落地为：**确定性推导可自动生效，模型推断按后果分级，无源之物仍不存在**。
- **兼容**：无 `structure` 的旧世界走原 `parent` 路径，**全链零扰动**（A-1）。
- `rel` v1 五值：`superior`（上级势力）`ruler`（统治者：可指向角色）`seat`（所在：地名/天层）`organ`（下属机构/编制）`agent`（代理/实际管辖，如"日常由瑶池主全权代理"）。

### 2.3 结构图轮（K63，编排层）

- **按体例三态分流**：`rich` → tag/field 边（大荒）；`medium`/`thin` → 增走 `sentence` 边（从关系句抽，带原句；三国/re0）；`none` → **不产边**，直接进玩家确认面（§2.5）从零手填。
- **输入单元＝条目，不是名号**（关键修正）：结构写在**特定条目**里（`[人帝天庭·下三天] 核心机构: 仙籍司…`），所以只喂"体例轮标记的结构承载条目"（大荒实测约 60-100 条），块小、密度高、每条边都有原文句。
- **只问结构问题**：这块文本里，谁是谁的上级/统治者/所在/下属机构/代理？输出**边**（`from/to/rel/依据句`），不要求模型给"实体类型"（类型优先读标签）。
- **全局归并＝确定性**：同名节点合并、指向解析（允许指向角色/地点）、**环/孤儿/多顶检测**、`apex` 指认——全部纯函数、可测。
- **成本**：条目子集（数十条）→ 1-3 次调用，比名册轮便宜一个量级。

### 2.4 折叠与位置接线（K64）

- **折叠走边表**：`seedBookEntities` 的折叠从"读 parent"改为"读 structure 边"——`superior`/`organ` 边 → 折成上级的 `branches`；`ruler`/`seat`/`agent` 边 → 落图与渲染（不参与折叠）。旧世界零扰动。
- **位置接线**：`context.positions` 从 `["未明"]` 升级为**书内 `seat` 值集合**（逐字、有据）；实体按 `seat` 边落位；**层级继承不做**（v1 不做推断落位）；天层/洲/驻地的层级关系登记 v2。
- 效果：掩码（分量×位置×情报）与"事件位置合法性"（未决点 2）终于有真坐标可用。

### 2.5 结构可见 + 确认面（K65，渲染层）

- 实体页/新页：**势力结构视图**（顶点 → 下属/编制/统治者/所在），让"天庭散落"这类错误**一眼可见**（检验三问③）。
- **面板＝异常处理器，不是编辑器**（leg22 用户质询后修订）：正常情况零操作——书读到的、算出来的、按后果分级自动生效的，都不打扰你。只有两件事会来找你：**①冲突**（书的边与推断的边打架）**②高后果推断的显著标注**（面板标"我推断的：天庭百官 → 天庭"，一键撤销）。
- **后果分级表**（推断/候选边的处置口径）：

| 后果档 | 例子 | 默认行为 |
|---|---|---|
| 低 | 类别标签、位置提示、置信标记 | 直接生效，可见可撤 |
| 中 | 编制/地界 vs 棋手（决定进不进棋局） | 直接生效，标注"我判的"，一键改判 |
| 高 | 折叠（子势力不独立入账）、实体合并 | 默认执行 + **显著标注** + **一键撤销** + 台账留痕（否则小白看到的就是平铺世界） |

- **`runtime` 边**（玩出来的结构）：与对话事实同级，**只入候选池**，可在面板一键采信；采信后不触发重抽。

### 2.6 读数与体检（K60，先做——判据的尺子）

把只读体检脚本机制化为正式工具（`demo/inspect-world.js` + 引擎层纯函数）：规模/结构边/覆盖率/退化/别名候选/置信度分布。**所有 A 判据以它读出**；没有它就无法证明结构轮有效。

## 3. 验收判据（可测）

- **A-1 零扰动**：无 `structure` 的旧世界走原路径；黄金锁与全部既有测试**逐字节不变**。
- **A-2 体例确定性**：同一本书两次体例轮产出逐字节一致（fields/tags/relWords/coordWords），且每条带出现次数与逐字样例；**零 LLM**。
- **A-3 标签优先（类别不再猜）**：书中有类型标签的名号，`kind`/`typeTag` 必须与标签一致——golden 用大荒片段锁（`<上界势力_蟠桃园>` **不得**判 location；`<上界势力_天庭百官>` 必须入册）。
- **A-4 边有据**：每条边带 `src` 与 `evidence`（逐字 ∈ 原文）；`inferred` 边不得缺 `evidence` 之外的标记；无依据边不存在。
- **A-5 结构读数**：以 (6) 复跑对比——势力→势力边数、孤儿率、`apex` 可指认（天庭体系顶点被认出）。**具体阈值首轮跑出后定（提案态）**，先锁"显著优于 3%"与"顶点被指认"两条硬判据。
- **A-6 折叠走边表**：`蟠桃园`（书标上界势力 + `辖属: 瑶池`）折叠进瑶池 branches；`天庭百官` 类编制条目不独立成顶点。
- **A-7 位置接线**：位置集不再只有"未明"；实体落位率显著上升（阈值首轮定）；`未明` 兜底保留。
- **A-8 确认面**：`inferred` 边在面板可见可确认/删除；确认后边升级为 `player` 且**不触发重抽**（指纹不变）。
- **A-9 回归 + 黑名单**：`node --test` 全绿（390+N）；新文案 A-3 零禁词。
- **A-10 泛化（跨书异质）**：体例轮在书架 7 本异质书上——三态判定稳定（rich:大荒／medium:三国／thin:re0·综漫／none:实力至上·Global·Yuzuki）、**逐字节可复现**、rich/medium 书能出边、none 书**明确报 none 且不产边**、宏型巨书（Global 21MB）被脚手架黑名单挡住、全程零崩溃。

1. **骨架来源**：①纯抽取 ②**抽取（tag/field 边）+ 玩家确认 inferred 边**（推荐）③玩家手填。
