### 3.1 三道上限不在保护预算（这是"删闸"的根据）

| 量什么 | 读数 |
|---|---|
| 刻度块实际占预算 | **3,472 token = 6.94%**（10,417 字符 / 50,000） |
| 三道上限**全部吃满**时的最坏体积 | **4,429 token = 8.9%**（≈13,288 字符） |
| 真账整包 | **27,185 token = 54.4%**，`trimmed` 是 **`null`**（预算根本没满） |

⇒ **闸在关着一扇预算根本没关的门。**

### 3.2 而它在真账上已经开始咬

| 书 | 表 / 档 | 旧上限下 |
|---|---|---|
| 真账 `大荒z` | 1 张 / 16 档 | 全进（目录空） |
| 真书 `real-world-dh` | **45 张 / 293 档** | 全进，**但离 `TIER_TOP=300` 只差 7 档** |
| 合成 45 张 × 12 档 | 45 张 / 540 档 | ★**只进 25 张，20 张整张丢** |

⇒ **真正的闸是 `TIER_TOP`（档位合计），不是表数**：表数上限几乎咬不到（200 张表 × 2 档 ⇒ 64 张全进）；
档位预算是**顺次扣**的，扣光就停，**后面的表一张都不进**（`pack.js` 的 `scaleAnchorCore`）。

### 3.3 抽取质量**不是**问题（用户猜的那条路，实测否掉）

`real-world-dh` 45 张表逐张看过：**表名重复 0 · 空表 0 · 只有 1 档的仅 1 张**（《战力详解 引气篇》= T1）；
分布 2-3 档 5 张 · 4-6 档 15 张 · 7-12 档 22 张 · 13+ 档 2 张（平均 **6.5 档/张**）。
★这 45 张是 **45 个不同的概念**（雷劫分级 / 蟠桃分级 / 灵石换算 / 通灵分级 / 宗门职务…），
每张都带得出原文出处 ⇒ **没有"无用刻度"可省**，没道理的是**上限本身**。

跑生产校验器 `validate(world, ssotSchema)`，逐格看 `meta` 层：
