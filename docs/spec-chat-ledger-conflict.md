## 0. 一句话

**聊天模型每轮读的是世界书，而账本早就不等于书了——谁死了、谁的哪一格被哪件事改成了什么，
账上全记着（连原值、轮次、因都记着），可这些东西一个字都没进过对话。这一笔要把"账上跟书不一样的那几条"递进对话。**

★**关键在后半句**：**不新建任何表、不加任何字段、不动任何契约**。那些"发票"账上本来就有
（`meta.entityFields` 与编年行），本笔只是**把它们读出来、排成人话、递过去**。

★★**这个病是真的、这个治法有效——都实测过了**（§1.6）：
真账最后一轮重掷 ⇒ 模型**把账上已死的人写成行动主语**；加上这一段 ⇒ 它**当场把人写死了**；
把这一段**写反** ⇒ 它**又写活了**。

## 1. 病：今日实测（不是推测）

### 1.1 用户从一开始要的就是"防冲突"

这一点必须写在最前面，因为**上一棒把它读成了"给玩家做窗口"**。

⇒ 本笔的目标只有一条：**让聊天模型别写出与账本冲突的正文。**

### 1.2 冲突是怎么长出来的：起点一致，之后分叉

**用户那句"一开始抽象完的时候不就是世界书的所有设定"——成立。** 时间线是这样的：

| 阶段 | 书 | 账 | 两边一致吗 |
|---|---|---|---|
| **起点** | 作者原稿 | 抽象把书抽成 `setting.frozen.canon`（书名录 ＋ 法则 ＋ 刻度），账上的实体是从它**播种**出来的 | ✔ **一致** |
| **之后每一轮** | **一个字不动**（只读原稿） | 世界步能改实体的格（`entityUpdates`）、能灭人（`entityFates`） | ✘ **开始分叉** |
| **聊天模型看到的** | **每轮照旧读得到书** | —— | ✘ **它读的是旧样子** |

★书那一侧是 **ST 自己在组装提示词时塞进去的**（`README.md:166` 原话："聊天模型仍然照常读你的世界书
（那是 ST 在组装提示词时塞的，与插件无关）"）⇒ **插件管不着模型读了什么，只能把"更正"递过去。**

★★**另一半（本笔只动聊天侧的理由）**：**世界模型那一侧没有这个病**。实测包里**没有书名录**——
包的全部键是 `world / tension / setting / positions / entities / agendas / pendingEvents / departed /
recentClosedEvents / playerMove / dialogueBook / closedAgendas / idleFaces / openRoots / threads / closedRoots`
（`src/pack.js:990-1034`），而其中的 `setting` 只有**张力、环境、刻度、法则**（`:998-1011`）
⇒ **世界模型从来没见过书里的原值**，它只看得见账上现值。
⇒ 一句人话：**"照书里的旧样子写"只可能是聊天模型干的。**

### 1.3 今天已经做了一半（如实登记，别以为是从零开始）

`web/inject.js` 现在有**四段注入**，其中第四段「账上往事」（开关 `injectLedgerRecall`）**默认开着**——
它是**唯一**一个默认开的（`web/index.js:906-908`，口径写得很清楚："**从没设过才算开**"）。

它每轮把最近几轮的往事递进对话（`web/inject.js:376-397`）。**但它答的是另一个问题**：

| | 第四段「账上往事」 | 本笔要补的 |
|---|---|---|
| 答的是 | **发生过什么**（时间线） | **现在跟书哪里不一样**（状态） |
| 驱动方式 | **检索驱动**：查询词 = 上一轮正文 ＋ 这一轮输入，按名取往事 | **无条件算**（不依赖检索） |
| 检索没命中时 | ★**那一段整个是空的**（`got.ok` 假 ⇒ `ledger = ''`，`web/inject.js:394-395`） | 照旧有（见 §2.4 第 4 行） |

### 1.6 ★★★ 实测记录（2026-09-23 · 真账副本 ＋ 真模型 · 装置 `demo/measure-leg121-divergence-live.js`）

#### 1.6.1 ★★ 我先量错了对象——这一条必须写在最前面

细案第一版立论时，我先去量"**账本改了书里多少东西**"。读数（61 轮真账 · 621 实体 · 751 条书名录）：

| 比什么 | 读数 |
|---|---|
| **两边都写了、值不一样** | ★★ **0 处** |
| 账上有、书里也有 | **617** 条（`kind` 617 全对 · `parent` 15 全对） |
| 书里有、账上没有 | **134** 条 —— ★**全是地名**（`location`），不是棋手 ⇒ **不是冲突** |
| 账上有、书里没有 | **4** 条 —— 薛铁衣 / 万子明 / 黄坤 / 转轮鬼使，全是**世界模型游戏里新造的人**（id 都是 `e_<轮次>_1`）⇒ 设计允许 |
| 61 轮里"被事件改过"的格 | **1 个**（黑山老妖的〈实力〉，第 60 轮）——★ 而书里**没有**那一格 |

⇒ 我一度据此写下"**这个病在真账上量出来是 0**"。**那个结论是错的——不是数字错，是尺子错。**

★★**真正的病不在"账 vs 书"，在"正文 vs 账"**：聊天模型读的是书，它**根本不知道账上已经变了**。
用同一份真账、把**真账最后一轮重掷**一次（真模型、真上下文、真玩家输入），当场抓到：

```
【行动】万子明｜献上｜秘库钥匙        ← 万子明是账上唯一的 dead
【行动】白小娥｜突破｜大境界          ← 白小娥账上是 retired
```

⇒ **模型把账上已死的人写成了行动的主语**，而生产解析器**认得出、收得下**
（`src/` 里关于死者的判据只有"已灭者不能当牵出者／不能重复覆灭／查书不选他"那几条，
**没有一条拦"死者行动"**）⇒ **这件事会一路落进账本**。

★**带走的一条**：**问"这个病有多大"之前，先问"量的是哪两者之间的差"**——
"账 vs 书"与"正文 vs 账"是两个完全不同的问题；拿前者的读数去否掉后者，就是拿错了尺子。

|---|---|---|---|---|
| **A 现状** | 无 | **无** | 无 | **0** |
| **B 治法** | 生产 `tagSpecText()` | ★**有** | 无 | ★**5** |

## 2. 治法：**只喂"分歧"，不喂"账本"**

**分层声明**（照 `docs/dev-process.md` §9，写清改哪层）：本笔只动 **取数层 ＋ 编排层 ＋ 判据**。
★**契约层与引擎层一个字节都不动**——因为要用的东西账上早就写好了。

### 2.1 分歧是什么、怎么机械地算出来（**两个**来源，全部读**现成**的账）

新增一个纯函数 `ledgerDivergenceText(ssot, { maxChars })` ⇒ 返回一段人话（**可能是空串**）：

| 来源 | 判据（逐格读账，零模型调用） | 出来的一句 |
|---|---|---|
| **① 已死** | `e.status === 'dead'`；**来路从编年行取**（见下） | 「〈名〉：已死（第 N 轮「那件事」）」 |
| **② 被事件改过的格** | `meta.entityFields[e.id].fields[f].source === '变更'` | 「〈名〉的〈某格〉：账上是「现值」，书里原样是「原值」（第 N 轮「因」）」 |

★★**来源③「引擎推的值」整条删掉**（细案第一版有它，实测后删除——**这是本细案最要紧的一处更正**）：
按原文实施，这一段在真账上是 **4044 字**，其中 **4000 字**是 **142 条**「X 的所在是引擎按结构推出来的（书里没写）」
（`meta.entityFields[id].位置来源 === '结构推导'`，真账实测 142 个）。**它根本不是冲突**——
**书里没写 ≠ 书里写了别的**；而且它**正好犯 §1.5 那条大忌**：142 条"账本状态"塞进对话，
就是把剧情拽着**围着账本转**（`inject.js:193-194` 当年有意堵掉的正是这个）。
⇒ **删掉它，本机制才真的只剩"更正"。**

★★**来源①的来路必须从编年行取，不许从 `entityFields` 取**（细案第一版写错了，实测更正）：
`applyEntityFates`（`src/settle.js:931-937`）**只写 `ent.status` 与一条编年行，不写 `meta.entityFields`**
——真账 3 个人（万子明 / 白小娥 / 东海龙宫）**都没记因、没记轮次**。
真源是那条编年行：**`id` 是 `ch_<轮次>_fate_<实体id>`，轮次就在号里**，文本里带着理由
（`「〈名〉」覆灭（〈理由〉）`）。⇒ **读编年行，不读 `entityFields`。**

★**`retired` 要不要说 —— v1 建议不说**（降为待拍板，见 §5 第 2 条）。
理由：`retired` 是**引擎机械背景化**（`src/settle.js:1138`），意思是"引擎把他归为背景了"，
**不是"他离开了"**；而且 `reactivateNamed` 会在新事件点名他时**自动把他升回 active**（`settle.js:1101-1106`）
⇒ 把它当"分歧"说出去，是**把一条记账分类说成了世界事实**，可能误导。
（★实测里它确实生效了：D 组说"白小娥：已离场"，模型就写她"离开江州"——**正因为它生效，才更要说清这是不是我们要的**。）

**四条口径（缺一条这次设计就是错的）**：

1. ★**零新数据**：两样全在账上（`status` ＋ 编年行 / `entityFields.fields[f]`）
   ⇒ **不加表、不加字段、不加可选组**，★而且**根本不进 `src/gate.js` 那条白名单路**
   （那条路本仓踩过**三次**，病历两份就写在 `src/gate.js:127-133`）。
2. **零模型调用**：纯读 ＋ 拼字。⇒ 每轮成本为零，不会因为"要多问一次模型"而变慢。
3. ★**原值缺了就不说原值**（红线 `STATE.md` §2.2 第 2 条"空着就是空着"）：
   `prev` 没有 ⇒ **只说现值**，**绝不许**编一句"书里是空的"。
4. **顺序与截断照第四段那把尺子**：**轮次新的在前**；
   ★**只列了前几条必须说出来**（不许静默截断——`leg112` 撤掉的那条静默闸是血证）。

### 2.2 措辞（人话、零引擎术语；`STATE.md` §2.5 红线）

```
【这一局里跟书里不一样的地方】
  · 万子明：已死（第 45 轮「…」）
  · 薛铁衣的〈实力〉：账上是「重伤未愈」，书里原样是「T9渡劫巅峰」（第 31 轮「…」）
```

一句说"**别念出来**"（防它把账本腔写进正文——那正是 §1.5 那条决定担心的东西）。

**而没有一个字变成台词**。

### 2.3 ★为什么"只喂分歧"能同时保住那条决定
