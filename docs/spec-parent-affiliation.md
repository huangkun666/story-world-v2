## 3. 四个方案（互相正交，可组合）

### 方案 ①　纯结构推导（零 token）
**做法**：`seedBookEntities` 时，从**势力条目**的成员行 / `key` 名单反查名号 → 写 `parent`。
**成本**：0 次调用、<1ms。
**实测**：严口径可填 **130 / 495 角色 = 26.3%**（`散修` 19、昆仑道宫 11、万法阁 10…）。
**致命伤**：**假关系**——实测样例 `散修 → 散修`（泛称被当成势力）、`虞昭华 → 人族皇朝`（小节标题被当成势力）。**结论：单独不可用**（违反「宁可漏填、不可错填」）。

### 方案 ②　纯模型抽取（v1 路线照抄）
**做法**：名册轮 prompt 加 v1 的 `affiliation` 字段，模型直接给"所属势力"，落账。
**成本**：名册轮本来就在跑（大书 4 块 @60k），加字段**不新增调用**。
**优点**：**语义正确**——模型能分清"散修"是泛称；跨书格式无关（西式条目也有 `affiliation` 可读）；`power` 同理（v1 的必抄规则）。
**风险**：模型会**编**（v1 的应对是事后 `findInBook` 校验并丢弃编造项，`director.js:70`）。

### 方案 ③　对账：模型提议 + 结构验伪（v1 召回 × v2 校验）
**做法**：模型给的 `parent` **不直接落账**，先过一道**确定性验伪**——该证据必须在书里真实存在：
- (a) 角色名 ∈ 该势力条目的成员行；或
- (b) 角色名 ∈ 该势力的 `key` 名单；或
- (c) 角色自己条目里有显式 `所属/势力=` 且点名该势力。
三条任一成立才落账，否则**弃关系 + 留警告**（照 `seedBookEntities` 现有 `missWords()` 惯例）。
**优点**：**模型不能凭空造关系**（校验是确定性的）；语义由模型把关（不误收泛称）。
**代价**：只覆盖"书里写得出证据"的那部分（大荒约 26% 角色 + 显式字段那批）。

### 方案 ④　专用抽取轮：只喂**组织条目**，回填剩余（补 ③ 覆盖）
**做法**：名册轮之后，把**判为势力的条目**（大荒 93 条）单独喂一次，问"每条下面列了哪些角色、各自身份/档位"→ 回填 ③ 未覆盖的空位。
**成本**：**+1 次调用**（93 条 ≈ 10 万字符 ⇒ 1–2 块）。相比 v1 的整本 50 块，便宜得多。
**优点**：召回来自**势力那一侧**（书里最可能有花名册的地方），对"角色没有自己条目"的书（大荒、三国）是**唯一能补齐的通道**；跨书通用（组织条目是各书都有的形态）。
**风险**：仍是模型输出 ⇒ 同样过 ③ 的验伪闸。

## 4. 选型（我的判断与理由）

**选 ③ + ④ 组合，落账时再接 ① 作为兜底**——理由：这三者不是并列竞争，而是**"语义判别"与"书面证据"两件正交的事**，缺哪一半都会出事：

| 谁 | 负责 | 若换成别人会怎样 |
|---|---|---|
| **模型**（v1 的 `affiliation`/身份档位） | **语义判别**：这是不是一个组织？这行是不是花名册？ | 纯结构（①）会收进「散修」「人族皇朝」——已实测 |
| **结构**（成员行 / key 名单 / 显式字段） | **验伪**：书里到底有没有这条关系的书面依据？ | 纯模型（②）会编——v1 自己都要 `findInBook` 兜 |
| **专用轮**（④） | **召回**：角色没有自己条目时，从势力那侧读花名册 | 只做 ③ 会漏掉大荒这种"角色只出现在势力条目里"的书 |
| **①** | **兜底**：模型没给、但结构证据确凿时补上（零成本） | 不做则白丢 26% |

**明确不选**：
- 纯 ①（**会造假关系**，实测有活证）；
- **目录/标题层级法**（8 本语料里 `#/【/<` 形态为 0，**无依据**）；
- **词表法判断势力**（用户明令过"被很多词表法弄得很烦"；且实教书的 key 名单是剧集标题，词表必炸）。

**纪律（沿用 leg25 d 已确立的两条，不新发明）**：
1. **只填空位**、**明述优先**（已有 `parent` 不被覆盖）；
2. **来源分账 + 外显**：`parent来源` ∈ `{书里原话, 结构推导, 模型抽取}` + `parent来源自`（哪一条 / 哪一次）；推出来的在面板与 pack 标「（推）」——与 `位置来源` 同款；
3. **宁缺勿造**：验伪不过一律弃关系 + 警告，**绝不写猜测值**（错归属比空着更坏）。
