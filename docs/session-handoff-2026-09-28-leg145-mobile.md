## 4. ★★★ 本笔最值钱的三条

### ① **"写了规则"不等于"规则生效"——那条窄屏断点从立起来那天起就是死的**

**病（本仓自己立的、自己没验的）**：leg104 给窄屏加了一条 `@media (max-width:620px)`——
"实体行首列写死 212px，620 以下读起来是碎行" ⇒ 改单列。**判据也写了**（`style-cues-layout.test.js` 的 SCue④）。
**而它一直是死的**：那条媒体查询住在**文件前半**（并页那一段附近），而被它覆盖的
`.sw2-entity-row` 基础规则住在**实体页那一段（更靠后）** —— 媒体查询**不加特异性**，
同特异性下**后写的赢** ⇒ 后写的基础规则反过来盖住了媒体查询。

**实测（本笔 · 390px 宽 · 无头 Chrome）**：`.sw2-entity-row` 的 `grid-template-columns` 是
`212px 15.25px 11.75px`（**三列**），不是 `minmax(0,1fr)`。★连带后果：实体行在手机上
**要 278px 塞进 265px**（横向溢出），而那一页的工具条还另有一块 450px。

**为什么原来的判据咬不住**：它咬的是"**这句话在不在那个媒体查询块里**"（`assert.match(mq620, /\.sw2-entity-row\{grid-template-columns:minmax\(0,1fr\)/)`）
——**在**，所以绿。它**没咬"这句话赢没赢"**。⇒ 这与本仓那条老话同源：
**判据只咬字面的时候，看起来永远像对**。

**治法**：把整个 620 块**搬到文件末尾**（规则文字一个字没改），并在新判据里咬**位置关系**
（`M2`：`@media (max-width:620px)` 的下标必须**大于** `.sw2-entity-row{` 的下标）。
★**给下一任的一句话**：**往媒体查询里加覆盖时，只能加在它覆盖的那条规则之后**——
加在前面的等于没写，而且**不会有任何东西报错**。

### ② **`modalBoost()` 那条内联规则排在样式表之后 ⇒ 手机要改遮罩留边，必须写"id ＋ 类"**

**病（差点踩上）**：手机上要把遮罩留边从 20px 收到 6px、把视口高从 `100vh` 换成 `100dvh`，
而这两项**第一版都写在 `web/index.js` 的 `modalBoost()` 里**（一条**内联** `<style>`，
特异性是 **id**，而且它是 `document.head.appendChild` 在样式表**之后**插进去的）。
⇒ 在 `web/style.css` 的媒体查询里写 `.sw2-window-mask{padding:6px}` **压不过它**——
**看着改了、其实没生效**（本仓"静默失效"家族的又一个形状）。

**治法**：手机的这两条写成 **`#story_world2_window.sw2-window-mask{…}`**（特异性 (1,1,0) > (1,0,0)，
与"谁在前谁在后"无关）。★**判据 `M3` 把它变成机械的**：先断言 `modalBoost()` 里**真有**那条
`padding:20px` ＋ `height:100%` 的 id 规则（前置自证——取不到就是空绿），再断言手机那两条
**带 id** 且值对。
★**另一条附带的好处**：本笔因此**一行都不用改 `web/index.js`**（接线层只剩 14 行余量）。

### ③ **"手机上的字号"没有机制可兜，只能用"名单 ＋ 棘轮"**

**病**：全表有 **94 条**规则的 `font-size` **小于 12px**（10 / 10.5 / 11 / 11.5px）——
在手机上那是"要凑近看"的字。用户点头"抬到 12px"，而 **CSS 没有"最小字号下限"这种写法**
（`font-size:max(12px,1em)` 会把层级全压平：小字变得跟父级一样大，信息带"副角安静"那条设计当场没了）。

**治法**：手机那一档里列**一份 94 个选择器的名单**，把 `font-size:12px` 一次性写上去；
★**关键在于那条判据**（`M7`）：它现读全表，把"基础规则里 <12px 的选择器"全抓出来，
再要求**每一个都在那份名单里**——**将来谁新加一个 10.5px 的类而没进名单，这条判据当场红并逐个列出**。
★这是本仓"**读数只许有一处**"的同一把尺子，用在 CSS 上：**名单会腐，棘轮不会**。

## 5. ★ 我栽的三跤（如实登记）

### 跤一：**装置骗了我一次——四张截图全一样**

第一版 `run.mjs --shots` 出来的四张图（编年/实体/设置/参数）**字节数完全相同**。
**根因**：截图模式也调了量尺函数 `__measure()`，而它**逐页量完之后会把页面切回第一页**（观棋）
⇒ 四张图全是观棋页。★**教训**：量尺与截图**是两个用途**，量尺的收尾动作（切回第一页）不能带进截图路径。

### 跤二：**`pointer:coarse` 在无头浏览器里恒为 false**（触摸那一档量不到）

试过 `--touch-events=enabled` 与 `--blink-settings=primaryPointerType=2,…`：**两个都让 `--dump-dom` 吐空**
（0 字节）。⇒ 定稿的办法是**把 `@media (pointer:coarse)` 那一块原样剥出来、当普通规则挂上**再量。
★**这是一处必须说清的边界**：这样量到的是"**这些规则一旦生效会得到什么版面**"
（会不会因为点击目标变大而挤出新的溢出——实测：**没有新溢出**），
**不是**"手机上到底匹不匹配"（那只有真机能验）。**别把这两件事混着读。**

### 跤三：**用 PowerShell 碰了含中文的文件**（本仓写过两次的铁律，我又踩了一次）

`frame.html` 里那几行中文注释被 `Set-Content` 按码页走了一遍 ⇒ **乱码 ＋ 吞掉一个换行**（把一条
`if` 语句并进了注释里，脚本当场坏掉）。★**治法与留档一致**：改文件只用 `edit`／`write`；
**这一笔的受损文件在仓外**（`F:/deepseek/tmp/`），重写一遍即可，**仓库里一个字节都没受影响**。
