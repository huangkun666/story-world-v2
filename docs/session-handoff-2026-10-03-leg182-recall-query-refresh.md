## 2. 最终行为

### 新问题的向量

`web/inject.js` 在准备请求、收到结果及使用缓存时核对同一组信息：聊天、人物或群组、世界对象、已有轮次和完整查询。完整查询仍由原有 `sw2RecallQueryText` 生成，包含上一段正文与玩家输入；不猜话题类别，不改查询规则。

发送消息时先准备当前查询，再同步注入当前名称、关键词结果。新问题会立即撤掉旧向量，准备期间不继续用上一话题的结果；请求在后台执行，不增加等待或超时阈值。返回后若仍属于当前查询且开关开启，则重设真实注入口。现有数组和 `{items}` 两种结果形状都支持。

同一查询的进行中或成功结果可复用。失败、服务尚未就绪和空返回允许重新尝试；查询临时修改后恢复原文，被丢弃的已结束请求也不会挡住重新获取。较旧请求的成功和失败回调都不能覆盖或清除较新请求。关闭、空查询、切聊天、换世界、同对象回档继续隔离旧结果。

### 关键词选择

`src/ledger-recall.js` 的关键词模式现在保留不同词的命中数排序，同分才按已有轮次的新旧。最近模式与名称模式单独使用时仍按新旧排序，向量模式仍按相似度。

聊天侧先合并名称与关键词的完整候选，再复用检索层的 `rankKeywordMatches` 选择预算，避免在排序前截掉多词命中的旧记录，也避免名称模式先认领同一旧记录后把它排到后面。排序只用于选择哪条占得到额度；选出的记录仍按时间顺序排成文本。

字面与向量的已有额度分配沿用现状。只对实际选入的记录去重，候选池中的旧行不能提前排除它的向量命中；字面与向量共用原行对象时也不会重复计入向量条数。匹配词数只表示字面匹配强弱，不判断故事语义、人物实力或重要性。
