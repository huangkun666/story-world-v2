## 0. ★★★ 一句话：那个"近 10 轮事件"印的是 83，而账上只有 76

同一个事实，仓里有两把尺子在量，答案不一样：

⇒ 本笔是把**引擎那一口回到已写定的口径**，**不是立新口径**。

★**为什么这个 bug 会印到玩家眼前**：`eventBornTick` 是**引擎唯一契约点**——

## 2. ★★ 修法与它的边界（判据锁着）

**修法**（`src/setting.js`，**一处**）：

```js
export function eventBornTick(id) {
    // 种子先判：它的数字段是枚举号、不是轮次（判据在 test/setting.test.js）
    if (/^ev_seed_\d+$/.test(String(id || ''))) return 0;
    const seg = String(id || '').split('_').find((s) => /^\d+$/.test(s));
    const n = seg === undefined ? NaN : Number(seg);
    return Number.isInteger(n) && n >= 0 ? n : -Infinity;
}
```

★**其余形状一个字未动**（`ev_<轮>_<序>` / `ev_pump_<轮>_<序>` / `m_<n>` 照旧"取首个数字段"）。

### 11.3 两栏各自独立滑动：为什么必须给容器**定高**

★**旧模型**是"**整页一条滚动条 ＋ 右栏 sticky**"——面板外壳自己就滚
（`#story_world2_window{max-height:88%;overflow:auto}`，写在 leg98 的注释里）。
要让**两栏各滑各的**，就得把"滚动"从**面板外壳下放**到两栏里；而"里面能滚"的前提是
**"外面有个确定的高度"**（不然内容会把容器撑开，两栏永远滚不动）。落地（`web/style.css`）：

| 处 | 定稿 | 为什么 |
|---|---|---|
| `.sw2-merged-grid` | `height:calc(88vh - 190px)` ＋ `min-height:320px` | 88vh 对齐面板那 88%；190px ≈ 页头一行 ＋ 信息带那个 1390 字节块；**下限**是"屏幕矮时宁可整页滚，不许把两栏压成两条缝" |
| `.sw2-merged-main` / `.sw2-merged-side` | 各 `overflow-y:auto` ＋ `height:100%` ＋ `overscroll-behavior:contain` | 各自能滑；`contain` = 滚到头条**不许把滚动传给外壳**（否则又变成"整页跟着动"） |
| `.sw2-merged-side` 的 `position:sticky;top:0` | **撤掉** | 它是"整页滚、右栏钉住"那个模型的产物；**两个模型并存会互相打架**（钉住的东西在滚动容器里不动） |
| `@media (max-width:980px)` | 定高与两栏滚动**一起取消**（`height:auto` ＋ `overflow:visible`） | 否则退回单列时那两栏会各自变成**一口小井**，反而更难读 |

★**为什么这条判据要读 CSS**（本族第一条**测样式**的判据，说书⑳）：
"两列都能独自滑动"在 **DOM 结构上看不出来**——`mergedMainHtml` 交出来的 DOM 与"整页一条滚动条"时**一模一样**，
差别**全在 CSS** ⇒ 照本仓"判据要咬在**那一层**上"的纪律，那条判据读 `web/style.css` 按**规则**咬
（咬**关系**不是色值：两栏都有纵向滚动 ＋ 容器有定高 ＋ 窄屏一起取消 ＋ sticky 不许回流）。
