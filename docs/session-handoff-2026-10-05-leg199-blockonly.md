## 二、令①的配套：JSON 转义那一档必须单独救

删降级时**当场踩到一个真问题**（判据 leg137① 翻红，我实测定位）：

- 模型把整块标签塞进 JSON 字符串时，换行成了**字面的两个字符** `\` `n`；还原真换行之后，**第一行是 `{"tags":"```tags`** —— 围栏前面还挂着 JSON 信封那几个字符。
- 而 `RE_FENCE_OPEN` 那条"**整行只有它**"（leg93 定的，**不许放宽**）当场不认 ⇒ **还原这一级白救** ⇒ leg137 治过的那条静默失效会原样复发。
- 它原来能work，**只因为降级那条路在旁边兜着**（逐行扫全篇，围栏认不认都无所谓）。

**治法**：给"还原过字面 `\n`"那一档**单独**放宽围栏识别（`RE_FENCE_OPEN_LOOSE` = 行尾锚定 `` /```\s*tags\s*$/ ``），并且**只对这一档开门**（`RE_ESCAPED_FENCE_CLOSE` 那道"已确认是 JSON 转义"的门槛先过）。
★**边界**：正常路径一个字没松（`RE_FENCE_OPEN` 原样）；这一档里的围栏前缀**必然是信封**、不是正文。

## 三、令②③：第 7 条改值口径（"实力"那一格）

**病**（用户原话）：「给一个角色修改实力字段，但是**不是写从筑基到金丹这样修改，而是写获取了资源然后大幅提升了当前实力**」。

★★**我第一版读错了**：我把它读成"过程 vs 状态"（第三格该是状态不是过程），用户当场更正——
「**我说的是实力按道理来说如果有境界那么应该是境界的变化，而不是一句抽象的实力大增**」。
⇒ 真正的口径是**两层**，第二层才是他要的：

1. 第三格是**变完之后那一格的值**（新状态），不是**过程**——「获取了资源」「大幅提升」是**怎么变的**。
2. ★★**变强/突破时，第三格要写书里那套档位的名字**（境界/等级/品阶/军阶——本书怎么分就怎么写）：
   书里分筑基／金丹／元婴，就从筑基写**金丹**；**不许**写成「实力大增」「功力大涨」「大幅提升」
   这类**抽象的变强总结**。
   ★为什么这一层更关键：它**看着像个状态**（"实力大增"是完成态），其实**说不出他什么水平**——
   而"实力"这一格在本仓的定义就是**档位标签原话**（`ssot.schema.js:282`：「character：档位标签原话（文本，引擎不换算）」），
   填了抽象总结，这一格从此**当不了值**。

**根因（三处）**：
1. 第 7 条原文说第三格是"**被改成了什么**"＋"**照抄戏里的说法**" ⇒ 模型把**过程句/总结句**照抄进去。
2. ★**示例本身就在教模型写错**：旧示例是 `【变化】黄坤｜实力｜踏入元婴`——"**踏入**元婴"是**过程**。
3. ★**引擎拦不住**：`registerDialogueFacts` 那条"值必须在正文里找得到"（`src/settle.js:1217`）对
   「获取了资源然后大幅提升了当前实力」「实力大增」**一律放行**（那几句话确实在正文里）。

**治法**（`web/inject.js` 的 `tagSpecText()`，第 7 条现在三行）：
- 第三格＝**变完之后那一格的值**（新状态）；对：「元婴期」「重伤」「边关防务总管」「剑术通神」；错：「获取了资源」「大幅提升」。
- ★★**有境界的书：写书里那一档的名字**（书里分筑基／金丹／元婴 ⇒ 写**金丹**）；**不许**「实力大增」这类抽象总结。
- ★**戏里没点出新档位就别写这一行**（只写"得了一枚丹药、功力大涨"而没说是哪个境界 ⇒ **留空**，不许拿过程或总结去凑）。
- ★**示例改成状态式**：`【变化】黄坤｜实力｜元婴期`（并把"不许回潮"写进判据）。

**为什么只能靠规范拦**：本仓 `ANCHOR.md` §4.8 明禁"用词表判语义"⇒ 引擎侧**判不出**"金丹"与"实力大增"
哪个是档位名，**没有**、也不该有那道闸。**规范那一句话是唯一的闸**，所以判据两头都咬（见 §4）。
