## 1. 记忆投递：一条真数据丢失 + 一个被吞掉的异常（leg27 g / i）

### 1.1 用户档案被清空（**真数据丢失**，已修）

**凶手一行**（`web/index.js` 的 `memoryStore().readState()`）：

```js
const s = Storage.loadState?.(null, null);   // ← 第 2 实参显式传 null
```

插件签名 `loadState(fallbackState, sessionId = getCurrentSessionId())`——**ES 形参默认值只在 `undefined` 时生效**。传 `null` ⇒ `sessionId=null` ⇒ `getStorageKeys(null)` 返空 ⇒ 插件开头 `if (!keys.length) return normalizeState(null, fallbackState)` 返回**非对象** ⇒ 我方 `typeof s === 'object'` 不成立 ⇒ 退回 `blank()`（自带表全空）⇒ `writeRecords` 再 `saveState(..., { force: true })`（**force 跳过插件全部保护闸**，含它自己那道"空状态不许覆盖更富的记忆"）⇒ **用户填过的「角色档案」被逐条抹掉**。物品追踪/世界设定"看着还在"是因为那两张表**记录本来就是空数组**。

**铁证（可复现）**：把插件**真存储代码**放进 Node `vm` 假浏览器（stub `window`/`localStorage`/`SillyTavern.getContext`/`saveChat`），同一夹具对照——

| 写法 | 投递前 | 投递后 |
|---|---|---|
| 现行 `loadState(null, null)` | character_profile **3 条** | **0 条**（localStorage + chatMetadata 同时被清） |
| 改成传插件默认态 | 3 条 | **3 条原样保留** |

**治法**：`readState()` 传 `blank()`（插件自己的默认态，正是形参本意）；`memoryStore` 提成**导出函数 + `YM` 依赖注入**（不这样这条永远进不了测试）。

**判据两条（均先证红）**：①结构层——禁 `null` 占位 sessionId，**精确到第 2 个位置实参**（`loadState(fallback ?? null)` 合法，宽判据会误伤），且**必须先剥注释再扫**（第一版红在我自己的事故留档注释上）②行为层——会话感知 fake 插件**真跑**，档案逐条保住 + 表定义不许被抹 + ★自检"返回非对象时**必须**认成档案丢了"。

**不可救的部分（如实留档）**：①用户给的 10 个 `yzm_` 键里**没有** `yzm_memory_branch_snapshots:` ⇒ 插件分支快照没在；②真账 156 行全文搜索：`character_profile`/`角色名` **只出现在第 1 行**（表定义）⇒ 该表**从未持久化过任何记录**。⇒ **档案无盘上/快照可救。**
