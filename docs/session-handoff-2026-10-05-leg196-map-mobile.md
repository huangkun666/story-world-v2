## 一、病根（**在真宿主页面上复现出来的，不是猜的**）

`.sw2-map-mask` 原来写的是：

```css
.sw2-map-mask{position:fixed;inset:0;…}
```

**只有四边偏移，自己不声明宽高。** 病根**不在 `inset` 这个写法本身**，而在**宿主页面把"视口"这件事改掉了**：

酒馆自己的 `public/style.css`（第 143 行起）给 `<html>` 加了

```css
html { -webkit-transform: translateZ(0); -webkit-backface-visibility: hidden; -webkit-perspective: 1000; }
```

按规范，**`transform` / `perspective` 会给"固定定位"的子孙另立包含块** ⇒ 这里的 `top:0;bottom:0`
**不再对着视口解析**，而是对着 **`<html>` 那个盒子**；而 `<html>` 自己没有高度规则
（高度在 `body` 上：`body{height:100dvh}`）⇒ 实测 `<html>` 算出来的高度是 **0**

⇒ 遮罩高度 = **0 ＋ 手机档那 6px 上下内边距 ×2 = 12px**，地图盒子被压成 **26px**，
里面七百多像素的内容全挤成一条带滚动条的缝。**用户那张截图就是这 12 / 26px。**

**实测读数**（真 `index.html` ＋ 真 `style.css` ＋ 无头 Chrome，`458×1017 @3x`，照用户那张图反推的尺寸）：

| | 地图遮罩 | 地图盒子 | 面板遮罩（对照） |
|---|---|---|---|
| **改前** | **458 × 12** | 446 × 26（scrollHeight 738 / clientHeight 24） | 458 × 1017 ✔ |
| **改后** | **458 × 1017** ✔ | 446 × 1005（填满） | 458 × 1017 ✔ |

★**同一页、同一台浏览器上，两张遮罩一个塌一个不塌**——差别只有一处：
面板遮罩与事件链遮罩都**自己声明了 `width:100%;height:100%`**，只有地图这张漏了。

## 二、治法（照另外两张遮罩抄）

```css
/* 基础规则 */
.sw2-map-mask{position:fixed;top:0;left:0;right:0;bottom:0;width:100%;height:100%;box-sizing:border-box;…}
/* 手机档：与 `.sw2-window-mask,.sw2-cv-mask` 同一条规矩 */
@media(max-width:620px){.sw2-map-mask{padding:6px;align-items:stretch;height:100dvh}…}
```

**为什么这样就对**：固定定位元素的**百分比宽高是按"初始包含块＝视口"解析的**，与 `<html>` 那个
0 高盒子无关 ⇒ 这一条从此**不再依赖"宿主怎么对待视口"**。手机档那条 `100dvh` 是既有惯例
（地址栏收起/展开时自己跟着变；不认 `dvh` 的浏览器整条被丢掉，退回上面那条 `height:100%`，也不会塌）。

★**别的遮罩不用动**（全仓 `position:fixed` 只有三条，另两条本来就有宽高）；判据把这一条**泛化**了
——将来谁再加第四张遮罩、漏了宽高，当场红。
