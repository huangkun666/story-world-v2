## 2. 治法：本笔的设计

### 2.1 给聊天模型的"格名表"（新增，约 40 字）

**只给格名，不给值**（每个实体各自的值那 2904 字不开）：

```
角色能写的格：所属 · 身份 · 定位 · 实力
势力能写的格：性质 · 倾向 · 规模
```

★这**不是新造名单**：它是 `src/schemas/ssot.schema.js:222-241` 的**按类别白名单**
（`sanitizeBookFields`：角色收前四项、势力收后三项），与"世界步能改哪些格"
（`src/check-step.js:62` 的禁写表之外全部可改）**是同一批**。⇒ 抄哪边都不会长出第二份真相。

### 2.2 标签规范 v2（全文草案；现在是 1104 字，v2 目标 ≤900 字）

> ★**块形状不动**：还是 ` ```tags ` 围栏块——那是 leg93 用户裁的（"就甲吧"），
> 解析器只扫块里、块外一律当正文（`src/tag-extract.js:90-121`），且**块不在时要退回逐行扫**
> （"整轮零标签"比"少认几条"严重得多）。本笔**一个字节都不动这两条**。

````text
【本回合必须用标签写清"已经发生的事"】
★这是本回合的硬要求，不是文风建议：正文照常写，但真正动了手的人、真正被改动的格，都要在末尾的标签块里写一行。
漏了 = 插件这一轮收不到（这一轮白跑）——先保证标签，再谈文风。

★★所有标签集中放在正文最末尾的一个 ```tags 块里（前后各一行围栏）。只有这个块里面的标签插件才看；
块外怎么写、怎么引用、怎么打比方，都不算数。

```tags
【此刻】复苏历三年 三月初七 卯时
【场景：忘川渡口】
【行动】薛铁衣｜迎战｜黄坤
【变化】黄坤｜实力｜踏入元婴
【承诺】黄坤｜护送白小娥回江州｜白小娥
```

规则：
1. 一个块，放在正文最末尾；开围栏那一行只有 ```tags 这几个字符，别的一律不写。
2. 一条标签占一整行——行首不许有别的东西（不缩进、不加「-」「*」「1.」），行尾不许再跟别的标签。
3. 【此刻】＝**现在是什么时候**——一个**时间点**，照你戏里的说法写（「某某历三年 三月初七 卯时」）。
   不用算、不用跟上一轮对账；★**写不出时间点就别写这一行**（空着就是空着）。
4. 【时长】（可写可不写）＝**从这里起又过了多久**——那是"过了多久"，**不是"现在几点"**（三日后／当夜／一炷香／半晌）。
   ★★**这两格是两回事，不许混**：【此刻】答"现在何时"、【时长】答"过了多久"。
   只会说相对时间（比如"三日后"）的时候，就**只写【时长】、【此刻】留空**。
5. 【场景：X】＝这一场戏在哪儿（X 用下面【本世界的名号】里列出的地名）。换了地方就再写一条。
6. 【行动】谁｜做了什么｜针对谁——只写真的动了手的人。中间用全角竖线｜分开。第一格必须有，后两格知道就写。
7. 【变化】谁｜哪一格｜变成什么——谁的哪个属性被改成了什么。★第二格只能用这几个名：
   角色＝所属／身份／定位／实力；势力＝性质／倾向／规模。第三格**照抄戏里的说法**（写「踏入元婴」，
   不要换算成数字、等级分或战力值）。
8. 【承诺】谁｜许了什么｜对谁——答应的事、欠下的债、结下的交情或仇（不是动手，但确实发生了）。
9. 只标真的发生了的：只是在场、只是被提到、只是说话，都不算；★比喻和夸张不算（"打得天崩地裂"不是变化）。
10. 主角照样标——他的行动、变化、承诺都写；插件只是记下来，不替他做决定。
11. ★写完自己数一遍：这轮有几个人动了手？谁被改了哪一格？谁许了什么？漏一条 = 少记一件事。

★自检：正文末尾应当有这一个块（照上面的样子）。没有这个块 = 这一轮没达标。
````

★**一处必须说清的边界**：**引擎分不出"绝对时间点"与"相对时长"**——要分辨就得判语义，而"词表判语义"是本仓
红线明禁的（`ANCHOR.md` §4.8）。⇒ 这两格的区别**只由提示词约束**，账上**各记各的、逐字照抄**：
`【此刻】`→ `timeMark`（时间点）、`【时长】`→ `elapsed`（相对流逝，leg115 已有）。**引擎不校验、不换算、不推算。**
★名字必须望文生义（`STATE.md` §2.5 第 2 条）：所以**不能**拿一个格兼收两种说法——
这正是本细案第一版草案写错的地方（把"三日后"塞进【此刻】，当场被用户抓出来）。

★**两处刻意的取舍**：
- `【时长】`**降为可选但保留**（不是删）——理由：判据 `test/tag-extract.test.js:284` 锁着这个字面、
  解析器认它、leg115 的 `elapsed` 通路也在用它 ⇒ 保留 = 三处零改动（见 §5 第 1 条）。
- 规范**压短**（1104 → 目标 ≤900）靠删重复示例，**不靠删规则**——因为 leg89 实测过
  "埋在长提示词里的规矩不咬人"，规则少了照做率会掉（要按 §4 量过再定稿）。

### 2.3 标签 → 账 的映射（这就是"颗粒度对齐"的实质）

账上事件契约（`src/schemas/ssot.schema.js:417-472`）：
必填 `id / title / source{type,ref} / position`；可选 `ripples / links / closed` ＋ `seedFrom{quote,why,fingerprint,at,tick}`。
★★**实施时更正（leg123 写代码时当场抓到的）**：本细案第一版把 `seedFrom` 记成了通用的 `evidence{quote,…}`
—— **事件契约里没有 `evidence` 这一格**（`seedFrom` 是"起根事件"专用的出处栏）。
⇒ 本笔**新增一格 `proseQuote`**（可选字符串，老事件零扰动）：它就是"正文里那句原话"的逐字回执。

| 标签格 | 引擎落成什么 | 校验什么（全是机械判据） |
|---|---|---|
| `【此刻】` | 本轮落账的**事件**与**编年行**各加一格 `timeMark`（**逐字照抄**；只收"**现在是什么时候**"这种**时间点**说法） | 不校验、不解析、不比较、不推算；★引擎**分不出**绝对与相对（§2.2 那条边界）；没写 ⇒ 那一格不出现 |
| `【时长】` | 编年行的 `elapsed`（**leg115 已有，一个字不改**；收"**从这里起又过了多久**"这种**相对**说法） | 同上 |
| `【场景：X】` | 事件的 `position` | X 须在册地名（已有归一）⇒ 不在册 ⇒ 丢 + 留痕 |
| `【行动】谁｜做了什么｜针对谁` | ① 一条 **`dialogue` 型事件**（`title` = 谁＋做了什么＋针对谁，`ripples` = [谁, 针对谁]）② 引擎给该实体盖 `lastActiveTick` | 谁／针对谁须**在册**（照名册＋别名归一）；归不上 ⇒ 丢 + 留痕（现有 `unresolved` 机制） |
| `【变化】谁｜哪一格｜变成什么` | ① 一条 **`dialogue` 型事件**（`title` = 谁的哪一格变成了什么；`proseQuote` = **正文里那行原话**）② **以那条事件为因**，把值落到实体格 | 谁须在册；「哪一格」须 ∈ 那 7 个名（＋`location`，且要过地名归一）；值非空、**逐字照抄**；**值必须在正文里找得到**；同轮同实体同格**只落一次** |
| `【承诺】谁｜许了什么｜对谁` | **`dialogue` 型事件**（`ripples` = [谁, 对谁]） | 两端须在册。★**关系边仍由世界步提议**（带因＝这条事件），不在这里直接写 |

★**逐字回执那一格**：`proseQuote`（本笔新增，见 2.3 那条更正）——正文原句照抄进去，
它同时也是"**值必须在正文里找得到**"这条闸的凭据（见 §7）。

★**为什么这条通道要覆盖所有在册实体（含玩家）**：正文里被改的角色**是既成事实**——
戏写了"薛铁衣断了一臂"，账上不记，世界下一轮就按旧样子演。**这不是"给谁特权"，是"别漏账"。**

### 2.5 时间：不带源、不从起点抽、只记不推

用户三条裁定（§0.1 的 2、3）落到这里的形状：

1. **两格分开记**：**"现在是什么时候"**（`【此刻】` → `timeMark`）与**"从这里起过了多久"**（`【时长】` → `elapsed`），
   **引擎不做加法**——不让模型算"三天后是几号"，也不让引擎累加。
   ★理由：模型算加法最容易错，而账上不需要一条算出来的时间。
2. **不带源**：`timeMark` 就是**逐字照抄**，不带"据书／据模型声明"这类标记。
   ★但**在代码注释与本文里如实登记一句**："这一格是聊天模型的声明，引擎不校验、不解析、不比较"——
   免得下一任把它当事实用（本仓栽过"名字替机制撒谎"的跟头）。
3. **不从书里抽起点**：账上的时间轴**从你开口那一刻开始**，第一轮模型说什么时候就是什么时候。
   ★这正好支持"有些卡让玩家从不同时间点开局"。
   ★**如实登记的后果**：账上的时间**不是连续轴**（只有一个个点，跨点间隔算不出来）。
   以后若要"过了多久"能被算，那是**另一条口径**，要单独拍。

### 2.6 ★★ 一轮内的顺序（治"冲突"：把它做成结构上不可能）

用户的模型（§0.1 第 5 条）是**流水线**：一轮里先有正文（谁动了手／谁被改了），世界模型**不再演这些行动过的人**；
"如果有冲突，那就说明本来就错了"。**这条顺序已经在提示词里写着**——`src/prompts.js` 第 8 条（leg89 加的）：

> 「这一轮正文里'已经发生'的行动，不要再演一遍」·「这些行动的**主语**……本回合不要再替它们出手、
> 也不要再给它们立一条新线」·「被它们**当成对象**的人是另一回事：**这一轮正是你该写他的时候**」

**但今天它只是"一句请求"，没有任何东西保证它**（这就是冲突还能发生的原因）。本笔要补三处结构：

| # | 落在哪 | 做什么 | 为什么 |
|---|---|---|---|
| ① | `src/gate.js` 的"点名面"（`:38-43`） | **并上 `turnFacts.actions[].target`**：被正文点到的人 ⇒ 获得**应答资格** | ★今天这里有**提示词与门控打架**：提示词说"被点到的人正是你该写他的时候"，而门控只算"未决事件波及 ∪ 世界步自己的动作目标 ∪ 玩家落子对象"——**正文里 NPC 行动的目标没算** ⇒ 久未出手的被点名者被判静默、**提议被丢掉** |

### 2.7 ★ 承重墙怎么守住（为什么这不是"聊天模型写账"）

全仓红线：**写账这件事只有引擎能做**（LLM 只提议）。本笔严格遵守，做法是**四道机械校验**：

1. **实体在册**（按名册＋别名归一；归不上 ⇒ 丢 + 留痕，不许凭空造人）；
2. **格在名单里**（那 7 个 ＋ `location`）；
3. **值逐字照抄**（不许换算成数、不许补默认值、空就是空）；
4. **必带因**（因＝同轮注册的那条 `dialogue` 事件）＋ 同轮同实体同格只落一次 ＋ `prev` 留痕。

⇒ **聊天模型没有直写账的路径**：它写的只是**标签**，落账的是引擎，而且落不落由上面四条定。
⇒ **世界步那条"玩家不可改"原样保留**（那是**世界模型的手**；`check-step.js:319-321`）。
⇒ **`status` 与覆灭不进这条通道**（覆灭有独立复核：无在飞盘算、玩家不可灭、必须挂在点名他的那件事上
——`check-step.js:349-358`）。戏能让"断了一臂"进账，但"他死了"仍归引擎裁定。
