## 5. ★★ 本棒踩的坑（下一任照做，能省一整轮）

> ★★★**本节是本棒最值钱的部分**：十二笔里有**八笔**是在修**我自己刚写的发布脚本**，
> 而每一条都是 **`--dry-run` 咬出来的**——**没有一次是真推之后才发现的灾难**。
> ⇒ 下一任：**凡"推/发布/覆盖"这类不可逆动作，先跑一遍演练**（`node scripts/publish-release.mjs --dry-run`）。

1. ★★★**幂等守卫必须比"本笔真正改掉的那一处"，而且要比对一个不会骗人的量**。
   第一版拿 `git cat-file -p <tree>` 比**内容列表**（输出形如 `100644 blob …`），与 tree id **永不相等**
   ⇒ 守卫等于失效。定稿：比 **tree id**（远端 main 根树 vs 本地子树树对象）——"这一份 vs 那一份"的逐字节身份。
   ★这与 leg101/102/103 **连栽三次是同一个形状**：守卫写死、或比一个本笔不会变的量 ⇒ 恒真跳过推送，而人以为推成功了。
2. ★★**发布脚本必须能在"没有 git 的地方"跑通**。`scripts/audit-docs.mjs` 会随发布件一起出门，
   而导出件是 `read-tree` 出来的**独立根树、不在任何 git 仓库里** ⇒ `git ls-files` 抛
   `fatal: not a git repository`；第一版 catch 成 `-1` 写进索引 ⇒ **导出件的守门判红、把推送拦下**
   （闸真的会咬，但拦错了原因）。定稿：**先探测在不在仓库里**，不在就如实写 `null`，不猜。
3. ★★**判据锁着的读数，不许让"环境"参与运算**（本例是**换行**）。
   导出件比工作区**少 145 字节**，我当缺陷连修三轮；真相是：`docs/session-handoff-2026-09-20-leg105.md`
   本机是 CRLF、git 里是 LF（`.gitattributes` `* text=auto eol=lf`），**145 = 它的 CRLF 条数**
   （`12532 − 145 = 12387` = blob = 导出件，逐字节相同）。
   定稿：体积**按 LF 归一**清点 ⇒ 本机与导出件同为 `3947516`，收敛。
   ★**三轮都栽在同一件事上：先把"差多少"量出来，再动手。**
4. ★★**生成物不能把自己算进自己的输入**（**自指计数**）。`docs/` 的体积里包含本脚本要写的 `docs/index.json`
   ⇒ 一写就变、变了又"过期" ⇒ **永不收敛**（实测连跑两次文件哈希都不同）。
   治法一（`总大小 − 生成物字节数`）**也错**：生成物自己会变长，减数与被减数同时在动。
   定稿：**遍历时直接排除生成物**（`skip` 集合，另排除调试用 `.bak`）⇒ "生成 → `--check`"成为**不动点**。
5. ★★**判据报红必须自己指路**。`docs/index.json 未过期` 这条前几版只说"不等"两个字
   ⇒ 我盲修三轮、每轮另写探针才看出差在哪。定稿：报红列出**前 5 处逐字段 diff**（路径 + 两侧的值）
   + 卷宗摘要，并在"逐字段相同但字节不同"时点明多半是换行/BOM。
   ⇒ 与"**用户的一张截图 > 十条推演**"同源：**判据报红要能自己指路**。
   ★同族两处小坑（都当场误报过）：**数格时 `split('|')` 的 `[1]` 是标签格、`[2]` 才是值格**，
   而**表头分隔行也以 `| 判据 |` 开头**（要跳过）；**`one()` 这类"取第一个捕获段"的助手**
   不能拿来取 `"1096 / 1096"`（只会得到 `"1096"`，打印出来像 `STATE 1`）。
   ★这是本仓第四次栽在"尺子错"上（leg55/57 台账守门两次、leg106 两次）——**错的可能是尺子，不是行**。
6. ★**`node --test` 的"在哪跑"给出两套完全不同的读数**：插件目录内 = **1096 条全绿**；
   仓库根（monorepo） = **7367 条 / 8 条红**（Node 递归扫到 `backups/`、`harness/`、旧项目的测试）。
   ⇒ README 与 `dev-process.md` 都补了"不这么做会看到什么"（只写"必须无命令"**不够**）。
7. ★**`git push` 在非交互环境会被 Git Credential Manager 抢答**（`could not read Username for 'https://github.com'`）。
   解法：URL 带 token **且**清空 credential helper 环境（`GIT_TERMINAL_PROMPT=0` / `GIT_ASKPASS=echo` / `GCM_INTERACTIVE=never`）。
   ★token 在 `%USERPROFILE%\.git-credentials`，**绝不打印、不进日志**（脚本里 `wash()` 会把 `https://…@` 洗成 `https://***@`）。
8. ★★**网络抖动不许被读成"脚本写错"**。本机到 github.com **时通时断**：同一分钟里 `ls-remote` 两败两成、
   `push` 头两次失败第三次成功。⇒ 推送加**退避重试 4 次**，并把失败情形分开说（**网络** ⇒ 提交与导出件都在，换网络重跑；
   **权限** ⇒ 先 `git ls-remote` 试读，读得通才谈写）。**人一旦以为是自己脚本错，就会去改守卫**——leg101/102/103 就是这么坏的。
9. ★**冻结一份文件要动两次**：加墓碑会**改变字节数** ⇒ `docs/index.json` 的体积清点当场过期、守门报红
   ⇒ 顺序是"**先加墓碑，后生成索引**"（本棒第一遍撞上，是对的——守门真会咬）。
10. ★**台账格数是判据锁着的**：`docs/ledger.md` **5 格**（日期/步骤/变更/测试/部署形态）、`LEDGER.md` **3 格**，
    新增行必须与表头同列数，否则 `test/ledger-shape.test.js` 的计数棘轮当场红。
    ★另：**PowerShell 会把 `git commit -m` 里的反引号当转义符吃掉** ⇒ 提交信息一律走 `-F <文件>`（本仓"含中文别用 PowerShell 写文件"的同族坑）。
