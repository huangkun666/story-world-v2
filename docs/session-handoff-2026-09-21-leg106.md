## 5. ★ 本棒踩的坑（下一任照做，能省一整轮）

1. ★★**脚本里"取一个数"用错了口径，连栽两次**：`one(text, re)` 返回的是**第一个捕获段**，不是整个匹配
   ⇒ 拿它去取 `"1096 / 1096"` 只得到 `"1096"`，于是打印出来像 `STATE 1`、还误报了一条红。
   ⇒ 与 `test/ledger-shape.test.js` 里那条"**错的可能是尺子，不是行**"是同一个形状（本仓第三次栽在尺子上）。
   ★另一处**同族**：数格时 `split('|')` 的 `[1]` 是**标签格**、`[2]` 才是值格；且**表头分隔行也以 `| 判据 |` 开头**，要跳过。
2. ★**`git push` 在非交互环境会被 Git Credential Manager 抢答**：报 `could not read Username for 'https://github.com'`。
   解法：URL 带 token + **清空 credential helper 环境**（`GIT_TERMINAL_PROMPT=0` / `GIT_ASKPASS=echo` / `GCM_INTERACTIVE=never`）。
   ★token 在 `%USERPROFILE%\.git-credentials` 里，**绝不打印、不进日志**（脚本里 `wash()` 会把 `https://…@` 洗成 `https://***@`）。
3. ★**`node --test` 的"在哪跑"会给出两套完全不同的读数**：插件目录内 = **1096 条全绿**；仓库根 = **7367 条 / 8 条红**（扫到了别的项目）。
   ⇒ README 与 `dev-process.md` 都补了这条（交接文档写"必须无参、必须在项目目录内"**不够**，得说清**不这么做会看到什么**）。
4. ★**冻结一份文件要动两次**：加墓碑行会**改变文件字节数** ⇒ `docs/index.json` 里的体积清点当场过期、守门报红
   ⇒ 顺序是"**先加墓碑，后生成索引**"（本棒第一遍就撞上，是对的——守门真的会咬）。
5. ★**台账格式守门（leg55）是按渲染口径数格的**：`docs/ledger.md` 是 **5 格**（日期/步骤/变更/测试/部署形态）、
   `LEDGER.md` 是 **3 格**。新增行**必须**与表头同列数，否则 `ledger-shape.test.js` 的计数棘轮当场红。
6. ★★**`--dry-run` 当场咬出发布脚本自己两个 bug（本棒最值钱的一手，已留档在脚本注释里）**：
   ① **幂等守卫等于失效**——第一版拿 `git cat-file -p <tree>` 比**内容列表**（输出形如 `100644 blob …`），
      与 tree id **永不相等** ⇒ 守卫恒不触发；定稿改成比 **tree id**（"这一份 vs 那一份"的逐字节身份）。
      ★这正是 leg101/102/103 连栽三次的同一个形状：**守卫比错了量**。
   ② **守门脚本会随发布件出门，而导出件不在任何 git 仓库里**——`git ls-files` 抛
      `fatal: not a git repository`，第一版 catch 成 `-1` 写进 index.json ⇒ **导出件的守门判红、把推送拦下了**
      （闸真的会咬，但拦错了原因）；定稿改成**先探测在不在仓库里**，不在就如实写 `null`，不猜。
   ⇒ ★**纪律**：**发布脚本必须能在"没有 git 的地方"跑通**（发布件会带着 `scripts/` 一起出门）；
     任何"靠 git 才成立"的检查都要先探测环境，**别把 `-1` 当结论**。
