## 4. ★★★ 两条真 bug（都是"接最后一根线"的时候咬出来的）

### ① ★★★ 递出来的每一行都是**空壳**（而读数看着完全正常）

**症状**：`recallForPack` 退出来的行只剩 `[第7轮] （第7轮 · 在你此刻之前 13 轮）`——**正文一个字都没有**；
而 `report` 照样报 `{reason: 'ok', candidates: 3, returned: 3}`。

**根因**：那一行原来只从 `ssot.events` 里按 id 现查标题。
而 leg152 已把**索引单元换成编年行** ⇒ 索引里的 id 是**编年行的 id**，在事件表里**根本不存在**
⇒ 查出来是空串。★生产形状（`vector-store.js` 那三个等长数组）里**只有一个 id**，连兜底都没有。

**为什么 leg152 那 32 条判据一条都没咬到它**：那些判据用的索引夹具是"**id 就是事件 id**"那种形状
（`makeWorld` 里 `ev_1_1` 那些）——**判据绿 ≠ 接线绿**。★这是本仓那条老话的第 N 次应验。

**血证**（仓外 `F:/deepseek/tmp/leg153/probe-recall-row.mjs`，同一份账两种形状各跑一次）：

```
★递出来的行（生产形状）：      "[第7轮] （第7轮 · 在你此刻之前 13 轮）"        ← 空壳
★递出来的行（判据那种形状）：  "[第7轮]盘算「守住北山」取消（薛铁衣） （…）"   ← 判据里一直是对的
```

**修法**：正文**回账上现查，两张表都认**（编年行优先，老账/判据退回事件标题）；
查不到正文的行**不进**（空壳比没有更坏：**它占额度还骗人**），并数进 `report.noBody`。
★判据 **P6** 钉住（含反证：账上查不到正文的行一件都不许递，且必须数出来）。

### ② ★ 换了模型号的老索引 ⇒ **白撞一次网络**

`recallForTick` 原来按**盘上那一份**判"索引空不空"，而 `harnessOf` 会把形状对不上的索引**解成空索引**
⇒ 形状不匹配时照样发一次嵌入请求，回来一件候选都没有。★判据 **R2** 当场红（这条判据自己抓出来的）。

**修法**：按**解出来的那份**判空（"换模型 = 与还没嵌过同一条路"）。

## 8. ★ 本笔最值钱的四条

### ① ★★★ **"判据全绿"不等于"接线绿"**——夹具的形状躲开了生产形状

leg152 给这一层写了 **32 条判据**，全绿；而**接最后一根线**的时候发现：
**递出来的每一行都是空壳**。差别只在夹具——判据用的是"**id 就是事件 id**"那种索引形状，
而生产用的是"**三个等长数组、只有一个 id**"。
★**教训**：**新模块的判据夹具，形状要照生产那一份做**；
凡是"某个 id 要去账上查正文"的地方，**夹具里必须放一个"查不到"的样本**。

### ② ★★ **"读数看着正常"是最贵的一种坏**

那个 bug 的症状是：`reason: 'ok'`、`candidates: 3`、`returned: 3`——**每一个数都对**，
只有**内容**是空的。★本仓为这个形状付过好几次账了；这一次的教训更具体：
**读数要能说出"内容有没有"，不只是"条数对不对"**（`noBody` 就是为此加的）。

### ③ ★★ **问法与料必须是同一种话**

用户那句「**应该是聊天侧本轮提供的事件吧**」的道理在这儿：
索引里的单元是**账上那行**，而"玩家说的原话"是另一种写法（人称、口语、没有账上的词）。
⇒ **问法换成账上那行的写法之后，两边才可比**。
★**一般化的教训**：**检索这一层，"问什么"和"存什么"要用同一种文体**——
这不是调参能补的。

### ④ ★ **"接最后一根线"要单独算一道工序**

这一笔真正的产出不是那一栏（那一栏是照设计接的），而是**接线时咬出来的两条真 bug**。
★**教训**：一个"有实现、有判据、有读数、就是没接上"的模块，
**它的判据覆盖率与它接上之后的表现，是两件事**——
**没接上的代码，测不出接线的问题**。
