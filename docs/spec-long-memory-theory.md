## 0. 先立规矩：什么算证据

### 0.1 一句话

**账上的"正在发生的事"是一片森林：每个节点只认一个来路；树是无条件切出来的（结构给定），
而"纪"必须是有条件立的（有形状才立）——卷管"哪一段"，纪管"哪一条"，两者正交。
★**摘要只长在纪上**（卷是纯存储，不承担叙事——2026-09-25 拍板，见 §6.1）。**

### 0.2 ★两个证据等级（本文件只认第一等）

| 等级 | 什么算 | 能不能用来改设计 |
|---|---|---|
| **一等：从契约推出来的** | 写入契约的形状（单亲、拒未知字段）、只增不改的层、时间先后 | ★**能**。而且**换个账本也成立** |
| **二等：在某份账上量出来的** | 计数、比例、分布、实例 | ★**不能单独用**，只能当"**没被证伪**" |

★**为什么立这一条**：我先前用一份账量出"树太碎／最大的故事没头"，**照着它差点去改设计**；
而那份账是**多个版本叠出来的产物**（指针指向已删的东西、事件表被剪、里程碑只有标题没有来路）。
⇒ **那些现象是事故现场，不是结构。**
★**本文件因此不写任何实测数字**（凡涉及数量的地方，一律标"**要量**"）。

## 1. 结构的六条基本法

**法一 · 只有两类节点在"活"。**

| 节点 | 是什么 | 活多久 |
|---|---|---|
| **事件** | 一件瞬时发生的事 | 出生的那一轮 |
| **盘算** | 一件"要做的事"，每轮走一步 | 多轮，直到结清／取消／委派 |

**法二 · 来路只有一口，而且最多填一个。**
每个节点写着"**我从哪来**"：一个**类型**（处境／事／盘算／种子／正文）＋ 一个**指向**。
⇒ ★**"单亲"不是世界长成的样子，是契约只许它长成这样。**

**法三 · 来路只能指向比自己早的东西。**
一个节点不可能指向还没出生的节点。
⇒ ★**结构上不可能成环**——这不是"我们检查过没有环"，是**根本写不出环**。

**法四 · 两个层只增不改。**
**编年**（世界那本流水）与**卷**（编年最旧那一段的存档）：只往后加，**从不回头改**。
⇒ 它们是**唯一能当真相放的地方**。

**法五 · 编年把因果写成了人话（可逆）。**
编年里的事件行与盘算行是**照固定模板**写的，六种文法：

```
事件「X」——沿「W」而来         ← 来路是一个事件
事件「X」——由盘算「Y」而生      ← 来路是一个盘算
事件「X」——由处境而生           ← 没有来路（这是根）
事件「X」闭环 / 涟漪平息         ← 收口
盘算「Y」推进：…                ← 这条线这一轮做了什么
盘算「Y」满步结算：结清          ← 这条线的终点
```

⇒ ★**「从哪来」和「到哪收」两件事，编年里都各有一行原文。**
（★这一条是**推出来的**：模板就是写法，写法决定可逆。它**不是**"我量过 95%"，那是二等证据。）

**法六 · 归档要连因果一起留。**
事件被归档进"大事纪"时，**它的来路必须跟着一起走**（契约里那一格已经有了）。
⇒ 归档造成的信息损失只许是"**少了几件**"，不许是"**断了链**"。

## 2. 四种节点（多出来的一种是"合流"）

| 节点 | 是不是节点 | 有没有来路 |
|---|---|---|
| 事件 | 是 | 有（或没有） |
| 盘算 | 是 | 有（或没有） |
| ★**合流** | ★**是**（从今天起它算一个节点） | ★**它带多个来路** |
| 处境／决策 | ★**也算**（它当"纪"的容器） | 可以没有来路 |

### 2.1 ★为什么"多因"必须长成一个节点，不许长成一个数组

先说清一个区分——**"多因"和"多爹"不是一回事**：

| | 是什么 | 今天行不行 |
|---|---|---|
| **多爹**（一个节点有很多来路） | 把"来路"那一格**撑成数组** | ❌ 契约是**一个对象**，且**拒未知字段** ⇒ 写不进去 |
| ★**多因**（好几件事共同促成一件新事） | **那件新事自己成为一个节点** | ✅ 本来就行 |

★**为什么不能撑成数组**（三条，一条比一条硬）：

1. **丢划分**：单亲之下，**每个节点恰好属于一条线**（线是互不相交的）；多爹之后，两棵树会因为共享一个节点而**合并成一团**——★**"这件事属于哪条线"从此没有确定答案**；
2. **丢终点**：一条线的终点是"**它下面所有节点都收口**"；一个节点挂到几条线上之后，"这条线讲完没有"要看**它连着的别的线**，**递归没有底**；
3. **丢语义**：就算你写了"爹 A、爹 B、爹 C"，**谁是主因、谁只是添柴、是同时到的还是先后到的**，一个平铺的列表**一个字都答不上来**。

⇒ **定稿**：**边永远单亲，节点可以多来路。**
多因的形状是：**好几件事 → 汇成一件有身份的新事 → 它再往下长。**

★**这条决定同时解掉两个问题**：
① **多因有了准确的表达**（那件新事有名字、有经过、有收口，**摘要正好该讲它**）；
② ★**小树被收拢了**（见 §4）——**它就是"纪"的挂点**。

## 3. 三条能证的性质（整套设计的承重墙）

| # | 性质 | 为什么成立 |
|---|---|---|
| **A** | ★**每条线都有确定的终点** | 一个节点只有三种下场：**闭环／平息／取消**（盘算另有**结清**），而世界**每轮都在算这件事** ⇒ **"这一条讲完了"是有定义的时刻**，不需要谁来裁 |
| **B** | ★**树可以从编年重建** | 法五：来路与收口在编年里**各有一行原文**；法四：编年只增不改 ⇒ **重建不依赖任何会被剪的表** |
| **C** | ★**划分是免费的** | 法二（单亲）＋ 法三（无环）⇒ 所有节点被**分成互不相交的一条条线**，各有唯一起点、唯一终点 |

★**这三条合起来才是"纪"能立的地基**：
**C 给"一条线"一个唯一边界 · A 给它一个终点 · B 让它在任何一届账本上都能重算。**

## 4. 树的血肉：三种连接（也是"碎"的三个来源）

★**"树太小"不是"一棵树一个纪"这条规矩的错，是"该有爹的地方没爹"**。三个来源：

| # | 来源 | 现象 | 理论上的解法 |
|---|---|---|---|
| ① | **处境型节点没有来路** | 世界自然而然冒出的事、"由处境而生"的盘算 ⇒ **各成一个根** | 处境**本身也是一格**（张力／动乱／大势）⇒ 落账时把"当时是哪种处境"记成来路，**它就落进了同一棵树** |
| ② | ★**同一个决策分给好几条盘算** | 三条盘算一起走 ⇒ **看着是三棵小树，其实是一段故事** | ★**插入一个"决策"合流节点**（"某人决定动手"）⇒ 它是唯一来路 ⇒ 三条线**自动在它下面汇成一棵** |
| ③ | **盘算一结束就散** | 结清之后，它下面的事失去汇合点 | 同②：汇合点上移到决策节点，**不依赖盘算活着** |

★**这三条都是"写入侧补一格"，不是"读的时候猜"**——**猜出来的结构不算结构**。

## 5. ★纪的三级（"有形状才立纪"）

**树是无条件的（结构给定）· 纪是有条件的（有内容才立）。**

| 级 | 什么条件 | 怎么进"记忆" | 要不要摘要 |
|---|---|---|---|
| **甲** | **一条树自己成了形状**（有分支或有纵深，跨多轮） | **独立成纪** | 要 |
| **乙** | 树不够大，但**同一个合流点（处境／决策）下的几棵树 ＋ 它们之间的事** | **合成一个纪**（容器＝合流点） | 要（合起来写一段） |
| **丙** | **孤立单点**（一件事，没有下文） | ★**不立纪**——它本来就在编年那一栏里 | 不要 |

★**这一条是"零散"的直接解药**：
- **丙级不立纪** ⇒ 一件小事**不会变成一个纪**（给它立纪反而更贵：摘要比它本身还长）；
- **乙级合并** ⇒ 中等大小的树**不各立一个纪**，而是照**合流点**收成一个；
- ★**纪的边界＝树的边界（或合流点的边界），不是轮次的边界** ⇒ **不会被时间切碎**。

## 6. 分层：卷与纪**正交**（★★摘要只长在纪上）

```
真相层（只增不改，永不删）
  ├─ 卷   = 按轮次切的容器（每 N 轮一卷）        ← 回答"哪一段"
  │         ★**纯存储**：它只为"热账不变胖"而存在，**不承担任何叙事职责**（见 §6.1）
  └─ 编年 = 逐行原文（因果的可逆存本）
                    ↓ 从编年算出来（不存）
结构层
  └─ 树   = 单亲森林（每个节点一个来路）
                    ↓ 有形状的才立
叙事层
  └─ 纪   = 一条线：起于哪 ＋ 经历了什么（★**摘要只住在这里**）＋ 收在哪 ＋ 指向（卷号 ＋ 根）
                                                        ← 回答"哪一条"
                    ↓
取用层
  └─ 三条取法：按卷 · 按根（"那条线后来怎么了"）· 按名字/词
```

★**"正交"是什么意思**（这一条要焊死）：

| | 卷 | 纪 |
|---|---|---|
| 按什么切 | **时间**（轮次） | **因果**（树的边界） |
| 数量由什么定 | 由**轮数**定（机械） | 由**内容**定（有形状才立） |
| 能不能互相替代 | ❌ 一条长线**会横跨好几卷** | ❌ 一卷里**可能有好几条纪** |

⇒ **所以检索层必须同时有两个键**，才能回答这句真问题：
**「第 3 卷里那条线后来怎么了」**——**卷号定位"哪一段"，根定位"哪一条"**。

### 6.1 ★★摘要只长在纪上（2026-09-25 用户拍板）

**给卷写摘要那一条路，已经量过、已经否决。** 用户当天原话：「**没多大用的设计直接摒弃即可**」，
并追问「**对卷的一句话摘要，你自己想想那省略的信息能有多大？**」——数在这里：

| 刀 | 数 |
|---|---|
| 第一次轮转那一卷 | ≈ **470 轮** ≈ **7.8 万 – 10.2 万字**（真账实测 218 字/轮） |
| 一次调用读得到多少 | 输入上限 10,000 字 ⇒ **约 46 轮 ＝ 这一卷的 10%** |
| 压成多少 | 输出上限 400 字 ⇒ 相对读到的那些是 **25:1** |
| **整卷净剩** | ★**0.4%（丢 99.6%，≈250:1）** |

**但真正判它死刑的不是这个比值，是形状**：

| | 摘要 | 它要替代的原文 | 结论 |
|---|---|---|---|
| **卷摘要** | 按时间的流水 | 按时间的流水（往事那一栏就是这个） | ★**同形状**，只是更糊 ⇒ **不带来新信息** |
| **纪摘要** | 一段**讲得完的因果**（一条线） | 按时间的流水 | ★**不同形状**，而且纪**自带回去的路**（卷号 ＋ 根）⇒ **是索引，不是替代品** |

⇒ ★**立在原则上的一条规矩**（比 N=5 更基础）：
**摘要只有在"跟原文形状不同"时才值钱。** 同形状的压缩＝图注，弃。
⇒ 附带一条结构上的死因（现读 `src/pack.js:796`）：`fetchChroniclePast` 把热账 ＋ 所有卷的往事
**一把**交给包、**自己不设上限**，真正的裁剪在 `trimPack`，而它是**最新优先、从最旧的丢**——
卷摘要挂在一个**很旧的 tick** 上 ⇒ **包宽裕时它没省下东西、包紧张时它第一批被丢**。两头不落好。

★**这一条带走的与没带走的**：

| | |
|---|---|
| **带走** | 给卷写摘要那一件（含一个新模块 · 4 处渲染 · 约 12 条判据 · 一次模型调用） |
| **没带走** | **卷本身照旧**（纯存储机制，与摘要无关）· §6 的**卷纪正交**照旧成立 · **纪摘要**照旧是必须的那一件（卡在 §9 第 2 条） |
| **如实登记** | `docs/spec-volume-summary.md` **不删**（§1.2/§1.3 那些实测读数还有用，且留着防重新发明），但**当作"已否决的方案"读** |

## 7. 三道承重墙（不可破）

| # | 红线 | 破了会怎样 |
|---|---|---|
| ① | ★**真相只放只增不改的那一层**（编年・卷）；**树与纪都是算出来的，不存第二份** | 存一份就会与编年分叉 ⇒ 本仓最贵的病（同一件事两套说法） |

它正是①的另一面：**正因为树是算出来的，事件表被剪就不威胁结构**（法 B）。

### 8.6 ★★四条量出来的（**比曲线本身更要紧**）

**发现一 · "线数 ÷ 卷数"这个算式不成立，分母得换。**
真去轮转才看清：`splitOffOldest`（`src/storage.js:53`）**只剥到"剩余跨度 ≤ 阈值"就停**，
是最小剥法 ⇒ 稳态下**每轮各剥出一卷**（实测 900 轮剥出 749 卷，每卷一轮）。
⇒ 那个比值会随轮数一路趋近于 0，**它不是个有意义的量**。
⇒ 换成 **"每 500 轮立出几条线"**——那才是那句话的本意：
包里装得下约 500 轮往事，**线就是跟它抢位置的东西**。（这条另立了一件活儿，见文档末尾。）

**发现二 · ★乙案三个条件里，有一个根本不干活。**
"**有来路**"在**100% 的树上都成立**（事件按契约必有 `source`）⇒
乙案实际只由"**有收口** ＋ **≥N 件事**"在分辨。而"有收口"也只砍掉几棵（72→67、281→271）。
⇒ **N 是这条判据唯一的旋钮**；另外两格留着不害事（它们把"没讲完的"和"断头的"挡在外面），
但**别以为它们在替你筛**。

**发现三 · ★"起根密度"是个**两端都会坏**的旋钮，而初稿只谈了一端。**
本稿 §4 谈的全是"树太碎"那一端（该有爹的地方没爹）。
而把"起根密度"拧到另一头（很少起新头）量出来的是**另一种坏**：
**长出一条 622 件事的巨线**（甲档甲案只有 2 条线，平均 622.5 件事、跨 482 轮、素材 11,860 字）
——**它同样讲不了**（摘要要么丢光细节、要么爆掉预算）。
⇒ 结论：**不是"越少起根越好"，是要一个健康的中段**。这也正是用户在那份真账上抱怨的
"**最多的那个故事没头**"的成因。

**发现四 · ★顺手撞出一个真的性能病（与 N 无关，但会疼）。**
`src/pack.js:1234-1238` 那个"**逐行把往事装回包、每装一行真量一次整包**"的循环，
一旦包超出预算就**每轮空转上千次**。实测单轮 **15ms → 1100ms**（`--trace` 看得见那个平台期）。
含义是：**聊天跑到往事撑满包预算之后，每一轮都会慢约 1 秒，而且是永久的**（不会自己好）。
★这条**不是本稿的设计问题**，是既有实现的一个成本特性 ⇒ 已另立一件活儿。

### 8.7 ★★定案：**N = 5**（用户 2026-09-25 拍板）

| 为什么是 5 | |
|---|---|
| 立出来的线数 | 每 500 轮 **24.4 条**（中）～ **40.6 条**（密）——落在"包塞得下"的量级 |
| 每条线多厚 | 平均 **11～12 件事**、跨 **61～65 轮**、素材 **212～230 字** |
| 覆盖率 | **56.8% ～ 87.0%** |
| 为什么不是 2、3 | 密档会立出 **93 / 63 条**（每 500 轮）——**多半塞不下**，而且线短到 6.7～9.1 件事，"故事"还没成形 |
| 为什么不是 8、10 | 覆盖率掉到 **42.6% / 72.8%**：一批真的发生过的事**再也不被立线**（等于世界忘掉一段） |

★**一条如实登记的边界**：把"几条线"换成"包里占多少位置"，**还差一格**——
**"一条线在包里长什么样"没定**（§9 第 2 条）。没有那一格，就不知道 40 条线是 2,000 est 还是 12,000 est。
⇒ **N=5 是在"线数合理"这个层面定的；包预算那一关要等 §9 第 2 条定了才能复核。**
★**另一条**：甲案（有分支或有纵深）**不能单独用**——它把那条 622 件事的巨线也算作"一条线"，
而且它的"覆盖率 100%"是**假象**（一棵巨树横跨全部轮次，不代表它是一条讲得完的故事）。

## 10. 一页纸的结论

1. **结构是森林**：单亲、无环、可划分——**这不是巧合，是契约的形状**；
2. ★**多因长成节点，不长成数组**：这样"合流"成为可讲、可检索的一件事，而**划分、终点、树的边界一个都不丢**；
3. ★**树无条件、纪有条件**：**丙级不立纪**（零散不进来）、**乙级按合流点合并**（中等的不散开）、**甲级独立成纪**；
4. ★**卷与纪正交**：**卷管哪一段，纪管哪一条**，检索层要**两个键**；
   ★**但摘要只长在纪上**——给卷写一句话那一条路**量过、否决了**（≈250:1 的图注，且进不了包，§6.1）；
5. ★**真相只住只增不改的那一层**（编年・卷），**树与纪都是算出来的**——所以**表被剪不威胁结构**；
6. ★**摘要只能是视图**，不许回写成账；
7. ★**那个数字已经量出来了：N = 5**（§8）——曲线出在一份**干净的合成世界**上（900 轮 × 三档起根密度，
   坏账 0 处 · 警告 0 条），**没拿存量账当标准**；
   量出来的四条比曲线本身更要紧：**"线数÷卷数"这个算式不成立**（卷在稳态下一轮一卷）·
   **"有来路"不干活**（100% 成立）· **"起根密度"两端都会坏**（另一头是一条 622 件事的巨线）·
   **顺手撞出一个真的性能病**（单轮 15ms → 1100ms，见 §8.6 发现四）。
