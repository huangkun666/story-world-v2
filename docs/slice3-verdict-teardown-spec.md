# 片3 拔除清单细案 · story-world v2（leg24 · 待拍板）

> 性质：**片 3「拆引擎裁定」的开工前置细案**——把"那个 0-1 的数（分量）"现在实际支配的每一处摊开，
> 每处给出**结构替代**与**拍板点**。不写这一步就开工＝拆承重墙（片2 已有一次实测证伪的教训）。
> 依据：用户 2026-09-11 拍板「**删掉分数**，改按确定性粗规则排（谁刚动过/谁在飞盘算里/谁在镜头名单上）」；
> 交接 leg23 §4 片3「settle 的比重分判谁赢→只校验不裁定；来源选择改确定性；门控改确定性排序」（**高风险，单独测单独提交**）。
> 数据：本文 §2 全部为 leg24 实跑读数（`runSmoke` 50t/100t，全量棋盘 346 实体），可复跑。

---

## 0. 人话版：这会怎么样

现在引擎里有一个"谁更重要"的分数（0 到 1，叫分量）。用户已经拍板：**这个数不要了**——因为它没法客观，
而且它其实已经在背地里替引擎做判断了。

但"删掉它"不是把一行代码删掉就完事：这个数现在**卡在七个地方**，其中两个是真在替引擎做决定的
（**谁能主动出手**、**谁在镜头里排前面**），另外几个只是算术（可见性、波及范围、因果半径）。

而且实测挖出一个更糟的事实：**这个数现在已经是坏的**——全量棋盘（346 个实体）跑 100 轮之后，
346 个里有 **345 个**跌到"静默线"以下（静默=不许主动出手）。也就是说，在真实规模的世界里，
引擎现在已经基本禁止所有人出手了。这不是我们删分数造成的，是它**本来就在退化**；
只是以前有"默认值兜底"替它撑着，现在不填了，退化会变成永久性的。

所以片 3 的正确形态不是"把分数删掉"，而是**用可数的结构事实替掉它**：
**谁刚动过、谁手上有在办的事、谁被未决事件点到名**——这三样都是账本上能查的、算不出歧义的。
下面 §3 逐条给替代方案与拍板点。

## 1. 那个数现在支配着什么（七处，代码实读）

| # | 位置 | 那个数在做什么 | 性质 |
|---|---|---|---|
| 1 | `gate.js` `SILENCE_THRESHOLD`（人物 0.25 / 势力 0.50） | **分量低于阈值 = 静默**（不许 actions/推进/开新盘算/取消，被点名可应答） | **替引擎做决定** |
| 2 | `pack.js` `lensList` 排序 | 镜头名单"保送之后按分量降序"取预算前缀 | **替引擎做决定** |
| 3 | `weight.js` `visibilityMask`（经 `streams.js`） | 注入侧可见性 = 源分量 ÷ 观察者分量 × 情报 × 位置 | 算能见度（design-core §2.1⑥ 说这归引擎） |
| 4 | `weight.js` `maxRippleTargets` | 一次事件能波及几个目标 = ceil(2×分量) | 算术上限 |
| 5 | `weight.js` `spreadRadius` | 因果传播半径 = 1 + 3×分量 | 算术（**实读未被调用，属死代码**） |
| 6 | `settle.js` 低分量动作方折减（P7） | 低分量方打高分量方 → 伤害按 w比折减 | **等于轻量裁胜负**（用户已定：不裁胜负） |
| 7 | `settle.js` `RETIRE_WEIGHT_FLOOR` | 分量 < 0.05 才准退休 | 生命周期判据 |

**结论**：1/2/6/7 必须换判据；3/4 是"算能见度/范围"，用户口径只要求"引擎不拿数值**裁胜负/排序**"——
但**观察者分量 = 0 会让它什么都看不见**（`visibilityMask` 的 obs=0 短路），所以 3 至少要把"0"的语义改掉。

## 2. 实测账（leg24 · 全量棋盘 346 实体 · 可复跑）

| 读数 | 值 |
|---|---|
| 起始分量分布 | 势力 118 个 = 0.75；角色 228 个 = 0.5（**全部同值**：账面无数 → 中立 floor） |
| 100t 后分量分布 | **0.000：227 个** ｜ 0.150：118 个 ｜ 0.480：1 个 |
| 静默线以下（终局） | **345 / 346** |
| 门控累计（100t） | 静默 20404 人次 ｜ 应答 0 ｜ 滤除 0 |
| 50t 黄金样本（1 实体） | 静默 0 ｜ 应答 0 ｜ 滤除 0（单实体世界看不出问题） |

**两条读数怎么来的**：`activityFactor` 静止衰减（人物 8 轮宽限后每轮 −2%、势力 20 轮后 −1%）——
**从来没出手过的在册实体，`lastActiveTick` 停在初值 → 100 轮后衰减把分量磨到 0 → 全体越线静默**。
即：**在册 ≠ 在动**，而现行判据把"没动过"读成了"不重要"。这正是用户说的"引擎不该算谁强谁弱"的现实版。

## 3. 逐处替代方案（含拍板点）

### 3.1 门控（#1）——**拍板点 P3-1**

**现状**：`分量 < 阈值 → 静默`。
**替代（建议）**：判据换成**可数的结构事实**——
> **沉默 = 手上没有在办的盘算（无未决 agenda）∧ 不曾在最近 N 轮出手（lastActiveTick 未推进）∧ 未被未决事件点名**

（三者同时成立才静默；任一成立即活跃。N 复用既有提案值口径，不新增数字。）

**为什么这样切**：设计已定"重心＝盘算"（design-core §3.4）——**手上没在办的事、又久未露面、又没人提到你**，
那这一轮确实没有你出手的理由；反之只要满足任一，你就该被放进门。**全部可数、可复现、无阈值调参**。

**备选**：门控整体废除（谁都能出手）——**不建议**：那等于把"节流"全推给模型自觉，预算与一致性检查会先崩。

**拍板点**：认「结构三条件」还是「整体废除」？（建议前者）

### 3.2 镜头排序（#2）——**拍板点 P3-2**

**现状**：保送名单（被点名/在飞盘算属主/近 2 轮动过）之后按分量降序。
**替代（建议）**：删掉分量降序这一层，改成**确定性固定序**：
> 保送（原样）→ 手上有在办盘算者（按 "盘算年龄" 新→旧）→ 近 N 轮出手者（近→远）→ **其余按实体 id**

**拍板点**：认此序？（建议认——它与我方已拍的"谁刚动过/谁在飞盘算里/谁在镜头名单上"逐字对应）

### 3.3 掩码（#3）——**拍板点 P3-3**

**现状**：`m = 源分量 ÷ 观察者分量 × 情报 × 位置`；观察者分量 0 → 全瞎。
**替代（建议）**：去掉比值里的分量，改成**事实驱动**：
> `m = 情报因子 × 位置因子`（同/异位置；玩家=观察者时，同位置/在飞盘算牵动/被点名 → 可见）

**拍板点**：掩码是否改"事实驱动"？（若不改，至少要把 `obsWeight=0 → 全瞎` 的短路改掉，否则新世界开局玩家什么都看不见）

### 3.4 波及上限 / 因果半径（#4/#5）——**拍板点 P3-4**

**现状**：`ceil(2×分量)` / `1+3×分量`（后者实读无调用点=死代码）。
**替代（建议）**：波及上限改**固定提案值**（如 ≤3 个目标，报批）；死代码直接删。

**拍板点**：认固定值 ≤3？（提案，随本片报批）

### 3.5 低分量折减（#6）——**拍板点 P3-5**

**现状**：弱的一方打强的一方时，伤害按分量比折减——**这就是"引擎裁胜负"最直白的一处**。
**替代（建议）**：**删掉折减**（引擎只做 [0,1] 边界钳制与"静默方自我增强被拒"），
强弱结果交给模型（用户定：LLM 提议结果、引擎只拦矛盾）。

**拍板点**：认删？（建议认——design-core §2.2 第一条就是这个）

### 3.6 退休（#7）——**已有实测教训**

片2 曾提前摘掉地板 → 应答机制塌半（66→34）／全册 active 破。**必须与 3.1 门控一并做**：
门控换成结构判据后，"谁静默"不再依赖分数，退休判据改用"多久没露面 + 有没有在办的事"才是安全的。
**拍板点 P3-6**：认"退休=久未露面+无在办+无未决引用，不再看分量"？

### 3.7 `weight.js` 的最终形态

用户口径：**引擎不再需要任何世界数值**。片 3 完成后 `computeWeight` 应当**没有任何调用者**
（#1-#7 全部换掉）——那时整块公式（COEFFS/层基线/衰减/折减）**整体删除**，`attrs` 只作账本事实保留
（模型每轮的提议照旧落账、照旧钳制，只是**没有引擎消费者**了）。
**拍板点 P3-7**：认"片3 结束时删除 weight.js 本体（而非保留空转）"？

## 4. 本片不做（范围限制）

1. **不动 `attrs` 的账本形状**（仍是可选 numRecord；模型提议照旧落账）——"数值下线"指的是**引擎不消费**，不是账本不许有。
2. **不动熵泵**（`pumpEntropy` 是引擎确定性、零模型，与分量无关）。
3. **不动环境初值**（它是熵泵的起点，报批已定；"书抽的真值 vs 引擎基线"的**来源标注**另开小改）。
4. **不动位置/归属的"查书"通道**（交接 leg23 §4 片2 遗留项，须先定形态：按需逐条 / 初始化只查有条目名号 / 全交模型提议）。
5. **不做旧世界迁移**（旧账里已有的分量缓存：片3 删掉消费者后成为惰性字段，schema 保留不报错＝零扰动）。

## 5. 验收判据（可测）

- **A-1 无消费者**：全仓 `grep` 证明 `computeWeight*` / `ssot.weights` 在引擎决策面零引用（渲染层除外，片5 处理）。
- **A-2 门控结构判据**：三条结构条件的真值表单测（各条件单独成立/组合成立/全不成立）。
- **A-3 全量棋盘回归**：346 实体 100t 后**静默面不再一刀切**（读数：静默人次 ≤ 起始实体数×轮数的 X%）——须先出曲线再定 X（数据说话）。
- **A-4 折减删除锁**：低分量方打高分量方 → 伤害**不再被折减**（断言实际生效值=提议值，除边界钳制外）。
- **A-5 掩码事实驱动**：新世界（全员账面无数）玩家**不会什么都看不见**（注入侧非全空）。
- **A-6 确定性**：同输入重跑逐字节一致；三处冒烟（smoke/weight-smoke/full-roster-smoke）全绿。
- **A-7 退休安全**：片2 的证伪场景复跑——应答机制不塌（重量冒烟"点名应答累计"不下降超过既有基线）。
