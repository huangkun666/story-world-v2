## 3. ★★★ 三件必须记住的事（这一棒最贵的产物）

### 3.1 `IN_CHAT` 的扩展提示词**根本不进 prompt**（leg91）

**出处**（用户本机 ST 源码）：`public/scripts/openai.js`

```js
// 1345 行
if (![extension_prompt_types.BEFORE_PROMPT, extension_prompt_types.IN_PROMPT].includes(prompt.position)) continue;
```

| position | 值 | `getPromptPosition` | 结果 |
|---|---|---|---|
| `BEFORE_PROMPT` | 2 | `'start'` | ✅ 进 prompt |
| **`IN_PROMPT`** | **0** | **`'end'`** | ✅ **进 prompt**（system 消息，排在提示词集合末尾） |
| `IN_CHAT` | 1 | `false` | ❌ **被 `continue` 丢掉** |

⇒ leg89 拍的 `IN_CHAT`（"贴着最后一条消息"，写在 `spec-tagged-actions-extraction.md` §6）
**让那两段一辈子没进过 model 的 prompt**——只躺在 ST 的 `extension_prompts` 字典里，
所以**面板读数"看着注入了 475 字"、模型却一个字都收不到**。

★**为什么 leg89 的判据没咬住**：它们锁的是"`setExtensionPrompt` 被调了、内容非空、锚点在里面"——
**那是"写进了字典"，不等于"进了发给模型的 prompt"**。
⇒ 现在 `test/tag-extract.test.js` 有一条**锁位置值本身**（必须 `IN_PROMPT`(0)、**绝不许** `IN_CHAT`(1)），
并做过**咬合演练**（把位置变异回 1 ⇒ 该条当红红在它自己身上；还原后同哈希）。

### 3.2 注入**跑在"世界载入之前"** ⇒ 开关是 1、构建号是新的、`sw2_` 一个都没有（leg92）

**三个原因叠在一起**（用户报的真症状就是这三条一起造成的）：

1. `initPanel` 里 `sw2Injector.apply()` 跑在 **`loadWorld()` 之前** ⇒ 那一刻 `sw2LastWorld` 还是 `null`；
2. `apply()` 算出两段都空时走**写空串**那条路（`clear()` 更会把 key **整个删掉**）
   ⇒ **"注入了 0 字"与"从没注入过"在字典里长得一样**（排查没有方向的原因）；
3. 重设注入**只挂在"世界推完一轮"**上——队列的 `refresh`（`src/async-tick.js:57`）**只在演算成功后**才跑，
   而**用户总闸是关的**（设置里 `autoAdvance` 缺键）⇒ **世界永远不推 ⇒ 永远没有第二次机会**。

**修法**（`d849159`）：
- 重设注入挪进 **`refreshWorld()`**（世界进内存之后；覆盖首载/切聊天/切世界/推一轮）
  —— 顺带发现 `refreshWorld` 里原本有**两处重复** `sw2LastWorld = world`，收成一处；
- `apply()` 交出 **`runs` 记账** `{count,lastOk,lastOff,lastChars,lastAt}`；面板读数**单列一格**
  「注入跑过 N 次 · 最后一次 …」，把 **从没跑过 / 跑了但 0 字 / 开关全关** 分成三种；
- **开关开着却一个字都没注入 ⇒ 明说并出声**（不再静默）。

★**另一条线索（用户提供）**：`[story-world-v2] signal is aborted without reason`
——`[story-world-v2]` 前缀出自我们自己的全局异常处理器（`web/index.js` 的 `onWinError`），
而"没带 reason 的 abort"⇒ **世界步正在被中止**（我们代码里唯一的 abort 是
`src/transport-http.js:74` 的主调用超时）。中止 ⇒ `refresh` 不跑 ⇒ 落进上面第 3 条。
★**这一棒只把线索登记下来、没有修**（见 §5 第 1 条）。

## 4. 本棒踩的坑（写下来免得下一任再踩）

1. ★★★**"读数对了"不等于"到终点了"**：`setExtensionPrompt` 被调用 ≠ 进了 prompt（§3.1）；
   面板印"注入了 475 字" ≠ 模型收到了。**这条是本棒全部返工的总根**。
2. ★★★**三种状态必须在界面上分得开**：没跑 / 跑了但空 / 跑了但失败。
   原来那一格印一句含糊兜底话（"还没注入过"）⇒ 用户与维护者都看不出方向。**修法是加 `runs` 记账**。
3. ★★**`getCtx()` 在 Node 里恒返回 null**：`web/index.js` 的 `getCtx()` 第一句是
   `if (typeof window === 'undefined') return null;` ⇒ 写诊断装置时**必须先造一个 `window`**，
   否则所有设置读写**静默落空**，症状看起来**完全像"开关失效"**（我第一次就这么被骗了）。
4. ★★**读返回值别读错层**：`buildEvolutionPack` 返回的是 **`{pack, text, estTokens}`**，
   载荷在 **`r.pack.pack`**；我拿 `r.pack.turnFacts` 读出 `null`，差点宣布"世界模型收不到行动"。
5. ★★**构建号起名被两条判据各咬一次**：`/^leg\d+-/` 里的 **`\d+` 是纯数字**
   ⇒ `leg90c-inject-position`、`leg90b-inject-position` **都不合格**
   （`leg40b` 那种写法能过，是因为它 = `leg`+`40`+`b-…`，`\d+` 只吃了 `40`）。
   另一条是禁词扫描（不许含 agenda/tick/ssot/schema/chronicle/entity/kind）。
   **定稿 `leg91-inject-position` / `leg92-inject-on-load`。**
6. ★★**台账插行**：用**脚本**插，且**落盘前算格数**（口径：**列数 = 裸竖线数 − 1**，`\|` 不算）。
   本会话**被自己的守卫拦下一次**——正文里写了 `||` 与 `【行动】…｜…` 的**裸竖线**（13 个 ⇒ 12 格）。
   ⇒ **正文里凡是要显示竖线，一律写 `\|`**；JS 的 `||` 在台账里写成"或"。
   ★另外：`node -e` 里写带引号的字符串**会被 PowerShell 吃掉一层**（本会话又踩一次）
   ⇒ **判断句/变异脚本一律写成 `.mjs` 文件再跑**。
7. ★**改 `PANEL_BUILD` 会让两条版本锁当红**（`test/render.test.js` 与 `test/param-hub.test.js`）
   —— 那是判据在干活，**照它的注释规矩改**（先过禁词扫描 + 形状），不是 bug。
8. ★**`MAIN_PROMPT` 里写反引号会截断模板**（leg89 那颗雷）：本棒改 8b 条时自证过
   ——成品里**裸反引号数 = 0**（装置 `leg90-prompt-check.mjs` 就打这个数）。
