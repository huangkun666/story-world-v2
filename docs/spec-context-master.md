## 1. 一句话

**账是真相（只增不改）· 卷只是搬走的旧段（纯存储）· 树是算出来的结构（不存第二份）·
线是"有形状才立"的索引（唯一能带摘要的东西）· 包是每轮真递出去的那一份 ——
预算不够时，按固定次序裁，裁过就如实留痕。**

★**先回答那句"不就是一个上下文压缩的事情吗"**：是，本质就是一次取舍。但它比"把长的写短"难，因为有**三道墙**：

| 墙 | 内容 | 破了会怎样 |
|---|---|---|
| **① 不许发明事实** | 引擎是账房 ＋ 史官，它**不发明**任何一件没发生的事 | 一旦为了让模型"看得懂"而补一句话，账就不是账了 |
| **② 真相只住只增不改的那一层** | 编年（世界那本流水）与卷；**树与线都是算出来的，不存第二份** | 存第二份 ⇒ 与编年分叉 ⇒ 同一件事两套说法（本仓最贵的病） |
| **③ 压缩的产物只能是"视图"** | 摘要**不许回写成账** | 回写即等于引擎自己编了一条事实 |
| **★判据** | **摘要只有在"跟原文形状不同"时才值钱**；同形状的压缩 ＝ 图注，弃 | 这就是"卷摘要"被砍掉的那一刀（§6） |

⇒ 所以这件事的正确答案不是"压得更狠"，是**"在有限的格子里按形状挑东西"**。

## 2. 机器里现在有什么（五层 · 代码在哪）

| 层 | 是什么（人话） | 代码里有吗 |
|---|---|---|
| **编年** | 世界那本流水：一轮一轮往下记，**只往后加、从不回头改** | ★**有**（老机制）。它是唯一能当真相的地方 |
| **卷** | 流水太长时，把**最旧的一段**剪下来另存到插件本地 | ★**有**（`src/storage.js` 的 `rotateChronicle`）。**纯存储**：只为热账不变胖，**不承担任何叙事职责** |
| **树** | 顺着「我从哪来」把事一件件串起来 —— **一片一片互不相交的森林** | ✘ **一行代码都没有**。账上的"来路"是真的，顺着走的函数只有 `src/chain.js` 的 `expandChain`，而它**只能从一个根展开** |
| **线** | 一条**讲得完的故事**（有头、有经过、有收口）—— ★**有形状才立**，不是每棵树都立 | ✘ **一行代码都没有** |
| **包** | 每一轮真递到模型眼前的那一份 | ★**有**（`buildEvolutionPack` ＋ `trimPack`） |

★**两条必须分开说的**（这两件事以前被混着说过一次，用户当场追问两次）：
**"卷机制"**（老）· **"看得见卷"**（= 取往事时把卷里的行也读进来，已落地）· **"卷摘要"**（从来没有过，已砍）。
⇒ **500 是"什么时候该搬"的门槛，不是"一卷多长"。**

## 3. 包：装什么、按什么次序裁（★现读代码，不是我推的）

### 3.1 尺子

| | |
|---|---|
| **预算** | `包预算`，默认 **30,000**（**估 token**），玩家可调（档位 30,000 / 60,000）——住在 `src/limits.js` |
| **怎么估** | 1 token ≈ **3 个字符**（中文）＝ 把包序列化后的字符数 ÷ 3（`estTokensOf`） |
| **★它是尺，不是闸** | 它**只裁料、不拦事**：世界该发生什么照发生，模型看不到而已 |
| ★一条实测教训（leg31） | 实体那一栏曾经 **56% 的字符是"键名＋标点"这种纯结构开销**（618 行各写一遍 `"kind":`…）；改成**一行一条的表格**之后整包 **−49.3%** ⇒ **行形状怎么选，直接决定装得下多少内容** |

### 3.2 装哪几栏（各栏的分工）

**当下的事**：实体段（这是"谁在棋盘上"，全量递、预算内取前缀）· 未决事件 · 在飞盘算 · 线捆（"这几条线，每条各写一步"的名单）·
待启用名单（从没出过手的人，每轮轮换露头）· 关系边 · 刻度/法则（书的原件）。
**过去的事**：★**往事（`纪事`）**——**唯一把"一路走过来的顺序"摊开的一栏**（按轮次从最早到现在，一行一条原文）·
已了结的盘算（清单）· 最近了结的事（快照）· 离场名册（谁不在了）。

★**为什么"往事"这一栏特别要紧**：模型每轮失忆就是因为它不在包里；而其余几栏都是**清单**（谁办过什么），**不带过程和顺序**。

### 3.3 裁的次序（`trimPack` 固定剪枝序，确定性）

| 顺位 | 裁什么 | 裁成什么样 |
|---|---|---|
| ① | 实体行的重字段 | 逐出麾下成员/分支/机构表 |
| ② | 实体行 | 只剩 `id`＋`name`（视野仍全量） |
| ③ | 最近了结的事 | 只留 id（★`closed` 那个记号必须留着） |
| ④ | 未决事件 | 只留 id＋title |
| ⑤ | 在飞盘算 | 只留 id＋goal＋progress |
| ⑥ | 已了结盘算 | 只留 id＋goal |
| ⑦ | **往事** | **整栏拿掉**（不是截短） |
| ⑧ | 待启用名单 | **整段丢弃**（不截短——名单靠轮换保证公平） |
| ★末 | **额度守卫** | 序全走完之后，把往事**按最新优先、一行一行装回来**，装到满为止；**整条收、整条丢**（绝不拦腰砍半句） |

★**每一段裁之前都重新量一次整包**，压进预算就停（序固定 ⇒ 结果确定）。
★**裁过就留痕**：包里会出现 `trimmed`，例如 `["entities.slim","纪事.留37条"]` —— **模型与调试者都看得出"你看到的是删过的"**，不是静默丢料。
★**空着就是空着**：一条都装不下时那一栏**根本不出现**（不写占位值充数）。

### 3.4 ★这一层曾经有个真的性能病（**已修**）

末道额度守卫是**一行一行装、每装一行真量一次整包**（这个口径本身是对的——见 §3.3 那条教训）。
但包**一超预算**，那个循环就每轮空转上千次：**实测单轮 15ms → 1100ms，而且不会自己好**（聊天越久越慢）。
⇒ **已修**（改二分找"最多装得下几条"；**语义一字未变**，4000 条往事实测 **33ms**，见 §7 第 0 步）。
★它曾经挡在"往包里加任何东西"前面——现在这条路通了。

## 4. ★★ 一条线在包里长什么样（本稿唯一新增的一格）

> 这一格从上次干活之前就悬着：**没有它，"每 500 轮 24～40 条线"换不成预算**（`spec-long-memory-theory.md` §8.7 如实登记过）。

### 4.1 形状：**一行一条，长成一句能读完的因果**（★已落地 · leg128）

```
"故事线": [
  "ev_12_7 万法阁商队集结 第12轮 → 11件 → 商队覆灭 第73轮 ·合流1"
]
```

**一行只写四样东西**（全是账上真有的字，**一个字都不生成**）：

| 位 | 是什么 | 从哪儿来 |
|---|---|---|
| ★**根 id**（行首） | 这条线**起于哪件事**——它同时是**取回原文的把手**（§4.3：★**引擎**照它取，**不是模型点名**） | 引擎发的号，模型照抄 |
| **头** | 那件事的标题 | 账上原文（`events[].title` / 归档副本 `milestones[].rows[].title`） |
| **件数** | 这条线一路走过 **N 件** | 数出来的（不生成） |
| **尾 ＋ 轮次** | **收在哪件事**、起于/收于第几轮 | 账上原文（收口那件事的标题） |
| ★`·合流N` | 这条线里有 **N 个多因点**（§4.7）——只在真有时才挂 | 数出来的 |

★**两条口径上的如实说明**（与初稿的差别，写下来免得对不上）：
① **行首是根 id，不是流水号**：流水号会随轮次漂（这一轮的"3"下一轮可能变成"7"）⇒ 取回原文会取错东西；
    根 id 是引擎发的、**跨轮不变**，所以拿它当**取回原文的把手**（代价约 3 est/行）。
② **没有"卷号"那一格**：`卷` 是编年的存储切法（一轮一卷，见 §6），它跟**因果线**不是一把尺；
    而且取回走的是检索层（卷它自己会读，§4.3）⇒ 行上写卷号**只是噪声**。起止轮次已经说清"多久以前"。

★**为什么是这个形状**（三条，一条比一条硬）：

1. **它跟原文形状不同**——原文是**流水**（一轮接一轮），这一行是**因果**（头 → 多少件 → 尾）。照本稿 §1 那条判据，**这才值钱**；
2. **它是索引，不是替代品**——它自带**回去的路**（号 ＋ 卷），所以"这一条到底怎么了"随时能取回原文（§4.3）；
3. ★**它不花一次模型调用**——头的名字、尾的名字、件数都是**编年里已经有的原文**（`spec-long-memory-theory.md` 法五：来路与收口各有一行原文）。
   ⇒ **不生成 ⇒ 不可能发明事实**（§1 墙①）。

### 4.2 成本（**估算，落笔前要量一次**）

| | |
|---|---|
| 一行 | ≈ **38–55 字符** ⇒ ≈ **13–19 est**（★比对象形状省约 40%：省掉的是键名与标点——§3.1 那条 leg31 实测教训就是这个道理） |
| 40 行（实测的密档上限） | ≈ **600–800 est** ⇒ **预算的 2%～3%** |
| ★口径 | 这是**照形状算的**（字符 ÷ 3），**不是量出来的**。真要拍板落地时，用现成的量测脚本补一次读数 |

★**所以答案是：装得下。** 40 条线占 2%～3%，而它换来的是"模型知道这个世界有哪几条故事、各自走到哪了"。

### 4.3 要细节怎么办：**要原文，不要生成摘要；取什么由引擎在出包那一刻定好**（★2026-09-25 订正口径）

★★**这一节改过一次口径，原因写在最前面（免得下一任照旧稿重新发明）**：
旧稿把取回的**发起方**写成"**模型点名 → 下一轮给原文**"。**这条已被用户逐字判死**——原话
「**我说过了下一轮才给检索答案就是他妈的垃圾查询，你为什么听不懂人话？？**」
（出处 `docs/session-handoff-2026-09-25-leg133-recent-window.md` §1 判据③；同文件 §4 再次明确）。
★判死的**不是"给原文"**，是**"模型发起的取回"整条**：**它不知道自己缺什么**——没看见的东西它不会去点；
而"下一轮才到"的答案**永远赶不上它写这一轮**。

⇒ **现行口径（已落地 · 照 leg132/leg133 那条"相关往事"）**：
**取什么，由引擎在出包那一刻自己定好，当轮到位**——引擎按"**这一轮正在动的东西**"取
（钥匙＝实体真名 / 盘算目标原话，钥匙表由检索层给：`matchedKeysOf`），取回来的原文**同一轮就进包**（`相关往事` 那一栏）。
★**模型不发起、不点名、也不等下一轮。**

★**旧稿拿来当样板的那条"点名"通道（刻度表）仍然在，但它只服务它自己那一件事**：
模型在输出里点表名 → `check-step.js` 净化后写进 `ssot.meta.scaleRequests` → 下一轮 `buildScaleOnDemand` 把**整张表**递给它。
⇒ **它是"下一轮给"的既有先例，不是本节的样板**——本仓**不再往这个形状上加东西**：
`src/pack.js` 里 leg132 那段留档已经写明，当年为"线的经过"加的那条点名通道（`lookupLines`）**不合格**
（实测三趟真跑共 150 轮，模型一次都没用过，而且就算用了也迟一轮）。

**"细节"这件事剩下的结论（这半条照旧成立）**：
★**不每轮都给"经历了一段什么"的生成式摘要**：索引那一行**已经带了两头的名字**；
而"中间到底经历了什么"最准的答案**永远是原文**。
★**索引那一行本身就是回去的路**：模型在包里看到"头 → N 件 → 尾"，
要细节时**细节已经由引擎按当轮"正在动的东西"取好、和索引同轮在包里**；
再要更远的，是**引擎换钥匙**的事，不是模型点名的事。

### 4.4 谁才立线（三级，照结构判，不看轮次）

树是**无条件**的（结构给定，切出来就是）；**线是有条件的（有形状才立）**：

| 级 | 条件 | 进包方式 |
|---|---|---|
| **甲** | 一棵树自己成了形状（有分支或有纵深、跨多轮） | **独立一行** |
| **乙** | 树不够大，但**同一个合流点（处境/决策）下的几棵树** | **合成一行**（容器＝那个合流点） |
| **丙** | 孤立单点（一件事，没有下文） | ★**不立线**——它本来就在"往事"那一栏里 |

★**判据只有两格**：**有收口 ＋ 中间经历 ≥ 5 件事**（N=5 是实测曲线定的，见理论稿 §8.4–§8.7）。
★**"有来路"那一格的口径：本格已定案删除**（实测它在 **100% 的树上都成立** ⇒ 不筛任何东西——见 §6 那张表；
★**代码那一侧的清理另有并行一笔**，本稿只登记口径、**不登记当前代码状态**）。
★★★**"有收口"这一格有一次修订**（2026-09-25，真模型 60 轮长跑实跑抓出来的病，已修）：
**"起点"不参与这一格**——根若是 `由处境而生`（`state`）或 `做种`（`seed`）的那件事，
它**不收口也不算"没讲完"**。
· **病**：引擎自己那一圈**永远不收这两种根**（`src/settle.js` 的自动收口只扫 `ripple` 源），
  而判据要"整棵树全收口、**根也算**"⇒ **凡挂在"处境／种子"上的树，永远立不成一条线**。
  实测：一棵 **17 件**、底下**全都收了口**的大树就卡在根那一格上，60 轮里**一次都没进过包**；
  而**生产做种走的就是 `seed` 型**（`src/seed-roots.js`）⇒ **世界的主线从第一天起就是这一栏的盲区**。
· **为什么这不是"放宽判据"**：引擎自己早就把这两型当"**起点、不是待办的事**"
  （`src/settle.js` 原话「播种源 / 处境源 = 链条的起点（不是"待办的事"）」）——
  **起点没收口 ≠ 故事没讲完**；"收口"说的是**底下那些事**讲完了。
· **闸没放宽**：起点之外**还有没收口的**⇒照样不算收口、照样不立线（判据锁着，见 `test/lines.test.js`）。
· ★旧口径原样保留在 `trees[].allNodesClosed`（两把尺都在，对账时谁也不冒充谁）；
  量测脚本 `demo/measure-leg127-line-curve.js` **同批改了同一条规矩**（本仓最忌"两把尺子"）。
★**"有来路"这一格从判据里删掉**：实测它在 **100% 的树上都成立**（事件按契约必有来路）⇒ **它不筛任何东西**，
它是**契约**、不是条件（详见 §6）。
★**"甲案"（有分支或有纵深）不当唯一判据**：它会把**一条 622 件事的巨线**也算作"一条线"，而且它的"覆盖率 100%"是假象（§6）。

### 4.5 它在裁剪序里的位置（★这条要焊死）

**先装地图，再装地皮**：末道额度守卫里，**先装"故事线"这一栏（≤2%～3%），再用剩下的地方装往事原文**。

| 为什么 | |
|---|---|
| **省** | 它是整包里最便宜的一栏（2%～3%） |
| **只有它带得回** | 往事那一条被丢，就是从模型眼前**永久消失**；而线被留下，模型至少知道**存在过这一条、并且有回去的路**（号＋卷） |
| **极少时也不亏** | 真到连 2% 都装不下，装别的也装不下——那时候 `budgetOverrun` 会如实留痕（本仓不许"预算已强制"变成一句空话） |

**丢哪一头**：① **未收的线优先留**（世界还在走的那几条，正是"接得上"最要紧的）② 收了口的按**收口轮次新→旧**留。
**留痕**：跟往事同款——整栏没装下记 `故事线`，只装下 N 条记 `故事线.留N条`。

★★**如实登记一处口径差异（还没定，别忘了）**：上面①"未收的线优先留"这一条**今天落不了地**——

而且会牵动 N=5 那条曲线（它是照"全收口"那一把尺量的）⇒ **本稿只登记，不动**。

### 4.6 ★★多因点：一条来路管"划分"，一张合流表管"多因"（已落地 · leg128）

**这是这一版新打通的那一格**（用户令「**包含多因点**」）。

先说清**病**（是结构上的，不是实现上的）：账上**只有一个**来路格子——`source` 是**单个对象**、而且
`additional:false`（写别的字段直接判"未知字段"）。⇒ **"好几件事共同促成一件新事"根本写不出来**：
账上只留得下其中一条因，另外几条**只活在标题那句话里** ⇒ 后来谁都认不出来（"猜出来的结构不算结构"）。

**落法（两个指针分工，各管一件事）**：

| 指针 | 管什么 | 能有几条 |
|---|---|---|
| `source` | **来路** —— 这件事属于哪条线（**划分**的根据） | **永远一条**（承重墙③不破） |
| `links.up` | **合流** —— 这件事是哪几件**共同**促成的 | **可以多条**（账上本来就是数组，而且是引擎维护的） |

写法：模型把**主因照旧写在 `source`** 里，**其余几条因写进 `newEvents[].alsoCausedBy`**；
引擎落账时并进 `links.up`（★只收**指得着**的：账上真有的，或**本轮新建的**——后者照 `ref-rules.js`
那条**位次**老路认，因为模型写不出引擎还没发的号；**对不上的那条因丢掉它、不丢整步**，也不写悬空指针）。

⇒ **多因点 = 记下来的因 ≥ 2 条**（主因 ＋ 至少一条别的因）。★**可判、可查，而且不参与划分**——
森林照样互不相交、终点照样有定义。包上以 `·合流N` 如实可见。
★★**2026-09-25 补记（长跑实跑抓出来的第四个病，已修）**：**归档会把多因点洗掉**——
归档原先只抄五格（没有 `links`）⇒ 立线时读不到第二条因 ⇒ `causes` 恒为 1 ⇒ **`·合流N` 一归档就消失**
（实测：热账里的多因点峰值 3、末段掉回 1）。⇒ 归档行**现在带上多因**
（只挂"主因之外还有别的因"那一种，单因事件的行形状一字不动）。见 §7.6 第 4 条。

★**三条别混的**（用户当场指出过的那两刀都在这里）：
- **多因点 ≠ 合流点**。多因是**入边**（好几件因 → 这一件，住在 `links.up`）；
  合流是**出边**（一个父、好几个子，住在 `source`）。两件互不蕴含。
- ★**单亲森林里"几条线汇成一棵"本来就恒真**（同一棵树里任何两个节点都共用根）
  ⇒ 唯一有意义的"合流"是**共用一个近处的头**（一个父、多个子），不是"这里真的汇合了"。
  ⇒ §4.4 的**乙级**照这个说法读：它是"**共用一个头的那几棵子树**"，不是"几棵独立的树来开会"。
- ★**"处境"今天没有号**（`state` 在契约里**明令不带 ref**：`ref-rules.js` 的 `state: () => null`，
  带了直接报 `state-source-has-ref`）⇒ 想"几条线共用一个处境"，今天只能**共用那个"由处境而生"的根事件**
  （别的线用 `ripple` 指向它）。★要一个**有号的处境**（张力/动乱/大势那种），是**新结构**，
  属"写入侧补处境那一格"——**本稿只登记，不做**。
  ★★**2026-09-25 补记（用户当场问「处境发号是不是必要的」）**：**不必要**。理由两条：
  ① 那条"指向处境根"的路**本来就通**（上面那句就是它），**不需要**给处境单独发号；
  ② 而它此前之所以"看着像不通"，是因为**另一处的病**——"处境根不收口 ⇒ 挂它的树永远立不成线"
     （见 §4.4 那条修订）。**病在判据那一格，不在处境有没有号**；给处境发号**也治不了它**。
  ⇒ 这一格**关掉**（不再当"剩下那一半"）。
