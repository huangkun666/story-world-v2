## 2. 主症：头衔式成员名（42 个势力 / 预计新写入 143 条）

### 2.1 现象（真账实测）

书条目里，成员不是每条都写成 `- 名号 (男, T8大乘中期): …`（**类型式**，这种能匹配上），
另有一批写成**头衔式**：

```
核心人物·北阴大帝·玄昭
核心人物·无间魔尊·血姬
帝君·太叔仪
巡天大统领·司空震
核心人物·凤主凤鸣岐
血姬亲传·血舞
```

而账上存的名号是**短名**：`玄昭` / `血姬` / `太叔仪` / `司空震` / `凤鸣岐` / `血舞`。

**为什么精确匹配必然失败**：`核心人物·凤主凤鸣岐` 与 `凤鸣岐` **双向子串都不成立**（多了"核心人物·凤主"6 个字）。
`normalizeParentName`（`abstract.js:187`）**只剥前导符号**（`/ ／ \ > · - — – 空白`），剥不掉**名字中间**的头衔，所以救不了这一类。

### 2.2 拟改法（最小、有先例、无词表）

**只在精确匹配失败时**，把成员名按 `·` 拆开，**从后往前取末段**再试一次；**候选必须唯一**（多于一个就放弃，不挂）。

依据不是新发明的规则——`·` 在本仓已被当**层级分隔符**用了两处：
- `bookNameAlias`：`混乱之地·万妖盟` → `万妖盟`（leg25 e）
- `normalizeToPositionSet`：`南荒部洲·十万大山` → `十万大山`（leg25 d）

**纪律**（照既有口径）：
1. **只填空位**——账上已有 `parent` 的一律不覆盖（明述优先）；
2. **歧义不挂**——末段命中 >1 个在册名号就放弃（宁缺勿造）；
3. **只给 kind=character 挂**，且目标势力必须是 canon 里 `kind=faction`；
4. **自指拒**（成员名 == 势力名）；
5. **来源照旧落账**：`parentSource='结构推导'` + `parentSourceFrom='成员行@<势力>'`（面板标「（推）」）。

### 2.3 实测影响面（真账 563 实体）

| 量 | 数 |
|---|---|
| 被救活的空壳势力 | **45** |
| **真正会新写入的归属** | **143** 条 |
| 歧义跳过（不挂） | 9 条 |
| 自指 | **0** |
| 已有归属被覆盖 | **0**（只填空位） |

样例（逐条看着都对）：
```
血姬   → 无间血海   （书里写作「核心人物·无间魔尊·血姬」）
玄昭   → 酆都鬼府   （书里写作「核心人物·北阴大帝·玄昭」）
太叔仪 → 太昊仙洲   （书里写作「帝君·太叔仪」）
司空震 → 太昊仙洲   （书里写作「巡天大统领·司空震」）
释空   → 无念禅境   （书里写作「首座·释空」）
```

### 2.4 ★必须一起决定的连带项（不然数字会虚高）

被救活的 45 个里，**有 6 个其实是 §3 的"别名空壳"**：`昆仑` / `瑶池圣地` / `姬家` / `姜家` / `大虞皇朝` / `合欢宗`。
它们和 `昆仑道宫` / `瑶池` / `荒古姬家` / … 是**同一个势力**。

⇒ **若只做 §2 不做 §3**：这 6 个会各自长出一份**与真身重复的成员名单**（两台账记同一批人）——**比空着更坏**。
⇒ 建议 §2 与 §3 **同批实施**。

## 3. 次症：书明说是别名的碎块（4 组，只能消掉 2 个空壳）

**判据取自书自己**（无词表）：**同一个书条目的 key 里同时列出了这几个名字** ⇒ 书自己在说"这些是同一个"。

| 组 | 依据（书条目） |
|---|---|
| `大虞`(1人) / `大虞皇朝`(0) / `大虞边境三十六凡俗小国`(0) | 条目 `人族皇朝` 的 key 同时列出这三个 |
| `昆仑`(0) / `昆仑道宫`(11人) | 条目 `昆仑道宫` 的 key 同时列出两者 |
| `姬家`(0) / `荒古姬家`(5人) | 条目 `荒古世家·姬家` 的 key |
| `姜家`(0) / `荒古姜家`(5人) | 条目 `荒古世家·姜家` 的 key |

**另有 8 组是"包含对但不是别名"，按宁缺勿造不许合**：
`万法阁/万法` · `无间魔宗/无间/无间血海` · `合欢魔宗/合欢/合欢宗` · `天庭/天庭百官/人帝天庭` · `瑶池/瑶池圣地` · `妖师宫/北冥妖师宫` · `剑垒/赎罪剑垒` · `姻缘阁/三生姻缘阁`

**为什么不许合**：`天庭百官`、`无间血海`、`瑶池` **各自有独立书条目**，且其 key **不含**那个"父名"——它们是**部门/独立势力**，不是同一个东西的别名。合并 = 造假事实。
（`天庭百官` 与 `天庭` 的**上下级**关系另有判据可查，但本轮**不做**——见 §5。）

## 4. 与既有机制的关系（会不会打架）

- **本棒 P3 已做的那个改法**（canon 势力 → key 精确命中它的书条目 → 成员行）：是**同一族的病**，治的是"**组织名**对不上"。本条治的是"**成员名**对不上"。两者互补，不冲突。
- **`verifyClaimedParent` 的 `member-line` 判据**：认的是"组织花名册里列了这个名号"。本改法**扩大了花名册的召回**（把 `核心人物·X` 也算作列了 X）⇒ 会让更多"模型声称的归属"**从 refuted 转为 member-line**（即**少弃一些真关系**）。这是**正向**的，但**属于判据放宽**，必须报备。
- **`audit-mechanism-genericity.js`（§4.8 泛用性）**：本改法依赖"书里用 `·` 写头衔"这一**形态**。**据实说：我只在大荒这一本上量到它**（八本书里另外七本 canon 侧无数据）。⇒ 见 §5 待办。

## 5. 我没验到的 / 建议一起报批的（不许当成已验证）

1. **跨书泛用性未验**：`·` 头衔式成员行我只在大荒实测。三国/春物/re0 那类书的成员行是别种形态（三国书里 `名号(…)` 多是正文对话）。**建议**：实施前拿**八本书**跑一遍 `MEMBER_LINE` + 末段兜底的命中面，确认"缺形态只许不生效"。
2. **`·` 末段的误合风险**：`核心人物·无间魔尊·血姬` 取末段 = `血姬`（对）；但若某书里 `X·Y` 是**并列复合名**（如 `混乱之地·万妖盟` 那种"地名+势力"），取末段会**丢掉限定**。本改法只在**成员名**上用、且有"唯一命中"闸，实测歧义跳过 9 条；**但跨书风险未验**。
3. **`天庭/天庭百官` 这类上下级没治**：本轮明确不做（需要另一套判据，且书里未必都写关系词）。⇒ 登记为待办。
4. **47 个"书里本来就没有花名册"的空壳**：**不该治**，那是诚实空着。
