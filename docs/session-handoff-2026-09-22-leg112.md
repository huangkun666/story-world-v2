## 1. C1 换书检测：它治什么、怎么做的

### 1.1 病（你上一场问过的那件事）

你原话（leg109b）：「**世界书一般都不会变的吧？变了重开一个聊天不就好了吗？**」
—— 前半句成立，后半句是**人的约定**。而插件此前**根本不知道有没有人违反它**：
同一个聊天里把书换了（换卡带的另一本内置书 / ST 的「挂到本聊天」/ 全局改选），
账本照旧按**旧书**跑，面板上却**一个字都不说**。

### 1.2 治法（四处，全是新代码，**没动任何既有契约**）

| 层 | 落点 | 做什么 |
|---|---|---|
| **引擎层（新文件）** | `src/book-check.js` | 纯函数：`checkBookSource`（比对）+ 两句人话（`bookChangedStatus` / `rebaselinedStatus`）+ 那一行 HTML（`bookChangedBannerHtml`）。★**零 import 的真叶子** |
| **取书层** | `web/book-source.js` | 新增 `currentBookFingerprint(ctx)`：照**抽取那条路**（`composeInitSource` + `bookFingerprint`）把现在的书重算一遍指纹；新增 `checkCurrentBook(world)` |
| **接线层** | `web/book-rebaseline.js`（**新文件**） | 载入期那一问 + 「就按现在这本算」那一条处理器（写账 + 显式落盘 + 重绘 + 写状态条） |
| **渲染层** | `src/render.js` | 设定页「世界设定」那一段贴一行 ⚠ + 一颗按钮（**只在书真换了时才出**） |

★**为什么必须复用 `composeInitSource`**：账上那个指纹是**抽取那一刻**由 `bookFingerprint(合订文本)` 算出来的
（`src/abstract.js:2050`，两条抽取路同一行）——只有用**同一个合订算法**重算，两个指纹才可比。
另拼一份书文 = 造第二把尺子（本仓最贵的病）。

### 1.3 ★★口径（三条，别越界）

1. **只出声，不动手**：发现不等**不自动重抽**（大书 20–30 分钟），也不偷偷把账上的指纹改掉。
2. **空着就是空着**（红线 2）：账上**没有**指纹（leg26 之前的老账）、或**这次没读到书** ⇒ **一律什么都不说**。
   **绝不拿「读不到」当「书变了」**。
3. **重新定基只改一格**：`setting.frozen.fingerprint`。设定正文、名册、实体账、事件、编年、轮次**一个字不动**
   ——它是「以后别拿这件事提醒我」，**不是**「把设定重抽一遍」（要重抽有隔壁那颗「只重抽设定」）。

### 1.4 ★它照出来的那件事（**你要知道**）

| | 指纹 | 合订文本长度 |
|---|---|---|
| 账上存着的（2026-09-11 15:59 抽取） | `fnv1a_pi8kez_6gui` | 约 **337,266** 字 |
| 现在现取的书（`大荒-姬元真.json`） | `fnv1a_15fuert_5rdo` | **268,542** 字 |

我顺手排除了几种可能：那本书文件**从 2026-08-25 起就没再改过**；聊天级挂载、全局挂载**都是空的**；
卡件的四段散文加不加**都不影响**这个指纹。⇒ **只能是"账上那份设定当初不是从你现在这本书抽的"**
（或是另一个版本的合订文本）。**你说记不清了** ⇒ 按现在这本重新定基。

★**这条对下一任的意义**：换书检测**不是纸面上的机制**——它在你的真账上**第一次跑就命中了**。

## 2. D1 撤掉「每轮改字段 ≤3」：先量再动

### 2.1 病

`check-step.js` 里那个 `FIELD_UPDATE_PER_TICK = 3` **自己就写着"提案"**，而 `docs/START-HERE.md` 自认
「所有新数字仍是提案态、一条曲线都没出」⇒ **一个没量过的数字在生产里当家**，而且**超一条就把整轮提议全部退回**
（连同一轮里写对的东西一起陪葬）。另一处（`sanitize-step.js`）是**静默截断**：砍掉尾巴只往 `dropped` 记一条，
**模型与玩家都看不见**。

### 2.2 ★撤前的实测（三份真账，只读副本）

| 量到的事 | 数 |
|---|---|
| 三份账加起来玩过的轮数 | 约 **119 轮** |
| 模型提出、并落账的字段变更 | **1 条**（`e_bk_146` 的「实力」，第 60 轮） |
| 那条上限**被撞到过几次** | **0 次** |
| `meta.entityFields`（只增不减的那一格簿记）现为 | **12.8 KB ＝账本的约 0.2%** |
| 每留一条变更痕要多少字节 | **130 字节** |
| 最坏情况（每轮 10 条变更、全记下来） | 一轮多 **1.3 KB** ⇒ 攒到账本的 10% 要 **480 轮** |

⇒ **你拍板「直接取消」成立**：它没在保护任何东西，只是**一颗没量过的雷**。

### 2.3 ★三处同批撤（少一处 = 半死的闸）

| 落点 | 改了什么 |
|---|---|
| `src/check-step.js` | 撤掉「超上限 ⇒ 整步拒」；**形状判据留着**（不是数组仍然拒） |
| `src/sanitize-step.js` | 撤掉那段**静默截断**（校验面放行了、净化器照砍 = 半死的闸） |
| `src/prompts.js` | 第 13 条撤掉「**一轮最多 3 条**」那一款，「四条硬规矩」→「三条」⇒ `MAIN_PROMPT_V` → `v2-agenda-t1-24` |

★**为什么提示词必须同批改**：不撤这一句 ⇒ **模型自己还会照着 3 条自我设限**，
你看到的现象**一模一样**（"该改十个人，世界只改三个"）——**闸撤了、话没撤 = 白撤**。

★**撤的只是条数**：「有因（cause 必须指向账上真实存在、且未闭环的事）/ 有痕（原值+现值落账）/
不越界（id·kind·name 不可改 · 玩家不可改 · 覆灭仍走 entityFates）」**一条都没动**；
「同一实体同一字段一轮内不许重复提议」也**留着**（判据 W7b 锁着）。
