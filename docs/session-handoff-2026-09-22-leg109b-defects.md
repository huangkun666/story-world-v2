### 1.1 四条都成立，各带证据

| # | 用户原话的意思 | 我核到的 |

| ② | **事件多了不可能全量注入**，必须有检索历史的能力 | 进包只带**最近 8 条**已闭环事件、**12 条**已了结盘算（`src/pack.js:38/39`）；旧编年不是压缩而是**整段搬进"卷"**（`src/storage.js:74`，逐行复制、**无摘要**），卷只给玩家看浮层；而 `recall.js` 检索的是**世界书原文**，**不是账本** ⇒ **账上"第 30 轮某人欠了谁人情"，模型没有任何办法查到** |
| ③ | **聊天输出的行动粒度太细**（细到具体身体动作），**插件颗粒度粗得多** | 聊天侧只有三格：`【行动】谁｜做了什么｜针对谁`（`web/inject.js:69`）；账本侧能改的只有字段值，且**每轮 ≤3、必带因、字段须在册**（`src/check-step.js:303-360`）⇒ 受伤/许诺/结仇/丢东西**没有任何通道进账** |
| ④ | **插件改了书里角色的状态，怎么保证不与世界书冲突** | 插件**确实不写书**（只读），但**两边没有任何对账机制**，而且已经能看到分叉：改书不重抽（`fingerprint` 那条缓存分支在生产上**是死的**）· 名册只列活人（`inject.js:107`）⇒ 账上死掉的人**从聊天模型视野里整个消失**，而书里还写着他活着 · `实力` 两边可以不同 · 出处发票留着但**从来没有一处拿它对账** |

### 1.2 用户补的第五条（关系网）——成立，而且查出是**有意删掉**的

- 账上**只有两种关系**：`parent`（层级归属：角色→势力、子势力→上级）与 `ripples`（一件事波及了谁 = **共现，不是关系**）。
- **没有任何一格**表示盟友 / 敌对 / 血亲 / 人情债 / 师徒 / 旧怨 / 效忠（全 `src/` 搜这些词**零命中**）。
- ★**它是有意删的**：`src/abstract.js:607` 写着「leg24 片1 删除位（原 K49 关系轮 prompt `buildRelationPrompt`）：
  隶属/所在/种族不再从书里抄」，理由是"那些产出**全属书的副本**，书随时可查，不必抄进账本"。
- ★**这条理由我认同前半、不认同后半**：不抄书的静态关系是对的（那是复制品）；但**玩出来的关系**
  （谁跟谁结了仇、谁欠了谁、谁叛了谁）**不是书的副本**——书里没有、账上也没有，**没有任何地方可查**。
- ⇒ 缺的不是"把书里的关系抄一遍"，是**一张"关系变更"的表**：有向边 + 类型（不预设封闭词表）+ 因 + 痕 + 额度。
