## 4. ★★别名正确性：一个**未解决且未实施**的设计问题（本棒最重要的一条，用户已定"先记下"）

### 4.1 问题

**别名 100% 来自 LLM，引擎没有任何验伪。** 真模型实测产出里，模型把**三类不同的东西**都当成了别名：

| 模型给的 | 实际是什么 |
|---|---|
| `昆仑道宫 ← [昆仑、**正道仙门魁首**]` | 前者可能是别名，后者是**称号/描述** |
| `太古仙域 ← [**仙界**]` | **类别名**，不是同一个东西的名字 |
| `下九重天·九霄 ← [**凡界**]`、`上二十四重天 ← [**真界**]` | **范围/上下级**，不是别名 |

**最危险的一种**：别名若正好是**另一个真实体名**，并查集会把两个不同实体**永久合成一个**，而账上**再也分不出来**（合并不可逆）。**这一项我没量过有多少**（不敢虚报）。

### 4.2 用户与我的结论（对话结论，**未实施**）

- 用户：**「这种语义理解只能给 llm 做，所以应该只能在 llm 上下功夫」** —— 我同意。
- 我补的两点：
  1. **这轮的坑是提示词措辞不精确**（我写的是"别的**叫法**"，而"叫法"边界模糊 ⇒ 模型把称号当叫法）。这属 LLM 侧可修，且**问法要收窄成"书里哪一处把它当成同一个东西的另一个名字"**（答案锚在出处、可被结构验伪）。
  2. **不能只靠 LLM**：合并不可逆这半件事**与模型准不准无关**，残留错误照样被永久化。⇒ **判断归 LLM、合并的不可逆性归引擎**。
  3. **代价不对称**：漏合只是碎片还在（可再治）；**错合是永久毁数据**。⇒ 别名这条的压力方向应**反过来**（其它规则是"宁可多不可漏"，这条必须"**宁可漏不可错**"）。

### 4.3 用户提出的办法 vs 我的补充（**用户已采纳"先记下"，未实施**）

**用户的办法**：抽象出来之后**再做一次小调用专门合并**。→ **我认同它治根**：分块抽取时模型看不到全书，而全册小调用是**唯一能看到全貌的判断者**。

**我的补充（三条护栏 + 一个互补机制 + 一个未解项）**：

1. **输出不该是名册，只该是"合并提案"**：模型返回 `{ 保留哪个, 哪些并进来, 依据出处在哪 }`，**引擎逐条验依据**，验不过整条丢弃、名册保持原样。理由 = 代价不对称（引擎握否决权）。
2. **问法要可判**：不要问"这些名字里哪些是同一个实体"，要问"**书里哪一处把它当成同一个东西的另一个名字**"。
3. **书 key 明说的那部分根本不用问模型**（零 token、不可能错）：条目名与它 `key` 里并列的名字（`【人族皇朝】` 的 key 含 `大虞`/`大虞皇朝`）。实测 14 组碎块里 **4 组属这种"书明说"**（大虞/昆仑/姬家/姜家），另 8 组（`万法阁/万法`、`天庭/天庭百官`）**书里没说是同一个**。
4. **未解项**：小调用让判断更准，但**消不掉"合并不可逆"**。要根除只有一条路——**别把合并做成销毁**：全册名号+别名另留一份记录，主名册标"疑似同一"，显示/查册按并集查 ⇒ 错合只是**显示问题、不是数据丢失**，可回退。**该方案未评估、未实施。**
5. **成本与失败语义**（待定）：699 名号+别名喂进去约 2 万字符、一次调用；**失败不许阻塞建世界**（本仓纪律"绝不阻塞调用方"）⇒ 退回"没合、碎片多几条"。

### 4.4 `aliases` 字段**留不留**（结论：**留，但定位改为"观测数据"**）

- **该留**：它是模型在**块内**看到的原始观测（别处拿不到），且是那遍小调用的**输入证据**；查册时按"名字 ∪ 别名"查也更不容易漏。
- **该收**：`dedupeRoster` 拿它**自动改写账本**——那是引擎在做自己判不了的判断。
- **代价（如实说）**：不自动合，碎片就还留着（真跑过：光靠提示词，块1 碎片从 8 降到 1，**没归零**）。这是**拿"碎片留着"换"不犯不可逆的错"**。

6. **两次"edit 吞掉换行"**：插入代码块时 `old_string` 末尾带了换行，把下一条语句拼到上一行。
7. **误用 `node -e` 传中文长路径**（本仓纪律明写禁止）⇒ 当场报错。
