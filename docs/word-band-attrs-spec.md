## 0. 人话版：这会怎么样

1. **子势力自动归并**：名册只管名单，新加一轮「关系轮」按批补"隶属/种族/所在"——"天庭百官"这类名号自动折进天庭的分支表，不再独立成行；
2. **实力值不再是模型手感**：模型从书里抄"档位词/数值 + 原文句"（出处校验），引擎查刻度表/归一算出实力值——"大虞只比天庭差 0.1"这种病从机制上消失（差至少一档）；分维度的书（力量/智力/外貌/财富…）同样支持：书带数值→数值直引归一；书带等级词→建档表；都没有→该维缺位；
3. **模拟器每轮看得见书内属性**：镜头内实体行带「档徽+原文依据句」，设定块带刻度带——模型知道"元婴后期（掌大荒灵脉）"是什么水平；引擎新增**无源跨档跃迁警告**——偷偷把凡间朝廷抬到天界级会留痕。

## 1. 背景与实证（数据说话）

- 名册回归 600+（leg21 瘦身生效）；但可选字段（parent/race/location）在名册规模压力下最易被模型省略——导出 (3) 对照：旧名册 504 条 parent 覆盖率 **82%（416/504）**，折叠仅 3 例（阐教/截教/瑶池），**"天庭百官"不在 (3) 名册**（首次出现于 600 版且未带 parent→独立入账）。规律与 leg20 attrs 被砍同源：**名册越大，可选字段越先被省略**。
- 属性不准实证：大虞（凡间皇朝）与天庭（书内至高）attrs 差距仅 ~0.1——批量手拍浮点的 0.5 均值区残留；出处校验只保证"有源"，不保证"值准"。
- 分维度体系（用户追问）：书维度自由（力量/智力/外貌/财富/意志…）、协议四维固定——维度自由只能住在词层，永不落实体字段（字段爆炸防火墙，2026-09-09 用户警告登记）。
- **leg22 实证（导出 (3)/(5) 对照 · 2026-09-10 · 只读取数脚本）**：
  - **ladder 实测＝16 档**：`canon.powerScale` 从 T1 感气境 … T16 道祖境（档名/说明全为原文措辞；(3)(5) 同书同指纹稳定）→ **拍板点②的数据到位**：等分精度 1/16≈0.06、首末≈0.06/0.94，**首末锚定几乎不增益（建议直接拍等分）**；K50「复用现成不重复抽取」前提**成立**。
  - **名册规模挤压规律量化**：parent 覆盖率 **82.5%（416/504）→ 69.0%（475/688）**（名册 504→688）；location 12.8% / race 9.9% / attrs 22.2%（leg21 属性轮生效面）；折叠仍稀（(3) 3 例 → (5) 1 例）。
  - **「天庭百官」在数据中复现**：(5) 名册在册（faction · location 第十二重天·朝天殿）而**无 parent** → 独立入账 `e_bk_54`——K49 的目标面实证确认。
  - **真病比「差 0.1」更重（本条修正上文旧述）**：大虞（凡间皇朝）attrs 0.8/0.9/0.9/0.8 → **分量 1.00（满分）**；天庭（书内至高）四维全落默认 0.25 → **0.375**——是**倒挂**，不是差距小。且 **453/602＝75.2%** 实体四维全为类别默认（无书内依据）；153 条有据属性中仍有 26 条落 0.5±0.05，其余扎堆 0.8/0.9 手拍整数（hardPower 值分布 0.9×40 / 0.5×37 / 0.8×25 …）。
  - **最有力例证**：项霸天依据原文＝「**项霸天(T8大乘巅峰): 气血如日**」——书内**本有档位词**，模型却压成 0.7。词档版要做的正是"把词交回来"。
  - **词档版不解决的部分（边界）**：分量函数顶端饱和——**18 个实体并列 w=1.00**、19 个 ≥0.95，而 474/602 ≤0.40（两极化结构）；词档版修方向，"顶档并列满分"的分辨率属分量引擎侧（另案）。
  - **新分歧点（K50-K53 形状相关 · 待拍）**：本书只有 hardPower 有书内刻度（16 档）；office/network/intel **无书内刻度**→按三态契约将落「缺位→类别默认」，即「附庸百国」这类政治实力**不再进数值**（世界更诚实但更扁）。处置建议：本棒按原细案走（只 hardPower 上 ladder），把"非刻度维的序"（比较句→序）登记为后续细案候选（触发＝词档版落地复验发现扁平化不可接受或用户点单）。

## 2. 设计

### 2.1 关系轮（K49，编排+契约层）

- **名册轮再瘦身**：`buildRosterPrompt` 只出 `{name, kind}`（最轻形态——输出预算压力彻底消除，600+ 名号无忧）；parent/race/location 全部移出名册轮；
- **新关系轮** `runRelationRound`（与 runAttrsRound 同构）：候选=名册定稿条目（按批 ≤`ATTRS_BATCH_MAX`=100 名号，行邻域文本上下文）→ `buildRelationPrompt(names, text)` 只问 parent/race/location（书中明述才填，**模板示例逐字写"天庭百官 → parent: 天庭"**）→ 净化+出处校验（race/location 逐字 ∈ 原文；parent 目标须在册且为 faction，否则弃关系+警告、名号保留）；
- 合并 first-wins；**seedBookEntities 折叠逻辑零改动**（原料补齐即生效："天庭百官" → 天庭.branches）；
- **属性轮批文本限流**（同轮做）：批文本累计 ≤60k 字符（超则拆更小批——防条目超长书（3k+/条）单批输入失控）；
- 增量入口并轨：`refine-pending` 候选扩展=「无 attrs 条目 ∪ 无 parent 的 faction 条目」（补关系/补属性一个入口）。

> **leg22 结构层修订（2026-09-10）**：本节「关系轮逐名号问 parent」的路线**已被 `docs/structure-layer-spec.md`（待拍板）取代**——结构性事实改由**体例轮 + 结构图轮**承担（实证：书里明写 `<上界势力_天庭百官>` / `辖属: 瑶池` / `统辖: 人帝姬元真`，而逐名号局部提问实测只抽到 **3%** 的势力→势力边）。关系轮保留 race/location 逐条事实。**K49 已实施部分（名册轮瘦身、批文本限流、refine-pending 并轨）不受影响**。

### 2.2 词档版三态（K50-K53，契约+引擎+编排+渲染）

**契约（全可选=旧世界零扰动）**：canon 增可选 `dimTables`：

```
dimTables: {
  hardPower: { type: 'ladder', words: ['炼气', …, '大乘'] } | { type: 'numeric', min: 0, max: 100 },
  office: … | 省略（该维无分级无数值 → 缺位）
}
```

- **ladder 优先复用现成**：hardPower ← canon.powerScale.level 序列（不重复抽取）；独立抽取时才走 LLM（每词出处校验 ∈ 原文，按书内语义序低→高）；
- **属性轮产出改版**：`{name, bands?: {维: {word | value, 依据}}, race?}`——只有书内明述才出，依据 ∈ 原文（出处校验沿用）；模型**不再输出浮点数**；
- **引擎三态落值**（全部确定性、可测）：
  - ladder：档序 → 档中心值（[0,1] 等分；首末档可用书中强弱断言锚定——提案态，拍板点 2）；
  - numeric：`normalizeValue(v, min, max)` 全书该维数值域归一（"武力 90/100" → 0.9）；
  - 缺位：该维不进 attrs（现有"账上无键不渲染"语义）；
  - **未命中回退（leg22 追加 · 缺口闭合）**：模型交的档词/数值必须对得上该维刻度表——ladder 词 ∉ `dimTables[维].words` 时**该维缺位 + warning 留痕，绝不猜档**（猜档=把"0.1 病"换成"猜档病"）；numeric 维数值超声明域 → 钳制落域内 + warning（不静默改）；
  - **numeric 数值域的出处要求（leg22 追加 · 缺口闭合）**：`min/max` 必须来自书内明述或书内该维数值的实取极值；二者皆无 → 该维缺位（不接受引擎凭空设域——域错=整维失真）；
- **数字仍是唯一真源**（attrs 不变、分量公式不变）；**档词=派生视图**：`bandOf(attrs, dimTables)` 供渲染/pack 查词（实体零新字段）；
- 分维度体系落地：书的自由维度 → LLM 投影到协议四维（力量→hardPower、权位→office、魅力人脉→network、智谋→intel 或 hardPower，带依据；意志力/气运 → 缺位），投影可溯、错位有限（档宽即精度）。

### 2.3 包改造（K54，契约层 pack + prompts）

- 实体行增 `band`（档徽：dimTables 存在时的派生词）+ `ev`（evidence ≤24 字——**已在账，零新抽取**）；模型视角从裸名号变成"元婴后期（掌大荒灵脉）"；
- 设定块增 `scale` 刻度带（ladder 词+区间，≤200 字，每轮常驻）；
- prompts 升版：字段说明（band/ev/scale 语义句）+ 铁律补"实力变化参照刻度带（破境=跨档、小进=档内）"；
- **成本断言**：镜头 30k 预算内（当前 ~3.6k → 预期 ~8-9k：500 实体 × ~10 token/行增量）。

### 2.4 档位跃迁监控（K55，引擎层 settle + observatory）

- settle 结算后：stateChanges 前后 `bandOf` 变化跨 ≥1 档（且 dimTables 有该维）→ 判**有源**：本轮 newAgendas/events/moveFact/盘算推进涉该实体；
- 无源 → warning `档位跃迁无源：<名> <档A>→<档B>`（警告上状态条/编年）- **不拦截**（提示词约束为主哲学），留痕进 simLog（observatory 新口径 `bandJumps` 可统计）。

## 3. 验收判据

- **A-1 关系轮**：名册轮 prompt 不含 parent/race/location 模板（瘦身锁）；关系轮调用数=ceil(候选/100)；天庭百官样例→`天庭.branches` 含之（golden 锁）；出处弃置留痕；批文本 ≤60k 生效
- **A-2 词档版**：dimTables 形状过 schema（旧世界零扰动）；ladder 每词 ∈ 原文；**golden：天庭档位索引 > 大虞档位索引（≥1 档）**；numeric 归一确定性（90,100→0.9）；缺位维不渲染；实体 attrs 仍数字且可逆查档徽；**未命中回退**：档词 ∉ 该维表 → 该维缺位+warning（不猜档）/ numeric 无声明域 → 缺位
- **A-3 包**：实体行含 band+ev；scale 在设定块；`estTokens ≤ 30000` 断言
- **A-4 监控**：跨档有源=无警告 / 无源=有警告 / 档内=无警告；simLog bandJumps 口径
- **A-5 回归+黑名单**：`node --test` 全绿（390+N）；新文案 A-3 零禁词

> **② 口径修订（leg22 讨论，2026-09-10）**：用户指出「16 档等分不符修仙；分段等比也不一定适合别的世界书」——**刻度形状不宜写死在"书→值"的映射里**。改为：**L1 书→序**（书只给序位/阶跃点/数值域，确定性）+ **L2 序→效力**（形状与陡度＝可调标定参数，缺省 linear＝现状零扰动）。本细案的 hardPower ladder 因此只出**序值**；效力形状落 `dimTables.shape`，调参面与体检/自标定属新机制，详见 `docs/param-tuning-spec.md`（待拍板，K56-K59）。

> **leg22 拍板记录（2026-09-10）**：①=**分步，K49 关系轮先行**；③=**做**（零新抽取，ev 已在账；成本断言 8~9k/30k 余量充足）；④=**警告不拦截**（与"提示词约束为主、引擎只守诚实底线"哲学一致）；②与⑤**待样本/确认**——②先出目标书 powerScale 实档数（等分精度=1/档数；档数 ≤4 时同档全等值：0.1 病消灭但精度问题转移）。
