# 常见问题与排查

先判断问题发生在哪一步：插件没有加载、世界初始化失败、抽取结果不理想，还是某一轮推进失败。记下原始提示和操作步骤，再查「设置 → 调试」。旧版调试台可能只显示概括提示；本地预览已补充抽取任务的具体诊断，仍有疑问时再核对模型服务端日志或浏览器网络面板中的响应。排查过程中尽量保留现状；重试会再次调用模型并可能产生费用，重置或删除数据前先导出备份。

> **版本口径（截至 2026-10-08）**：新增的抽取设置、停止按钮和诊断功能尚未公开发布，只在本地预览构建中。公开 main 仍为 1.1.2 · leg209；GitHub Releases 仍是 1.1.0。请先按[社区使用指南](community-guide.md#安装与更新)核对安装来源，再提供插件窗口当前显示的版本和构建号。当前只在 SillyTavern 1.15.0 上验证过，其他版本尚未验证。

## 插件没显示、窗口打不开或启动报错

**现象：** 扩展列表里没有插件，打开窗口后是空白/回退窗口，或页面出现加载错误。

**检查：** 扩展目录名是否为 `story-world-v2`；如果用 ZIP，解压目录是否还带着 `-main`。更新后是否做过浏览器硬刷新。检查浏览器控制台、插件窗口状态栏和「设置 → 调试」里的错误；确认错误是否指向本插件，避免把 ST 或其他扩展的消息误认为插件错误。

**处理：** Git 安装可用 ST 扩展管理器更新，再硬刷新。ZIP 没有 Git 元数据，需手动替换为新文件并确认目录名。不要一遇到加载错误就清空聊天数据或快照；这些操作不能修复目录名、网络请求或浏览器缓存问题。不要关闭浏览器的广域安全或广告过滤规则。若怀疑某条过滤规则拦截了本地资源，只记录规则名称和被拦截的具体请求，先按站点级方式核实。

**反馈材料：** 面板版本/构建号、ST 版本、浏览器及版本、安装方式、完整错误文本、出现错误的步骤、调试报告（发布前检查并脱敏）。

## 「开始新世界」或「推进一轮」失败

**现象：** 点按钮后提示「模型通道未配置」、无进展、等待后报错，或模型回复无法写入世界账。

**检查：** 插件的「设置 → 模型通道」与 ST 聊天模型设置是两条独立配置。确认插件通道中的服务地址、密钥和世界模型；必要时用页面提供的模型列表或连通检查。连通检查或重试会向模型服务发请求。连通检查成功只说明那次检查通过，不保证后续抽取请求一定成功：连通检查没有验证正式抽取请求所用的全部 JSON 参数。查看状态栏和「设置 → 调试」里的记录；如果日志只有概括提示，再核对模型服务端日志或浏览器网络面板中的状态码与响应。

**处理：** 地址、凭据或模型选择错误时修正插件自己的通道。若请求未到达服务端，先检查 ST 所在网络、服务地址和服务端状态；若收到服务端错误，记录 HTTP 状态码及服务返回的错误正文，再按服务商的限制检查额度、模型名和输入/输出限制。不要仅凭“失败”就重复点多次；先确认请求是否已经送达，避免重复消耗。不要为了绕过问题关闭浏览器的 CORS 或广告拦截广域规则。

所有模型提议都不能通过本轮处理时，世界轮次不会增加。检查调试记录中哪一步失败，再决定是否重试；重试会产生新的模型请求。

## 抽取失败：先分清是哪一种返回

抽取是模型通道对角色卡/世界书来源发出的真实请求。遇到失败时，请按调试记录区分下列情况；“抽不到内容”和“请求没有成功”不能混为一谈。新的本地预览诊断会在任务开始、结束及失败时记录模型名称、来源规模、块大小、并发和真实调用数，并记录 HTTP、超时、截断、过滤、空回复、JSON 或数据形状等原因。进度块数与真实模型调用数是两项不同数据。调试报告默认不包含详细请求正文或完整模型输出；不要假设它会自动保存这些内容。若日志仍不足以判断原因，可从模型服务端日志或浏览器网络面板核对请求和响应，但分享前要去掉密钥、聊天正文及其他私人内容。

| 现象 | 检查 | 处理与反馈材料 |
|---|---|---|
| HTTP 错误，例如 401、403、404、429，或明确不支持请求参数 | 看调试任务记录里的错误类型、HTTP 状态和服务端拒因；必要时再核对服务商日志/网络响应 | 这些错误不会靠拆小来源修复，会停止发送后续新请求。修正凭据、权限或模型路径；如果服务拒绝 JSON 模式，可更换支持该模式的接口/模型，或把拒因反馈维护者。限流时降低并发、等待服务恢复后再试。已发出的并发请求可能仍在服务端处理并计费 |
| 超时 | 看失败阶段、任务实际调用数和等待时长；普通「单轮超时」设置不控制抽取 | 停止这次任务的后续请求。先确认服务状态和模型端是否收到请求，再决定重试；不要调高「单轮超时」来修抽取 |
| 网络失败或临时服务故障 | 看调试任务记录、服务端日志或浏览器网络面板中的请求失败信息；地址先去掉敏感查询参数 | 这类错误可进行有限重试；有限尝试耗尽后停止。不要关闭 CORS 或广告拦截广域规则 |
| 普通空回复 | 看任务记录中的阶段、调用次数和错误类别；确认不是过滤或截断 | 空回复不代表“世界书没有设定”。不要反复重抽来掩盖空返回 |
| 响应被截断或过滤 | 看任务诊断中的结束原因，区分输出长度限制和服务端内容过滤 | 不会把残缺 JSON 拼起来，也不会额外调用模型猜原因。「单轮输出上限」和「单轮超时」不控制开局抽取；服务端过滤也不等于上下文太长 |
| JSON 格式错误或内容不是预期结构 | 看任务诊断里的具体错误类别、失败块和阶段 | 部分不完整 JSON 或数据形状错误可按规则拆分相关内容再试；是否继续取决于错误类别。服务端明确的上下文限制才适合靠缩小块处理。提供错误类别和脱敏诊断；不要把它们等同于网络失败 |
| 数据校验/来源依据错误 | 查看调试记录标出的阶段、字段和来源核验结果；确认来源是否真的被选中，原文是否含有支持该字段的内容 | 修正来源选择或原文片段后再考虑后续抽象。出处未核实、字段形状不符等情况可能影响结果；不要把任何一个验证状态都理解为“整本书读取失败” |
| 任务成功但设定或角色很少 | 回到「设置 → 抽象来源」检查选择、预览和来源是否读取到；确认该卡/世界书是否确实写了相关内容 | 可选择更合适的原文范围。抽取选择不会自动重做已有世界；如要重新初始化或重新抽取，先导出，并阅读操作提示确认它会影响什么 |

## 调整抽取块大小与停止任务

以下两项只在本地预览构建中可用，尚未进入公开 main 或 Release。

**「抽取每块字符数」设置什么？**

它位于「设置 → 模型通道」，默认 30,000。数值按每块的来源正文字符计算，不是 token；只接受正整数，且不能超过程序可准确表示的整数范围。完整原文行不会被拆断或截掉；单行超过设定值时仍作为完整内容保留，并在任务记录中提示超长。初始化和「只重抽设定」使用此设置；「只抽刻度」仍对整份来源调用一次，不受它影响。来源比设定值小时会单发；调小后可能增加请求数和总耗时，不能保证更快。

**「中止抽象」在哪里？**

它在窗口操作区；窄屏先点窗口顶部的「操作」展开。没有任务时按钮不可用。开始新世界、只重抽设定、只抽刻度共用一个抽象任务，同一时间只能运行一项。中止或失败后可以重新开始；原世界和已有有效缓存会保留。任务失败或中止时，已抽到的部分内容不会写入成功缓存。中止会阻止后续新请求，但已经发出的请求可能仍在服务端处理或计费；不能保证服务端取消或退款。

如果中止时正在保存，插件会等待确认或回存原账，再允许下一次操作。保存已成功后，中止按钮会关闭；随后出现「世界已保存，但界面刷新失败」时，先刷新查看，不要按未保存来重复开局。若明确提示回存失败或保存状态未确认，请保留现场、核对备份并附上原始错误反馈。

**抽取诊断里看哪些信息？**

本地预览的调试台在开始、结束和失败时记录任务类型、模型名、来源字符数、块大小、配置与实际并发、实际模型调用数、总耗时和具体失败阶段/原因。实际调用数包括已经发出的重试请求；块进度不是调用次数。调试报告默认不记录详细正文和完整提示词。连通测试通过只说明那次最小请求成功，不证明正式抽取的 JSON 参数也被服务支持。

## 标签、行动记录和空字段

**这一轮没有标签，为什么聊天里的事没有记进世界？**

「让聊天模型按标签写行动」启用时，插件按聊天模型正文里的标签提取行动。若这一轮正文没有标签，状态栏会说明这一轮没有标签，正文里的行动没有通过这条路径记下来。检查设置开关，以及聊天模型是否真的按要求输出标签；标签开关关闭时，插件不会用关键词猜测正文中谁做了什么。可以在后续消息中按规范记录行动，但不要假设补标签会自动改写已经结束的那一轮。

**没有标签是不是插件没调用模型？**

不是同一件事。标签来自聊天模型生成的聊天正文；世界推进使用插件自己的世界模型通道。标签缺失表示这条聊天提取路径没有标签可读，不能据此推断世界模型请求是否发生。分别查看状态栏和调试记录。

**设定页、角色页或事件里有空白，是抽取坏了吗？**

不一定。空白可能表示来源没有提供依据、抽取没有得到结果，或相关内容没有进入当前账本。空白不是“原作明确没有”，也不是程序自动识别出的否定。回到来源页检查实际被选中的内容和预览，再结合调试记录区分未加载、请求失败与确实没有抽出数据。不要手工填入猜测值来让页面看起来完整。

**程序能判断故事里的所有含义吗？**

不能。程序可以检查数据形状、名册引用和已有来源依据等明确规则；它不理解全部叙事含义，也不会靠关键词表猜“这一定是势力/角色/地点”。模型可能遗漏或误解原文。反馈时请指出原文位置、抽取结果和你认为不一致之处，避免只说“AI 不准”。

## 玩家保护、禁止模拟与调用次数

**保护玩家棋子会不会多调用一次模型？**

不会。玩家棋子始终受保护；角色资料行里的「禁止模拟」开关保存保护设置；本轮正文实际行动过的角色也会暂时受到保护。角色保护与权限检查不增加模型调用次数。玩家角色不可改为允许模拟。

保护能拦截对受保护角色的直接动作、盘算和字段写入，但不能保证其他角色的标题或描述永远不会间接提到其处境。若看到越权的直接写入，请提供轮次、角色、错误表现和调试报告；对间接叙述的模型编造也请提供具体例子，不要笼统描述为“保护完全失效”。

**抽取并发设置如何处理？**

「设置 → 模型通道」里的「同时问几块」控制抽取时并行请求数。提高它可能增加服务端同时压力；遇到限流或连接问题时，先按诊断原因处理，再决定是否降低并发后重新开始。明确的 HTTP 拒绝、超时等错误会停止后续新请求；网络或临时服务错误只会进行有限重试，耗尽后停止。不会把所有失败都退回单路继续，也不保证降低并发就能修好问题。反馈并发设置、服务端错误类别和失败发生在哪一块。

抽取期间不要切换聊天，初始化、载入或导入保存尚未结束时尤其如此；同一世界尽量不要从多个标签页同时操作。如果发现账本串到了别的聊天或出现异常，先导出当前整聊天保留现场，再反馈排查；不要马上重新开局覆盖现状。

## 导入、快照与数据安全

**导入恢复前要做什么？**

导入会以文件里的聊天和世界账替换当前状态，不会自动先拍当前快照。先用「快照 → 拍一份快照」保存当前世界账；若需要聊天备份，再用「设置 → 导出整聊天」。检查选中的文件和聊天对象后再确认导入。导出的文件可能包含私人正文，不要未经检查就公开。

**恢复快照后，为什么对话还在后面？**

快照只恢复世界账，不回退、不删除聊天对话。恢复后世界轮次和聊天内容可能不同步；如果你需要完整聊天备份，应使用整聊天导出。快照有保留数量限制，不是长期归档。

**清空快照或删缓存能修复所有问题吗？**

不能。清空/重置快照会影响当前聊天的快照库；删除浏览器缓存可能让资源重新载入，但不能修复错误的服务配置、模型返回、目录名或世界数据。先导出重要数据，记录问题现象与调试报告，再根据明确证据选择操作。不要把清空世界、删除存档、重置快照作为第一步。
