## 0. 一句话

**模型每轮先选"本轮上场的实体"，引擎只对其中"还没查过书的"去查一次书（走模型），把 `实力`/`位置` 按原文原话回写进实体账；查不到就留查书标记痕迹、下轮再补；势力不写实力。**

## 1. 范围

**做**：
1. `实力` 字段：**只有角色**有；值 = 书里紧贴名字的括号/冒号标签原话（`T9渡劫巅峰`）。
2. `位置` 字段：书里明述的所在地/驻地原话（`北俱荒洲不周山`）。
3. 两条 ≤15 上限（见 §6）。
4. 面板查书标记 + 势力的实力**派生显示**（不落字段）。

**不做**（用户明令或本轮不碰）：
- ❌ 势力写实力字段（用户 2026-09-11 拍板："势力干脆不要写实力字段"）。
- ❌ `资源` 字段（用户已点名，**以后再加**；登记在 §10）。
- ❌ 引擎读 `实力` 做任何计算（不进 weight/streams/settle/gate/镜头）。
- ❌ 词表/正则当**判据**（用户明令）；零 token 解析只作**兜底**，且校验词来自本书自己的标尺（见 §5 ③）。
- ❌ 存量实体"移动"通道（`stateChanges[].location`）——另案，等用户点单。

## 2. 三个失败态必须在账上分开（本细案的核心）

用户问："如果部分字段加载不出来怎么办（注意，这是 llm 没有加载到而不是这个字段没有的情况）"。
**答：账上把"这一次查询成没成"如实分成**四种查书标记**（有值 / 未查 / 未加载到 / 书未明述），且"没加载到"永远不等于"字段没有"。**

| 态 | 触发条件 | 账上记什么 | 面板显示 |
|---|---|---|---|
| **值** | 模型回了非空字符串 | `entity.实力 = "T9渡劫巅峰"` + `meta.entityFields[<id>].fields.实力 = { value, from: '<条目名>', fetchedAt }` | `实力：T9渡劫巅峰（据书）` |
| **未加载** | 该轮查了、模型没给这一栏（可能只是漏抽） | `fields.实力` **不写**；`attempts.实力 += 1`；`lastTriedAt` 更新 | `实力：本轮未加载到（下轮再补）` |
| **书未明述** | **引擎**能确定性判定：该名号在世界书里没有任何相关条目（`sources` 为空） | `attempts.实力.state = 'absent'` + `note` | `实力：书未明述` |

**红线**：只有"引擎确认书里没有相关条目"才允许写"书未明述"；**模型没返回一律记"未加载"**，绝不用空值反推事实空缺。
**这条有实测依据**：本轮真模型实验里，同一批 5 个势力，模型对"实力"全部返回 null —— 我当时的 prompt 写的是"该名号自身的档位"，而书里档位挂在**成员行**上。**null 是口径错，不是书里没有**（同一实验里"位置"5/5 全中，说明模型没有漏读倾向）。

### 数据形状（契约层登记）

```js
// entity（可选字段；旧世界零扰动——不写就不存在）
{ id, kind, name, location, parent, attrs, /* 新增 ↓ */ 实力?: string }

// meta（新增一个键，机器可读留痕）
meta.entityFields = {
  "<entityId>": {
    fields:   { 实力?: { value, from, fetchedAt }, 位置?: { value, from, fetchedAt } },
    attempts: { 实力?: { count, lastTriedAt, state: 'ok'|'pending'|'absent' }, 位置?: {...} },
    sources:  ["<查过的世界书条目名>", ...],     // 审计：查过哪几条
  },
}
```

**键名口径**：用中文 `实力`（不是 `power`）。理由：①与 v1 的字段名/界面标签一致（用户截图那张表单就是「实力」）；②账本已有中文键先例——`env` 四键就是 `['民生度','动乱度','天时','张力推手']`（`src/entropy.js` `ENV_KEYS`，定案），ssot schema 的 `env` 也照此登记，故中文键**不破契约**；③本字段是**给人看/给模型读的文本**，不是引擎量，中文键反而提醒"这不是机器字段"。位置沿用既有英文键 `location`（账本里已有，不改旧名）。

**幂等**：`attempts.<字段>.state === 'ok'` → 永不再查；`'absent'` → 不再查；`'pending'` → 下轮可再试（`count` 超阈值见 §4）。

## 3. 流程（四步，接在现有 tick 队列上）

```
① 选人（LLM，1 次小调用）
   输入：全量在册名号（id+名号+类别，书序，不排序不裁剪；623 个 ≈3-4k tokens）
        + 未结盘算 + 未决事件 + 玩家落子事实
   输出：{ "pick": ["<id 或 名号>", ...] }     ← 只选名，不带字段
   引擎护栏：名单外/已灭/已退休 → 拒；去重；上限 15（超则拒整条并记警告）；空/坏 JSON → 用上轮名单 + 记警告
        ↓
② 查书（LLM，仅在"选中且缺字段"时发，可与①合并成一次；默认合并以省调用）
   输入：这些实体在世界书里的条目原文（含成员行）
   输出：{ "<名号>": { "实力": "...", "位置": "..." } }
        ↓
③ 回写（引擎，纯函数）
   逐实体、逐字段：非空字符串 → 落值 + 留痕；缺失 → 记 pending；sources 为空 → 记 absent
        ↓
④ 主调用（世界步）
   名单 = ①选的实体 + 引擎事实（在飞盘算/未决事件/位置集/张力）；引擎只拦矛盾，不裁胜负
```

**为什么选人必须走 LLM**：现状 `pack.js` 的 `lensList` 是**引擎**按 30k 预算截前缀——镜头外的人连"想让谁动"都表达不了。leg24 片3 之前那个按分量算的静默线实测把 345/346 全判静默（引擎实际上禁止了所有人出手）。**选择权交给 LLM，引擎只给全量事实 + 只做校验。**（改 `pack.js` 名单口径 = 承重墙，故本细案报批。）

## 4. 失败与重试（三种失败分开治）

| 情形 | 判据 | 处置 |
|---|---|---|
| 调用失败（超时/429/非 JSON） | transport 抛错或解析失败 | **不写任何 attempts**；本轮照常演算（世界不动）；下轮自动重试；连续 3 轮失败 → 面板报"实力查询连续失败（N 次）" |
| 返回不全（要 15 只回 9） | 逐实体判定 | 只写回来的；缺的不写 attempts（**同一批不算"未加载"**，避免把批内漏抽记成该实体的问题） |
| 该实体单独重试仍空 | `attempts.<字段>.count ≥ 2` | 记 `pending` 并**停止自动重试**（防死循环）；面板显示"未加载到（可手动重查）" |
| 书里没有相关条目 | `sources.length === 0` | 记 `absent`（面板"书未明述"），不再查 |

**超时与熔断**：查书调用走与抽取同款 transport，`timeoutMs` 取 `PROPOSED_CALL_LIMITS`；**熔断条件 = 连续 3 轮失败或单轮耗时超上限 → 本轮跳过查书**（世界推进优先；字段是附加信息，绝不阻塞 tick）。

## 5. 抽取 prompt 与三条纪律

**① 必抄规则照 v1 的实证口径**（`plugins/story-world/src/prompts.js:455` 同款，不改写）：
> 找到该名号时把紧贴名字的括号或冒号里的标签**照抄**；原文确实没写才留空。

**①b 实力是文本，不是分档枚举（用户 2026-09-11 追加）**：
> 原话：「记住实力是用文本类型，以后如果不是分段境界就可以灵活输入」。
- **分段境界的书**（如本书）→ 抄档位原话（`T9渡劫巅峰`）。
- **不分段的书** → 抄它自己的原话写法（`剑术通神`、`执玄铁剑`、`三万铁骑`、`偏将军`…）。
- **判定标准只有一条：这句话在不在原文里**。原文写了判断词（"顶级宗门"）就照抄那个词；原文没写就**不许自己下判断**——实测反例：模型曾凭空答出「武道顶级宗门」，而原文里没有这句。
- 长度上限 30 字（v1 是 ≤20 字；本细案放宽到 30 以容纳"执玄铁剑"这类半句描述）。
- **不做枚举/白名单校验**：不要求命中 `powerScale` 档位表（那是分段书才有的东西），也就不会把不分段的书判成"没实力"。

**② 势力不抽实力**（用户拍板）：prompt 明写"只对角色条目抽实力；势力条目返回空"。

**③ 兜底（可选，开关默认关）**：v1 的零 token 解析（`powerFromNameContext`）只填空位，且**只认紧贴名字的标签**（名字后 80 字符内，不许跳过中间文字抓后面的括号），校验词来自**本书自己的标尺** `setting.frozen.canon.powerScale[].level`——**不是我们编的词表**。用户对词表法有明确反感，故此项**默认关闭**，仅作"模型连续失败"时的候选开关。

**④ 不许出现的事**：不写"顶级宗门/很强/中游"这类判断词（实测模型被约束前会这么答）；不把 `实力` 转成数字；不比较两个实体的档位高低。

## 6. 两条 ≤15 上限（用户 2026-09-11 拍板）

**R1｜每轮上场实体 ≤15**（本细案 ①）：
- 计数 = ①输出的 pick 去重后条数；上限真源 `ROUND_PICK_CAP = 15`（提案，集中一处）。
- 超限处置：**拒整条 pick**（不用前 15 个截断）→ 退回上轮名单 + 记警告"选人超限（当前 17/15）"。理由：截断＝引擎替模型做选择（旧病）。

**R2｜单个盘算一轮内涉及的实体 ≤15**（用户口径：属主 + 行动方 + 被波及方，逐轮算）：
- **不新增存储字段**（agenda 里没有涉及名单；加字段=加机制）。逐轮**算**：
  - 属主 = `agenda.owner`
  - 行动方 / 目标 = 本步 `actions[]` 中，其"归属该盘算"的动作：`source.ref === agenda.id` 的 plot 事件所牵动的动作，以及 `agendaAdvances[].agendaId === agenda.id` 对应的动作实体
  - 被波及方 = 该盘算产出的 plot 事件 `ripples[]`，以及沿链上溯到它的 ripple 事件的 `ripples[]`
  - **涉及集合 = 上述实体 id 去重**
- 上限真源 `AGENDA_INVOLVED_CAP = 15`（提案）；**计数与拒绝都写在 `check-step.js` 的校验面**（与 `RIPPLE_TARGET_CAP` 同一处，保持"上限有强制点"）。
- 处置待你选：**(a) 拒整步**（与 ripples 超限一致，世界停摆一轮，可重试）／**(b) 只警告不拒**（世界照演，留痕）。**我建议 (a)**——上限不拒绝就是纸面机制（leg25 G 组的教训）。
- 与 `RIPPLE_TARGET_CAP = 3`（一次事件波及 ≤3）**并存不冲突**：一个盘算可以有多个事件，每个事件各自 ≤3，合计 ≤15 由 R2 兜。

## 9. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 前置步压在关键路径上，拖慢/打断 tick | 超时 + 熔断（连续 3 轮失败即跳过）；失败绝不阻塞世界推进 |
| 选人调用成为每轮必经 → 调用数上升 | ②查书只在"缺字段"时发；实测第 2-3 轮起基本为 0（候选实体都带字段了）。若仍嫌多，可把①降频为"每 N 轮或盘面变化时" |
| 模型选到不该动的实体 | 引擎只校验（未知 id/已灭/超限→拒或退回上轮），**不替它改选** |
| 账本膨胀（623 实体 × 每实体一条留痕） | `meta.entityFields` 按需生长，只对真查过的实体写；`sources` 只记条目名（短串） |
| 旧世界兼容 | 新字段全可选；旧账无 `meta.entityFields` → 全部视为"未加载"，按需补即可；`ssotSchema` 只加不删 |

**回滚**：本细案全部改动集中在一个新模块 + 若干接线点，开关（`ENTITY_LOOKUP_ENABLED` 提案常量）关掉即回到现状（不选人、不查书、不显示查书标记）。
