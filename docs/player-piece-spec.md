## 0. 人话版：这会怎么样

世界棋盘的账本里从此有你的位置：你不是被系统另眼相待的"主角"，而是实体池里的一枚普通棋子（id `e_player`，类别 character）。引擎的计算路径对你零分支——分量、衰减、掩码、裁定全走统一管线；只有两条**写权限规则**是显式的：模型永远不能写你的行动或状态（红线 1 代码化），你的状态变化只由引擎给——世界对你的影响（被打、被波及）由引擎按分量比计算落账，你的成长由"兑现通道"（你的尝试被裁决成什么）负责（该通道依赖独立细案，本细案只立接线）。初始属性先手动填（与实体 attrs 同路径），自动注入等设定注入管线落地。收益：你随时能在观棋窗口看见自己的分量（格局行）、世界的风浪怎么拍你（影响留痕）、未来榜单/全局视图类扩展直接复用实体渲染——因为你就是一枚实体。

## 1. 目标与验收判据

**目标**：玩家作为棋子入实体池（context.playerId 标注）；模型禁写玩家；引擎影响通道写玩家；玩家衰减同尺；注入掩码观察者=玩家（K4 解挂）。

| # | 判据 | 断言形态 |
|---|---|---|
| P-1 | **无特殊路径** | settle/gate/streams 对 e_player 零分支（除两条写权限规则所在模块）；grep 断言无 player 条件分支 |
| P-2 | **模型禁写玩家** | `actions.entity === playerId` / `stateChanges.entity === playerId` 的世界步被校验拒绝，世界如实不动 |
| P-3 | **影响通道** | 他人动作 targeting 玩家 → 引擎按分量比写玩家 hardPower（确定性断言：0.05×min(1, w_actor/w_player)）；波及事件含玩家 → 波及影响落账；两通道都记 simLog 审计字段 |
| P-4 | **玩家衰减同尺** | 玩家连续 OOC/无落子 N 轮 → weight 单调递减（人物层 8 tick/−2%），有落子轮立即回满——与实体同公式同入口 |
| P-5 | **掩码真值（K4 接回）** | 注入侧按 玩家分量×情报×位置 掩码（V6 数值序 + m<0.3 省略）；玩家 low weight → 远事不可见 |
| P-6 | **旁观兼容** | 无玩家世界（bystander）照常可跑，注入降级为全见；观棋侧不变 |
| P-7 | **回归** | 既有 109 测试全绿；分量引擎 V1-V5/V7-V9 不退化 |

## 2. 范围限制（本棒不做）

- **兑现通道细则**（attempt 成败/成长/学习）——依赖独立细案"玩家尝试兑现机制"（队列项），本细案只立"兑现通道存在"的接线与 schema 预留；
- **初始值自动注入**——依赖设定注入管线（大势层阶段），当前人工设定（与实体 attrs 同路径）；
- 玩家不引入 agenda/盘算（玩家是棋子不是模拟主体，盘算树阶段不动此语义）；
- 不影响旁观者世界语义（玩家缺席 = 合法世界形态）；
- 不做玩家专属 UI（榜单类扩展为后续红利，非本细案交付）。

## 3. 设计

### 3.1 玩家入实体池

- SSOT：`context.playerId`（可选字符串）标注"这是你的棋子"；玩家实体 `{ id: playerId, kind: 'character', name, location, attrs, lastActiveTick? }` 与其余实体同形状（schema 零新类型）。
- 无 `playerId` 的世界（bystander）= 合法：观察者缺席，注入降级（P-E）。
- **收益（用户点名的红利，写进设计理由）**：玩家与实体同等——观棋位置行自然包含玩家、格局行可显示玩家分量（用户可见，模型不可见——P3 已隐藏）、榜单/全局视图类扩展直接复用实体渲染与排序，无需任何特判。

### 3.2 写权限规则（红线代码化，唯一的两处玩家特判）

1. **模型禁写玩家**（check-step 一条规则）：`actions[].entity === playerId` → 拒绝；`stateChanges[].entity === playerId` → 拒绝（"模拟器永不写主角行动"从 prompt 自觉降为引擎规则）。玩家无盘算 → advances 天然无此问题。
2. **引擎独占写玩家**：玩家 attrs 只经影响通道（§3.3-2）与兑现通道（§3.3-3，依赖）变化。

- gate 语义收紧（文档级）：玩家**永不被"静默"滤除**——他没有 proposals 可滤，静默对他只表现为"衰减 + 看得少"（权重低 → 注入掩码变窄）。此条无需代码（天然成立），写清防误解。
- K3 记账规则顺延：玩家 active = 该轮有落子事实（moveFact.verb 非空）→ `lastActiveTick = tick`；OOC/静默轮不记 → 站桩权力照萎缩（长跑 §2.3 直译落地）。

### 3.3 玩家 attrs 三条通道

| 通道 | 写入者 | 规则 | 状态 |
|---|---|---|---|
| 初始值 | 人工 | 同实体 attrs：手填初始（活档/设定提取），值域 [0,1] | 本细案（自动注入入队，触发=设定注入管线） |
| 影响通道 | 引擎 | ① 他人 `actions[].target === player`（源实体分量 w_src）：`hardPower −= 0.05 × min(1, w_src/w_player)`（提案值，钳制 [0,1]，记 simLog 审计）；② 波及事件 ripples 含玩家（源分量 w_src）：各 attrs `−= 0.02 × min(1, w_src/w_player)`（提案值）——被打击/被波及是客体性变化，与实体被裁定同哲学（薄裁定只按量） | 本细案（系数 K11 曲线校准） |
| 兑现通道 | 引擎 | attempt → 裁决 → attrs 增量；**接线占位**（schema/入口预留），细则依赖独立细案 | 依赖（排队） |
| 衰减通道 | 引擎 | 同尺：与实体同公式同入口（computeWeightAtTick × player.lastActiveTick） | 本细案 |

**客观性边界保持**（dev-process 红线④）：玩家分量 = 确定性计算 + 有界输入；输入由引擎通道写、模型不可写；"客观"表述不扩大。

### 3.4 掩码再接（K4 解挂）

- 注入侧观察者 = `weights[playerId]`（K1 `visibilityMask` 直接接上：m = clamp(src/obs × 情报 × 位置, 0, 1)，m<0.3 省略事实）；
- 无玩家世界：注入降级为全见（P-E 提案）——旁观场景是工具性实证，产品形态总有玩家；
- 观棋侧全局可见不变。

### 3.5 simLog 审计扩展

- 每 tick 记：`playerAffected`（影响通道条目：{tick, source, attr, delta, ratio}（可选字段，schema 扩展））——供 P-3 断言与日后榜单/复盘。
