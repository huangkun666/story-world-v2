## 2. ★★★ 交付二：发布仓与部署位——**"两个版本"这件事被清掉了**

### ① 发布仓 `main` 的旧状态（这是"不稳定"的真正来源）

`main` **不是分支、是导出的快照**：它是从 **v1.0.1** 那棵树抠出来的，
**只在上面叠了 leg154 那一处 hotfix**；而开发目录从那以后又走了 leg149/150/153/155。
⇒ 两边差 **24 个代码文件**（`src/abstract.js` +158/−112 · `src/seed-roots.js` +199/−35 ·
`src/pack.js` +102/−3 · `src/schemas/ssot.schema.js` +75 · `web/index.js` +69/−67 …）。

★**用户为此问过一句很关键的话**：「**main 分支不是远端和本地都一样的吗？？？**」
——**答案是"确实一样，因为两边都还是旧的"**。GitHub 的接口对
`main...leg151-prefetch` 的原话是 **`No common ancestor between main and leg151-prefetch`**（两支无共同祖先）。

### ② 这一棒做了什么

把**开发目录那一棵树**导出、推到发布仓 `main`，让**发布版 = 开发目录的导出**：

| 步骤 | 结果 |
|---|---|
| 第一次推（含记忆层） | `main` = `1c3c097` ★**这一次是错的**：用户随后说"稳定不带" |
| 撤走记忆层后重推 | `main` = **`3ffd892`**（记忆层不在里面） |
| 修完"推过了"那条再推 | `main` = **`ced167b`**（当前） |

★**发布仓现在只有一支 `main`**：过时的 `leg151-prefetch`（带着记忆层）**本地与远端都已删除**
——留着它就是"两个真相"。

### ③ 部署位：**加了同名双份，随后发现它根本不生效**

★★★**这一条是环境级的新发现，接手的人一定会撞上**：

SillyTavern 有**两条路**都能发扩展文件，**谁先注册谁先接**：

| 顺序 | 谁 | 注册在哪 |
|---|---|---|
| **先** | `express.static(public)` | `src/server-main.js:219`，**在鉴权之前** |
| 后 | 用户目录那条路由（"同名盖掉全局"就是它） | `src/users.js:1082`，在鉴权之后 |

扩展加载时取的是**同一个地址**（`/scripts/extensions/third-party/<名>/…`）。
**只要全局那份真实存在**（这台机器上它曾是一条 junction），**静态中间件先一步命中、
用户目录那条路永远轮不到** ⇒ **"同名双份"这个官方推荐做法在这里根本不起作用**。

**证据链**（三条，都是实测）：① 改全局那份的一个文件 ⇒ 服务端吐出的字节立刻跟着变；
② 把 junction **改名让路** ⇒ 服务端立刻改吐用户目录那份，开发版独有的三个文件同时变 404；
③ 用 HTTP 状态码判定两个分支：`main` 全 404 / 开发版全 200。

**本棒定稿的摆法**（用户要"能切分支看两版"）：

| 位置 | 是什么 | 为什么 |
|---|---|---|
| `data/<用户>/extensions/story-world-v2` | **发布仓的一个 git 克隆**（真仓、能 fetch、能切分支） | 唯一被加载的那一份 |
| `public/scripts/extensions/third-party/story-world-v2` | ★**已删除**（原来是 junction → 开发目录） | 它只要在那儿，就会**抢先**被静态中间件发出去 |

★**代价如实登记**：**"改一行代码刷新即生效"那条路没了**。开发仍在
`F:\deepseek\plugins\story-world-v2`（分文未动），但要进面板得走
**本地改 → 提交 → 推发布仓 → 面板切分支/fetch ＋ 硬刷新**。
★要退回"活的"那份：把用户目录那份移走、再把 junction 建回去（一条命令，见 §7）。

### ④ 换分支的两条纪律（血证）

1. **切完分支必须硬刷新**：扩展入口是 `<script type="module">` 注入的，
   **地址后面不带任何版本号/时间戳**（`public/scripts/extensions.js`），
   而 ES 模块**按 URL 缓存** ⇒ 不硬刷新，跑的还是**旧模块**（用户当场撞过这一条）。
   服务端也不设 `Cache-Control`（`src/users.js` 的扩展路由）。
2. **本机 git 必须先配代理**：`git` **不读系统（WinINET）代理**——
   代理在 `127.0.0.1:7897` 听着，而 `git config http.proxy` 是空的 ⇒ 直连 github 被挡。
   临时用法：`git -c http.proxy=http://127.0.0.1:7897 …`；
   发布仓那个克隆已经把代理**写进它自己的 `.git/config`**（只影响这一个仓）。

## 3. ★★ 交付三：用户实机报的那个 bug（已修、已推送）

### 两条病，是两件事

| # | 病 | 改法 |
|---|---|---|
| **①** | **成功之后也不许**对同一条正文再推 ⇒ **按钮变哑** | **手动那颗「推进一轮」不再受这条闸管**（闸的本职是"同一段正文别被自动提两遍标签"；按按钮是"让世界走一步"——两件事）。**自动路照旧挡。** |
| **②** | **失败也记成"推过了"** | `sw2LastAdvancedMes` 改成**只有 `res.ok` 才记账**——那一轮超时/报错/关页面，**立刻能重推** |

★**②与仓里既有口径直接矛盾**（这是它值得单独说的原因）：`src/async-tick.js` 自己写着
"tick 失败：世界未写，**可立即重试**"，而接线层在推进**之前**就把这条正文记成"推过了" ⇒
**那句话是假的**。这正是本仓"一个数两把尺子"的又一例。

### 判据（＋3，**先证过红**）

把 `manual` 豁免撤掉 ⇒ 新判据当场咬住（报"手动路必须豁免这条闸"）⇒ 还原后全绿。

## 4. ★★ 交付四：滚轮那条——**只查清病根，一个字没改**（等用户拍板）

**用户原话**：「**还有我滑到最底部滚轮就失效了**」。

**病根（推导 ＋ 旁证，★不是真机量到的）**：`web/style.css` 给
**外层页容器**（`.sw2-view.sw2-active{overscroll-behavior:contain}`）与**两栏**
（`.sw2-merged-main` / `.sw2-merged-side` 各一条）都设了"滚到头/尾时别把滚动传给外面"。
而**外层那个"页"自己也是能滚的**（里面有 `.sw2-merged-grid`，它比页高一截）
⇒ 在左栏里往下滚、滚到左栏尽头时，**这一滚被拦在那里、传给外层的那条路被人为切断** ⇒
**滚轮"失效"**。

★**为什么不敢直接改**：我搭了个量测装置想复现，但它**量出来的 `overflow` 与真实布局对不上**
（`.sw2-view` 那格算成 `visible`，而样式表写的是 `overflow:auto` ⇒ 父级链没搭对）
⇒ **这个装置不可信**。而本仓文档自己写着：**版面的真机行为只有人能验**。
**所以这是推导，不是我在真机上量到的**——不拿"应该没问题"再糊用户一次（这一棒的教训就是它）。

**三种改法（`web/style.css` 一行级，动样式按规矩要同批升 `CSS_VERSION`）**：

| | 改法 | 好处 | 代价 |
|---|---|---|---|
| **甲（我推荐）** | 撤掉**外层**那条 `contain`（两栏的留着） | 滚到栏尾自动接着滚外层，滚轮不死 | 滚过栏尾时外层会跟着动一点 |
| 乙 | 撤掉**两栏**的 `contain` | 同上 | 同上（一件事的两面） |
| 丙 | **两栏不再各自滚**，整页一条滚动条 | 最不容易再打架 | ★**用户当年明确要"两栏各自滑"**，所以要他点头 |
