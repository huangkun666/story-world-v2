## 1. 四个病根（逐条实测，都指得出出处）

### 1.1 ★★★ 禁用仓储 = 全书的 81%（交接完全没提的一条）

| | 三国 | 大荒-姬元真 |
|---|---|---|
| 条目 | 827（启用 264 / **禁用 563**） | 235（启用 213 / 禁用 20） |
| 禁用正文 | **850,282 字** | 37,527 字 |
| 引擎看得到 | **18.9%** | **87.6%** |
| 被点名过的禁用条目 | **554 条 / 835,647 字** | 7 条 / 1,673 字 |

`src/init-source.js` 旧法一条不剩地跳过 `disable`。而 **ST 生态里"禁用"常常是作者的仓储**：
条目关掉（ST 自己的注入器不烧它），改由**控制器脚本**运行时 `getwi(null,'张辽正史')` 按需开抽屉。
三国的 220 条控制器壳点名了 554 个标题——**那正是每个角色的档案**。
⇒ **这就是"127 vs 537"的主因**：引擎只能从 JS 代码里捞名字，一个字的人物档案都读不到。

### 1.2 ★★★ 别名通道是死的（硬 bug，两本书都中）

模型**一直在交别名**（`test/fixtures/extract-samples.json:6` 就录着真输出 `{"name":"白小娥","aliases":["小娥"]}`）、
`ssot.schema.js` 登记了契约键、`dedupeRoster` 整套并查集靠它做跨块归一——**而 `sanitizeCanon` 只收 `{name,kind}`，
把 `aliases` 静默丢了**（无 error、无 warning）。
⇒ **leg25 g 那一整棒"跨块归一"从 leg24 片1 起一次都没生效过**。
症状（真账）：`曹操` 与 `曹孟德` 各占一条、`大汉/汉室/东汉` 三条并列、大荒 152 个势力里 108 个空壳。
★判据为什么没咬到：`roster-merge.test.js` 全程**直接喂 `dedupeRoster`** 手工对象 ⇒ **锁住了机制、没锁住接线**。

### 1.3 ★★ 标签用的是"触发词"，不是题名（两本书都中）

`normalizeEntryKey` 取 `key[0]`，而 ST 的 `key` 是**触发词表**（"什么时候该注入这条"），不是"这条叫什么"。
模型看到的是 `【吕氏】人物档案：吕玲绮`（题名 `吕玲绮`）、`【九宸玄陆】`（题名 `世界总设定`）、
`【境界】`（题名 `战力准则`）；`key=[]` 的 15 条更直接变成 **`【36】`** 这种纯数字。
⇒ **作者亲手写的题名一个字都没进过抽取**。

### 1.4 ★★ 大小书两条路、两种口径：**小书从来没抽过设定**

`srcLen ≤ 30000` 那条路走的是"只问名号"的提示词。实测复现（`leg60-probe-small.js`）：
1 次调用、提示词 `powerScale/situation/tension` 全 false ⇒ **canon 恒空**。
⇒ 四本真书（Eldoria 4,168 / Global 438 / 实教 9,158 / 综漫 14,557）**没有力量体系、没有法则、没有社会格局**。
★交接的验收里"小书输出逐字节不变"与"把抽象做好"**不可能同时成立**——本棒按用户令选了修好。

### 1.5 ★ canon 只读头 3 万（交接唯一说到的那条，只管设定那半边）

`Array.from(src).slice(0, CANON_SRC_CHAR)`。真账代价：真正的档位表 `演义战力体系`
（`T0级_天下无双 数值标定 勇武100`）在窗口外 ⇒ 模型照抄了窗口里唯一那张表【声誉】十级
（真账逐字 `里闾称善…遗臭斧钺`）。**不是模型错，是取样错。**

## 2. 四刀（全部落地 · 判据 814/814 · 冒烟 8231 字节未变）

### 2.1 一刀：全条目分块读全 + 一遍抽完（取消大小书分叉）
- 删掉 `slice(0, CANON_SRC_CHAR)`；**同一批块、一遍抽完**（块里有什么就抽什么；分块按书序，不按数据类型切）。
- 块间合并 = 纯函数 `mergeCanonChunks`：`powerScale`/`rules`/`historyNotes`/`dims` **并集去重**；
  `society`/`techOrMagic`/`situation` 取**信息量最大的那块**——**绝不合成一句**（合成=摘要=创作）。
- 拆半降级也带上设定（旧法只并 `bookEntities`，拆半会让设定静默消失）。
- 大小书**共用同一份合并提示词**（`buildRosterPrompt`，leg60 起它不再是"名册轮"）。

### 2.2 二刀：声明面取料（治 81%）
判据（纯函数、零词表、与方言无关）：① **恒注入壳声明的目录**必读；② **"自成一套"的壳声明的料**必读
（一个壳点名的标题**互相成族**：共享 2–3 字前后缀且 ≥3 条 = 它声明的是一**套**）；③ 零散点名 = **实例**
（一人一条人物档案）⇒ 不进料，**题名照旧进名册**。
★先后否掉两条更"聪明"的判据并留档：按标题含"体系/规则"选（词表 + leg58 已证否）、按姓氏/前缀族选
（`公孙`、`貂蝉_` 全被误判）——**leg58 那句"形态判据分不开分类定义与分类的实例"是真的**。

### 2.3 三刀：题名即名册（零 token）
判据三步：① 题名 2–3 字前后缀频次 ≥3 = 书自己的体例；② 剥体例得残差；
③ ★**自证**：残差必须**被这本书当过名字**（是某条条目的 `key`）。
★还要**只认主导体例**：`貂蝉演义` 既能剥前缀 `貂蝉`（×6）也能剥后缀 `演义`（×185）⇒ 取族最大的那个，
否则会把 `演义`/`正史` 两个**路由词**当名号收进册（首版实测就中了这两条）。

### 2.4 四刀：刻度进包 + 编译完整性自检
- canon 新增 `dims`（维度 + 取值范围，照抄原文）；`pack.setting` 新增 **`刻度`** 块
  （维度 ≤ `DIM_TOP`8 · 档位 ≤ `TIER_TOP`24 · 每串 ≤ `SCALE_STR_MAX`30 字 ⇒ 最坏 ≈ 1,216 字符）。
  **这是 A-8"冻结层不入包"体积纪律的唯一一处窄口**，理由：它是**锚**（模型写实力/属性有尺子可依）。
  散文型设定（社会格局/力量体系描述/史略）**不进每轮包**。空表 ⇒ 键不出现（既有世界零扰动）。
- `setting.frozen.compile` 落账（全是数字与短题名）：书里条目/启用/禁用 · 声明面读数 ·
  题名面贡献 · **设定类条目覆盖率与未编译点名**。面板「设定」页新增两栏，**漏了如实报**。

## 5. 已知限制（如实登记，未打补丁）

1. **题名面的精度**：题名是**类目式**的书会剥出类目词——re0 3 条（`种族/地理/怪物`）、实教 76 条（`班级点数/转班券`）。
   根因：作者把类目词也写进了 `key`，自证闸拦不住。★**没有再加第三层启发式**（leg58 的教训：层层打补丁的判据自己会烂）；
   每条都带 `from/why` 可追，不静默。这两本不是活世界。
2. **题名面不猜类别**（判不出就留白，不写 `kind`），下游按既有缺省走。
3. **50 万防御上限对三国已咬到**（合订 50.8 万 > `INIT_SOURCE_HARD_CEILING=500000`，声明面尾巴被截 8 条）。
   要害在前（启用条目 → 设定/年份档 → 分阶段剧本），且 `catalog.declaredDropped` **如实上报**（面板也印）。
   抬不抬这个数是**数字**，按"数字先报批"等用户点头。
4. **`chunkRows` 会抹掉每行行首空白**（`.map(s => s.trim())`）——三国那份 9,079 字的 YAML 变量规则缩进即层级，
   实测 7,686 行共抹掉约 18,600 字。与"读全"独立，未动（改它会再动一次书指纹）。
5. **`综漫-春物` 的字数两处对不上**：leg59c 路由表记 1,031,515 字，装置实测 14,557 字（小书）。
   本棒以装置为准；那条路由表读数不要再引用。
