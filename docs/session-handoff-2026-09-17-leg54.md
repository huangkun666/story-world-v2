## 0. 一句话

「世界尺度 · 可调上限」那四个框：**`<select>`（只能点 3/6/9 那几档）⇒ `<input type="number">`（键盘直接填、没有上限）**。
只留四条"能让代码跑起来"的最小校验：**≥1 的整数**；空 = 未定（回出厂默认）。★顺带修掉一个**真的显示 bug**。

## 1. ★★ 我改口的那一段（**这条最该带走：我差点用错数把用户劝住**）

**我自己先说了错话**，用户一句追问把我拉回来了：他说「**无上限其实就是模型自由发挥**」。
我去核数字，**他是对的**：

| 我一开始的说法 | 核完之后 |
|---|---|
| 「单轮输出预算 **4096**，一条事件 120–200 字符 ⇒ 上限 12 已经不小了」 | ★**预算实值 16384**（第十九棒拍板 `4096→16384`，`transport-http.js` 的 E3 记档，`test/transport-http.test.js` 锁着） |
| ⇒ 据此劝他"别放开上限" | ⇒ 16384 token 够写**几十条**事件 ⇒ **那个 12 从来没咬到过模型，它只是一张纸** |

**★★我为什么会说错**：我**只看了设置页那一行**——它印着「单轮演算上限（提案：120 秒 / **4096 字**）」，而**实值是 16384**
（那行从 E3 之后就没跟着改，**过期了好几棒**）。⇒ **教训：UI 上的数字也是要核的**，它和代码一样会过期；
本仓"一个数两把尺子"的老病，这次是以**文档/UI 过期**的形状出现的。

**其余三条佐证**（都在本仓既有台账里）：
- leg40b 实测：**59 轮真账逐轮新事件 max 4**，引擎闸**一次没咬到**；
- "请求 6 ⇒ 真推 6.00 / 请求 12 ⇒ 真推 12.00"——**都推满了**（不是"写不动"，是"要多少给多少"）；
- ⇒ **上限的真实边界是"模型一次能写多长"，不是我们的白名单。** 撤掉白名单＝**把边界还回它本来该在的地方**。

⇒ **定稿：真无上限**（用户原意），并**在页上如实写明后果**（见 §3）。

## 2. 改了什么（逐处）

| 文件 | 改动 |
|---|---|
| `src/limits.js` | `normalizeLimit`：**白名单撤掉** ⇒ 认**任意 ≥1 的整数**；空/缺值 ⇒ `null`（未定，回默认）；非数字/小数/0/负数 ⇒ 弃键。**键白名单仍在**（`limitKey('天时')` 仍返 `null`，两张表不许互相吃） |
| `src/render.js` | 那四个框 `<select>` → **`<input type="number" min="1" step="1">`**；框后加「**常用：3 / 6 / 9**」（`LIMIT_GEARS` **从白名单降级为建议值**）；折叠说明里写明**"没有上限"+ 那个不直观的后果**；★**设置页那行预算改成从 `PROPOSED_CALL_LIMITS` 现读** |
| `web/style.css` | 新增 `.sw2-param-input` 一族（**定宽 72px / 右对齐 / 去掉 number 框的上下箭头**——一屏四个框，箭头既占地方又容易被滚轮误触） |
| `web/index.js` | ★★**两处接线补 `<input>`**（见 §4）；`CSS_VERSION` → `20260917-leg54-unlimited-limits` |
| 测试 | `limits.test.js` 归一口径升级；`render.test.js` 的"四个可调档位"锁改成"四个可调输入框"+ 新增"无上限必须写在脸上"；`param-hub`/`param-store` 里拿 `'7'`/`'99'`/`'999'` 当"非法值"的四处按新口径换掉 |

★**`LIMIT_GEARS` 没删**（降级为建议值），三个理由：①面板要在框下面提示"常用"（玩家不知道该填几）；
②`LIMIT_DEFAULTS` 必须与它自洽（判据锁着）；③**旧账里那些值（3/6/12/15/20/30/40）照旧读得出来**（都是合法整数）。

## 3. ★★ 无上限的后果必须写在页上（否则是一个静默的失败）

「填大了不会凭空多出事情」这件事**不直观**，不说清玩家会以为"填 100 却只长了 3 件"＝插件坏了。
⇒ 折叠说明里加了这一句（**逐字**）：

> ☆ 填得很大**不会凭空多出事情**：一轮里到底发生几件，是模型自己决定的（它一次回复能写多长就是那个真天花板）。
> 超出它一次能写的量时，你不会看到"被拦"，只会看到**这一轮没长出新事**——要查就翻观棋窗口底部的「⚖ 本轮裁定」。

★这条不是"限制"，是**如实告知**：被拒的世界**原样不动**（leg40b 的死锁自愈保证 tick 照常前进），
所以它不会以"报错"的形式出现——**不告诉玩家去哪看，就等于让他自己去猜**。

## 4. ★★ 换控件类型时踩到的两处接线（**都是"漏一条路"的形状**）

控件从 `<select>` 换成 `<input>` 之后，**采集 / 对齐 / 写格**是**三条独立的代码路**，
而它们当初都只认 `SELECT`（或 `SELECT`+`BUTTON`）。★**漏任何一条的后果都是同一个形状**：
**"我填了它自己跳回去"**（leg48 治过的那条症状）。

| 路 | 函数 | 本棒实测 |
|---|---|---|
| ① 采集（`paramEnv` 的来源） | `sw2CollectLiveParamValues` | ★**真的漏了**（只判 `SELECT`/`BUTTON`）⇒ 已补 `INPUT` 分支 |
| ② 对齐（一笔操作后把控件退回真源值） | `sw2SetParamControl` | ★**漏了**（`tagName !== 'SELECT'` 就 `return false` = 静默退让）⇒ 改成同时认 `SELECT`/`INPUT` |
| ③ 写格（控件值 → 那一格的字） | `sw2ControlText` | **当初就写对了**（早就同时认）——这一条只是加锁防它被改窄 |

★**①那条是本棒最值钱的一处**：它不是"读代码看出来的"，是**我写判据的思路逼出来的**
（"换控件之后，哪几条路会认不出它？"）⇒ 新判据 `leg54：接线三条路都得认它`。
★**为什么它特别容易漏**：`web/index.js` 里这三条路**相距几百行**、各写各的分支，
没有任何东西提示"它们必须一起改"（本仓"同一件事三处实现"的老病，换了个形状）。

## 5. 判据

**790/790**（新增 3 条：`limits` 归一口径 + `render` 无上限写脸上 + `param-hub` 三条接线；**8 条旧锁按新口径升位**）。

★**旧锁升位的类型**（照 leg39 立的规矩"口径变了就升级锁"）：
- 拿 **`'7'` / `'99'` / `'999'` 当"非法值"**的四处 ⇒ 换成真正非法的（`'0'`/`'-5'`/`'2.5'`/`'abc'`），
  并**各加一条对照**（"★大数现在是合法的"）——防那条锁退化成"什么都不认"；
- "四个可调**档位**（下拉 + 选项逐项等于白名单）" ⇒ "四个可调**输入框**（`min=1`/`step=1`/值=真源）"。
  ★**旧口径里"面板不许造出引擎不认的值"这一条随白名单一起作废**（引擎现在什么都认），
  取而代之的新守门是"**是数字输入框且带 `min=1`**"（读不懂的值仍然进不去）。

★**判据当场抓出我自己的三个错**（留档）：
① 取控件值第一版写成"向前找最近的 `<`" ⇒ 取到了 `<select>` **里面** `<option>` 的 value（假红）；
② 只认标签上的 `value=` ⇒ **`<select>` 标签上根本没有 value**（选中项在 `<option … selected>` 里）⇒ 天时读到 undefined；
③ 写测试时把 `'7'` 从"非法"名单里搬走，却**忘了同一文件里另有一处**也拿它当非法（判据自己红了）。
⇒ 三条都是"**同一件事在不同地方各写一遍**"的形状——与本棒 §4 是同一个病。

**冒烟终态 8231 字节逐字节未变** · **真浏览器六档宽度（360–1280）横向溢出 0**（收起与全展开都是 0）。

## 6. ★ 留给下一任的

1. ★★**"填得很大"到底会发生什么，本棒没实测**（只核了预算这个数）。真要给结论，得真跑：

   ⇒ 那是**出数**的活（花几次调用），本仓铁律 8：**先有数后说话**。★别凭预算推算当实测。
2. **`每轮递线` 的"请求"与提示词条数是否还同步**：`prompts.js` 第 14 条那句"最多只有三条"的矛盾
   （`limits.js` 头部登记的旧债）——**本棒没碰**。用户真源里是 9，这条债是活的。
3. `民生度` 的键仍留在账本键表（leg53 有意）；抽书提示词里还在问它——**要报批**。
4. ★**凡是"面板上印出来的数字"，都要问一句"它是现算的还是写死的"**——本棒的 4096 就是这么来的
   （已修成现读 `PROPOSED_CALL_LIMITS`）。同一类隐患还可能在别处；要查就 grep 面板里的字面数字。
5. **`0` 与"空"在数字输入框上的语义**：现在是「空 = 未定（回出厂默认）」「`0`/负数 = 弃键，不当一次改动」。
