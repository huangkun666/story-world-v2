| | |

## 4. ★★★如实登记：**判据全绿 ≠ 机制生效**——真模型 60 轮当场抓出本笔的 bug

★★**这一节是本笔最该带走的东西，比改动本身要紧。**

**病**：本笔第一版把"窗口"实现成了**裁剪偏好**——只让 `trimPack` 的额度守卫"优先保窗口内那一段"。
**而那条守卫只在 `pack.纪事 === undefined` 时才跑**（它管的是"整栏被固定序丢掉之后装回多少"），
而出包侧**早已把整栏挂上了** ⇒ 那条分支**一次都没进** ⇒ **窗口等于没写**。

**为什么判据没抓到**：我写的 W1 只验了"**窗口内那一段没丢**"——而旧行为（全量）**当然也没丢**，
所以那条判据在**坏的实现上照样全绿**。★**判据验的是"我没弄丢"，没验"我少给了"**。

**怎么抓到的**：真模型 60 轮跑完，`summary.json` 里那一栏是 **684 行**，而窗口只有 50 轮
（按该世界约 13 行/轮 ⇒ 应约 540–615 行）⇒ 数对不上，回头读代码才发现那条分支进不去。

**修**：窗口**在装载那一步就切**（`buildEvolutionPack` 里 `briefAll.filter(tick >= windowFloor)`）——
**窗口是"这一栏的装载范围"，不是"裁剪时的偏好"**。
**并补判据 W7**：预算宽裕到**根本不会裁**时，那一栏**仍然只有窗口内那一段**
（★这条判据在坏的实现上**当场红**：它验的正是"我少给了"）。

**修完实测**（拿同一次真跑存下来的世界复现）：
`纪事` **615 行 · 全部在窗口内 · 窗口外混进来 0 行** · 包 **21286 est（71%）**（修前 22505 / 75%）。
★然后又**整跑了一趟 60 轮**（`F:/deepseek/tmp/leg133-real60b`）确认修好的版本端到端没问题：
**60/60 成功 · 报废 0% · 白花 0% · 连卡 0 轮**。

★★**同时如实登记一条"这条保证没买到的东西"**：**窗口没有让包变小**。
那个世界**一轮长约 13 行编年** ⇒ "最近 50 轮"本身就有 **615 行**（≈71% 的包）
⇒ 包 est 峰 **20397（改前）→ 22303（改后）**、占比峰 **68% → 74%**。
⇒ **窗口买到的是"最近 50 轮一定在"这条保证，不是省预算**——要省预算只有两条路：
**把 N 调小**（旋钮就在面板上），或者做那层**至今没有的压缩**（§5③）。
