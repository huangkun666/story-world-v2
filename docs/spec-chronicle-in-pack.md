## 1. 病：世界模型每轮失忆

### 1.1 用一句人话讲这个病

这个插件里有两个模型在干活：

- **世界模型**：世界本身。它每轮提议"接下来发生什么"，引擎再把它的提议结算成账。
- **聊天模型**：写正文的那支笔。

**世界模型每轮收到的"世界状态"摘要（下面叫「包」）里，没有它自己的过去。** 它知道"有哪些事还没结束"，但**不知道"以前发生过什么"**——连它自己前几轮亲手写出来的事都不记得。

后果：世界接不上自己。它会把一条线忘了、或者把早就收场的事又拎出来当新的写。

### 1.2 用户的原话（这条口径是用户早就立过的）

> 「**为什么聊天 llm 能够直接获取想要的世界书内容呢还能通过向量化搜索直接在插件里搜到呢都是一轮解决的啊，也没有产生额外的文件**」
> —— 2026-09-13，`docs/ledger.md` 第三十四棒（leg34）

leg34 照这句办了：把"模型点名要"**撤掉**，改成 `src/recall.js` 的**出包前检索注入**（**当轮可见**、零额外调用、零跨轮状态）。

⇒ **"当轮就拿到"是用户已拍的口径**，不是新要求。本笔照这条办。

## 3. 设计

### 3.1 口径：收哪些、弃哪些

**收**（`keep`）：
1. **来路话**——`沿「X」而来` / `由盘算「X」而生` / `由世界处境而生`（编年独有，救回断掉的因果链）；
2. **经过话**——`盘算「X」推进：…`（编年独有：这是模型自己上轮写的"这一步到底干了什么、代价是什么"，**账上别处都没有**）；
3. **收场得失话**——`盘算「X」取消/结清（谁）：理由…`（见 §3.2，**不许当记账行弃掉**）。

**弃**（纯记账，语义为零）：满步结算 · 涟漪平息 · 闭环 · 入局离场。

### 3.2 ★关键约束（这一条漏了就是半死的闸）

`pack.js:872` 记着一条既有事实：

> 「⚠**不报结局**——账上没有结局字段：`settle.js` 把"结清/变形/取消"写进了**编年文本**，盘算上不存。」

⇒ **收场理由只活在编年文本里，没有结构字段。** 所以过滤时必须**只弃"格式化的机械记账行"，保留"带理由的收场话"**——否则本笔会把这个信息在包里彻底抹掉（比现在更坏）。

判据里必须有这一条（见 §5）。

### 3.3 ★★口径上的一个大决定（**待用户确认，本细案取"单一来源：编年"**）

同一个键（比如 `纪事`）里放什么，有两条路：

| | 做法 | 代价 |
|---|---|---|
| **路一（本细案取这条）** | **只搬编年**（过滤后 249 行） | 编年是**人话叙述**，来路/经过/得失三种话都在里面，**一个来源、不会自相矛盾** |
| 路二 | 编年 + 事件表因果边（结构化的"谁 → 因何而起 → 牵动谁"）**合并** | 同一件事会有**两种写法**（结构化一处、人话一处）⇒ 两份真相，本仓最贵的病 |

**为什么取路一**：用户在本场明确选的是"**只做编年进包**"；且路一单人来源、无一致性风险。
**路二的潜在价值**（模型既能读人话、又能拿到可引用的 id）**留给检索层**（见 `spec-retrieval-layer-interface.md`），不在本笔。

### 3.4 时间窗：★**不设上限**（关键：不新增提案态数字）

**理由**（本仓刚流过血）：`entityUpdates 每轮 ≤3` 就是**一个没量过的提案态数字在生产里当家、还静默拦**——用户 2026-09-22 拍板**直接取消**（leg112）。
⇒ **同一个坑不跳第二次**：本笔**不引入"编年最多 N 行 / 最多 N 轮"这类常数**。

**那长跑怎么办**（用户问过，这里给死答案）：

| 道 | 机制 | 谁在兜 |
|---|---|---|
| ① | **包本身有总预算**（`trimPack`，固定剪枝序 + `trimmed` 痕迹）⇒ 编年**只能吃"别处算完剩下的"** | 已有机制，**不新增** |
| ② | 装不下 ⇒ **从最旧的整条丢**（★**不许拦腰砍**：砍半句"沿「死煞杀局启动」而"比不写更坏，模型会拿半句话说事） | 挂进 `trimPack` 现有那道 stage |
