## 4. ★ 通用解的形状（与题材无关，三条判据）

> 这套判据**不依赖三国、不依赖"战力"这类词**，只依赖"模板壳 + 料库"这个书型。

### 4.1 声明表（零模型、零 JS 执行）
对每条**启用**条目扫正文，剥注释后抓 `getwi(` 的字面量标题 ⇒ `声明表: 标题 → {来自哪些壳, 条件}`。
- **不需要** `eval`、**不需要**跑 EJS ⇒ 是**纯函数、可复现、可判据锁**（本仓一贯的"确定性净化"口径）。
- 条件只认两种模式串：`route === 'X'`（模式）与 `currentYear >= a && < b`（年份段）——
  **其余一律当"无条件"**（宁可多取，不可漏取）。

### 4.2 三档分级（§2）：档 = 壳的触发方式（`constant` / `key` 非空）+ 题名形态。

### 4.3 递送规则
1. **① 必读档**（恒注入壳声明的）**整档进**；
2. **② 档按本回合的 key 命中取**（与 ST 自己的扫描同口径：谁的 key 在上下文里出现就取谁的声明）；
3. **③ 档按"本回合有戏的角色"取**；
4. **模式**（`route`）：能从账/变量读出就只取那一支；读不出 ⇒ **两支都取**
   （正史 4,841 + 演义 12,156 = **16,997 字，仍装得下**）——★本仓 三国真账里
   **MVU 变量 `stat_data` 根本不存在**（272 个 chat 变量里没有 `stat_data`，`剧本方向` 取默认 `'无'`），
   所以"模式判定"这一格**现成可用的信号是没有的**，只能靠"两支都取"或问玩家。

## 5. ★ 与 leg58 失败修法的关系（为什么这次不一样）

| | leg58 的 `pickCanonSource` | leg59b 的"按声明取料" |
|---|---|---|
| 判据来源 | 我们猜"体系条目长什么样"（标题词/字段名/数值区间） | **作者亲笔写的目录**（`getwi` 声明） |
| 真书结果 | 挑出**人物档案**（假阳性） | **精确命中** `演义战力体系`/`智谋内政体系`/`鬼神道德体系` |
| 为什么 | 「分类定义 vs 分类实例」同形，判据分不开 | **不需要分开**——作者已经分好了 |
| 覆盖面 | 只有一本书调参 ⇒ 过拟合 | 只要书里有壳就有目录；**没有壳的书 ⇒ 退回旧口径**（**可探测**：`声明表.size === 0`） |
| 是否要跑 JS | 不跑 | **也不跑**（只做静态字面量扫描） |

★**结论**：leg58 的判据方向（猜形态）**作废**；leg59b 的方向（**读书的自我声明**）**有正样本**。
★但要如实登记一条**新未知**：**不是每本书都有壳**（本书 221 条壳 = 27%）。
没有壳的书（纯文档型世界书）仍要走旧口径 —— 那时"头 30000"至少是正文，反而比本书现状好。
