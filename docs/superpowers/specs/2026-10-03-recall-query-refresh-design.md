# 当前问题的召回与关键词排序

用户于 2026-10-03 在讨论上一棒两项建议后明确说「可以开工吧」。本次只处理查询变化后的旧向量结果，以及关键词排序在预算选择时被新旧顺序覆盖。

## 行为

向量结果只属于获取它时的聊天、人物或群组、世界对象、世界轮次及完整查询文本。发送消息时按现行查询准备结果；查询不同，立即撤掉旧结果。准备中的请求不会阻塞发送，当前没有可用向量时使用名称与关键词检索。结果返回后，只有所属信息仍一致且开关开启才重设注入。相同所属信息的成功或正在进行的请求复用；失败、服务未就绪及被丢弃的已结束请求释放缓存，允许再次准备。迟到结果不能覆盖或清除新请求。空查询、关闭、切聊天及回档仍隔离旧结果。

关键词检索先比较命中的不同词数，同分再比较已有轮次的新旧。名称检索单独使用时仍按新旧排序；聊天合并名称与关键词候选后，使用同一字面匹配排序选取预算内的记录。先收集候选再排序再切预算，不能先截掉更匹配的旧记录。向量保留相似度顺序和已有预算分配。选出的记录仍按时间顺序排成文本。匹配词数只表示字面匹配，不判断故事事实、人物实力或语义重要性。

## 边界

不增加阈值、预算、网络等待、契约字段或模型提示词。保留故事详情、时间展示、世界演化、记忆归档和发布版本的现有行为。业务改动集中在 `src/ledger-recall.js` 和 `web/inject.js`；测试、README、STATE 及生成索引随之同步。新交接放 `F:/deepseek/plugins/story-world-v2/docs/`，本地安装沿用已提交插件子树导出和快进更新。

## 验收

旧记录命中多词、新记录仅命中一词时，检索层及真实聊天注入都优先保留旧记录；同分仍选较新记录。查询切换后，准备期间、失败和旧请求迟到都不注入上一话题的结果。新结果完成后真实注入口收到当前话题的记录。重复发送相同查询不重复请求。无查询、关闭、切聊天、换世界和同对象回档均有回归。全量测试、冒烟、文档守门通过，本地安装跟踪文件与源码逐字节一致。
