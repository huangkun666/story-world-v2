## 1. 人话版：这会怎么样

## 3. 方案选择

| 方案 | 能解决什么 | 代价与缺口 |
| --- | --- | --- |
| 只扩展当前勾选列表 | 能增加角色卡正文和禁用状态展示 | 下游仍分别取料，预览和入账仍可能不一致 |
| 将整个输入作为一大段可编辑文本 | 用户容易直接控制文字 | 原文出处、来源选择和后续补查难以维护，原书变化时容易丢失选择 |
| **推荐：完整来源列表 + 每条全文或原文选段 + 一次生成生效内容** | 同时控制来源与内容，保持出处；所有消费者使用相同规则 | 需调整来源契约及多个调用入口，必须验证完整数据流 |

采用第三种。正文定制以原文选段为基础，允许按阅读顺序组合多个片段；不引入任意改写原书、词表判身份或新的数值阈值。

## 4. 抽象来源页

### 4.1 列出哪些来源

- 当前取书流程成功读取的角色卡内嵌世界书、角色挂载、聊天挂载和全局挂载世界书条目。
- 角色卡描述、场景、性格、开场白，各自作为独立来源。
- 启用、禁用、技术条目、空正文条目全部保留展示。原始正文可查看；清理后的文本在生效预览中查看。
- 来源相同且条目身份相同的重复读取只列一次；不同书中正文相同的条目仍各列一行。正文相同不代表条目身份相同。
- 读取失败的书显示读取失败，未加载的角色卡显示未加载，不与真正空内容混为一谈。

“所有”限定为插件本次实际读取范围，不扫描未挂载的全部世界书，不自动读取群聊其他未选中的角色卡。切换角色或聊天、点击重读时重新收集。

### 4.2 页面结构与操作

沿用设置中的抽象来源子页签。桌面采用条目列表与正文查看两栏；窄屏按列表、展开正文的顺序阅读，主要控件始终可操作。

顶部保留来源模式、搜索、来源分组筛选、全选结果、取消结果、反选结果、重读。批量菜单提供取消禁用、取消技术、取消空正文；按来源整组选择、取消与反选放在相应组头。搜索只控制可见行，所有批量操作只作用于当前筛选范围；隐藏的选择保持原值。批量操作不替用户隐式改酒馆开关。

每行仅显示勾选、题名、必要的来源状态和实际读取字数。点开条目后提供：

- **全文**：读取该条的全部原文。
- **选段**：在只读原文中选中文字，添加到选段；支持多段、删除、按原文顺序排列和恢复全文。选段可单独预览。
- **自动清理**：剔除已有技术区块规则命中的内容；默认采用这一项。用户在自选模式可明确切为原文全文或原文选段。
- 不勾选即排除该条。空正文仍可查看题名和来源，不能伪装成有正文。

默认模式下查看与预览不会改选择；用户首次更改条目或正文读取方式即进入自选。默认状态和自选清空严格区分。

页底提供可展开的**实际读取内容**，展示与抽取调用共用的生成结果、实际生效条目、排除原因和现有上限造成的截取。解释只放在展开区域，常态页面保持简洁。最终提示词中的任务说明仍由抽取器添加，不能把此预览误称为完整 HTTP 请求。

### 4.3 默认与自选的确定规则

| 情况 | 默认来源 | 自选来源 |
| --- | --- | --- |
| 普通启用条目 | 纳入，沿用自动技术清理 | 仅在勾选后纳入，正文按用户选择 |
| 普通禁用条目 | 正文排除 | **明确勾选可纳入**，不修改酒馆开关 |
| 作者明确取用的禁用仓储条目 | 保留既有合法声明读取规则，显示对应依据 | 该仓储条目也必须被勾选；未选的依赖只提示，不自动突破选择 |
| 专用技术条目 | 不作为世界事实正文输入 | 允许查看；明确选择原文后作为文本材料送入，插件永不执行其中代码 |
| 角色卡四项正文 | 沿用既有读取和截取规则 | 和条目一样独立勾选与选段；排除后不另行补回 |
| 自选为空 | 不适用 | 不读取来源正文，保持为空并给出可理解的状态 |
| 新增条目 | 根据默认规则计算 | 默认不勾选 |

“默认沿用”指合法的启用、声明取件和技术清理规则，不包括旧代码让被排除题名或禁用正文从旁路进入的缺口。角色名字等上下文信息按既有身份规则处理，与四项正文分开，不额外编造事实。

## 5. 统一取料与选择保存

### 5.1 原始来源与生效文本分开

来源收集先生成只读清单。每项包含来源身份、条目身份、题名、原文、原禁用状态及读取结果；角色卡四项正文使用独立且稳定的字段身份。条目的搜索键只用于定位，不自动解释为人物、别名或成员。

选择设置继续按聊天保存，只保存选择、读取方式和原文选段的位置与对应原文核对信息。原始世界书和角色卡不写回。默认模式、自选模式及旧配置迁移均采用显式的兼容规则。

同一来源内使用现有条目号；无条目号时沿用题名与键的稳定身份。跨书条目号相同不会互相影响，列表挪动不会改变选择。

旧自选记录迁移时保留其世界书选择；新增的角色卡四项正文依照旧配置的实际读取结果初始化，以维持已保存配置的语义，并在界面列出来供用户继续取消或裁选。迁移一次后，新条目遵守不自动勾选规则。缺失条目保留选择记录，禁止回退成全选。

若选段对应的原文发生变化，完整核对失效的选段不自动挪到另一段，也不自动改成全文；显示需要重新选择，相关内容暂不生效。全文模式直接使用本次读到的原文。

### 5.2 只生成一次生效结果

纯函数根据原始来源清单、选择、技术清理方式和现有输入边界，生成本次生效条目、正文、题名候选和诊断明细。预览与实际调用均使用这个结果，不复制一套 UI 专用计算。

初始化抽取、题名声明、种账补缺、实体查书、位置继承、起根、重抽、输入指纹及缓存核对，都通过此入口取得允许内容。选段之外的原文不参与模型、出处校验或兜底。

一次抽取开始时固定本次结果；请求进行中修改选择仅作用于下一次请求，不把新旧条目混在一个结果中。切换聊天、角色或书源时废弃过期的读取结果，沿用现有异步防护。文本变化参与输入指纹；被排除内容的无关变化不使模型缓存失效。

生效条目写明已完成内容选择和清理，下游不能再次套用旧禁用判断或自动清理来改变用户指定的正文。默认声明取件与自选依赖排除的差异也在这一入口解决。

## 6. 模型识别、校验与入账

### 6.1 分工

模型识别人、势力、地点、同一实体的别名、属性和归属。输出附相应来源条目及原文依据；沿用现有调用，不增加每条单独询问的固定调用轮数。

程序核对来源是否属于本次生效材料、引用是否能对应到指定原文、格式是否合法、引用的实体是否能解析。原文存在仅能证明引用真实，不能保证模型对原文的解释正确；有歧义的判断仍需复核，不宣称字符串检查可以证明全部语义。

原文依据与处理记录进入现有抽取诊断，受已有详细调试开关和脱敏规则约束。保持此前用户对世界关系账本的规定，不在关系边上新增常驻出处章。实体已有的来源字段继续遵守当前契约。

### 6.2 删除会替代语义判断的路径

- 成员行正则和关键词命中只用于定位相关原文，不直接新增关系、不删除模型关系。
- 不完整名单中未列出的角色，不能据此判定不属于该势力。发生明确矛盾时保留诊断并复核相关原文，不能静默选择先到的值。
- 名字包含仅用作搜索候选，不单凭两个名字互相包含就建立势力上下级。
- 搜索键、题名片段只作为候选与定位信息；没有模型确认或合法作者明确声明的类别，不默认将其种为角色或势力。
- 别名合并要求同一实体判断和对应依据；共享关键词、相似名和不同类别的同名项不能自动合并为一个实体。
- 势力规模保留原文，不根据“十人”等描述发明成员，不把规模当作实际已入账人数。

### 6.3 确认哪些结果最终保存

保留原始模型结果与清理、合并、入账各步的诊断对照。实体类别、别名、属性、归属及未入账候选具有明确去向；每次拒收或合并都可追到具体原因。

类别未确认的题名候选使用现有抽取调用一并确认；仍未确认则保留为待核对候选，不猜类别，不悄悄消失。不同名字的同一实体在名册到实体账的转换中保留全部已确认叫法，相关搜索与实体解析使用相同的身份信息。

程序仍负责实体编号、合法引用和幂等写账，模型不能直接改世界账。既有世界的演化结果与快照不自动重建；用户主动重新抽取或补查时应用新规则，并沿用既有不复活、不重复建实体的约束。

## 8. 验收

必须先建立能捕获现有错误的回归，再修改生产逻辑；既有规则需要改变时保留修改前的数据和失败证据，不通过放宽测试掩盖缺口。

- 完整列表包括禁用、技术、空内容、跨来源重复正文及角色卡四项正文；未挂载书不混入列表，取书失败明确显示。
- 自选的禁用全文确实进入模型原文；未选条目和选段外内容不进入题名补名、种账、补资料或起根。
- 原书和角色卡字节不变；选段来源变化后不误读别的文字；切换聊天不串选择。
- UI 实际读取预览与生产抽取使用的原文一致；模式清空、新增条目、搜索批量操作与旧设置迁移正确。
- 固定正确模型输出，增加性格等普通字段或改变成员名单的部分列举，不改变正确归属。
- 同一事实分别以叙述、列表、表格和包裹题名出现，都能经过生产抽取、清理、入账；题材无关字段不被当成成员。
- 候选缺类别会明确显示待核对；明确类别者最终入账；姓名与别名均能解析到正确实体；不同身份的同名项不被强行合并。
- 明确无出处或不允许来源的字段不能进入世界事实；引用真实但语义存疑时有复核记录。
- 用多本不同格式世界书检查实际取料范围。离线固定响应验证程序保存链，真实模型验证另行报告；没有真实模型证据时不宣称模型识别质量已经验收。
- 浏览器验证桌面和手机的列表、选段、预览、键盘操作以及页面重开后的选择恢复。
- 按 `STATE.md` §2 执行全量判据、冒烟、知识索引和文档守门；本机预览独立运行并核对跟踪文件。

真实模型复验不在本次自动执行范围，保持此前调用规则；实施的离线验证不需要密钥。新交接按 `AGENTS.md` 写入 F 盘指定目录。

## 9. 需要拍板的行为

建议一次批准以下相互关联的行为，再进入实施：

1. 自选明确勾选可覆盖酒馆禁用状态，原开关不变；未选的声明取件依赖不得自动补入。
2. 正文定制使用原文全文、自动清理和多个原文选段；角色卡四项正文也可独立排除，技术原文只作为文本材料读取。
3. 来源控制与抽取入账一起调整：移除形态和名单缺席裁关系的路径，类别待确认不冒充人物，别名完整保存。

没有新增数值阈值或数量上限。本文完成后由主 agent 自查范围、矛盾和遗漏；用户批准具体设计后，再编写逐步实施计划。
