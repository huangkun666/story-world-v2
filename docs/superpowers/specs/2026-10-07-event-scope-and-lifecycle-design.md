# 事件类别、影响范围、重要传播与持续条件设计

日期：2026-10-07（Asia/Shanghai）。状态：用户以「可以，开工吧，之后安装在本地我测试下质量」授权实施。较轻方案已实现：保留事件范围、重要传播后果与持续条件，不维护独立知情账或逐笔接收记录。当前实现与现场读数见 `STATE.md` §1，实施交接为 `docs/session-handoff-2026-10-07-leg203-event-scope.md`。项目根：`F:/deepseek/plugins/story-world-v2`。

## 1. 人话版：这会怎么样

## 2. 已查到的结构问题

以下证据来自当前源码和内存中的合成输入，没有修改用户的聊天、世界账或世界书。

| 路径 | 当前行为 | 影响 |
|---|---|---|
| `src/tag-extract.js` 的 v3 事件读取 | 参与者必须非空；未知名称保留为 `participantNames` | 无明确人物的环境结果难以表达；“全体学生”不会成为成员集合 |
| `src/settle.js` 的 `registerDialogueFacts` | 已解析参与者直接写入 `ripples` | 直接当事人与受影响者混在一起 |
| `src/gate.js` 的点名判断 | 未决事件、当轮聊天结果的 `ripples` 参与解除人物静默 | 标签名单会影响人物的行动资格，不只是展示 |
| `src/check-step.js` 与聊天登记 | 世界侧限制具体波及名单，聊天侧不采用相同限制 | 把群体展开为长名单会遇到两侧处理差异 |
| `src/tag-extract.js` 与 `src/settle.js` 的时间处理 | 消息只保留首个 `facts.at`，所有聊天结果沿用它 | 同一消息中不同场景、不同时间的结果会被盖成同一时刻 |
| `web/message-consumption.js` | 同一消息版本只消费一次，不比较跨消息事实是否同一件事 | 不同消息重复提交同一公告会再次建事件 |
| `src/pack.js` 与归档路径 | 已完成事件按历史窗口、相关性与预算提供 | 不能把仍有效的制度只寄存在已完成事件标题中 |

内存复现确认：只填“全体学生”可以登记结果，但具体受影响者为空；省略参与者会被拒；只列一个学生时，另一个没有在办事项且未被点名的学生不会因此获得反应资格。另用两个时间点复现了后一个结果仍登记为第一个时刻。超过世界侧现行名单上限的样例被拒，而相同人数的聊天结果可以登记。不同消息重复提交同一公告会生成不同事件 ID。

这些证据说明结构边界，不等于已经证明用户真账发生了全部问题，也不以合成样例宣称模型语义质量已经验收。

## 3. 方案选择

| 方案 | 能得到什么 | 限制 |
|---|---|---|
| 仅增加类别与提示词说明 | 模型更容易写出“公示”“约定”等标题与范围文字 | 程序仍混用名单，持续条件仍依赖历史召回 |
| **采用：统一结果事件，独立保存范围与持续条件，重要传播作为普通结果事件** | 聊天与世界用同一含义记账；群体事实不依赖长名单；模型可以创作合理获知途径与反应 | 信息边界主要由模型按事实保持，不能提供逐人知情的硬保证 |
| 逐笔传播与逐人知情维护 | 可追踪接收、版本、修订与相关人物的信息依据 | 保存本身较便宜，但历史一致性、模型输入与语义验证成本高；本阶段不采用 |

类别用于描述和筛选，可以提示模型检查相应信息；类别不替代范围，不通过关键词决定成员、真假、完成状态或传播速度。

## 4. 一件事件应分别回答什么

| 信息 | 新事件字段 | 含义 |
|---|---|---|
| 事实结果 | `title` | 已发生的事实或已确立的义务；不把发言内容默认当成客观真相 |
| 类别 | `category`，可省的原文短文本 | 例如公示、交付、约定、冲突、环境变化；不设世界专用类别词表 |
| 直接当事人 | `actors`，可省 | 谁发布、执行、接受或承担义务；可以没有明确人物 |
| 实际影响或适用范围 | `affected`，可省 | 谁的现实条件受到改变，或明确适用哪些对象 |
| 信息公开或传递范围 | `audience`，可省 | 消息面向谁公开、定向发送给谁；不等于全部已经获知 |
| 时间、地点与完成状态 | `timeMark`、`position`、`closed` | 每件结果的发生时间、地点与事项是否完成；完成不表示后果消失 |
| 来路 | 既有 `source` 与 `links` | 保留生产来源、主线归属与已有因果；类别不覆盖这些字段 |

`actors` 中每个对象保留原名，有在册实体则同时保存其实体引用。不得为了满足当事人字段创建“校方”“全体学生”等虚构实体。`affected`、`audience` 使用下一节的范围结构；字段缺席表示未声明，不得解释为“无人受影响”或“无人知道”。明确空集合只有正文或结果确实声明空集合时才写。人物获知的途径体现在本轮行动缘由或重要传播结果中，不新增事件知情名单、传播记录数组或逐人知识表。

发布错误公告时，结果应写“某方发布了某说法”，不能写成说法中的灾害、死亡或胜负已经成立。可以保留说法正文作为可省的 `reportedContent`，不新增真假分数，不恢复原文匹配拒收规则。

## 5. 范围怎么保存与核对

范围使用描述对象数组。每项必须保留非空 `text` 原话；`kind` 只描述引用的结构，不用于判故事含义：

| `kind` | 内容 | 程序能够核对什么 |
|---|---|---|
| `entity` | 一个明确对象；能解析时保存 `ref` | 引用是否在册；未知原名继续保留 |
| `members` | 明确在册组织或分支的成员，保存 `ref` | 使用已有成员关系的同一实现；不按姓名或职位猜成员 |
| `place` | 明确地区或地点；能对上地点表时保存其名 | 保存地理范围；不把当前在场者当成历史上全部受影响者 |
| `text` | “全体学生”“往返边境的商旅”等尚不能完整核对的范围 | 保留完整原话，说明尚未完整识别，不伪造成员名单 |

几个范围并列时保存为并列项；限定条件、交集或排除项只有能用账上明确结构核对时才展开，否则整段保留为 `text`。例如学校成员可能包括教师，不能把“全体学生”直接换成学校所有成员；有明确的学生组织或年级分支，才可引用相应成员关系。

范围描述对象使用 `{ kind, text, ref? }`。`ref` 仅用于可核对的在册对象或组织；地点以 `text` 对应已有地点名。程序确实核对过的已知对象可以附加引擎独占的 `resolution: { knownIds, asOfTick }`，作为当时名册中确认部分的记录。`knownIds` 不由模型填写，也不代表已经覆盖现实中的全部成员；没有核对结果就省略 `resolution`，不能用空数组冒充已经确认无人。

必须区分历史事件与现行条件：

- 历史事件保留发生时确认的范围、关系版本和具体命中者。后来迁入、调班或加入组织的人，不补进当初的参与者或范围核对结果。
- 已经声明持续有效的条件，按该条件的适用范围核对当前明确的成员关系。新成员可能适用规则，但不据此算成早先公告的参与者。
- 地点范围不等于事件发生地点；在体育馆公布的规则，可以适用于全校，也可以仅适用于某个年级。
- 成员关系资料不足时，识别到的成员只是已确认部分。诊断保留原文范围、匹配依据和未覆盖部分，不宣称已经覆盖全体。

引擎可以缓存派生的已确认对象以供候选选择，但缓存不是事实真源，不能替代范围原文，也不能把当前名单反写成历史事实。

### 5.1 获知途径与重要传播结果

必须区分事件的现实影响与事件消息的传播。道路封闭会影响尚不知道封路的旅客；旅客后来看到封路告示而改道，可以作为本轮行动缘由。角色听到错误说法，不等于说法已经成为客观事实。

本阶段不维护每个人知道什么，也不记录所有查看、听取和转述。模型可以依据世界事实和人物处境，创作“某人通过某种途径获知消息，因此做出行动”；已在剧情中确立的渠道应保持连续性，也可以在本轮实际写出新的合理渠道。获知不要求此前已有一条专门的知情记录。

| 情况 | 使用现有哪种记录 |
|---|---|
| 日常查阅公开规则，随即安排自己的行动 | 在 `actions[].note` 或相应盘算提议说明中写获知途径与缘由；无独立新影响时不另建事件 |
| 密信被截、消息传到敌方、谣言改变局势 | 作为普通结果事件，记录新事实、实际当事人或影响范围，因果指向原事件 |
| 重提或普通转发，没有改变后续条件 | 引用已有事实，不重复建原公告，也不生成接收流水账 |
| 公开内容被修订或被辟谣 | 新结果写明修订或纠正；有持续条件变化则沿原条件处理，不维护每人的版本矩阵 |
| 私密事实引起外人的行动 | 模型应说明可成立的获知途径；全局模型读到秘密不能直接写成所有人都知道 |

重要与否沿共同事件定义判断：是否改变后续局面，不能仅因“有人看过”就成为事件，也不通过词表裁定。引擎核对在册身份、已知引用、因果与事务；故事中的获知合理性由模型判断，不凭空计算传播概率或时延。

缺少获知记录不能当成确定不知道，模型也不能仅因事实面向全校公开，就替全部学生写出看过、理解或服从的行为。公开和私密背景作为输入依据提供，不作为逐人知识状态的硬裁判。这一取舍不提供严格的信息隔离保证；验收分别检查结构行为和模型在固定情景中的信息边界表现。

## 6. 持续条件与未决义务

结果事件记录“发生了一件事”；持续条件记录“此后仍应遵守或成立的条件”。例如公告已经发布，但规则下周才生效；规定已经生效，但公告事件可以完成和归档。

新增世界账的可省 `conditions` 数组，每项包含：引擎发出的 `id`、原因 `eventRef`、非空 `statement`、可省的 `scope`、明确声明的 `state`，以及可省的 `effectiveFrom`、`effectiveUntil`、`supersedes`、`endCause`。`state` 的结构值为 `planned`、`active`、`ended`，分别表示尚未生效、仍有效、已结束。

明确的状态变化另在条件自身的 `changes` 中追加 `{ state, eventRef, tick }`，保留每次变化的因。`eventRef` 仍指最初确立条件的事件，`endCause` 只在明确结束时指向结束原因；不能用状态变更覆盖原始出处。`changes` 是随该条件保存的依据，不另建一份全局待办清单。

条件仅在模型明确声明时登记，不因事件标题包含“公告”“规定”就自动创建。一个事件可以确立多项条件；条件内容和适用范围不同，就分别保存，不强迫一件公告只有一条规则。

日期、期限、例外均照原话保留，程序不推算故事日历。模型依据本轮已发生事实提议生效或终止，必须提供账上存在的原因事件。修改内容或适用范围时，新建替代条件并引用旧条件；旧内容保留，旧条件的状态变化留原因。不能覆写过去的条文，也不能只凭标题相似自动合并。

未决事件仍只表示明确尚未完成的义务或事项。持续有效的制度不因此成为一个永远未决的事件；“公告已发布”“承诺仍待履行”“制度继续有效”分别表达。

仍有效或已明确声明尚未生效的条件进入世界输入中的 `conditions`。已经结束的条件留在保存与历史中，按相关性取回。有效条件不随着原因事件归档而消失；同一原因事件的正文仍遵守现有只递一次的规则。

## 7. 聊天标签提案与旧版兼容

新标签采用 `【协议】4`，作为待审阅的协议升级。保留 `tags` 围栏、一行一标签、行动保护与既有变化字段纪律。

新版 `【事件】` 改成三格：本消息编号、事实摘要、已完成或未决。可选第四格为已有因果事件 ID。参与者不再是事件的必填格，信息通过关联标签提供：

````text
```tags
【协议】4
【此刻】2016年-04月-06日-星期三-08:15
【场景：主体育馆】
【事件】E1｜学校向全体学生公开OAA应用与评级规则｜已完成
【类别】E1｜公示
【影响范围】E1｜原文｜全体学生
【公开范围】E1｜原文｜全体学生
【行动】黄坤｜查阅OAA应用
```
````

示例没有凭空声明发布人的身份，也没有凭空列出制度具体条文或其他学生的反应。查阅应用作为当轮行动，不另外登记知情状态。

关联标签形状：

- `【类别】事件编号｜类别原话`。
- `【当事人】事件编号｜对象名`，多对象用顿号分隔。未知名字照存，缺少当事人可以整行省略。
- `【影响范围】事件编号｜对象/成员/地点/原文｜范围内容`。
- `【公开范围】事件编号｜对象/成员/地点/原文｜范围内容`。
- 多项范围或多组当事人可以重复关联行，按本消息事件编号合并结构，不另建事件。
- `【引用】已有事件ID` 只引用既有事实，不发新事件、不改旧账。传播确实改变后续局面时，用普通 `【事件】` 写新结果并把旧事件作为原因。
- `【持续条件】本消息条件编号｜原因事件编号｜条件正文｜尚未生效/有效/已结束`。
- `【条件范围】本消息条件编号｜对象/成员/地点/原文｜范围内容`。
- `【条件时间】本消息条件编号｜开始时间原话｜结束时间原话`；知道哪格填哪格，未知格保留空位，整行也可省略。
- `【条件变更】已有条件ID｜有效/已结束｜原因事件编号`。替代内容用新的持续条件行，另以 `【替代条件】本消息条件编号｜已有条件ID` 标明替代关系。

声明顺序不影响编号关联；时间与场景按结果前面最近的对应标签继承。后面的时间不回填前面的结果。范围关联行不改变其他事件的时间或场景。

既有 v3 与真正的旧协议继续读取；旧参与者名单保留其旧含义，标记为旧版混合名单，不追认成明确当事人或公开对象。旧事件不迁移、不删除、不按标题补范围。含新版专用标签但协议缺失、无效或冲突时，新版内容留拒绝诊断，不能按旧格数解释或拼进状态值。

## 8. 世界侧、后续反应与预算

世界侧 JSON 新增可省的顶层 `eventProtocol`。声明为新协议时，`newEvents` 使用与聊天相同的类别、当事人、影响范围、公开范围和明确 `pending` 状态；落账时转换为现有 `closed`。出现新版专用字段但没有有效协议声明时，留结构诊断，不静默降为旧含义。原七组和既有因果字段保留；不含新声明和新字段的旧输出仍走旧入口。

新协议的 `eventProtocol` 值对应聊天协议；新事件的 `pending` 必填。`actors` 的对象形状为 `{ name, ref? }`，范围数组的项按 §5；`affected` 与 `audience` 的结构相同、含义不同。`actors`、范围和类别可以缺席，不能为满足格式而补值。原有 `ripples` 留在旧协议入口，新协议不接受同时用 `ripples` 重复声明新范围；新旧含义不得在同一事件中混合。

新增可省的 `conditionUpdates` 组，分别声明创建条件或变更已有条件状态。创建必须绑定有效事件，状态变更必须绑定存在的条件与有效事件。同轮事件按既有临时引用核对机制解析；条件 ID 由引擎发号，模型不自造持久 ID。聊天标签与世界 JSON 经各自适配后进入同一个事件及条件登记模块。

创建项形状为 `{ op: "create", localId, eventRef, statement, state, scope?, effectiveFrom?, effectiveUntil?, supersedes? }`；`localId` 只在本次提议中使用，`supersedes` 只能指账上已有条件。状态变更项为 `{ op: "state", conditionRef, state, eventRef }`，只能将已存在的条件按明确事实转为 `active` 或 `ended`。已经结束的条件不能重新激活；后来重新实施要创建有新因的新条件。`conditionUpdates` 也受协议声明约束，坏引用留逐项诊断，不把关联编号拼进正文。

获知途径使用已有行动 `note`、盘算说明或重要传播事件正文。没有独立的信息更新组或知情字段，不要求世界模型先提交一笔接收记录才能写人物的反应。

后续反应遵循：

1. 大范围事实只存一份；具体反应才指向具体对象，沿原事件形成新因果，不复制原公告。
2. 已确认受影响对象与本轮有明确事件依据的具体反应者可以成为候选；公开范围不能直接变成全体都已经行动。
3. 未明确识别的范围继续提供给模型理解，但不以“全体”字符串解除整个名册的行动限制。
4. 获得候选资格只表示可以产生合理反应，不表示必然知情，也不要求每个人当轮行动。物理或制度影响可以存在于本人尚未获知时，反应内容仍由模型依据事实提议。
5. 受影响不等于已经行动，仍使用独立的 `actedIds` 和 `changedFields` 保护当轮事实；不把整个群体加进已行动名单。
6. 对已退场、覆灭对象保持现有规则。群体范围不能自动复活对象，也不能免除既有写回与因果核对。

现行具体反应数量与整包预算不提出新数值。群体范围不展开塞入 `ripples`，不按名单上限截断事实范围。旧 `ripples` 继续服务旧事件和已有通道；新版范围的匹配与直接当事人分开，不能把全部当事人无条件当成消息受众。

世界输入保留结果、范围、相关行动及重要传播的缘由与持续条件，去重以事件 ID 为依据。模型根据本轮人物处境提议合理获知途径与反应；引擎不能以不存在的知情名单为前置门槛。获知后行动仍按事件或盘算的明确引用核对，必要时通过本步已核对的传播结果关联具体反应者，不能只写一句获知缘由却被旧静默门无条件丢掉。这里不新增词表或引用原文匹配裁判。预算不足时先缩减重复描述及历史细节，不将一个群体事实裁成几个代表人物。必要条件与范围仍放不下时明确报告无法完整提供，不发送一份声称完整但缺失适用条件的输入。

## 9. 保存、归档、召回与界面

新增字段进入 `src/schemas/ssot.schema.js` 和 `src/schemas/world-step.schema.js`，热账、里程碑事件行、冷卷、导出导入与快照均保留类别、范围、因果、时间与条件引用。重要传播作为普通事件沿既有归档路径保存；有效条件随世界保存，与事件及消息消费记录同笔提交。不另存每个人的获知历史或消息版本矩阵。

归档、恢复或召回不能只留下标题和几个名字。输入格式化与展示共用事件投影，避免一条路径显示全体、另一条路径解释成少数人。群体名称保持原文，不伪装成已登记角色。

现有事件展示增加有值才显示的类别、适用或影响范围与公开范围；获知缘由沿现有行动或事件描述呈现。沿既有页面呈现，不新增诊断页或成排开关。成员核对结果、未解析范围、保存与预算诊断进入既有复制报告。

继续遵守已批准的聊天来源过滤：聊天自己提交的结果不返回聊天；世界产生的新后果正常返回；需要保持一致的当前状态与持续条件可以提供。持续条件按身份只提供一份，不以保存条件为由复述聊天公告正文。观棋窗口既有全局可见口径不改；模型能够阅读全局事实，不代表剧情中的人物都知情。

## 10. 可验证的验收情景

| 情景 | 必须观察到的行为 |
|---|---|
| 全校公告、部分学生有戏份 | 一个结果保留完整公开范围，不枚举全体，不把未写反应的学生登记为已行动 |
| 全校公开、只对一个年级生效 | 公开范围与适用范围分别保存；其他年级不被误写状态 |
| 私下承诺 | 记录当事人、义务与私密背景；第三方反应由模型说明合理获知途径，不靠知情账硬判 |
| 谣言或虚假公告 | 登记传播或发布说法，不把说法内容直接落成客观事实 |
| 群体灾害、没有人物名册 | 无当事人仍能记录地点范围与事实，不造受灾实体 |
| 已完成公告、未来生效制度 | 公告完成、条件尚未生效；明确生效事实后才变为有效 |
| 有效制度归档与重载 | 原事件归档后条件仍提供；刷新、导出导入及快照恢复不丢范围 |
| 调班、加入组织、迁入地区 | 历史事件不改；当前适用范围只依据明确关系处理新成员 |
| 部分成员资料、带例外的范围 | 原文范围完整保留，匹配结果标为已确认部分，不扩充未知成员 |
| 重提公告、转发公告、修订公告 | 重提只引用；普通转发不另记，改变局面的传播或修订有原事件原因，不按标题相同强行合并 |
| 同条消息跨场景、跨时间 | 每件结果保存其前面最近的时间和场景，互不回填 |
| 群体范围超过具体名单上限 | 事实范围不截短、不拆成重复事件；具体反应仍走现行预算与核对 |
| 公开但没有逐人查阅记录 | 保存公开范围，不要求补齐获知名单，不替所有人编反应 |
| 日常查看或普通转述 | 可作为行动缘由，不创建专用接收记录或复制原公告 |
| 密信截获、泄密或重要传播失败 | 改变后续条件时登记普通结果事件，保留原原因与实际影响 |
| 歪曲说法与辟谣 | 发布说法与客观事实分清，纠正有新结果，不维护逐人的消息版本矩阵 |
| 本轮获知后采取行动 | 模型能说明合理途径，具体反应走合法身份与因果核对，不要求历史知情记录 |
| v3、旧账与新版坏头 | 旧输入保持兼容，新版坏头不降级误写，不猜旧账范围 |
| 失败重试、切聊天、回档与编辑 | 新字段、条件和消费记录同笔保存，既有作用域与迟到结果保护仍有效 |

先用合成夹具验证结构，再使用获准的世界副本作固定输入对照。真实 ST/TT 保存回读与模型质量分别记录实测，不能以单测通过替代。新增泛用性检查覆盖校园、组织公告、地区环境变化及未结构化的世界书；组织、地点或成员关系缺失不能导致整套事件机制不能工作。

## 11. 实施边界与层次

本阶段实施事件及持续条件的统一结构、协议、范围保存、重要传播结果和明确关系核对，贯通世界反应、保存、归档、召回与已有界面。独立知情账、逐笔传播流水、消息版本接收矩阵、渠道网络、传播速度或时延仿真、逐人信念模拟、自动计算故事日历与移动耗时留在范围外。未获授权不访问真实账修改，不调用真实模型，不安装宿主，不推送发布仓。

层次按既有开发流程声明：契约层登记事件及条件结构；引擎层提供统一登记、范围核对和条件变化；编排层接入聊天与世界输入及同笔保存；渲染层呈现明确字段。范围与登记各自保持可独立验证的模块，不继续把功能集中塞入有行数硬锁的 `web/index.js`。

实施依赖顺序：共同契约与范围语义 → 双侧协议适配及登记 → 条件生命周期和反应候选 → 保存归档及输入展示 → 全量验证与获准的本地安装。将实际行为变化对应的面板构建标识同步更新，使玩家能够辨别新预览；当前读数不在本稿复制，统一见 `STATE.md`。

## 12. 细案审阅点

总体方向经成本讨论后明确采用较轻方案：升级新版协议，事件不再强制填写人物；类别为可省原文；影响范围与公开范围分别保存；模型可以创作合理获知途径与行动，重要传播使用普通结果事件，不维护逐人知情；持续条件使用独立账项；未知范围保持原话，只有明确关系参与程序匹配；同消息按每件结果继承时间；重提事实显式引用已有事件。

这些选择经细案审阅后再进入实施计划。当前文件是设计依据，不是生产行为变更或真实世界账迁移授权。
