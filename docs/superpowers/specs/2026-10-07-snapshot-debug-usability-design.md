# 快照选择与调试信息设计

日期：2026-10-07（Asia/Shanghai）。用户本次要求优化快照选择及调试台，本文记录本次实施范围。当前权威读数见 `STATE.md`。

## 人话版：这会怎么样

同一轮保存过多次时，每份快照显示与前一份可用状态相比的具体变化，帮助选择回档位置；当前状态与保存日期明确显示。调试台去掉关窗及重复的通用存储成功提示，补齐错误来源和详情，并在有新记录时更新。

## 已确认的原因

`web/hot-ledger.js` 的两种写回入口均使用“落账”作为快照原因。轮次只有世界演算推进时才改变；查书、补全和保存记录等可能在同轮修改内容。`src/render.js` 的列表只展示原因、轮次、存储形态、大小和截取的 UTC 时分秒，没有内容变化。合成复现中同轮人物位置改变仍只显示“落账”，无法辨别；截图不足以确定用户两份快照的具体差异。

`web/status-bar.js` 将每句状态文字写入诊断，包括关窗。外部未捕获错误只写浏览器控制台；本插件异常的状态记录缺少完整来源。调试台没有订阅记录变化。

## 方案与边界

仅改原因文字不能解释已有快照；按轮删除快照会丢掉同轮有意义的状态。本次采用已有快照内容生成比较说明，保留全部可用回档点，兼容旧记录，不迁移或改写用户快照。

快照清单在读取时用现有 `restoreFrom` 还原每份内容，再与前一份成功还原的记录比较。摘要描述新增或改变的事件、人物、盘算、关系、持续条件与设定，详情展示真实名称和变化。没有更早状态时明确无法比较；无法还原的记录明确不可读取，不提供误导性的可恢复承诺。完整/增量仍作为存储信息显示，不能代表剧情进度。保存时间以浏览器本地日期和时间显示；当前标记沿用已保存的 `current`，不按最新编号推断。

状态显示与诊断记录分开：关窗仍恢复中性状态，但不入调试台。通用 IDB 写入成功消息取消，操作完成、错误及警告继续记录。重复进度刷新不反复占用日志。

现有全局错误分流保留本插件与外部来源的区别；错误信息、来源文件、行列、堆栈写入诊断。资源加载失败另外通过捕获阶段监听。控制台只补采警告和错误，保留原方法及参数调用，不接管普通日志；采集可卸载、重复安装不重复包裹，诊断自身输出不递归采集。报告仍使用现有脱敏，完整模型文本不会因增加正常日志监听自动采集。

诊断记录器提供订阅；调试台收到更新后刷新日志与摘要，保留筛选控件和焦点。容量及快照保留策略沿用现有设置，不引入新的数量阈值。

## 验证

先以同轮不同状态、旧增量记录、断链、恢复后当前标记为快照用例；以关窗无日志、外部错误不写状态条但进入报告、资源失败、控制台原方法保留、安装与卸载、订阅更新及脱敏为诊断用例。执行相关与全量测试、冒烟、文档核验及桌面/窄屏真实浏览器合成展示，最后安装到现有本地预览位并核对实际 HTTP 文件。

不调用真实模型，不改真实聊天、世界书和世界账，不清空已有快照，不推送远端。真实宿主与手机现场效果仍需用户验收。
