# 抽取块大小、失败说明与载入保护：已批准设计

## 人话版：这会怎么样

玩家可以设置每块交给抽取模型的正文字符数。任务开始和结束时，调试台记录实际模型、来源规模、块大小、并发和请求次数；失败时说明是密钥或接口拒绝、限流、超时、空回复、截断，还是 JSON/数据形状不对。确定无法靠拆小书文解决的错误停止重复请求。载入聊天时，旧任务不能把另一场聊天的世界写进当前聊天。

用户于 2026-10-08 回复“按推荐范围开工”，批准四项一起实施。社区引导与 FAQ 已写入 `docs/community-guide.md`、`docs/community-faq.md`，并接入 README。下列证据来自实施前取证，使用假模型应答与假聊天，未调用真实模型、读取或改写真实聊天。

## 用户本次反馈与要求

> 最主要就是调试台显示抽取失败但也不知道具体是什么失败，还有有些用户抱怨抽象太久，大约半小时，但是其他信息也不给，比如并发度还有使用的模型，还有调试台日志，我想的是再添加一个设置抽取块的大小的设置得了，那么就能完全自定义抽象了

批准实施后用户追加：“对了再添加一个抽象中止的功能，要不然误点了就停不了，还要保证抽取失败不要影响下一次抽取”。本次据此加入可中止抽取与失败后可重试；用户已明确要求添加，不重复索要实施许可。

块大小可以让玩家调整单次输入压力，但不能保证总耗时缩短。大书通常分两遍读取；块越小，请求可能越多。现有抽取超时和输出上限与设置页的“单轮”限制是两份独立设置，因此只增加块大小还不能称为所有抽取参数都可自定义。

## 已确认的原因与证据

所有例子直接调用当前生产函数，向其已有注入口传入假应答；没有修改生产函数或现有测试。全量 `node --test --test-reporter=spec` 与 `node demo/smoke-demo.js` 本次均退出 0；当前权威测试读数仍见 `STATE.md` §1。它们通过与下列缺陷可同时成立。

| 问题 | 本次复现 | 根因与位置 |
|---|---|---|
| 配置错误被反复发送 | 40 行、40269 字符的合成源，抽取函数每次抛 `HTTP 401`；整次任务实际调用 158 次，最终失败 | `src/abstract.js` 的 `tryRosterChunk` 只特别停止超时和部分网络错误；401 仍进入拆半与末端重试，后续遍继续发送 |
| 小书超时也会重复 | 7 字符源，抛带 `sw2Timeout: true` 的错误，调用两次；401 同样调用两次 | `extractWorldSetting` 小书路径在 `first.callError` 时无条件再跑一次，绕过了底层“不重试超时”的判断 |
| 报告的调用数与实际不同 | 上述 158 次请求只产生 4 对块进度；小书失败的 `timing` 没有 `calls`，界面用缺省零次 | `timing.calls` 按块完成事件计数，不按 `extract()` 实际进入次数计数；`callOnce` 错误文案还会写固定“已试 2 次” |
| 连通成功仍可能正式拒绝 | 假网关只拒带 `response_format` 的请求；`probeModel` 成功，正式调用返回 HTTP 400 | `src/transport-http.js` 的探测不带 JSON 参数，正式调用总带；这次只证明请求条件不同，不证明某家真实服务存在该限制 |
| 截断/过滤原因丢失 | 应答带 `finish_reason: 'length'`，正文分别为半截 JSON、空串；带 `content_filter` 的空串也一样 | `createHttpTransport` 仅返回 `message.content`，丢掉结束原因；`diagExtract` 再转成“空响应”，无法与普通空回复区分 |
| HTTP 正文没有进入具体失败记录 | 假网关返回“不支持 response_format”；异常有 `bodySnippet`，但上层主要记录 `err.message` 的 HTTP 400 | `src/transport-http.js`、`web/diagnostic-transport.js`、`diagSettingOutcome` 没有把结构化拒因完整接到调试报告 |
| 载入任务会写错聊天 | 用假 IDB 挂起 A 的卷清单读取，切当前上下文到 B，再完成读取；观察到 `updateChatMetadata` 的目标聊天是 B，写入世界是 A | `web/index.js` 的 `loadWorld` 没有聊天/任务版本检查；`ensureChronicleRotated(world)` 没传已有事务保护；`writeHotMeta` 每次读取当前上下文 |

载入复现是在首次观察到写错目标后结束，未测试之后的完整渲染/保存流程。社区“载入报错”和“半小时”的具体个案仍缺日志，不能把这些已复现缺陷说成所有社区报错的共同原因。

公开状态只读核验：GitHub main 的 manifest 为 1.1.2，最新 Release API 为 v1.1.0；社区文档已注明检查日期和安装来源差异。

## 可选范围

1. **只加块大小**：改动小，玩家可以调单次输入；错误分类、重复请求、调用数和串聊天问题仍存在。
2. **块大小 + 具体诊断 + 错误请求停止 + 载入保护（推荐）**：每个修改都对应已确认的问题，保持原有抽取语义与默认设置，补实际失败和异步切聊天回归。
3. **整体重写抽取流程**：可能统一复杂路径，但改动范围大、要重验缓存和来源身份，本次证据不足以支持整套重写。

## 推荐设计

### 每块字符数

- “设置 → 模型通道”在“同时问几块”附近增加“抽取每块字符数”，键为 `extractChunkChars`。
- 未填过时沿用 `SETTING_CHUNK_CHAR` 的现有默认值；默认值不变。只接受正的安全整数；非法输入明确提示且不写配置，不新增未经测量的最大值。
- 使用者设置的是正文分块目标，不是 token 数，也不包含提示词和来源说明的额外字符。
- 初始化和“只重抽设定”都传入同一个有效值。源比玩家设置更小时单发；玩家把值调小后，小于旧的小书阈值的源也要真正分块，不能让新设置被小书分支跳过。
- 保持完整原文行和来源对应关系。单行超过目标时独立成块并在任务记录中提示超限；不静默截断，不为了凑长度丢弃条目。现有单行完整性契约保持。若用户需要硬性拆开长行，那是后续需要另行确认的设计。
- 块大小改变后，下一次实际抽取按新值分块。缓存匹配记录有效块大小，避免改了设置却悄悄沿用旧块大小缓存；不自动修改已有世界，不自动启动真实请求。
- “只抽刻度”是现有一次完整源调用，不默默改成分块新流程；界面和文档写清块大小作用范围。

### 调试台说明实际发生了什么

- 开始、完成与失败都记录任务类型、实际模型、源字符数、目标/实际块大小、配置/实际并发、总耗时，以及实际调用次数。结束记录重复带上配置，让早期记录被滚动淘汰后仍能判断用户用的条件。
- 实际次数在进入模型调用时增加，包括重试和拆分；进度块数与调用次数分别记录，不能继续叫同一个数。
- 记录错误类别、HTTP 状态、经过现有脱敏和截断处理的服务端拒因、返回的结束原因、失败块与阶段。正文和完整提示词仍只在玩家选择详细记录时记录，密钥不进入报告。
- `length` 明确报输出截断；`content_filter` 明确报服务端过滤；保留类型标记给上层。正文仍保持原有字符串接口，遇已知失败明确抛出带元信息的异常，不额外调用模型判断，也不拼接残缺 JSON。
- 请求结果本身没有给出的信息标“未报告”，不猜具体模型容量、剩余时间或失败原因。
- 连通测试保持“一次最小请求”的含义，文案说明它不验证正式抽取所用的全部参数。正式拒绝时显示实际拒因，不偷偷删参数再发第二次。

### 只对合适的失败继续尝试

- 401/403、404、429、明确的请求参数不支持、超时等不会因为把书文拆半而改善，停止这次任务的后续新请求，保留当前世界。已发出的并发请求可完成，停止不等于它们从未发送。
- 网络错误或服务端临时故障沿用已存在的有限尝试；有限尝试耗尽后不再把同一错误放大成递归拆半请求。
- 单块返回不完整/不合法的数据，可沿用已有内容级拆分规则；由结构化错误判定分支，避免再靠一串文案猜。上下文长度等确有可能靠缩小输入改善的错误，必须有服务端明确错误码才能归入这一类。
- 小书路径也执行同一策略；真实尝试数如实进入错误提示。不得修改、放松世界数据和角色保护的既有校验。

### 载入与聊天范围

- `loadWorld` 启动时捕获聊天标识和载入任务版本；每次异步返回之后、每次写账和刷新之前检查仍然属于当前聊天及当前载入。
- 已存在的轮转事务检查需要在载入路径也实际接入。切聊天后旧任务不得写新聊天、不得刷新成旧世界、不得覆盖新任务状态。
- 初始化等长任务的最终写账也要核对开始时的聊天和世界版本，避免同类问题换入口复发；使用已有写账保护，不增加第二套世界状态。

### 中止抽象与下一次可正常开始

- 初始化、只重抽设定、只抽刻度开始后，窗口提供“中止抽象”按钮；没有抽象任务时禁用。一次只允许一个改世界设定的抽象任务，避免不同入口并行写入。
- 取消信号传到HTTP请求、有限重试等待、并发取块和递归拆分。用户中止与模型超时分别记录；中止不再尝试、不再发下一块、不写缓存或新世界。
- 原世界保留；在临时新世界上完成的准备工作不落到账本。已有服务端请求可能已开始计费，不承诺服务端取消或退费。
- 每次任务用新的控制器。成功、失败、异常和中止都经 finally 释放忙闩、监听和进度计时器，并还原操作按钮；下一次任务不继承旧取消信号或失败状态。
- 失败或中止的部分抽取结果不写成功缓存；旧的有效缓存和世界保持可用。切聊天也中止旧抽象任务，其提示不能覆盖新聊天状态。

## 验收

- 设置保存/重载、默认值、非法值拒绝；初始化与重抽的真实参数传递都实际运行。
- 调小块大小后，小书也分块；尾部不丢、超长行完整、非 BMP 字符不损坏、来源身份不变；默认配置输出不变。
- 假 401/429/不支持参数应答不触发拆半瀑布；小书超时只发一次；网络有限重试耗尽后停止。
- 截断、过滤、普通空回复、非法 JSON、HTTP 拒绝在报告中能区分；报告含实际配置和真实调用数，密钥仍脱敏。
- 挂起 A 的载入后切 B、同聊天先后载入乱序、初始化等待中切聊天：旧任务不写新世界、不刷新旧面板。
- 中止挂起HTTP、并发分块、重试等待均停止后续调用；原世界与成功缓存未被覆盖；失败/中止之后立即再次抽取能成功，旧计时器不继续显示进度。
- 完成全量测试、合成冒烟、文档守门和语法检查；使用假接口验证，不擅自真实调用。版本、公开推送和 Release 分开处理。
