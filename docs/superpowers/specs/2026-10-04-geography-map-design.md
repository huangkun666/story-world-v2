# 地图落地设计

日期：2026-10-04。

状态：用户已批准实施；地图展示按最新要求改为弹出式。

用户命令：「现在到地图的落地设计了」。用户已选择首版范围：「地点关系参与演化，并展示地图（推荐）」。

实施授权：「地图就别展开式了吧，搞成弹出式即可，否则不好装，你认为呢，如果你同意的话就开工吧」。

## 1. 首版要解决什么

让世界模型知道地点之间已有的关系，并让玩家能查看这些关系、账上人物的位置与发生在各处的故事。

首版交付三件事：从当前选定的世界源提取地理关系；将这些事实在当轮演化前送进模型输入；升级已有的「地图」入口。

完整地图划分不是前提。书里只有三个地点、一条关系，就能显示三个地点、一条关系；其余地方继续保留未载状态。校园、城市、洲际世界、星区与位面使用相同的数据结构，不要求固定的行政层级。

移动耗时、角色行程、角色知情范围、消息传播时延、道路封锁的专用状态更新，以及坐标和比例尺不属于首版。

## 2. 现有代码给出的边界

| 现状 | 设计如何接入 |
| --- | --- |
| `web/index.js` 的 `derivePositions` 从名册地名及驻地生成自由文本参照表 | 保留兼容表，不恢复白名单拒收 |
| `src/render.js` 的 `renderSideHtml` 仅按 `entities[].location` 分组 | 保留「地图」入口，改用地理关系与账上位置共同生成视图 |
| 书名录里的 `kind=location` 不进入人物、势力行动池 | 地点继续属于空间资料，不能因此变成行动实体 |
| `src/entity-lookup.js` 可从组织驻地推成员位置，并记「结构推导」 | 地图与演化输入都保留来源区别，不能当成此刻目击位置 |
| `src/pack.js` 目前给模型地名表与人物位置，没有地理关系 | 增加独立的地理事实块；原有因果、盘算、名号仍按既有规则入包 |
| `entityUpdates` 已允许有原因的 `location` 更新 | 移位继续走现有通道，不再建一个会相互覆盖的位置字段 |
| `src/abstract-evidence.js` 核本次允许来源与逐字引用 | 地理身份和关系复用此核验；引用只进既有诊断，不落世界账 |
| 新事件的 `position` 已可省略 | 缺位置事件仍有效，不依靠地图补一个发生地点 |

观棋侧仍可查看全局。地点只提供空间事实，不据此屏蔽人物、事件、因果或互动资格。

## 3. 三种路线与选择

| 路线 | 收益 | 代价与限制 |
| --- | --- | --- |
| **地点与关系组成的图，配合层级展示（推荐）** | 能表达包含、相邻和通道；允许局部地图与孤立地点 | 需要处理地点叫法、来源与关系冲突 |
| 只做地点层级树 | 实现较小，区域浏览清楚 | 无法表达商路、传送门、跨区连接；多重包含不适合硬塞进一棵树 |
| 坐标地图与距离模拟 | 将来有条件计算路线、距离和行程 | 通用世界源通常缺坐标、距离、速度和统一时间；补数字会制造事实 |

采用第一条。所谓「图」，就是地点记录加地点之间的关系记录；屏幕摆放的位置只用于阅读。

## 4. 数据放在哪里

在 `context.setting.frozen.canon` 下新增可选的 `geography`。它只保存抽取后的空间事实，随设定保存、导出和快照恢复，不另建地图数据库。

以下为结构示例，地点及关系均为示意，不代表本局世界书事实：

```json
{
  "geography": {
    "version": 1,
    "places": [
      { "id": "p_1", "name": "地区甲" },
      { "id": "p_2", "name": "山脉乙", "aliases": ["乙山脉"] },
      { "id": "p_3", "name": "古战场丙" },
      { "id": "p_4", "name": "关口丁" }
    ],
    "links": [
      { "from": "p_2", "type": "within", "to": "p_1" },
      { "from": "p_3", "type": "within", "to": "p_2" },
      { "from": "p_3", "type": "adjacent", "to": "p_4" },
      { "from": "p_3", "type": "passage", "to": "p_4", "via": "山道", "direction": "both" }
    ]
  }
}
```

`version` 是数据格式编号，不是世界数值。地点编号由引擎生成；模型只交临时引用，不能决定最终编号。

`geography.places` 是地图身份与别名的唯一解析入口。现有名册地名是生成它的材料，旧名册仍保留，但地图消费者不再从两套别名表各猜一次。地点与人物、势力使用不同的编号空间；同一个名称可以同时指一个组织和它所在的场所，不改组织的类型。

同名不同地点保留不同编号。跨块合并和重抽只能在身份明确、唯一对应时复用编号；有歧义就保留未决身份，不凭短名合并。原始的 `location` 和 `position` 仍是自由文本，不强制改成编号，也不重写历史文本。

三种关系的含义固定：

| 类型 | 含义 | 允许推导的内容 |
| --- | --- | --- |
| `within` | 地点 A 位于地点 B 内 | 包含链；已知的共同上层地点 |
| `adjacent` | A 与 B 相邻或接壤 | 对称的相邻关系；不推导有路可走 |
| `passage` | A 与 B 存在书中明述的通道 | 通道存在；不推导当前畅通、时长或成本 |

`via` 是书中通道叫法，可省。`direction` 只在依据明确时写 `both` 或 `forward`；缺失表示方向未载，不能补成双向。通行条件可另存可选 `condition` 文本，照书保留，程序不把境界、权限和能力换算成数。

包含关系可以有多个明确上层，但不能成环。相邻和通道允许成环，也允许并存，彼此不能替代。通道没有记录表示资料未载，不表示不存在通道。

`context.positions` 继续承担旧接口的自由文本参照表职责，不成为第二份可编辑的地图。地图身份和关系的读写只经过 `geography`；参照表按既有地点文本及地图名称派生补充，缺 `geography` 的旧世界照旧工作。

## 5. 地图怎样得到资料

### 新世界

在既有世界源抽取流程中增加地理输出，复用本次选定条目、角色卡材料、分块与出处核验。不按标题词表只选「地理条目」，也不把所有书名录关系直接翻译成地理关系。模型负责判断语义，程序核本次材料、端点引用与结构是否合法。

地理输出随既有名册抽取调用返回，跨块归并交给独立模块，不新增每轮地图模型调用。地理字段不应无限扩充现有大文件。

程序能证明引用在本次材料中，不能凭字符串匹配证明模型解释一定正确。诊断明确保留这一限制；展示地理事实属于模型已提取的世界源内容。

### 已有世界

未生成地图时，仍显示账上的地点与位置，不补地理关系。用户可在地图入口点「补抽地图」，用当前选择的抽象来源补地理资料。这是一次用户触发的抽取，可以复用分块调用与缓存；不会开始新世界，不重种人物，不重置事件和盘算。

补抽在临时结果上核验完成后才写回。写回前重新核对世界身份、来源版本和当前账版本；调用期间换聊天、回档或来源变了，结果不落到另一份世界。补抽失败保留原地图。

重抽地图更新的只是来源派生的地理部分。复用身份能明确对应的地点编号，不改既有事件文本；不同来源版本不混并。缓存同时识别地理格式版本与既有来源摘要，老缓存缺地图不能冒充已完成地图抽取。

只重抽刻度等局部操作，在来源版本相同时保留已有地图，不因响应里没有地理字段而删除它；来源已经改变时不能把旧图算作新来源的抽取结果。相关入口必须有回归覆盖，不能只接新世界初始化。

### 没有地名条目的书与新出现的地点

允许从被选材料的正文提取明确地点，不要求预先存在 `kind=location` 条目。人物和事件后来使用的表外位置也照常显示，但归入「关系未载」，不自动升为书中确认的地图身份，更不补上层、相邻和道路。

地点解析只用精确名称和已确认别名。字面包含、模糊相似、同属某势力，均不能证明是同一地点。重复短名命中多个地点时返回歧义，保留原文本。

## 6. 地图如何参与当轮演化

在主调用之前读取地图，以账上人物位置、未决事件地点和本轮已提及地点为起点，自动准备地理事实。模型不用另发查询，也不用等下一轮。

地理块包含紧凑的地点、关系与本轮相关的位置对应。规模能容纳时全量提供；预算紧时先保留直接相关地点、它们的完整包含链、相邻和通道，再装其他地点。沿用总包预算，不另设固定的地点数或关系数配额。真裁掉时给出已装与未装计数；不能让缺失资料看起来像不存在关系。空地图不加入无用块；无地图旧世界的演化输入保持原口径。

若一组相关关系连同完整包含链仍装不下，整体省略这组并报告未装计数，不截出一条假完整的链，不挤掉因果主资料。保存的地图与界面仍完整，裁剪只影响本轮输入。

原有事件原因、盘算及直接点名信息优先级不降低。地图不会替代因果检索，也不据地图删掉远处事件。第一版不改镜头选人算法和静默门，只增加模型当轮可以使用的空间事实。

模型可以据此选择更有空间依据的行动与后续事件，例如先波及已知的同处地点，再考虑相邻区域或书中通道。共同上层地点只说明共同归在哪个区域，不称为「附近」，更不称为「同一现场」。

这些是模型决策的事实依据，不是引擎保证每轮必产生的结果。是否改善实际叙事，需要后续在相同输入下对比有、无地图的模型输出；结构测试只证明接线和资料正确，不能代替效果实测。

位置的语义严格分开：

- `entities[].location`：账上记录的位置；可能来自书中驻地、结构推导或有因的后续更新。
- `newEvents[].position`：事件发生地点；可省。
- `actions[].position`：行动涉及地点；单凭这个字段不自动认定行动者已到达。
- `ripples`：被事件牵动的人；不表示这些人都在事发现场。

模型明确提议位置变化时继续使用 `entityUpdates` 的 `field=location`、`value` 与合法 `cause`。地图仅解析更新后的记录，不能因某人被点名、某事发生在某处而把他搬过去。玩家禁写等既有约束继续生效。

位置来源要同时进入视图与地理输入。沿用 `meta.entityFields` 中已有的「位置来源」及 location 变更记录；缺来源时写「来源未载」，不补「书中明述」。结构推导必须标明。历史默认值不作为确定位置；先匹配来源确认的真实地点，再识别旧占位值，避免按词表误删恰好同名的真实地点。

聊天侧若已有对应的注入开关，可在既有开启通道携带相关地理事实；地图功能不替用户打开关闭的开关。

## 7. 地图界面

升级现有的「地图」入口为一个按钮，点击打开独立弹窗，不在主页面展开地图内容。弹窗挂在 document.body 上，页面重绘不能移除它；关闭按钮、点遮罩和 ESC 均可关闭，关闭后焦点回到入口。

首版以区域层级浏览为主，关系连线为辅：进入一个地点，查看它的下层地点、明确上层、相邻地点和通道。包含是分组依据，连线只画真实关系。多重包含使用交叉入口访问同一编号，不重复计算为两个地点。

界面中显示的是关系排版，不给地图加虚构的东南西北、比例尺或几何距离。画面上两个格子的远近不代表世界中的路程。

点击地点可查看：账上位于此处的角色和势力、相关事件和故事、明确的地点关系。人物记录按项标出结构推导或来源未载，混合来源不能只在组头盖一个统一标签。驻地记录不称为实时目击。

搜索同时覆盖地点正名、确认别名、人物和事件。层级关系未载的地点仍可搜到；位置未载的人和缺地点的事件仍有入口查看。状态区分「地图未生成」「本次未提取到关系」「关系未载」，不写成「书里没有」。

窄屏弹窗占用可用视口，按单栏顺序显示区域、地点和详情，点击操作不依赖悬停。地图视图和控制在独立模块中，使用本地 HTML/SVG；首版不增加地图服务、底图下载或第三方图布局依赖。

## 8. 模块与接入点

| 模块 | 单一职责 | 接入点 |
| --- | --- | --- |
| `src/geography-extract.js`（新增） | 地理抽取形状、逐条净化、跨块身份归并与关系冲突处理 | 既有 `src/abstract.js` 抽取流程与缓存；复用 `abstract-evidence.js` |
| `src/geography.js`（新增） | 地点解析、关系查询、当轮地理事实与地图视图数据；不读 DOM、不调用模型 | `src/pack.js` 和地图展示共同使用 |
| `src/map-view.js`（新增） | 从统一视图数据生成地图内容 | `src/render.js` 的已有地图入口 |
| `web/map-reader.js`（新增） | 搜索、区域切换和详情交互 | 既有页面装配与重绘生命周期 |
| `web/geography-wiring.js`（新增） | 用户触发补抽、版本检查、写回与状态提示 | 现有来源、传输、保存和快照入口，通过注入取得依赖 |
| 现有契约与提示词 | 登记可选地理形状、说明三种关系与位置语义 | `src/schemas/ssot.schema.js`、`src/prompts.js` |

世界步不增加一个新的移动或地图更新提议族。`src/schemas/world-step.schema.js` 不为了地图把位置改回必填。已有持久化、导出与快照链保存同一份世界数据，不另写地图副本。

新模块依赖方向保持单向。已有入口只负责调用，不能把同一个地点解析逻辑再写进渲染、检索和校验各处。

## 9. 异常与兼容

- 无出处的地理身份或关系不成为确定事实；其拒收诊断不拖垮合法的设定、人物与事件。
- 悬空端点和自指关系逐条拒收。包含成环时剔除环内包含边并留痕，保留地点及不受影响的关系；不因输入顺序任选一条当真。相邻和通道环不误删。
- 不把模糊名称匹配升级为确认别名；不自动认定「所属势力」是地理包含。
- 模型调用、净化或写回失败不覆盖原地图；主演化仍沿用现有异常处理。
- 旧世界缺地图合法，旧缓存缺地图如实标未生成。已有导出、载入与回档路径必须实测，不能只靠契约可选就宣布兼容。
- 地图未记录到某处，不拒绝写在事件或角色位置里的那个地点。缺位置事件正常入账与同轮引用能力保持。
- 首版地理关系是世界源里的静态关系。道路被事件封锁时，模型结合现有事件判断；界面不得把「有通道」标成「当前畅通」。专用的动态道路状态留给后续设计。

## 10. 实现顺序与验收

按一个首版计划分四步：

1. 先建立可选地理契约、出处净化与地点解析。验证包含、相邻、通道、别名、歧义、混合身份与部分地图。
2. 接入新世界抽取和已有世界补抽，验证失败保留旧图、缓存版本、换聊天及回档期间的写回保护。
3. 接入当轮演化包与提示词，验证地理事实在主调用前到位、来源区别可见、预算裁剪可见、因果和盘算不被地图替代。
4. 升级地图入口，验证区域浏览、搜索、人物与故事详情、手机操作，以及导出、载入和快照恢复。

以下均是必须通过的验收场景：

- 三层包含能查询上层；相邻不变成道路；通道方向未载不变成双向或即时抵达。
- 同处匹配与同一区域明确区分；两个别名确属同地时对应同一编号；重名不确定时不自动合并。
- 书中驻地、结构推导、动态更新、来源未载的记录分别呈现；被波及人物不会自动出现在现场。
- 没有地名条目但正文有地理事实的书可得到部分地图；没有足够地理资料的书仍能正常演化。
- 未登记地点与省略位置事件照常接受；与同轮新盘算的引用继续正确。
- 在真实 `runTick` 主调用入口捕获地理输入，而不是只测试独立函数；同轮使用，不新增演化前查询调用。
- 无地图旧世界与原基线行为一致；新增地图后不改变玩家禁写、静默门、全局查看权限和既有开关选择。
- 输入超预算有明确计数，已装关系的相关包含链完整；连同包含链也装不下的关系组整体省略并计数。地图省掉的部分不被解释为否定事实。
- 用户正在看的地图、当轮输入和恢复出的地图使用同一份事实；不出现界面有边、演化却从另一个解析口拿边的情况。
- 至少覆盖区域型、室内型、星区或位面型资料及无地理资料；效果实测结果与结构测试结果分开报告。

机制实施前按项目规矩运行泛用性审计，功能完成后运行相关回归、全量测试、合成冒烟及文档守门。当前产品验证读数仅引用 `STATE.md` §1；本稿不声称尚未实施的地图已经通过验证。

## 11. 后续扩展需要另外解决的前提

行程计算需要世界时间与轮次的对应、交通方式、可用路径和速度或明确耗时。消息传播还需要发送方式、发送者、接收者以及角色的知情记录。距离坐标图需要真实坐标或可校准的距离数据。

地点编号与地理关系会为这些功能提供基础，但包含层数、图上连线条数和屏幕像素均不能换算成旅行轮数。首版不提前保存一套尚无消费者的行程或知情字段。
