# 设计原件 · leg70（A6）：「只抽刻度」抽完**能存**

> 本文件是**拍板与口径的原件**（交接 `docs/session-handoff-2026-09-19-leg70.md` 引用它）。
> 起因：`docs/leg68-recon-pending.md` §A6 实测 + 用户 leg63 原话「**我刚刚抽了有很多表，但是原本的内容还在**」。
> 用户上一棒的令：「你还可以再做几棒，上下文才到百分之17」⇒ 本棒挑**唯一的功能新增 + 玩家可见面**

## 1. 病（一句话）

**卡的不是抽取，是落地。** 直抽那条路（`bus['extract-scales']`，`web/index.js`）把结果只挂到
`world.context.__scaleDraft`（**会话态**），而 `applySettingToSsot` / `writeHotMeta` / `flushHotMeta`
**一个都没调** ⇒ 三件事同时发生：

1. **不写盘** ⇒ 刷新页面即丢（`loadHotAccount` 读回的那份里没有草稿）；
2. **不入账** ⇒ `frozen.canon.刻度` 一个字不动 ⇒ 面板上"原本的内容还在"（用户的病就是这个）；
3. **不愿意让它顺手存是有意的**（不是漏接）：`web/index.js` 那三条口径注释里明写
   "**本按钮不当第二条写入口**" ⇒ 这是**设计留的口**。

⇒ 于是那一栏从 leg62 起**永远只能看**：想看第二眼就得重抽，想真用就得走「初始化」（重开世界）
或「只重抽设定」（换掉整份设定）——而用户要的只是"**这一次抽到的尺子，就用它**"。

## 2. 拍板点（本棒自己拍的，逐条给理由；凡"没拍"的也登记）

| # | 问题 | 拍板 | 理由 |
|---|---|---|---|
| 1 | 走哪条路：改造 `extract-scales` 顺手存 / 另起一个 `bus` 动作？ | **另起 `bus['adopt-scale-draft']`** | `test/scales-concept-table.test.js:323` 有一条**硬锁**「直抽那条路上不许出现 `extractWorldSetting`」，而更根本的理由是**口径**：**抽 = 一次调用瞄一眼**、**存 = 写账落盘**，两件事同处一地，早晚有人把它们接成一条（"抽一下就改了世界"，本仓最贵的病） |
| 2 | 换多少：整份 `canon` / 只换刻度那三格？ | **只换 `刻度` + 派生的 `powerScale`/`dims`** | 用户要的是"换尺子"，不是"换设定"；法则/名册/史略/张力一律不动 ⇒ 与「只重抽设定」**同一条口径**（那条也只换 setting），差别只在**料从哪来** |
| 3 | 名册怎么保命？ | **canon 从账上那份展开**（`{...before, 刻度, powerScale, dims}`） | 这是**结构上**保命，不靠"记得别删"。同族的「只重抽设定」换的是**整份** canon ⇒ 它必须**显式**保 `bookEntities`（`:2948` 那条老病注）；本动作只换三格 ⇒ 保命属于形状。★判据锁的正是"展开旧 canon"这个形状 |
| 4 | 旧两列（`powerScale`/`dims`）怎么来？ | **`scalesToFlat` 重算**，不许手写 | `abstract.js:1075` 那句"**概念表是源、旧两列是派生视图**，一处生产、两处消费"；手写第二份就是本仓"一个数两把尺子"的老病（leg56 在"盘算上限"上治过一次） |
| 5 | `fingerprint` 动不动？ | **不动** | 它是"这份设定取自**哪本书**"的指纹，而本次**没有重读源** ⇒ 动它就是**谎报"书变了"**，会让"书没变 ⇒ 不重抽"那条判断失去依据 |
| 6 | `extractedAt` 动不动？ | **要动**（置为此刻） | 它印在设定页副标题「抽取于 …」上，而刻度**确实是这一刻换的** ⇒ 留旧时刻就是"面板印一个不再为真的数"。★**代价如实说**：它不再表示"整份设定来自同一次抽取"。更准的做法是**另加一个键**（如"刻度换于"）——那要动契约，**先报批**，本棒不做 |
| 7 | 草稿入账后留不留？ | **删掉**（`delete next.context.__scaleDraft`） | 留着 ⇒ 面板同时画"草稿"与"账本"两份刻度，看着像**没生效**（正是 leg62b 那个误会的形状） |
| 8 | 要不要如实报"两边不会逐字相同"？ | **要**，面板 + 状态条 + 控制台三处 | 草稿是**单次调用**的产物，生产那条走**多块 + 块间合并**（`mergeCanonChunks`）⇒ 两边不会逐字相同。这是 `leg63.md` §5.3 登记过的**必须告知的局限**，本仓纪律："漏了如实报"是病 |
| 9 | 旧的那一份要不要留痕？ | **要**（`console.info` 打旧 canon 读数） | 覆盖不可回；照「只重抽设定」那条（"改一次留一次痕"） |
| 10 | 落盘要不要 `await`？ | **要**（`await flushHotMeta()`，且 `flushed.ok === false` 如实报） | leg20 语义：关键路径显式落盘后才报成功 |
| 11 | `PANEL_BUILD` 升不升？ | **升**（`leg69-pack-fit-trace` → **`leg70-adopt-scale-draft`**） | 这次是**玩家可见面真的变了**（多按钮 + 多两段说明 + 读数行 + 入口措辞改了）——与 leg69 那次"**模型**可见面变了"不是同一条理由，交接里已如实区分 |

**没拍的（登记不猜）**：

12. **草稿本身能不能跨刷新活下来？** ——本棒**没做**。直抽那条路仍然只挂会话态（不入盘）⇒
    **抽完不按"采用"就刷新 = 那一栏没了**。这不是本棒引入的，是 leg62 起就有的口径
    （"只瞄一眼"字面意思），且改成写盘会让"瞄一眼"变成一次**落盘副作用**。
    ⇒ 若用户要"草稿也能留"，那是**另一个拍板点**（应当单独一棒，且要决定草稿落在哪个键、算不算契约字段）。
13. **`INIT_SOURCE_HARD_CEILING` 抬不抬** · **366 条人物档案读不读** —— 仍在旧待办里，本棒没碰。

## 3. 落地形状（改 2 个生产文件）

```
web/index.js    bus['adopt-scale-draft'] = async () => {
                    const world = loadHotAccount(readHotMeta())          ← 前置：世界在 + 有草稿 + 草稿非空
                    const before = world.context.setting.frozen.canon
                    const flat = scalesToFlat(scales)                    ← 拍板 4：唯一派生路
                    const canon = { ...before, 刻度: scales,             ← 拍板 3：名册结构保命
                                    powerScale: flat.powerScale, dims: flat.dims }
                    const setting = { ...world.context.setting,
                                      frozen: { ...frozen, canon, extractedAt: now } }   ← 拍板 5/6
                    console.info(旧读数备份)                                        ← 拍板 9
                    const next = applySettingToSsot(world, setting)      ← 唯一那条换设定路
                    delete next.context.__scaleDraft                     ← 拍板 7
                    writeHotMeta(hotAccountShape(next))                  ← 拍板 10
                    const flushed = await flushHotMeta()                 ← 同上（带行尾注释，见下）
                    refreshWorld + refreshSections(['setting'])
                    setStatus(如实报：换了什么 / 没动什么 / 单次调用的局限)
                }

src/render.js   renderScaleDraftHtml(draft, world)   ← 多收一个 world（报"账上现在几张三档"）
                  + oldScales = resolveScales(canon)  ← 读数与「维度与刻度」那一栏**同一把尺子**
                  + 采用按钮（sw2-primary）+ 两段如实说明
                  + PANEL_BUILD 升位
```

★**那一行行尾注释是有意留的**（`const flushed = await flushHotMeta();   // 采用入账：…`）：
全仓另有 **5** 处同名调用（账户形状同步 / 初始化 / 导入 / 快照恢复 / 重抽设定）
⇒ 判据与**演练锚点**都靠这句注释才定位得到本动作。**删注释 = 判据与演练一起失准**（本棒演练当场踩过，见下）。
