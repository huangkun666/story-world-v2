## 4. ★★★ 本笔最值钱的四条

### ① **"装安全带"要装到每一个调用点——我漏了一处，用户真机替我抓出来了**

**病（我自己的）**：并发这一刀配了一条安全带（"任何一块失败 ⇒ 剩下的当场退回串行"），
我在细案里跟用户说的原话是"**失败即退回串行**"，覆盖**三处**（名册遍 · 设定遍 · 起根）。
**而第一版我只把它装进了 `extractWorldSetting`**（管前两处）——**起根那一遍的并发度是定死的**：
网关一限流，连着几块一起 429、**每块 0.8 秒就丢一个**，既不降速也不重试。

**用户真机把它抓出来了**（这是本笔最值钱的一条，因为它**只能靠真跑发现**）：

```
[story-world-v2] 抽取调用失败（输入 31631 字符 · 已花 0.8s） HTTP 429
  ← seed-roots.js:331
  ← runLane @ parallel-run.js:78
```

他报的原话是「**有四个连续的抽取调用失败**」。
★★★**"为什么恰好是 4 个"我说不准——而我第一版在这里写过一句错的，如实登记（别照那句推）**：
我原来写的是"'四个'就是那条安全带缺失的形状：第一波 3 块 ＋ 第 4 个是降级后那条 lane 再试的一块"。
**那句是错的**：**他跑的那一版，起根根本没有降级**（那正是本笔要补的东西）⇒ 当时是 **3 路一直并发、9 块分 3 波**，
不存在"降级后那条 lane"。⇒ 4 个连续失败更像**一次限流突发**（0.8 秒被拒 = 网关主动推回），
**后面几块网关放行了**——而"为什么是 4 不是 3 或 9"，**没有读数能回答，我不编**。

★★**那条安全带能保证的到底是什么**（这才是它的价值，别夸大成"把 429 修好了"）：

| | 网关**突发**不高兴一下 | 网关**持续**不高兴 |
|---|---|---|
| **没有安全带** | 撞上的那几块丢（他这次：4 块） | 3 路一直并发着撞 ⇒ **损失随块数走**（9 块就可能全丢） |
| **有安全带** | 一样丢撞上的那几块（第一波已经在飞，收不回来） | ★**损失有界**：最多第一波那几块（出厂值 2 ⇒ 2 块），剩下的**退回串行、多半能过** |

★**它治不了"网关就是不让你并发"**——那种情况该做的是把「**同时问几块**」调小（甚至填 1）。
★**所以本笔给的是"损失有界 ＋ 你自己能调"，不是"429 不会再来"。**

**治法**：起根也装 `degraded` / `concurrencyNow`（与抽取那两遍**同一个开关、同一条口径**）。
★**判据怎么锁它**（这条锁的夹具是本条的要点，别改成"随便一个失败"）：假抽取**只要发现"自己在飞的过程中
身边还有别人"就回 429**（这正是限流的形状：并发越多越挨打）。
⇒ 有安全带：第一波全 429 ⇒ 退回 1 路 ⇒ **后面的块一个人跑 ⇒ 成**；没安全带：3 路一直并发 ⇒ **全丢**。
先证红实测：拿掉 `degraded = true` ⇒ **成功 0 / 失败 6**。

### ② **"按原下标收回"不是洁癖，是质量**

**病**：把 `for … await`（一块一块排队）改成并发，最自然的写法是"谁先回来谁先往数组里写"。
而下游有**两条吃次序的定稿口径**：

| 那条口径 | 它住在哪 | 按完成次序收回会怎样 |
|---|---|---|
| 「每组取**最先出现**的叫法当 `name`」 | `dedupeRoster`（`src/abstract.js`） | 同一个实体的正名**换成另一个叫法** |
| 「**首块优先**」（张力与四个环境档位只看第一块） | `mergeCanonChunks`（`src/abstract.js`） | 张力极/方向、四个环境档位**整组换人** |

⇒ 定稿：`runParallel` 里那一行 **`out[i] = await worker(list[i], i)`** —— **按下标写回**。
`extractWorldSetting` / `seedRootsChunked` 的 worker **只交结果**，一切累加（`rawCanons` / `rawBookNames` /
`rawSettingEnts` / `errors` / `chunkLog` / `seenTitles` 去重）**一律挪到"按块序重放"那一步**。

★★**判据怎么锁它**（这一条是本笔的承重判据）：同一份夹具、同一个 `extractedAt`，**并发 1 与并发 3 的
`setting` 与 `errors` 深度相等**；并**反向自证探针真的在咬**——夹具让**块 0 最慢**（并发下最后回来），
断言结果里的张力仍是 `正邪k0`（块 0 的值）。若按完成次序累加，这里会变成后面某一块的值。

### ③ **书指纹缓存"从没接线"——机制在、线断了**

**病（现读代码）**：`extractWorldSetting` 支持 `cache`，`test/abstract.test.js` 一直在验它，
`demo/diag-extract-realbook.js` 也在用；而 **`web/index.js` 两处生产调用（初始化 · 重抽）从没传过 `cache`**
⇒ 这条缓存**在真机上一次都没被行使过**。
★这不是我发现的：`docs/handoffs/session-handoff-2026-09-11-leg25.md:14` 早就写着「**书指纹缓存从没接线**」，
**从 leg25 挂到今天没人修**。本仓把这类病叫"**没有消费方的抽象 = 死抽屉**"，这是它的又一个实例。

**代价（用户能感觉到的）**：同一本书**再点一次「初始化」= 又是完整一遍 20–30 分钟**（真钱）。

★**它只活在这一次页面会话里**（内存 · `CACHE_MAX=5` · 按时间淘汰），不落盘、不污染设置区。

### ④ **两个"串行下天经地义"的共享变量，并发下会静默出错**

| 那个共享变量 | 串行时它是对的 | 并发时它会怎样 | 有判据会红吗 |
