## 0. 一句话

**世界模型每轮收到的那份"世界状态摘要"里，有一栏叫「往事」（键名 `纪事`）。它现在是"自己去编年账里把全部往事抓过来"，本笔要把它改成"向检索层要"。**

| # | 事 | 结论 |

| ① | ★**硬约束落到哪** | 世界模型那一次调用**只有一条消息**（`transport-http.js:91`）⇒ "同一次调用"就是**那份包** ⇒ 包里几栏往事，模型就看到几份 |

## 3. ★★实读发现的三个硬钉子（B2 一接就撞；今天没有判据咬得住）

### 3.1 ★事件条目**没有"第几轮"那一格** ⇒ 排版那一步**静默丢掉**，回执还说"成功"

`recallLedger(...).items` 里可能有三种东西：

| 种类 | 谁取回来的 | 有 `tick` 吗 |
|---|---|---|
| **编年行**（账上那句话本身） | 按名取 / 按词取 / 按轮次取 / 最近优先 | **有** |
| **事件本体**（一件事的"五格"：id/标题/来路/地点/波及） | **照因果上溯** / **照指针取** | ★**没有** |
| 里程碑里还原出来的旧事 | 显式要归档（`includeArchive`）才取 | 有（拿里程碑那一段的末轮） |

**②为什么没有 `tick`**：事件的"第几轮"**不在事件对象里，在它的 id 里**——id 是 `ev_<轮次>_<第几件>`，
账上唯一那把解析器是 `eventBornTick()`（`src/setting.js:38`，`leg99` 定的契约：开局种子 `ev_seed_N` 算第 0 轮）。
实读两处落账：热池里的事件五格在 `settle.js:238-246`，**没有 `tick`**；归档留档在 `settle.js:711-717`，**也没有**。

**③后果（这是要害）**：消费者面的排版函数 `formatRecalled` 第一步是**按轮次分组**（`ledger-recall.js:137`）：

```js
for (const it of items || []) {
    const t = Number(it?.tick);
    if (!Number.isFinite(t)) continue;        // ← 事件本体在这里被丢掉
```

⇒ **整段一个字都不印**（`formatRecalled` 返回空串），而回执仍是 `ok: true`、`total: 3`。
**消费者拿到的是一段空白 + 一个"成功"的回执。**

★这正是本仓记过的那条老病，换了个门又进来了：`START-HERE.md:1298`——
「**返空是静默的……界面分不出"没命中"和"根本没在检索"**」。

★**为什么一条判据都没咬住它**（实读 `test/ledger-recall.test.js`）：那个排版函数**只在两种取法上被真跑过**
（`RECENT` 与 `BY_TICK`，`:126`/`:133`/`:145`/`:159`——取回的都是**编年行**，有 `tick`）。
而 `L25`/`L26`（`leg117` 新加的两条跨归档判据，`:495`/`:516`）**只断言 `items`**，没让结果过一遍排版那一步。
⇒ **"照因果上溯"取回来的东西，到今天为止没有任何一条判据证明它排得出版。**

★**真账实测（本笔探针，见 §9）——这一条不再是"读码可证"，是当场发生的**：

```
锚 = 42 个未决事件的号 · modes=[照因果上溯] · depth=12 · 含归档
  ⇒ 回执 ok=true · items=114（事件本体 50 · 编年行 0 · 里程碑还原 64）· 1 ms
  ⇒ 过一遍排版那一步：只渲染出 64 行 ⇒ ★静默丢掉 50 条（43.9%），而回执仍是 ok=true、total=114
```

★★**这一条同笔就治了**（用户令「把那个没有轮次的小活解决了然后交接」）：取回来时把轮次**补在返回的副本上**
（用账上唯一那把解析器 `eventBornTick`），并且**解不出来的也不再沉默**（照印 + 如实说"不知道第几轮"）。
★真账复量：**没有轮次的 50 → 0 · 渲染 114/114 · 静默丢 0**。
见交接 `session-handoff-2026-09-23-leg118.md` §5.2（两刀、判据 `L27`/`L28`/`L29`）。

★**今天为什么不显形**：唯一的生产消费者（第四段注入）用的是"按名取 + 按词取"，两种都只出编年行。
⇒ **B2 是第一个会用"照因果上溯"的消费者**——它一接，就撞在这上面。

★**这不是 B2 的坑，是检索层的坑**；B2 只是第一个踩上去的人。修法见 §8.2（要你点头才能量）。

### 3.2 `maxChars` 这个参数**表达不出"不限"**（`Infinity` 会掉进默认 6000）

`ledger-recall.js:500`：

```js
const maxChars = Number.isFinite(q.maxChars) ? q.maxChars : DEFAULTS.maxChars;   // DEFAULTS 里是 6000
```

⇒ 传 `maxChars: Infinity` **不是"不限"，是"回到出厂 6000"**（`Number.isFinite(Infinity)` 是 `false`）。

**为什么这条对 B2 是要紧的**：本仓有一条血证级的口径——**上限只认包的总预算，不设条数/字符上限**
（`leg113` §3.4：`entityUpdates 每轮 ≤3` 就是"一个没量过的提案态数字在生产里当家、还静默拦"，
2026-09-22 用户拍板**直接取消**；同一个坑不跳第二次）。
而今天这一栏正是照那条办的：**没有条数上限、没有字符上限**，唯一的尺是包的总预算 + 额度守卫。

★**顺带量到一处不对称**：同一个函数里，**条数**那个参数是能表达"不限"的
（`ledger-recall.js:493`：`Number.isFinite(q.limit) && q.limit >= 0 ? q.limit : Infinity` ⇒ 传 `null` 就是不限），
**字符**那个不能。⇒ 这不是风格问题，是**接口缺一格表达**（本仓管这叫"接口上宣告的旋钮，每一个都要能改出不同的结果"的反面）。

### 3.3 那一栏的两条锁，都长在**旧住处**上

| 锁 | 锁的是什么 | 出处 |
|---|---|---|
| 行形状 | `Object.keys(每一行) === ['tick', 'text']`——**只两格**（原话：「多一格就是新造字段」） | `test/chronicle-brief.test.js:122` |
| 不许有上限 | 扫 `chronicle-brief.js` 的**源码**：不许出现 `TOP/LIMIT/MAX/CAP` 这类常量、不许 `.slice(0, 数字)` | `test/chronicle-brief.test.js:90-96` |

**为什么要紧**：
- 第一条 ⇒ **检索层取回来的富信息（id / 来路 / `archivedIn`）不许直接进这一栏**，必须先投影成两格（见 §4.4）；

  ⇒ 取数搬到哪，这条闸就要跟到哪（§5 判据 J9）。

## 4. 设计

### 4.1 形状：**一栏，不并列**（用户那条硬约束的直接落地）

世界模型那份包里，"往事叙述"**有且只有一栏**，就是 `纪事`。
★**它不是"再加一栏检索结果"**——并列即重复：同一行会在两栏各出现一次（`leg117` §5.1 的探针实测）。

★**同时写死一条不许顺手做的事**：包里另外还有几栏**看着像往事、但不是往事**，**不许拿"不许重复"当理由并掉它们**：

| 栏 | 它是什么 | 为什么不能并 |
|---|---|---|
| `recentClosedEvents` | 最近了结的那几件（**带 `closed` 记号**） | `leg100` 专门加的那个记号是用来分"候选 / 墓碑"的——真机上模型就是在这儿挑错号；**并掉＝把那个修复撤了** |
| `pendingEvents` / `openRoots` / `threads` | **还没结束**的事与线 | 那是"现状"，不是往事（`leg113` §3.4 原话：往事永远不许挤掉现状） |
| `closedRoots` / `closedAgendas` | 已了结但没人接的旧料台账 | 它们是**候选池**（"接上它也算一步"），语义与"往事"不同 |

⇒ 口径一句话：**"往事"只指"那时候发生了什么"的叙述；上面这些是"现在该怎么办"的台账。两者不并。**

### 4.2 取数：**一条路**——向检索层要

`pack.js` 不再 import `chronicleBrief` 去抓账，改成调 `recallLedger(ssot, {...})`。
★**单向、不造环**：`pack.js → ledger-recall.js → chronicle-brief.js`（`ledger-recall` 只 import 那一张规则表，
`chronicle-brief` 是零 import 的真叶子）⇒ `module-layout.test.js` 的环基线**一条不动**
（`src` 模块数也**不变**：这一笔**不新增模块**）。

### 4.3 取舍：**同一张表**

检索层**全收**（认不出的 `OTHER` 也收），弃不弃是**消费者**的事（`leg117` 定稿：
「取数是检索层的事，认'这是什么话'是这一张表的事」）。
⇒ B2 用**同一个** `isChronicleBriefLine()` 筛掉机械记账行——**不另写一套规则**（那正是 §2.1 的病）。

### 4.4 行形状：**仍然是两格 `{tick, text}`**（那两条锁一条不动）

| 检索层给回来的 | 进栏之前 |
|---|---|
| 编年行 `{id, tick, text, eventRef, elapsed…}` | `text` 过一遍 `briefLineText()`（去掉固定前后缀）⇒ 只留 `{tick, text}` |
| 事件本体 `{id, title, source, position, ripples}` | 投影成 `{tick: 它出生那一轮, text: 标题}`（"第几轮"从 id 解，见 §3.1） |

★**理由**：那两格锁不是形式主义——它保证"这一栏里每一行都是账上的一句原话"，**模型读到的是一种声音**。
检索层的富信息（id、`archivedIn`）**到包边界为止**，不往里灌。
★**代价要说清**：事件本体被投影成标题之后，**它的来路（`source.ref`）就看不见了**——
而"照因果上溯"取它回来的**目的恰恰是来路**。这一处的取舍见 §8.1 的甲/乙/丙三案。

### 4.5 顺序：**取数的排序 ≠ 栏内的顺序**（两件事，别混）

- **取数层的"新的在前"**（`leg116` 统一的排序）管的是：**谁先来谁占得到字符预算**——它决定**成员资格**；
- **这一栏的栏内顺序**管的是：**模型读到的是一条时间线**。今天是从最早到现在（升序），
  而 `prompts.js` 第 9 条的指路原话也是「**一轮接一轮，从最早到现在**」。

⇒ 口径：**栏内保持升序**（时间线），**"从最旧那一端丢"照旧由额度守卫做**（`pack.js:1141-1167`，逐行装、整条收整条丢、记账只写一处）。
若取数层给回的是倒序，**投影那一步把它正过来**。
★**这一条是设计判断，不是实测**：有向取法（照因果上溯）取回来的顺序**本身带信息**，
把它按轮次插回时间线**会把"谁因谁而起"的顺序抹平**。好在**这件事在编年行的正文里就写着**
（`事件「X」——沿「Y」而来`）⇒ **抹平顺序不丢信息**。★实施时要**拿真账比对一次**再定（写进判据 J8）。

### 4.6 上限：**只认包的总预算**（不新增任何提案态数字）

- **不设条数上限**：`limit` 传 `null`（=不限，检索层本来就支持）；
- **不设字符上限**：★但这一格现在**表达不出来**（§3.2）⇒ 见 §8.1 第 4 条，要你拍；
- 唯一的真尺仍是我们**已经有**的那把：包总预算 + `trimPack` 的额度守卫。

### 4.7 ★★分两步走（这一条是本文最实在的建议）

| 步 | 做什么 | 硬标准 |
|---|---|---|
| **第一步：只接线** | 那一栏的取数改由 `recallLedger` 出（取法 = 与今天**同一批**往事），B2 用同一张表筛 ⇒ **模型看到的东西一个字不变** | ★**出包那一栏逐行相同** · 冒烟**终态 SSOT 8351 字节逐字节不变**（`leg117` 立的那把尺） |
| **第二步：改口径** | 才动"取哪一批"（窄口按未决事件的号照因果上溯 / 宽口最近优先 / 两者合并） | 先出**实测曲线**，再报批（`STATE.md` §2.3 第 2 条） |

**为什么必须先做"零行为变化"那一步**（`leg117` 的血证，原话）：

> 「**合并两处重复实现之前，先把两边的输出冻结下来**」——*"我觉得合并是等价的"不算证据，"逐行相同"才算。*
