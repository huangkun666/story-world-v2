## 0. 人话版：这会怎么样

世界现在有两笔欠账，都在"事件"这半边（盘算那半边 K13-K17 已经齐了）：**事件只生不死**——引擎只会在源盘算结算时闭环一条事件（K9 顺手做的最小面），波及链的尾巴永远悬着，而已经闭环的旧账也永远赖在账本里（100 tick 跑下来事件池 91 条、61KB，线性涨，无界）；**暗处不暗**——盘算标了 concealed（暗盘算）但推进照常进动态流，暗处的人其实站在灯下。这个细案把事件的"一生"补齐：**事件有终了**（链尾结清：波及链源头了结且涟漪平息后自动闭环；常驻的处境事件如实保留）、**事件有闸**（每 tick 产率上限，超了拒建留警告）、**旧账有书签**（已闭环的老事件按"热窗 20 tick"压成里程碑摘要搬进温层——摘要由引擎确定性生成，带全量 id 清单和上下游指针，链条不断，模型输入也从不含它们）；**暗处真正暗下来**（concealed 盘算的推进、委派、兑现不进动态流——露出水面的事件与终结照常上桌；数据窗口全局可见不变）；**谋划有后悔药**（模型可提议放弃盘算、带理由，引擎裁决终结+联闭，与出生对称——模型依然只有提议权）；**历史的真跑物证转正成回归防线**（7 份真模型快照转制成 fixture，引擎对历史真实输出跑回归，再锁一遍 12 条 newAgendas 真样本）。你看到的世界：因果链自己会净、暗处真的暗、谋划可以收手、历史可以翻阅也不会涨爆账本。

## 1. 目标与验收判据

**目标**：事件闭环完整（三型结清）+ 产率闸 + 摘要化归档（存储有界，长跑防线①落地）+ 暗处渲染 + 取消通道 + 快照 fixture 回归。

**配套曲线（本细案数据，铁律 8；K16 树冒烟同源 100t 逐 tick 实测）**：
- 每 tick 事件产率：max **4**（开局 t1-4）/ 均值 0.91 / 非零均值 1.12 / p50=1 / p90=1——稳态 1/tick；
- 源类型分布：plot **90** / state **1** / ripple **0**（树冒烟无波及链样本，链尾结清测试须补 ripple 样本）；
- 闭环率：**90/91** 闭环（K9 源结清工作良好）；未决事件稳态 **1**（良性流动平衡）；
- 事件池：91 条 → 61KB，~550B/tick 线性增长，**全部为"已闭环未归档"的堆积**（无界症状实锤）；
- 归档模拟（HOT=20 提案）：t30 起生效，终态 74/91 可归档、等效热池 17 条。

## 3. 设计

### 3.1 事件闭环三型（引擎，拍板点 T1）

| 型 | 判据（引擎裁决，模型无关闭权） | 编年 |
|---|---|---|
| **源结清**（既有 K9） | plot 源盘算终结（达成/败露/变形/取消） | "事件「…」闭环（源盘算已结算）" |
| **链尾结清**（新） | ripple 源：链头（沿 source.ref 上溯至 plot/state）已结清 **且** 落账已 ≥ 涟漪平息窗（提案 `CHAIN_SETTLE=5` tick）**且** 无未决下游引用（events 中 links.up 含本事件的未决事件不存在） | "事件「…」涟漪平息（链源已了结）" |
| **常驻保留** | state 源未决事件**永不自动闭环**（环境处境语义；K6 点名应答持续是特性） | — |

- 事件年龄从 id 契约解析出生 tick（`ev_<tick>_<n>`，hangEvents 唯一生成点，格式已锁）；闭环时写可选字段 `closedAt`（ssot.schema 扩展，供归档判龄；历史已闭环无 closedAt 视为可直接归档——旧账）；
- 落实：`closeEventsOfClosedAgendas`（settle.js:142）扩展为 `closeEvents`（源结清 + 链尾结清 + 取消联闭共用，见 §3.5），链尾判据逐事件评估（O(n) 扫描 links.up，n=事件数小，确定性）；
- 与 K6 发现的衔接：链尾结清让波及链尾巴自然收敛，点名应答窗口随之缩短（世界不自锁）。

### 3.2 事件产率上限（引擎，拍板点 T2）

- 常量：`EVENT_CAPS = { perTick: 6 }`（**提案**——曲线：max 4/tick 开局 + 波及余量；正式报批走报批支线，铁律 2/8）；
- 落点：settle 管线 gate → 出生裁判 → 裁定 → hurtWindow **之后、K9 影响通道与 hangEvents 之前**（超限事件先被裁掉再谈影响/挂链/编年）：
  - 按提议序保留前 N 条，其余拒建；警告"裁定: 事件洪峰（每 tick ≤≤N）：「title」被拒"；被拒事件不落账、不编年、不进影响通道（与盘算大厦顶同哲学——双面无痕于世界，留痕于 simLog）；
- 语义：上限是闸不是计划——从不主动造事件补数；常驻 state 事件受同一闸（其总数也因此有界）。

### 3.3 档案摘要化（引擎 + 契约，拍板点 T3；长跑防线①落地，"跟 GC 一起做"欠账清偿）

- **常量（提案，longrun §2.2 原值）**：`ARCHIVE = { hotWindow: 20, milestoneEvery: 10 }`——热窗 20 tick + 里程碑粒度 10 tick；曲线支撑：HOT=20 于 t30 起生效、100t 内归档 74/91；
- **契约（零破坏扩展）**：ssot 增可选 `milestones`（数组；缺省=旧世界合法）；事件增可选 `closedAt`；
- **里程碑形状**（链上节点，§4.3"剪枝只砍文本不砍链条"）：
  `{ id: m_<段末tick>_<n>, span: { from, to }, counts: { events }, titles: [全部标题], ids: [归档事件 id 清单], links: { up, down } }`——ids 使"任取归档事件可回溯"成立；
- **归档执行**（settle 末尾、recordMetrics 前，新函数 `archiveClosedEvents(world, tick)`）：
  1. 候选 = 事件中 `closed === true` 且（closedAt 缺失 或 tick − closedAt ≥ hotWindow）且**无未决下游**（同 3.1 链尾判据——保证整链结清才使指针跨段不悬）；
  2. 按出生 tick 段（段 = 10 tick 一档）分组；该段首笔归档时建里程碑（并入同段后续）；
  3. 段内事件移出 events 入里程碑 ids；段外遗留节点 links.up/down 指向段内 id → 改指里程碑 id；
  4. 里程碑是温层节点：**不进模型输入**（pack 只取未决 + 近 2 tick 关闭——自动剥离，零改 pack）、不进本 tick 动态流（不产生编年条目；可读性归里程碑阅读视图，UI 阶段）；
  5. 跨段解析防御：`resolveEventSource`（settle.js:88）上溯未命中 events 时查 milestones.ids（不变式的保底：未决事件链上游必在热池——归档条件保证，防御不删）；
- **度量**：simLog 增 `milestones` 计数（长跑防线 §2.5 四字段的扩展）；冒烟统计增里程碑数；断言更新（§5）。

### 3.4 暗处渲染（引擎编年侧，拍板点 T4；C2 拍板落地）

- **原则**（ANCHOR §6 拍板原文）：concealed 盘算推进不进动态流、露出水面部分照常；数据窗口全局可见不变（K10 不冲突）；
- **抑制面**（编年生成处抑制——引擎层 settle，渲染层零改）：
  - `applyAgendaAdvances`（settle.js:275）推进编年：agenda.visibility === 'concealed' → 不 push（memory.done 照写——数据属于账）；
  - `spawnAgendas`（settle.js:198）委派编年：新盘算 concealed → 不 push（父 memory.promises 照写）；
  - 兑现编年（settle.js:330）：子盘算 concealed → 不 push（父 memory.done 照写）；
- **上桌面**（不变）：事件条目（chronicleEvents——事件即露出水面）、终结三态（满步/取消——终结即上桌）、拆环、源结清联闭；
- **数据窗口不变**（renderStreams 格局行照列全部在飞盘算含 concealed——"数据窗口全局可见不变"明示拍板）；
- 与审查结论一致：这是"世界的好看"最后一环（三问自查③ 兑现后半）。

### 3.5 取消通道（契约 + 引擎，拍板点 T5；C3 拍板落地）

- **契约**（world-step schema）：required 增 `agendaCancels`（六组形状，全部既有构造点补键——机械，盘算树 K13 先例）：
  `{ agendaId: 必填, reason: 可选 }`——模型只提议放弃（带理由），引擎裁决；
- **校验**（check-step）：agendaId 必须在飞（存在且未 closed——"已结算盘算不可取消"）；玩家不可被取消也不可发取消（玩家非模拟主体，红线 1 三通道同哲学——agendaCancels 不涉 entity，天然无玩家通道，补一句防御）；
- **门控**（gate）：静默方 agendaCancels → 滤除（`silentDropped.agendaCancels` 计数，双面无痕——与出生对称）；
- **裁决**（settle 新函数 `applyAgendaCancels`，落点在 `applyAgendaAdvances` 之前——**取消先于推进**，被取消者当 tick 的推进落入既有 closed 拦截）：
  1. `a.closed = true` + `memory.blocked.push('放弃：<reason>')`（回查留痕）；
  2. 编年"盘算「goal」取消（owner）：<reason>"（措辞精确，不复用败露/达成）；
  3. 在飞子盘算（parentId === a.id 且未 closed）→ 断父链转独立 + 编年"遗留子盘算 N 项转独立（事业未竟）"（不悬挂已死之父——K15 托孤判序同哲学）；
  4. plot 源事件联闭（复用 §3.1 的 closeEvents，closedIds 传取消集）——"终结产果联闭"完整覆盖取消路径；
  5. 不记兑现/败露/达成（取消是独立结局，六态补全 §3④）；
- **不变式**：T3"模型无直接终结通道"保持——模型只有提议权，closed/结局全归引擎（取消与出生完全对称）；
- **prompts**：模板 + 第六组示例 + 字段说明 + 铁律 7 补"可提议放弃（agendaCancels，带理由）；盘算的出生、终结、取消全归引擎裁决，你只有提议与推进权"。

### 3.6 快照 fixture 转制（编排层 + 测试，拍板点 T6；快照 fixture 队列项落地）
