### 1.3 ★★★为什么**仍然不能**改成"让提示词别抽这几类"（leg74 的关键设计，本棒沿用）

`rules` 是**未分类的纯字符串数组**，类别挂在 `判据` 那一列（按位对齐）。词表一旦删掉这几类：
模型遇到"不算世界"的原文时**必须**塞进剩下两类之一 ⇒ 多半进「世界观设定」⇒
**再也认不出来、清不掉**，而「世界观设定」**是进包的** ⇒ 杂物会**混进每轮包**（比现在坏得多）。
⇒ 定稿：**词表保留 = 丢弃标记**，模型**照标**，**记账边界确定性丢弃**。
★丢弃凭**模型的标注**，**不靠关键词猜内容**（本仓明禁过拟合；猜错会误删真法则）。
★代码里这条口径写在 `abstract-tier.js` 的 `RULE_CLASS_STYLE` 头注 + `pruneJunkRules` 头注两处，
★判据里也锁着（`RULE_CLASS_GUIDE` 必须**逐类点名**三类都不进账本）。

### 1.4 唯一一份"哪几类不进账本"

```js
export const RULE_CLASSES_DROP = [RULE_CLASS_STYLE, RULE_CLASS_VAR, RULE_CLASS_MISC];
export const RULE_CLASSES      = ['判断依据', '世界观设定', ...RULE_CLASSES_DROP];
export const RULE_CLASSES_PACK = ['判断依据', '世界观设定'];   // 进包的两类（与"留账的两类"天然一致）
```
★判据锁：`abstract-tier.js` 里那三个类别字面量**恰好各一处**（就是那三个常量）；
`abstract.js`/`settle.js`/`pack.js` 的**代码**里一处都不许有（摘除只许走 `pruneJunkRules`）。

### 2.5 ★★★本棒自查发现的**真缺陷**：孤儿键（leg74 没照到）

1. **陈旧键的值是"保留类"** ⇒ 第②步只清"已废弃类别"的值，**不碰它**；
2. 它**不在 `list` 里** ⇒ 第①步 `for (const s of list)` **遍历不到它**
   （★所以 `delete kinds[s]` 那句**与这条缺陷无关**——本棒实测证实，见下）。

**实测**（`leg75-diag-bite3d.mjs`）：`rules=['…（补）'] + kinds={'…（说法）':'判断依据'}`
⇒ **旧版留下 1 个孤儿键**；而判据 ① 那条"防孤儿键"的自证夹具里，陈旧键的值恰好是**已废弃类别**
（被第②步清掉了）⇒ **它只覆盖了两条来路里的一条**。

**治法**：`pruneJunkRules` 末尾加**第④步"按 `kept` 白名单收口"**——
`ruleKinds` 只保留"账上真有的那几条"的键 ⇒ **问什么答什么**，不再依赖前三步的巧合。
**判据**：新增 `★★★leg75：孤儿键必须扫干净`（含"先确认这一轮真的发生了摘除"与反向自证）。
