## 5. 三件的做法与判据（含先证红）

### 5.1 ① 模型调用那道门（`src/transport-http.js`）

**治法**：缺省发送器 **`pickSender()`**——有 `XMLHttpRequest` 就用 **XHR**（别人的补丁只包了 `fetch`，
**另一套 API 碰不到它**），没有（Node：demo / scripts / 判据）就用原生 `fetch`。
★**为什么不"把 fetch 抄一份留着"**：抄的那一份**谁先加载谁说了算**，赌不过别人的加载顺序；
XHR 是**形态上**的隔离。★显式注入的 `fetchImpl` **仍然优先**（判据与 demo 走这条，零扰动）。

**契约一个字没改**：仍只发 `messages:[{role:'user',content:prompt}]`；超时/中止语义照旧——
`xhrSender` **忠实照抄真 fetch 被中止时的形状**（抛 `DOMException`、reason 不参与），
与 leg93d 那条判据锁的形状**同形**（否则状态条上又会出一句看不懂的英文）。
网络层失败给人话「连不上模型服务（network error）」——`isTransientCallError` 认这一类（链路断要重试）。

**如实报一句**：`pageFetchLooksPatched()` ＋ 一次性日志——**只在浏览器里回答**
（Node 的 `fetch` 本来就是 JS 实现，拿它当"被换过"是**假话**），且**只在真被换过时**出声。

**判据**：`test/transport-channel.test.js` 8 条。**先证红内建**：同一个假补丁显式当发送器用 ⇒
请求体里**真的多出一条**外来消息（旧写法会漏，新写法一条都不多）。
