## 1. 位置收成「地图」入口（用户拍板）

**问题**：上一棒把 563 张卡压成 21 组（231 KB → 36 KB），但**整片铺开**——21 组 + 390 人的「位置未载」筐一展开，**动态流被挤到下面看不见**。用户原话：「有是有但是太拥挤了」。

**改法**：侧栏位置区收进**原生 `<details>`**，入口就叫「**地图**」，**默认收起**，开口只报一行摘要：

```
地图   20 处 · 173 人有处可循 · 未载 390 人
```

- **不用新组件**：本仓已有两处同款折叠（`.sw2-milestone` / `.sw2-source-alt`），样式按它们写。
- **★纪律：折叠 ≠ 删除**。内容与「未载 ≠ 在别处」的口径文案**全留在 DOM 里**。理由两条：
  ① 「未载 ≠ 在别处」这条口径是靠那段说明文案承载的，删了就等于把口径删了；
  ② 现有回归锁断言的是**内容与 class**（`sw2-locgroup-name">江州` / `位置未载…书里没写`），真删了会当场红——那正是"别把呈现改版做成功能删减"的防线。
- **实测**：旧形态 36073 字节 → **默认态 175 字节（206×，省 99.5%）**；点开后仍是 **20 组 + 未载筐 + 584 个 chip**（零删减）。
  - 开口那行现在是 `20 处 · 177 人有处可循 · 未载 386 人`——**比上一棒的 173/390 多了 4 个有位置的人**：因为本棒 P3 接通了「大虞」等归属，而 `deriveLocationFromBook` 会顺着组织条目把新成员的驻地一起推出来（同一批改动，位置列顺带受益）。

## 2. P1：无地名表的书（★交接的验收判据是「空绿」）

**交接原判据**：「拿 `三国`/`春物`/`re0` 真跑一次，证实**推出 0** 且一个错值都不写」。

**★这条判据实测是空的**：没有地名表的书，位置集会退化成 `['未明']`（`derivePositions` 的兜底词）。这时函数**不会早退**（`positions.length` 是 1，不是 0），但**结果必然一样**——因为 `normalizeToPositionSet` **显式把兜底词 `'未明'` 排除在包含匹配之外**（`p !== LOCATION_FALLBACK`），所以任何 key 串或正文串都归一不到任何值 ⇒ `cand` 恒空 ⇒ 推出 0，**一个实体都没被写过**。

**所以「推出 0」在这 5 本书上是必然的、验不到东西的绿。** 把这条当验收判据，等于**用一句必然为真的话证明机制是安全的**（这正是本仓最怕的"测试全绿而接线是断的"的同款病）。

**真正危险的是另一半**：**没有地名条目、但正文有「所在地/驻地」串**的书（三国 16 / re0 12 / 春物 2）——位置集**非空**（那些串自己会成为位置集项）、**闸门是开的**，这时才可能写错值。

**实测结果**（两套 canon 都跑：①只有地名条目 ②带驻地串；判据 = 推出 0 且一个错值都不写）：

| 书 | 位置集 | 推出 | 判据 |
|---|---|---|---|
| Eldoria / Global / re0 / 春物 | 1 项 `['未明']` | 0 | 合规（平凡 0） |
| 三国（带驻地串） | 3 项 | **1**（`用户信息→汜水关`） | **逐条查证是真归属** |

三国那条**不是张冠李戴**：`[用户信息]` 条目正文原文就是 `所在地域: 汜水关`。⇒ **P1 结论：无地名表的书上一律「不生效」，一个错值都没写（不共线成立）。**

### 2.1 顺手挖出并修掉的真缺陷：「所在地域」幻影地名

追那条三国结果时发现：驻地正则会命中「**所在地域**」的**前缀**。

```
正文： 所在地域: 汜水关
旧正则 /(?:所在地|核心底蕴|驻地)[:：]?\s*(...)/   →  抽出「域: 汜水关」   ← 碎片！
```

碎片经位置集/归一后就是**幻影地名**（违反「引擎不发明地名」）。八本书里「所在地域」出现在 **2 本**（三国 2 处）。

**修法（`src/entity-lookup.js`）两处**：
1. **汉字边界** `(?![\u4e00-\u9fff])`：字段名是**汉字词**，后面还跟汉字说明这条不是该字段（如「所在地不详」）。**这是形态判据，没有词表。**
2. **扫全部命中而非只取第一条**：旧法正文里第一处是个幌子（「所在地不详」）或不该收的段落时，**后面真正的「驻地: X」永远读不到**。

**★我自己写歪又被自己否掉的一版（如实留档）**：先加了「所在地域」变体 + 一个 `!m[1].includes('域')` 的守卫——那个守卫是**"用词表判语义"**（`ANCHOR.md` §2 明令禁止），且会**误杀「须弥界域」这类真地名**，当场撤掉，只留形态修正。

**残留如实登记**：仍有 3 处碎片来自 `[mvu_update]变量更新规则]` 这种**机器条目**（`string;` / `check:`），不是人类写的驻地数据。它们照旧被 `∈位置集` 闸挡掉（**用户账上位置集实测 60 项、判为碎片 = 0**）。**不为它加噪声过滤器**——那是新判据，得先报批。

## 3. P2：9 条 `parentSource` 漏打（+ 一个"老账补不上"的坑）

**交接叙述经实测成立**：9 条全是 `faction → character`（子势力→皇帝角色），parent 的 kind 分布 `{"character":9}`、自己的 `{"faction":9}`。

**根因**：`abstract.js` 子势力折叠那条路（上级是在册**角色**时）只写了 `ent.parent`，**没写 `parentSource`/`parentSourceFrom`**；而第三遍的 `if (ent.parent) continue;` 正好把它挡在**会写来源**的那条路之外。

**修**：①那条路补打来源（用已有的 `declaredParent` 判"照书办" vs "模型抽取"）；②`declaredParent` 的构造**提前**到子势力折叠之前（它原本在第三遍才算——**改完当场撞 TDZ**：`ReferenceError: Cannot access 'declaredParent' before initialization`，被 `book-tags.test.js` 现行锁抓住）。

**★但只改这条路，老账补不上**：`pushEntity` 对**已入账**的实体直接返回 `null` ⇒ 用户账上那 9 条**永远不会被重新赋值**。实测：改完仍是 `缺来源 9`。⇒ 按本仓 **「名册落账做成可重入」的既有治法**，加**一步幂等回填**（只补空位、只认"上级是统治者"、挂在加载期收口里）。

**实测**：真账 **缺来源 9 → 0**；来源分账 `{模型抽取:93, 结构推导:89, 模型抽取(未验证):22}`。

## 4. P3：`虞昭华 → 大虞`（★四版机制，前三版被自己的多书测量否掉）

**用户定论**：虞昭华是大虞的。**真因**：

```
canon 势力：  大虞（kind=faction，在册）
书条目：      人族皇朝（key 第一项就是「大虞」）
正文：        代表人物:
              - 虞昭华（女，T8大乘中期）：大虞女帝。…
```

`resolveCanonName('人族皇朝')` **无解**——`大虞` 与 `人族皇朝` **双向子串都不成立**（"朝代" vs "人名+朝代"）。而 canon 条目**零正文**（实测 699 条只有 `name`+`kind`），正文只在书条目里 ⇒ 接不上的唯一原因是**名字没关系**。

### 四版机制（前三版全被否掉，这是本棒最重要的方法论记录）

| 版 | 改法 | 多书实测 | 结论 |
|---|---|---|---|
| ① | 改**归一尺**（双向子串） | 对 `大虞`↔`人族皇朝` **无解** | ✗ |
| ② | 认 **key 当别名**（任意条目 key 命中任意势力名） | **三国 735 条**（`if→貂蝉`）· **大荒 10087 条** · 自指 **225** | ✗ 炸 |
| ③ | 收窄：只从 **canon 势力**出发 + key 精确 + 该条目**像花名册**（≥2 成员行） | 真账真正新写入 **8 条**、逐条有据、自指 0 | ✓ |

**第 ② 版为什么炸**：那些书里 **key 是任意关键词表，不是别名**（三国书 key 里是「绝对禁止使用《新三国》标志性魔改台词」这类审查规则）。

**★方法论**：单看大荒手挑的那 8 条，**前 3 版都"对"**。是**「改判据前先多书出数」这条规矩救了场**（`demo/measure-leg25g-p3-genericity.js` / `-scoped.js`）。

**最终影响面（真账）**：**真正新写入 8 条**——

- `虞昭华` / `秦红袖` / `沈天君` → **大虞**（成员行来自书条目 `人族皇朝`）
- `瑶池圣母` / `灭情师太` / `蟠桃树灵·夭夭` / `青鸟` / `叶清璇` → **瑶池圣地**（来自书条目 `隐世圣地·瑶池`）

**逐条查证全部是书里的成员行形态**（「代表人物:」下的 `- 名号（…）：…`）；**自指 0**；**账上原有归属不覆盖**（明述优先）；走生产链 **8/8**、**幂等 ✓**。

**三道闸缺一不可**（写进代码注释，防回退）：①出发点只能是 **canon 里 kind=faction** 的条目；②只认**精确等于**该势力名的 key（不模糊）；③该 key 名在那个书条目下**必须本身像花名册**（≥2 条成员行）。

**★闸③是必要不充分**（如实登记）：实测确有"设定段落恰好含 ≥2 条成员形态行"的碰撞（真账里 `人族` 会靠 `[寿元]` 拿到散文碎片）。真正把炸点收住的是**闸①+②**。所以残留的"扩面"里大部分**不产生实际写入**——因为那些"成员名"根本不在 canon 名册里。
