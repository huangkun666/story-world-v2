## 3. 关键决策与实测发现（全部有台账条目可查）

1. **落子契约 v1 经活档实测定稿**，六发现：OOC 元指令层必滤（继续/更新变量/重写密集出现）；玩家侧位置几乎只以代词出现 → location 可空；对象用简称（小娥≠白小娥）→ 别名表必需；玩家自称不得作对象；对象不止实体（灵脉）→ 双名单；条件句真实存在 → 切片取主动作、残余为已知限制（未决点 1 深化项）。
2. **未提取落子的回合照常结算**（OOC/静默也给世界推进），注入无行迹行——世界步原料=世界自身状态（§3②）。
3. **真 schema 强制在真模型下被证明有效且必要**：首跑 8/8 字段名漂移（verb→action、attr→field、step 漏写），全部被拒、世界如实不动；修复 = prompt 内嵌显式 JSON 模板（沿用旧项目"JSON 结构由 prompt 显式模板约束"教训）。
4. **满步重播 bug**：已结算盘算（5/5）继续被推进成 8/5 且每 tick 重唱"达成"。修复：pack 排除 closed 盘算 + 结算器拦截（警告+跳过）。
5. **可省字段禁写 null**（target:null 被拒）→ prompt 硬性说明。
6. **薄裁定器已经在真世界工作**：万法阁 hardPower 被连续 stateChanges 打击 0.9→0（打崩），薛铁衣 0.8→1.0，属性边界全部钳制并记警告——**"分量"数据流已在运转，只差引擎拿它做决策**。
7. **齐步走问题**（实测确认）：所有实体每 tick 都推进，没有"谁这轮不值得动"——分量引擎的验收判据由数据指明：**低分量方应静默**。
8. **旁观指数 8/8**：世界不围绕玩家也能自己转（围谷→破阵→突围→镇压→分赃完整一战，波及链双线）。活演示夹具曾把活档的主角中心一起抓进来——知错记录在台账。
9. **事件闭环不存在**（切片已知限制）：未决事件只增不减（一轮 18+ 条）；**盘算创建路径不存在**：模型无法开新盘算 → 盘算全结清后世界进入"余波模式"（只产波及事件）。两者都属后续阶段（GC/因果链强化、盘算树）。
10. **酒馆预设接入**：旧插件 llmPresets 存在 ST settings.json（含明文密钥，运行时本地读取、不落库不打印）；活跃预设 = gemini-3.1-pro-preview @ gcli.ggchan.dev（base 需 /v1 结尾，已自动归一化）。
11. **黄金三锁**（引擎确定性逐字节锁 / 标准 tick 锚点锁 / 体积锁）与 65→74 测试体系，全部纯函数可回归。
