## 1. 熵泵：删的、留的、改的（用户点破的三件事逐条落地）

### 1.1 用户的三问，各自答出了什么（这是本棒的理解基础）

1. **「熵泵怎么算的」** ⇒ `src/entropy.js` 全文 87 行，**四行代码就是全部**：
   `phase = floor(tick / ENV_TICK)`（**只看 tick**）→ `sawStep` 查一张写死的 down/up 表 → `±0.06` → 钳 [0,1]。
   **输入只有 `tick` 一个数**：不看账本、不看事件、不看谁在打谁、不看玩家做了什么。
2. **「它怎么知道民生这些属性」** ⇒ **它不知道，而且结构上不可能知道**。"民生度 0.20"要成立，先得回答"以什么为刻度、拿什么当基准"——书里、账上都没有答案。那个数是**被"选"出来的，不是推出来的**。真正让它有含义的是 `BANDS` 里**写死的四条模板**（「熵泵·民生凋敝：劳役征发四起」…）。
3. **★「那不就是几句固定文本吗，这也叫事件？」** ⇒ **这一刀是对的，而且比"算不出民生"更根本**：
   引擎认的是**记录的形状**（能当上游引用、能当盘算挂因、能闭环、进张力计数），**不认 title 写了什么** ⇒ 一句抄来的台词照样混过全部校验。**它不是事件，是一个"看起来像成因的占位符"。**

### 1.2 删 / 留 / 改

**删（全是编出来的，无任何引擎消费者）**
| 删掉 | 为什么 |
|---|---|
| `ENV_KEYS`（民生度/动乱度/天时/张力推手四个 0~1 的数） | 片3 之后**没有任何判据读它做决定** |
| `SAW` 锯齿表 + `ENV_DRIFT_STEP` | 就是那四行"只看 tick"的推演 |
| `BANDS` 危险带/回缓带 + `render.js` 的 `envBand` | 给那四个编出来的数配的判态 |
| **四句写死的事件台词** | 引擎替世界宣布事实 |
| `patchDynamic`（引擎独占的数值写通道） | 唯一调用者是锯齿推演；**已加"不得复活"测试锁** |
| `abstract.js` 的 `ENV_INIT_BASELINE`(0.5 基线) | 档位没有"基线值" |

**留（真机制，一条都不是修辞）**
- **每 `ENTROPY_TICK`=3 一拍**：全引擎**唯一不看模型脸色**的东西。
- **「到点出声 / 世界动了收声」这个循环**：它是**唯一会自己闭环**的事件——`plot` 源要等源盘算终结、`ripple` 源要等涟漪平息窗、而**模型提的 `state` 源事件永不自动闭环**（`settle.js:176` 常驻保留）。
- **它是未决事件的"保底供货商"**：模型可以连着很多轮不提事（提示词规则 6 明写"没有就输出空数组，不要编造"），熵泵保证不会连续很久一件新货都没有。
  ⚠ **本棒之前我说错过一次**：我曾说"拿掉熵泵 `event` 源会枯竭"——**不成立**（模型自己能提）。**池子不会枯竭，只会无限膨胀**（模型提的 state 源事件只进不出）。熵泵的独特性在**闭环那一半**，不在供货那一半。

**改定义（本棒核心）**
| | 旧 | 新 |
|---|---|---|
| 出声条件 | 编出来的数越阈 | **账本自己能证明的事实**：`tick - 最近一条真实事件出生轮 ≥ QUIET_WINDOW(10)` |
| 收声条件 | 数字回摆 | **世界真动了**（有真实事件落在本熵泵事件之后） |
| 落账内容 | 抄来的台词 | `天下安稳：已 N 轮无新事上桌`——**轮数可由账复核** |

**两条对抗式细节（都是写测试时踩出来的，别改回去）**
1. **熵泵不许自己把自己哄睡**：`lastRealEventTick` 必须跳过 `ev_pump_*`，否则它出声后自己就成了最新事件 ⇒ 永远不静默。
2. **静默锚点与标题必须同一个**：没有真实事件的历史从 **t0** 算起；第一版只用 `max(lastReal,0)` 算标题、用 `-Infinity` 算条件 ⇒ 出现"检查说安静、标题说 Infinity 轮"的自相矛盾。

## 2. 世界参数：档位 + 自变量/因变量（含一次返工）

### 2.1 档位（新模块 `src/params.js` 是唯一真源）

```
民生度:   崩溃 | 艰难 | 尚可 | 富足
动乱度:   太平 | 小乱 | 动荡 | 大乱
天时:     大灾 | 失调 | 平常 | 风调雨顺
张力推手: 沉寂 | 平缓 | 暗涌 | 紧绷
```

- **值是"人话档位原话"**（不再是四个数），**玩家可选、引擎照抄**——与既有先例 `canon.powerScale`（力量谱系档位，每本书自己那套档位名）**同形**。
- 契约层：`dynamic.env` 由 `numRecord` 改 **`strRecord`**（`src/schema.js` 新增该 kind）；抽取侧 `sanitizeCanon` 只收本表档位词，数值/表外词**弃键并留痕**；`resetDynamicLayer` 的 env 由"回四键 0.5"改**清空**（空着就是空着）。

### 2.2 ★返工：用户截图指出「这都是因变量啊，参数要调的应该是自变量」

**我上一版把四个键一律做成了下拉旋钮**——而**民生/乱象是因变量（结果）**。给结果做旋钮 = 面板**假装**"拧一下结果就变了"，而引擎既没有那个函数、也没有那个资格（它不发明事实）。

**改法**：`PARAM_NATURE`（在 `src/params.js`，**不是装饰，它决定面板上能不能当旋钮**）：

| 键（面板词） | 性质 | 面板 |
|---|---|---|
| 天时 | **自变量**（给定的条件） | ✅ 给下拉 |
| 张力推手（时局） | **自变量**（外压） | ✅ 给下拉 |
| 民生度（民生） | **因变量**（结果） | ❌ **只呈现** |
| 动乱度（乱象） | **因变量**（结果） | ❌ **只呈现** |

因变量区文案：**书里写了就照书里的词显示，没写就「未定」+「书里没写 ⇒ 空着（引擎不替它算）」**。页面口径句：**能拧的只有自变量**。

**为什么不给因变量编个推导函数**（这是我刻意不做的）：那需要"天时=大灾 ⇒ 民不聊生"这类**世界知识**——写进代码就是引擎在编书。⇒ **引擎只记账与照抄；因果链让模型去讲。**

### 2.3 UI 重复渲染（截图里的「未定未定」）——两处都是我的错

| 位置 | 错法 |
|---|---|
| `renderParamsHtml` | 「当前档位 值」之外**又**打了一个同义小 chip |
| `envRowHtml` | 值已经是「未定」时**又**打一个「未定」标签（信息带 4 行全中） |

**修法**：值只呈现一次；chip 改成不会与值同字的「无据」。

## 3. 记忆投递（用户自己发现的裂缝，用户给的解法）

### 3.1 病的准确名字

> **RP 注入只有本 tick 的 `【世界动向】`（带因果指针的编年行）**，位置/格局/旧账**都不进注入**，而注入是 **append-only**：旧行被上下文窗口挤出 ⇒ 模型忘 ⇒ **它就开始自己编**。⇒ **真相（账）与对话（笔）之间没有桥。**

### 3.2 为什么投记忆插件，而不是我上一轮提的"自建锚块"

用户一句点掉：**「其实只要将发生的事提交到记忆插件就好了」**——"记住发生过什么"本来就是记忆插件的活，**不该自己写一个更差的记忆**。

### 3.3 ★读实的插件事实（决定实现路线）

| 项 | 事实（都在真码里） |
|---|---|
| 公共接口 | `window.YuzukiMemory.*`——`MemoryTagParser`（`extractMemoryRows`/`applyRowsToState`，**纯函数**）· `VariableInjector`（`buildMemoryText`…）· **`Storage.loadState/saveState`** · `GlobalSettings` |
| 记忆语法 | `<Memory>` 包裹 + `#表名` + `[主键] \| 字段：值` |
| 存放 | `chatMetadata[<key>].records[表ID] = [{ id, hidden, values }]` + localStorage 镜像 |
| 注入 | 预设里的锚点消息带 `{{MEMORY}}` / `{{MEMORY_TABLE_表名}}` → 插件在 `CHAT_COMPLETION_PROMPT_READY` 把记忆**克隆成 system 消息**插进请求体 |
| **★关键** | **它的自动总结跳过 system 消息**（`task-runner.js:296/307`） |

⇒ **所以走"代码级直接写记忆表"**：走它那条文本抽取路，等于让它的 LLM **把引擎事实再总结一遍 = 意译一次**（正是本项目一路在躲的事）。**逐字投引擎原话、不经过任何 LLM。**

### 3.4 交付物（`src/memory-bridge.js`，编排层纯函数 + 依赖注入）

| 表 | 口径 |
|---|---|
| **世界状态** | **一表一条、每轮覆盖**：世界 / 轮次 / 参数档位 / 各归何处 / 在办之事 / 未了结之事 |
| **世界大事** | **只收已了结**（在飞的归状态表，不重复占地）、追加、最新在前、≤60 条 |
| **史卷纪要** | 里程碑（引擎结构摘要）≤12 段 |

**四条口径**：**逐字原话** · **剥掉引擎内码**（`ev_143_2`/`a_12_1`/`e_bk_7` 对聊天 LLM 无意义）· **按闭环不按 tick**（位置那一仗的教训：563 卡平铺 231 KB）· **失败零阻塞**（插件没装/抛错都只是"这次没投上"）。

**web 接线**：`memoryStore()` 适配器走插件自己的 `Storage.loadState/saveState`（读不到就用它自己的 `createDefaultState`，**不自己造形状**）；投递挂 `setupAsyncTicks` 的 `save` 回调（每轮落盘后）；**开关** `memoryEnabled`（参数页，**缺省关**；打开时立刻投一次）。

## 4. 我方的错（如实留档）

1. **★"供货商"那个判断我说错过**：曾断言"拿掉熵泵 `event` 源会枯竭"——**错**，模型自己能提事件；真相是**池子不会枯竭、只会无限膨胀**。是用户追着问"未决事件是啥/怎么生成"才逼出来的。
