### 4.6 ★技术结论：tools 为什么必然是两趟（用户当场追问的）

- **两趟不是 JSON 的错，是 tools 这个协议的形状**：你第一趟带上"可用工具清单"，模型若决定用，
  **它那一趟根本不写答案**——只回一句"我要调 X、参数是 Y"（**答案那一格是空的**，东西在 `tool_calls` 里）。
  工具**只有调用方能执行**，所以必须执行完、把结果**再发一趟**，模型才写得出最终答案。
- **JSON 那道冲突是另一件、且是接口层的**：现在请求里写死了"只许回 JSON"
  （`src/transport-http.js:93` 的 `response_format: { type: 'json_object' }`），**它和"可用工具清单"同时给，
  多数接口直接报错** ⇒ 要用 tools 得先撤掉这道强制（★代价：**强制没了，解析就没那么保险**）。
- **★唯一绕开两趟的办法是不让模型发起**——由引擎在出包那一刻自己取（`相关往事` 那条路）。**那只要一趟**，
  因为**取数发生在模型开口之前**。
