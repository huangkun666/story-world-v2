## 1. 病与治法

### 1.1 ★★★ 病：三件长活儿跑起来"看不出来在跑"，连点就白花一份钱

| # | 处 | 现状（逐行取证） |
|---|---|---|
| ① | `bus['reextract-setting']` | 一进门就跑 `extractWorldSetting`（多块 + 块间合并）——**真账实测 20–30 分钟**；期间按钮照旧可点、界面照旧，状态条只在开头写一句"只重抽设定中…" |
| ② | `bus['extract-scales']` | 一次模型调用，也是分钟级 |
| ③ | `bus['adopt-scale-draft']` | 采用草稿要写账 + 落盘，也会卡一下 |
| ④ | 三处**都没有闸** | 连点两次 ⇒ 两个处理器并发跑 ⇒ **两串模型调用**（白等一份时间、花两份钱；采用那一条还会两笔覆盖写账） |

★**为什么它排在 B 类最前**：另外几条是"话说得不好"，这一条**会真的多花钱、且会写坏账**。

★**仓库里已有现成做法，本笔照抄不新造**：
- `web/param-panel.js` 的**忙闩**：`bus['set-param']` 就是 `get → 有就出声 / 没有就 set → finally delete`；
- `src/async-tick.js` 的 `createTickQueue`：并发时返 `{ ok: false, skipped: 'busy' }`（推进一轮的连点保护）。
  ★本笔**不碰**它——那条闸已经有了，leg108 只补了"被挡住要出声"。

### 1.2 ★★★ 治法：新模块 `web/long-task.js`（四件事，一件都不许多做）

`createLongTask({ win, setStatus, log })` 交出 `wrap(action, label, fn)`：

1. **闸**：同一个动作已在跑 ⇒ **立刻返回、绝不并发**。★**这一条不依赖 DOM**，是真正的保证。
2. **出声**：被挡住时状态条写「⏳ 上一次还在跑（<人话名字>）——这一下没有重复发」
   （口径与 leg108 给「推进一轮」补的那条一致：**被挡住不许静默**）。
3. **看得见**：`[data-action="<动作>"]` 的**每一枚**按钮置 `disabled`、文字改成「正在跑…」，
   跑完/抛错都**还原成原文字**（原文字原样存下来，不许自己编一个）。
   ★**如实说清它的边界**：长活儿跑的时候面板会重绘、会把那个按钮节点换掉 ⇒ "灰掉"是**尽力而为**；
   本模块**不去猜**新节点该写什么（`isConnected === false` 就一个字都不碰）。**真正的保证是第 1 条那道闸。**
4. **收尾**：`try/finally` 释放闸——**抛错也必须释放**，否则那一格被永久挡住。

**接线三处，每处只改两行**（注册那一行与结尾那一行），`web/index.js` **净增 0 行**：

```js
bus['extract-scales'] = longTask.wrap('extract-scales', LONG_TASK_LABELS['extract-scales'], async () => {
    …原主体一字不改…
});
```

### 1.3 ★★★ 撞上行数硬锁：细案的账算错了（本棒最该带走的一课）

`web/index.js` 有一条**硬锁**：**不许超过 3100 行**（`test/web-view-state-layout.test.js:339`）。
leg108 交棒时它是 **3096 行 ⇒ 余量只有 4 行**。

细案 §2 写的是"这种包法**净增 0 行**"——**那笔账只算了一半**：它算对了三处 `= async () => {` → `});`，
**漏了"新模块还得被 import 一次、还得建一次"**。实测：

| 项 | 行数 |
|---|---|
| `import { createLongTask, LONG_TASK_LABELS } from './long-task.js';` | +1 |
| 三处 `wrap` 的接线（同一行内改） | 0 |
| `const longTask = createLongTask({ setStatus });` | +1 |
| 说明注释（两行，已经压到最少） | +2 |
| 空行与 import 前那一段说明 | +5 |
| **合计** | **+9 ⇒ 文件涨到 3105，破锁 5 行** |

**处置（照本仓纪律，一步没跳）**：**先量后说**（把真实行数摆出来）→ **停下报因** → 用户问"啥意思"⇒
**用大白话重说一遍** → 用户裁「**甲：搬出状态条那两小段**」→ 搬。

**搬法**：新文件 `web/status-bar.js`，装三样——
① `setStatus`（写状态条那行字）② `reportTrouble`（未捕获异常那一句）③ `injectCss` + `CSS_HREF`（挂样式表）。
⇒ 接线层 **3096 → 3089 行（余量 11 行）**。

★**两个必须记住的细节**：
- `CSS_VERSION` 那个号**没有搬**：`test/render.test.js` 是按 `web/index.js` 里那行 `const CSS_VERSION = '…'` 取值的，
  连"样式表内容指纹"那条判据都挂在它上面 ⇒ **改号仍只改那一处**，模块只负责"把号拼进地址"。
- ★**顺手收掉一处"两个写手写同一格"**：`onWinError` 原来自己 `document.getElementById('sw2_status_text')`
  写一句话，与 `setStatus` 是**同一个格子的两个写手**（本仓最忌讳的"两份真相"，虽然只是显示层）
  ⇒ 现在它调 `reportTrouble`，全仓写状态条只有一条路。

### 1.4 ★★ 反向自证三轮（在副本上做，绝不原地重写）——并因此修掉我自己判据里的一个真缺陷

| 轮 | 故意改坏 | 结果 |
|---|---|---|
| ① | 把闸拆掉（`if (inFlight.has(action))` → `if (false)`） | **2 条红**（①闸 · ④出声） |
| ② | 把 `finally` 里的 `inFlight.delete(action)` 注释掉 | **2 条红**（②反向对照 · ③抛错也要放闸） |
| ③ | 把 `undoBtn()` 注释掉（不还原按钮文字） | **2 条红**（③ · ⑤看得见） |

★★★**第①轮当场咬出我自己判据里的一个真缺陷（最值钱的一条）**：
判据第一版是直接 `await wrapped()` 取第二次的返回值。闸一拆，第二次调用**不再早退**，而是
**并发跑进内层**、跟着一起 `await` 那道永远不放开的 gate ⇒ `node --test` **挂死**
（跑满 180 秒超时被杀，**一条红都没印出来**）。
★**挂死比红更坏**：红会告诉你哪儿错了，挂死只会让你以为"测试跑得慢"。
⇒ 定稿加了一个 `settled(promise, 2000, …)`：等 2 秒没回来就当场判红，并印出
「**它没被挡住，而是并发跑进去了**」。⇒ 反向自证从此得到**一条干净的红**。

★**过程留档（本仓纪律：在副本上做）**：三轮都在 `%TEMP%\sw2-leg109-rev\`（整棵 web/test/src 的副本）上做，
**绝不原地重写**；做完删掉副本。工作区从头到尾没有被"改坏—改回"过。

## 3. ★★ 本棒踩的坑（下一任照做，能省一整轮）

1. ★★★**细案里的行数账要自己复量**：细案是"提案态"的账，写的人可能漏算（本棒漏的是"import + 建一次"）。
   ★**行数余量只剩个位数时，先把"新模块要几行"算清楚再动手**——本棒是先改了才发现破锁，白走一轮。

   ★挂死比红更坏（本棒实测：挂死 180 秒，一条红都没印出来）。

   ① `CSS_HREF` 用 `import.meta.url` 算路径（两个文件同在 `web/` ⇒ 算出来同一个串，已核）；
   ② `CSS_VERSION` 被 `test/render.test.js` 按 `web/index.js` 取值 ⇒ **号不能搬**；
   ③ `injectCss` / `setStatus` 全仓没有别的引用点（grep 实测）。三条都查过才动手。
4. ★★**用户说"啥意思"就是"你说的话我没懂"，不是"你再说一遍"**：本棒第一次解释时夹了英文

5. ★**判据的第一版写错要如实留档**：第 ⑥ 条第一版写成"接线层里不许出现那三句人话"——太钝，
