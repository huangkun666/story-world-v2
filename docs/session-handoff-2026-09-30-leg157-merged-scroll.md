## 1. ★★★ 交付一：观棋页滚轮（用户令「顺便把下拉的bug解决了」）

### 用户原话（逐字）

> ①（上一棒）「**还有我滑到最底部滚轮就失效了**」
> ②（本棒追问"下拉是哪个"时）「**不是，下拉是我在观其页滚到最底部滚轮就失效了拉不上去了**」

### 真因（**量到的**，装置 `F:/deepseek/tmp/leg157-scroll/`）

`web/style.css` 的 `.sw2-merged-grid{height:100%}` 里那个 **`100%` 解的是"页内容盒"的高度**，
而 grid 上面还压着**说书页头 ＋ 信息带** ⇒ **页永远多出"恰好这么高"的一截要滚**
（实测 `page.client=751 / scrollH=1000` ⇒ 余 **249px**，与"页头＋信息带"同高；**与屏幕大小无关**）。
而两栏各带 `overscroll-behavior:contain`（那是"两列各自滑"要的闸）
⇒ **指针在栏里时那一截够不着**：把页滚到底、指针回栏里（栏在顶）再往上滚 = **一个字都不动**（实测 `page 249→249 · main 0→0`）。

### 五臂对照（同一台装置 · 1080 高窗口 · 真滚轮事件）

| 臂 | 页幻影滚动 | ⑤"滚到底再往上拉" | ④滚轮漏给面板后面那页 | 两列各自滑 | 结论 |
|---|---|---|---|---|---|
| **基线（leg156 交付态）** | **249px** | ★**拉不动（就是用户报的那一句）** | 0 | ✓ | 病 |
| **甲**（leg156 推荐：撤外层 contain） | 249px | ★**拉不动** | 0 | ✓ | ★**与基线逐项相同＝一个字的效果都没有** |
| **乙**（撤两栏 contain） | 249px | 能拉动 | **2034px** | ✓ | 副作用太大 |
| **丙**（整页一条滚动条） | 0（整页滚 2866） | 能拉动 | **2034px** | ✗ | 与用户 2026-09-27 明令冲突 |
| **★定案**（并页改 flex 列 ＋ 页自己也 contain） | **0** | 无需拉（页没得滚） | **0** | ✓ | 治好了 |

★**甲案为什么是零效果**（这是本棒最贵的一条）：那条 `overscroll-behavior:contain` **只在文件末尾的手机档**
（`@media (max-width:620px)`，本意是拦"下拉刷新"），**桌面上本来就没有它** ⇒ 撤它当然什么都没有发生。

### 定稿（改了什么）

| 文件 | 改法 |
|---|---|
| `web/style.css` | ① `.sw2-merged-grid`：`height:100%` → **`height:auto;flex:1 1 auto`**（`min-height:320px` **不撤**）② **新增** `#sw2_view_panorama.sw2-active{display:flex;flex-direction:column;overscroll-behavior:contain}` ③ **新增** 页头两块 `.sw2-pan-head`/`.sw2-infoband{flex:none}`（不许被 flex 压扁） |
| `src/render-base.js` | `PANEL_BUILD` → **`leg157-merged-scroll`**（两栏可视高度真变了：715 → 466） |
| `web/index.js` | `CSS_VERSION` → **`20260930-leg157-merged-scroll`**（`+2` 行注释，3097 → 3099） |
| `test/panorama.test.js` | 那条"容器必须有**确定高度**"的锁**换写法**（`100%` 或 `flex:1`）＋ **新增两条前置自证**（页必须是 flex、必须是**列**）——三条**都先证过红**（撤掉 flex ⇒ 红；改 `display:block` ⇒ 红；改 `flex-direction:row` ⇒ 红） |
| `test/render.test.js` | `CSS_PIN`（号 ＋ 指纹）与 `buildLeg` 自证值同批换掉 |

★**手机档也核过**（同一装置，390 宽那档实测出来是 512 宽、仍在 `≤620px` 媒体查询内）：
**改动前 vs 改动后逐项相同**——`page.scrollHeight` 都 **6315**、两栏盒子都 4653/1218、两栏之间的
16px 缝原样（`overlap=-16`）、"最深那个元素"都够得着 ⇒ **一个像素的内容都没丢**（变短的只是 grid 那个盒子本身）。

### 判据（＋2，全是**先证过红**）

见上表最后两行。★**改了一条旧锁并如实登记**：`test/panorama.test.js` 那条从
`height:100%` 改成"`height:100%/calc` **或** `flex:1`"——它咬的**仍是同一件事**（"高度必须是**确定值**"），
只是 `100%` 那种给法本身就是病根；同时**新增两条前置**（父级必须是**列** flex 容器），
否则一个空转的 `flex` 就能骗过它（本仓"空绿"家族的老毛病）。

## 2. ★★★ 交付二：主调用输出上限 ＋ 直接读网关报的容量

### 起点：社区用户那份账（第 11 轮起「返回空」/「非法 JSON」交替）

他把**导出的世界账**发来（`story-world-v2-export (2).json`，tick 11），两张截图分别是

★★**本仓自己的先例**早就写着同一件事（leg62，抽取侧：@16,384 出 `finish_reason=length`、@32,768 才 `stop`；
`src/render.js:2281` 把真因写成"**推理与正文共享这一份预算**"）——**当时只抬了抽取侧、主调用"不动"**，
