## 4. ★★★ 那条真 bug 的逐条留档

### ① 根因（在酒馆源码里，不是猜的）

- `SillyTavern/src/endpoints/characters.js:35`：`const useShallowCharacters = !!getConfigValue('performance.lazyLoadCharacters', false, 'boolean')`
- 同一个文件 `:1327`：角色列表接口按这个开关决定 `processCharacter(..., { shallow })`
- 同一个文件 `:371` 的 `toShallow()`：**懒加载卡只交回这些字段**——
  `shallow: true · name · avatar · chat · fav · date_added · create_date · date_last_chat · chat_size · data_size · tags · data: { name, character_version, creator, creator_notes, tags, extensions: { fav } }`
  ⇒ ★**description／personality／scenario／first_mes 没有；`world` 没有；`character_book` 没有；
  `data.extensions.world` 也没有**（`data.extensions` 里只剩一个 `fav`）。
- 而本插件那三条取书来源（`web/book-source.js` 的 `characterWorldNames` / `collectWorldInfoEntries`）
  **全靠这几格**：`character.world` · `character.data.extensions.world` · `character.character_book`。
  ★另一条来源 `Object.keys(extensionSettings.world_info)` **不是书名录**（那是
  `globalSelect`／`charLore`／`chatLore`／`personaLore` 这几个设置项），所以**它不是兜底**。
- ⇒ **两个症状一个原因**：四件套全空 ＋ 那本书一个名字都找不到。

### ② 血证（判据里的原话）

```
★★leg154·②：要不到全卡（老 ST / 取回失败）⇒ 不许抛，且不许把"没取到"说成"卡里没有"
  AssertionError: ★★★不许把"卡还没加载完"说成"卡里没有"——两种空必须分形；
  实际 reason：角色卡四件套全空；世界信息/内置书为空
```

★这一行**与社区那张截图上的字一字不差**——所以它不是"我猜的复现"，是**同一句话**。

### ③ 修法（三条，缺一条都不算修好）

1. **读卡前先要全卡**：`ensureCharacterLoaded(ctx)` —— 只做一件事：卡上带 `shallow` 时调
   `ctx.unshallowCharacter(<那一格的下标>)`。★下标按 `characters.indexOf(我们刚挑中的那张)` 现算：
   单卡、**群聊成员**、欢迎页那位助手都是同一条路（酒馆自家的 `unshallowGroupMembers` 也是这么找人的——
   **同一把尺，不另立**）。★**永不抛**：老酒馆没有这个口 / 取回失败 ⇒ 照旧把手上那份交出去。
2. **两种空分形**：`src/init-source.js` 里，卡上带 `shallow` ⇒ 说「**还没加载完**」；
   否则照旧「四件套全空」。★这不是"改文案"，是**红线二**（绝不用空值反推"书里没有"）在**用户看得见的那一处**的落实。
3. **"读不到"不许被缓存锁死**：`worldBookCached` 只缓存 **readable** 的那一份。
   ★旧实现与**本文件顶上那条三态纪律**（"读不到 ⇒ 下轮再试"）**自相矛盾**——
   纪律写着"下轮再试"，实现却把空结果缓存了 ⇒ 那个"下轮"永远吃同一份空结果（静默、不报错）。

### ④ 判据（5 条，全部**先证过红**）

- **①** 懒加载卡 ⇒ 必须问过 ST 一次、四件套与世界书都要回来（断言"问过没有"＋"条目名可读"）
- **②** 要不到 ⇒ 不许抛、不许把"没取到"说成"卡里没有"（★就是上面那条血证）
- **③** ★**反证的反证**：一张**真·空卡**照旧说「四件套全空」——否则②就变成"把消息删掉"而不是"把两种空分开"
- **④** 缓存：一次"读不到"不许锁死整局；★**反向自证**：**读到**的那份必须照旧缓存（不许把缓存整个删掉）
- **⑤** 群聊成员卡走同一口

## 7. ★ 给社区的回话草稿（★发之前让用户过一眼）

> **一、装不上**：那条红字是**你这台机器连不上 github**（酒馆的"下载扩展"是在**服务器端**跑
> `git clone`，报错原文 `Failed to connect to github.com port 443`）。三条路任选：
> ① 开代理/加速，让**跑酒馆的那台机器**（不是手机）能连 github，再点一次安装；
> ② **手动装**：在 github 上点 `Code → Download ZIP`，解压后把**整个文件夹**放到
> `SillyTavern/data/<你的用户名>/extensions/` 下（文件夹名随意，**里面必须直接看得到 `manifest.json`**，
> 别多套一层）——★放好后**重启酒馆或刷新页面**；
> ③ 让能连 github 的朋友用 ② 的办法打包给你。
>
> **二、加载失败 `[object Event]`**：这句话是酒馆自己吐的——它把浏览器给的那个错误**原样**印了出来，
> 所以它什么也说明不了。绝大多数情形是**上面那次安装没装全**（半个文件夹）。
> 自查两步：① 打开插件目录，确认 `manifest.json`、`web/`、`src/` **都在**；
> ② 按 `F12` 开控制台 → `Network` → 刷新页面 → 看有没有**红色的 404**，那个文件名贴给我们。
>
> **三、读不到世界书（「角色卡四件套全空」）**：★**这条是我们的错，已经修好了**（下一个版本里）。
> 原因是我们没处理酒馆的"角色卡懒加载"（`config.yaml` 里的 `performance.lazyLoadCharacters`）——
> 那个开关开着时，酒馆交给扩展的只是一张**只有名字的空壳卡**，我们却当成了"你的卡是空的"。
> ★在你更新到修好的版本之前，有个**临时办法**：把 `config.yaml` 里的
> `performance.lazyLoadCharacters` 改成 `false`（或注释掉）再重启酒馆。
