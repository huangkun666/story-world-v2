## 1. 病：今日实测（不是推测）

### 1.1 账上只有两种"关系"，两种都不是"关系"

账本（代码里叫 **SSOT**，就是那份存世界状态的对象）顶层有 **9 张表**：`version` / `context` / `entities` /
`weights` / `agendas` / `events` / `milestones` / `chronicle` / `meta`（权威在 `src/schemas/ssot.schema.js:8` 的
`required` 与 `:10`–`:564` 的逐表定义）。**里面没有一张记"谁跟谁是什么关系"。**

今天最像关系的东西只有两处，都不是：

| 是什么 | 在哪 | 为什么不算"关系" |
|---|---|---|
| `parent`（谁归谁管） | `src/schemas/ssot.schema.js:342`（"character→所属势力/分支名，faction→上级势力名（书中明述）"） | **单向的从属字段**，而且是**照书办**从书里来的；角色与角色之间**一条都不连**（`src/abstract.js:640` 的 `linkContainedFactions` 只连势力隶属） |
| `ripples`（一件事沾到了谁） | `src/schemas/ssot.schema.js:523` | 那是**共现**，不是关系：同一件事波及两个人，不等于这两个人有交情 |

★**逐词实测（全仓搜，不是印象）**：`盟友` / `敌对` / `血亲` / `人情债` / `师徒` —— **`src/`、`web/`、`test/` 全零命中**；
`旧怨` 只有 **2 处**，都在 `src/prompts.js`（`:262`、`:290`）的**提示词散文**里当例子用，**不是任何一格字段**。

⇒ 一句人话：**模型可以在台词里写"我记着你这份情"，而引擎这边一个字都不会留下。**

### 1.2 ★它是有意删的——而那条理由只对了一半

它不是从来没做过。`src/abstract.js:607-609` 留着一块**删除位**（逐字）：

```
// leg24 片1 删除位（原 K49 关系轮 prompt `buildRelationPrompt`）：隶属/所在/种族不再从书里抄。
// 书里真写着的结构走「照书办」（零模型调用）；位置与归属按 design-core §2.3 改为用得着时查书（片2）。
// 整个函数已删（不是停用）。
```

而且**删得被测试锁死了**（防它无声复活）：`test/abstract-chunk.test.js:231` 那条用例的清单里就有
`buildRelationPrompt` / `runRelationRound`，`:236` 断言它们「应已删除（停抄书）」。

**那条理由，前半对、后半不对**（照抄 `leg109b` §1.2 的判断，我核过代码后同意）：

- **对的一半**：不抄书里的**静态**关系是对的。书里写着"甲是乙的师父"，书随时可查，抄进账本就是**第二份副本**
  ——本仓在"同一份真相不许有两个住处"上吃过很多次亏。
- **不对的一半**：**玩出来的关系不是书的副本**。"薛铁衣在第 42 轮叛了镇抚使""黄坤欠了明素问一条命"——
  **书里没有、账上也没有，没有任何地方可查**。删掉的是"抄书"，连带把"记录玩出来的"也一起删了。

### 1.3 所以缺的不是"抄书"，是"玩出来的"

| | 静态关系（书里写着的） | 玩出来的关系（**今天无处可放**） |
|---|---|---|
| 例子 | 谁是谁的师父、谁隶属哪个门派 | 谁跟谁结了仇、谁欠了谁、谁叛了谁 |
| 今天怎么查 | **照书办**（零模型调用）+ 检索层查书 | ★**查不到**——书里没有，账上也没有 |
| 该不该进账 | **不该**（是副本） | **该**（这是世界的**新事实**） |

⇒ 要补的是一张**"关系变更"表**：有向边 + 类型（**不预设封闭词表**）+ **因** + 痕 + 额度。这四条是 `leg109b` §1.2 末句的原话。

## 2. 治法：**一张新表 + 一条提议通道**（不新造机制）

**分层声明**（照 `docs/dev-process.md` §2.3 第 4 条，写清改哪层）：本笔动 **契约层** ＋ **引擎层** ＋ **渲染层**，
编排层只加透传。★**不新增 `src/` 模块**——理由见 §2.4 第 4 条。

### 2.1 那张表长什么样

新表 `relations`，**可选表**（照 `milestones` 的先例：`src/schemas/ssot.schema.js:476` 注释写着"可选——缺省=旧世界合法形态"）
⇒ ★**旧账一个字节不用迁**（本仓的"零迁移纪律"）。**一行 = 一条有向边的一次变更**：

| 格 | 是什么 | 谁写 |
|---|---|---|
| `id` | 引擎发号：`rel_<轮次>_<第几条>`（与事件号 `ev_<轮次>_<位次>` 同规） | **引擎** |
| `from` / `to` | 谁 → 对谁（**实体 id**，不是名字） | 模型提议，引擎校验在册 |
| `type` | ★**模型的原话**（"结下死仇""欠他一条命"）——**自由文本，不给菜单** | 模型 |
| `cause` | ★**因**：`{type:'event'\|'agenda', ref:'…'}`，**必须指账上真有的那一件** | 模型提议，引擎校验 |
| `tick` | 落账那一轮 | **引擎** |
| `note` | 一句话：这次事件让它怎么变了 | 模型（可选） |
| `endedTick` | 这条边从哪一轮起不再算数（见 §2.2 的"了结"） | **引擎**（模型提议了结） |

### 2.2 提议通道：照 `entityUpdates` 那条现成的路

世界模型每轮交的那份 JSON 叫**世界步**（world step）。它现在是**封闭形状**（`src/schemas/world-step.schema.js:8`
`additional: false`），里面已经有 4 个**可选组**（`entityUpdates` / `lookupScales` / `eventClosures` …，
`additional: false` 意味着**没声明过的键一律拒**）。本笔加**第 5 个可选组**：

```
relationChanges: [
  { change: '建立', from: 'e_bk_194', to: 'e_bk_146',
    type: '结下死仇', cause: { type: 'event', ref: 'ev_59_2' }, note: '…' },
  { change: '了结', id: 'rel_42_1', why: '人情还清了' }
]
```

口径**完全照 `entityUpdates`**（`src/schemas/world-step.schema.js:113`）：**缺席 = 本轮不提议，不是形状错误**。

两条设计取舍，先说清：

1. **`change` 只有两个值（建立 / 了结）**——这是**提议的形状**，不是"判定书里的语义"，所以不撞
   §4.8 禁用清单里那条"用词表判语义"（先例：`entityFates.verdict` 就是 `enum: ['dead']`）。
2. ★**"了结"必须引 `id`，不许靠 `type` 文本去认边**。因为 `type` 是模型的原话，它这轮写"死仇"、下轮写"深仇"，
   引擎**不许去猜这是不是同一条边**（本仓的老账：`leg95` 定过"引擎负责这单结没结清、模型负责这故事还要不要往下讲"，
   两个角色不许互相替）。⇒ **引擎发号、模型引号**，同事件那一套。
   ★**同轮内**引用要按**位次**解析（模型无法知道本轮新发的号）——这条本仓踩过并有现成治法（`leg40b`：
   "同轮引用在结构上无法靠 id 对上，只能按位次解析"，`normalizeSameStepEventRefs`）。

### 2.3 ★★为什么"必带因"是整个设计的枢纽

**这一条同时守住三件本来会互相打架的事**：

1. **它保住 leg24 的决定**（不抄书）：书里的静态关系**指不出账上的事**当因 ⇒ **结构上就写不进这张表**。
   ⇒ 不需要靠"提醒大家别抄"这种自律，**形状本身不允许**。
2. **它守住红线 §2.2 第 2 条**（空着就是空着）：`cause` 指不到账上真物 ⇒ **不落账**，
   **绝不许**给它编一个"默认因"或者把 `tick` 填 0 冒充（`leg118` 刚踩过"补 `tick: 0` 占位"这个坑）。
3. **它顺带就是额度**（§3）：世界步每轮能凭空造的事是有限的，而每条关系都要挂在一件真事上 ⇒
   **产率被世界的因果产量天然卡住**，不需要另设一个我没量过的数字。

★这也是本笔与 `leg109b` §4 第 2 问那句倾向（"要单独设限"）的**分歧点**，见 §3 与 §5 第 1 条——**你拍**。

## 3. 曲线（**数字先报批**：本节所有数字都是提案态）

`leg109b` §4 第 2 问要你拍的是"**每轮允许几条关系变更**"。它给了两条路：**① 不限** ／ **② 单独设一个上限**，
并注明"数字得用户拍"，原文**没有给任何候选数字**。

**我的建议：走 ① 不设上限**，理由三条：

| # | 理由 |
|---|---|
| 1 | ★**本仓刚为"没量过的上限当家"流过血**：`entityUpdates 每轮 ≤3` 是个**提案态数字**，却在生产里拦了十几棒，**而且拦的时候是静默的**（`src/sanitize-step.js:342` 只进 `dropped`），用户 2026-09-22 拍板**直接撤销**（leg112）。同一个坑不跳第二次。 |
| 2 | ★**"必带因"已经是量闸**（§2.3）：关系不能凭空长，每条都要挂在一件账上真事上 ⇒ 产率被因果产量卡住。**这是结构给的闸，不是我想出来的数。** |
| 3 | 若照本仓纪律"要设限就先出曲线" ⇒ **这条曲线今天画不出来**：表还不存在，零数据。硬画只能借用邻近通道的数，见下表。 |

**借来的邻近读数（都不是本机制的实测，别当本机制的读数用）**：

| 邻近通道 | 读数 | 出处 |
|---|---|---|
| 模型主动提 `entityUpdates` 并真落账（**真模型真账**） | **3 条 / 5 轮**（≈0.6 条/轮） | `leg35` V-3（真账 tick 59 · `gemini-3.1-pro-preview`） |

| 合成冒烟 50 轮 | 编年只长 **7 行**（≈0.14 行/轮） | 本笔复跑 `node demo/smoke-demo.js`（终态 SSOT 8351 字节 · 编年 7 · simLog 50） |

⇒ **量级判断**：本机制的自然产率**大概率也是"每轮 0–2 条"这个量级**，不是"每轮几十条"。

（照铁律"一律先 cp 副本再解析"）——**要不要做，见 §5 第 6 条**。

## 4. ★泛用性（`ANCHOR.md` §4.8）：本机制**按构造过关**

§4.8 是**设计否决线**（用户 2026-09-11 立："不能泛用到所有世界书的设计都是垃圾"），三条判据：

| 判据 | 本机制 |
|---|---|
| ① **能跑不崩**（换任何一本书都不许抛错/卡住） | ✔ **本机制一个字节的书都不读**——它读的是账上的事件与盘算。空书、无条目、非中文，全套照跑 |
| ② ★**不共线**（"书里没有某形态"只许**不生效**，不许**给错结果**） | ✔★**本机制不依赖书的任何形态**：书里有没有花名册、有没有标签行、有没有层级标题，**与它无关** ⇒ "缺形态"这个失败模式**在本机制上不存在**（比现有三个机制都干净） |
| ③ **宁缺勿造**（形态不满足就不写，不填占位值） | ✔ 没人提 ⇒ 表**空着**；因指不到 ⇒ **不落账**；`tick` 由引擎盖章，**不补 0** |

**如实登记一处**（免得你以为我没做功课）：§2.3 第 5 条要求"加任何机制前先跑
`demo/audit-mechanism-genericity.js` 拿八本书的数"。**本笔跑不了**——我读了那个脚本，
它**写死了三个机制**（①成员行→归属 ②位置继承 ③势力规模兜底，`demo/audit-mechanism-genericity.js:5-7`），
**量不到"关系"这个新机制**。它现有的八本书读数（机制① **1/8** · ② **3/8** · ③ **2/8**，
见 `docs/handoffs/session-handoff-2026-09-11-leg25e.md:108-114`）恰好说明：**凡依赖书形态的机制，跨书都很弱**。
⇒ 本机制走的是**相反的路**：不读书 ⇒ 不共线。★若你要一个"数"而不是"构造论证"，
