## 2. 为什么批量补全**不**放初始化（裁定 + 依据）

初始化现状（实测）：设定五件套只取书文**前 30,000 字符（全书 9.9%）**，书名录按 60,000 字符分 6 块 → **合计 ≈7 次调用**、一次性、有预算、失败可退。

放进初始化 = 多 5–6 次调用 + 多 5 个失败点 + 开局多等一截；而**绝大多数实体永不上场**（每轮上限 15 个）。

**口径定案**：
- 初始化 = **世界的框架**（书的世界观 / 名册 / 位置集）——一次性的全局事实。
- 实力/位置 = **从书里取的按需原话**——性质上可分批、可中断、可重查，**不是初始化事实**。
- ⇒ 批量补全是**独立的手动操作**（热加载，面板按钮），不冻进初始化。

## 3. 批量补全（全补 623 个在册实体）

### 3.1 分批口径（关键：**按条目载荷打包，不按实体个数**）

| 错法 | 对法 |
|---|---|
| 「每 15 个实体一次调用」→ 623/15 ≈ 42 次 | **按命中条目的并集打包**：实体大量共享条目（吞天妖王/混元妖圣同属一条 548 字符），载荷要去重 |

**实测**：全库 302,317 字符 ÷ 60,000 字符/次（30k tokens 预算）= **理想 5.0 次**；按条目不可分最优装箱 = **6 次**。

**算法**：
1. 取在册可查实体（`pickable`）∩ 缺字段者；
2. 逐批累积命中的世界书条目正文（**条目级去重**），加到 60,000 字符（可配 `BATCH_BUDGET_CHAR`）就封批；
3. 每条实体按“名号”作 prompt 键，模型逐名号回 `{实力, 位置}` 原话；
4. 单批失败不毁全局：该批记失败、跳过，继续下一批（沿用既有 `noteFailure` 熔断口径）。

### 3.2 节奏：借轮次分批跑（不阻塞世界推进）

- 一个**手动触发的任务对象**（内存，不落盘）：`{ ids, cursor, done, failed, running }`；
- 每次世界推进（tick 前置步）顺手处理**已凑满一批**的实体（或按 `BATCH_PER_TICK` 上限）；
- 面板显示进度：`补全中 312/623（成功 288 · 未加载到 24）`；可**停**（停 = 不再取新批，已查的留账）；
- 退出/刷新（Ctrl+F5）后任务丢失——**已查的字段已在账上**，重开可续（`missingFields` 自然只剩没查的）。

### 3.3 不做的事

- ❌ 不改初始化路径；❌ 不新增存储字段（进度只在内存）；❌ 不替模型截断（沿用「拒整条」护栏）；❌ 不给实体算分。

## 4. 单实体重查（接口 + 覆盖开关）

### 4.1 两个新入口（`src/entity-lookup.js`，纯编排层，可 Node 测）

| 函数 | 语义 |
|---|---|
| `pickOneForLookup(world, id, { fields })` | 该实体缺哪些字段（**含覆盖模式**：把已定案字段视为“要查”） |
| `runSingleLookup({ ssot, transport, bookText, id, fields, force, tick })` | 查一个实体 → `applyLookup` → 返回 `{ ssot, stats, warning }` |

### 4.2 覆盖开关（`force`）——**必须做**

现状坑：`absent`（书未明述）是**永久闸**，`missingFields` 对 `absent`/`ok` 一律跳过。用户盘上已被旧 bug 误标「书未明述」的字段**永远查不动**。

`force: true` 语义：无视 `ok`/`absent`/重试上限，**重查一次并覆盖**。用于：
- 面板单个实体的「重查」；
- 批量补全的「含已明述的」（勾选框）。

**留档**：覆盖时旧的 `attempts`/`fields` 记录被新值替换，`stats.forced` 计数上账（可审计）。
**纪律**：`force` 只清**查书标记**，不动实体已落账的 `实力` 文本值以外的任何字段。

## 5. 选人可见（把已有的原话摆给选择器）

`buildSelectPrompt` 现名单行：

```
${e.id}\t${e.name}\t${势力|角色}
```

改后（**只加已有值，未查的不摆**）：

```
${e.id}\t${e.name}\t${势力|角色}\t${实力原话 | —}\t${位置原话 | —}
```

- 只显示**账上已有**的 `实力`/`位置`（查书查回来的原话，或书里已有的）；没有就写 `—`（**不填占位值**，硬规矩二）；
- 引擎**不换算、不排序、不比较**这些字——只是把原话摆出来给模型看（`design-core` §4 第 1 条）；
- 势力不显示实力（用户前拍板沿旧）；
- 头部加一句口径：`实力/位置列 = 书里的原话（未查的显示 — ）`。

**判据**：调用次数不变（仍是选人 1 次）；名单 token 增量 = 每行约 +6~12 字符。

## 7. 实测依据（用户真书，只读副本）

**取书真口径**（`web/index.js:650-661` 逐字）：按名号匹配条目 → **最多取 4 条** → **每条截前 1200 字符** →
`hit.slice(0, 4).map(e => ({ text: content.slice(0, 1200) }))`。**没有“只取该名号那一行”的能力**：命中即整条。

| 项 | 实测值 |
|---|---|
| 世界书 | 235 条 / 正文 **302,317 字符**（≈15 万 tokens） |
| 初始化现状 | 前 30,000 字符（9.9%）+ 名册 6 块 = **≈7 次调用** |
| 名号命中条目的**并集** | **206 条**（名号虽多，搬来搬去就是这 206 条） |
| 并集载荷（原始正文） | 234,970 字符 |
| **并集载荷（截 1200 后 = 引擎实际喂的）** | **175,962 字符** |
| **分批（60,000 字符/批）** | **≈3 次**（原始口径 4 次） |
| 超 1200 字符的长条目 | **84 条**，一律只取前 1200（最大一条 22,008 字符，丢 20,808） |
| 账上实体数 | **623**（书的 `key` 名号 1472 个 > 623 ⇒ key 里混有非实体词条） |

**★★ 订正两处我自己的估算错误（如实登记，防下一棒重走）**：
1. **「每 15 个实体一次 → 42 次」是错的**：无视实体会**共享条目**。正解按**条目级去重**打包 ⇒ **≈3–4 次**，
   且**不随实体数增长**（账上从 623 涨到 5000，载荷仍被“书只有 235 条”顶住）。
2. **「A 类 152 个有自身原话行 → 1 次全清」是错的**：那一行**住在宿主条目里**，引擎取书按条目命中、
   取到就整条给 ⇒ “有那一行”**不等于**“取书便宜”。吞天妖王就是典型（有自己一行，取书仍搬 548 字符整条）。
   按真口径重算：极便宜名号（命中 1 条且 <300 字符）**只有 2 个**。

**登记未决隐患（不在本细案范围，需单独拍板）**：84 条长条目被截到前 1200 字符。本例实测
**0 例**名号描述行落在窗口外（安全），但换一本书，若某角色的描述住在长条目后半段 ⇒ 模型在截断后的
原文里找不到它 ⇒ 与 `absent` 结合会写出**假的「书未明述」**（同款病，已在本棒治过一次）。
候选对策：①`LOOKUP_ENTRY_CHAR` 上限提高 ②命中窗口外的名号改记 `pending` 而不是 `absent`。
**两者都是阈值/判据改动，按纪律须先出曲线再报批**。

## B6. 取原文按名号定位到它那一行（已实施，含**实测修正**）

**做法**：命中条目后，先在**截断前**的正文里按形态判据定位"该名号自己那一行"
（`^[-*·•\s]*名号\s*(?:[（(]|[：:])`，出处 = v1 `powerFromNameContext` 实证写法；
**不引词表**——用户明令过"被很多词表法弄得很烦"，v1 那个 `tierWords` 不搬）；
定位到就只喂这一行，**定位不到退回整条**（= 原行为，零回归）。

**★实测结果（用户真书，用真函数 `locateNameLine` 跑，2026-09-11）——与我的预期不符，如实登记**：

| 项 | 实测 |
|---|---|
| 名号 × 命中条目 的次数 | 1814 |
| 其中**定位到自身行** | **281**（15.5%） |
| 退回整条 | 1533 |
| 载荷：改前（整条截 1200） | 1,600,416 字符 |
| 载荷：改后（B6） | 1,388,785 字符 |
| **省下** | **13%** |

**订正**：我先前预判"B6 能把 3 次降到 1 次"——**不成立**。原因是**大多数名号在正文里没有自己那一行**
（它们只作为 `key` 存在，描述住在宿主条目的段落里），所以 84.5% 仍然要退回整条。

**B6 的真实价值因此要改口径**（不吹）：
1. **精度**（主要）：定位到的那 281 处，喂进去的是那一名号的原话，**不夹带同条目里别人的资料**；
2. **顺带修掉截断风险**：定位在**截断前**做 ⇒ "描述行落在 1200 字符之后"的那类假「书未明述」被消掉；
3. 载荷只省 13%（不是数量级），**不构成"少几次调用"的理由**。

**保留与否**：保留（零回归：定位不到退回整条）。但**不再拿它当性能杠杆**。
