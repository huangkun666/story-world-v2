# 核心设计（第二十三棒收敛稿）· 书 / 引擎 / LLM 三者分工

> 性质：**设计定稿候选**，取代此前所有关于"结构层 / 抽数值 / 档位换算"的临时方案。
> 来源：本棒用户逐条拍板（§5 逐条列明哪句话是谁说的）。凡用户已定的，本文件不再当"建议"讨论。
> 纪律：开口先人话版（铁律 3）；本文件只写"是什么"，不写实施步骤（实施另开细案）。

---

## 0. 人话版：这会怎么样

**世界书是作者的原稿，我们一个字不改。**引擎是这个世界的账房兼史官——它只记"这里发生过什么、世界现在是什么样"，**不裁谁强谁弱、不判谁打赢**。LLM 是那个能读会写的人：要细节就翻书，每回合提议"接下来发生什么"，然后把账本上的冷冰冰状态写成像样的场景。

**结果**：引擎从"裁判"退成"记录员"，它不再需要把整本书抄成一张精确表格——**书随时可查，账本只记玩出来的东西**。世界转不转得起来，取决于账本有没有逻辑（谁归谁管、谁在哪、谁在谋划），不取决于某个数是 0.53 还是 0.6。

## 1. 三个角色，各干什么

| 角色 | 一句话职责 | 可以做 | **绝对不做** |
|---|---|---|---|
| **世界书** | 作者的原料 | 被查、被引用、被玩家修改（玩家改=作者改） | 不被引擎写、不被引擎"整理"、不被抄成副本 |
| **引擎** | 账房 + 史官 | 记账、守连续性、守身份、管盘算生命周期、算能见度 | **不裁胜负、不算战力、不给实体打分、不发明事实** |
| **LLM** | 读者 + 提议者 + 笔 | 查书、提议（发生什么/谁赢/状态怎么变）、撰写叙述、从玩家对话提取落子 | **不记账**（它说的话只有经引擎校验落账后才算事实） |

**承重墙一条**：**写账这件事，只有引擎能做。**LLM 说的任何话，在落账之前都只是提议。

## 2. 引擎的定义（分毫不差）

### 2.1 引擎做的六件事

1. **组装现状包**：每回合把"当下该让模型知道的东西"拼出来（谁能动、在谋划什么、什么事件未决、格局张力）——**拼装是确定性的，不含创作**。
2. **校验提议**：模型说"甲杀了乙"，引擎校验——甲在册吗？乙还活着吗？跟已记的事实矛盾吗？**合法则收，非法则整条拒收、世界如实不动**（非法不半收）。
3. **落账**：把收到的提议写进账本，**每一条变更留痕**（谁改的、因为什么事件、第几回合）。
4. **守连续性**：拦住自相矛盾——上轮记了"重伤"这轮不能"毫发无伤"；上轮记了"已灭"这轮不能还有手下活动。
5. **管盘算生命周期**：谁在谋划什么、推进到哪一步、成了/败了/变形了、到点强制结算。**盘算是世界自转的燃料，由引擎管生死。**
6. **算能见度**：谁知道什么、玩家能感知到多远（靠**位置 + 归属 + 情报关系**推，不靠战力）。

### 2.2 引擎明确不做的四件事（这是本棒最重要的减法）

- ❌ **不裁胜负**（用户定：能力不在战力维度上，引擎裁不了；硬裁就得堆规则＝旧债复发）
- ❌ **不算战力总分**（不给实体打四维分、不做维度合成）
- ❌ **不预抽全书**（不把书抄进账本）
- ❌ **不发明事实**（模型没提的、书里没写的，引擎不补）

### 2.3 账本记什么（六项，多一项都不加）

| # | 项 | 内容 | 谁给 | 缺了怎么办 |
|---|---|---|---|---|
| 1 | **身份** | 名字 + 类别（人/势力/地方） | 书 + 模型 | **不能缺**（这是主键） |
| 2 | **位置** | 粗粒度（哪一层/哪一域） | 查书 | 空 → 「未明」，且**标注未明** |
| 3 | **归属** | 归谁管/属于谁 | 查书 | 空 → **就空着** |
| 4 | **标尺档位** | 书里的原话（如「T8大乘」）+ 依据 | 查书 | 空 → **就空着**，不填默认值 |
| 5 | **状态** | 活着/重伤/突破/被灭/退休 | 模型提议 + 引擎校验 | —— |
| 6 | **事件** | 何时、谁、做了什么、结果如何、跟哪条因果相连 | 模型提议 + 引擎校验 | —— |

另有两块本来就属账本：**盘算**（谁在谋划什么、推进到哪）与**编年**（可读的历史）。

### 2.4 三条硬规矩

1. **空着就是空着**——书没写的，标"无据"。**不许填默认值冒充客观**（倒挂、75% 全默认的病根就在这）。
2. **不裁胜负，但拦矛盾**——引擎不判谁该赢；但上轮说过的、这轮不能翻脸不认。
3. **每一条变更留痕**——谁在什么时候因为什么改了账，可回查。

### 2.5 账本是"玩出来的"，不是"书的副本"

- 书变 → 账本**不自动重抄**（书是参照，不是真相源）
- 账本里只有这个世界的历史：**起点从书来，之后全是自己攒的**
- 冲突时：**账本为准，但标注书里怎么写的**（权威阶梯：设定 > 引擎结算 > 对话事实 > 渲染）

## 3. LLM 的职能（分毫不差）

### 3.1 四个职能（按发生频率排）

| # | 职能 | 输入 | 输出 | 什么时候做 |
|---|---|---|---|---|
| 1 | **查** | 一个名号（或一个问题） | 书里对应的原话与事实（位置、归属、档位、来历、有什么手段） | 要用到的时候，**按需** |
| 2 | **提** | 现状包（引擎拼的） | 这一回合发生什么：谁出手、结果如何、谁的状态变了、开不开新盘算 | **每回合一次** |
| 3 | **写** | 账本状态 + 本回合的结果 | 给人看的叙述（场景、对话、编年风味） | **每回合一次** |
| 4 | **拾** | 玩家的 RP 对话 | 一条事实：玩家这步做了什么 | **每回合一次** |

（职能 2/3/4 现在就是主调用/落子提取的既有分工，本棒不改；改动集中在职能 1。）

### 3.2 职能 1（查）的产出形态——本棒定稿

**查出来的东西分两桶：**

**第一桶：事实**（照抄，不换算）
- 位置、归属、书里的档位原话、有什么手段（神通/法宝/秘术，单列不当数值）

**第二桶：数值**（只有引擎之外的用途时才产出）

数值的产生方式（用户定的三步）：

1. **LLM 自问一次**：读这本书的力量体系，产出一张**标尺表**——书里每一档对应一个数
   （大荒：T1 感气境…T16 道祖境；三国：超一流/一流/二流…；没明写阶梯的书：LLM 按这类书的通例自定）
2. **查实体**：每个名号只做一件事——查它属于书的哪一档 → **照表取数**
3. **区间内微调**（用户定）：档位给底，**同档的人可以因神通/法宝/功法小幅浮动**

**微调的硬约束两条**：
- **不许越档**——同档调到顶也打不过上一档（物理上堵死"手拍 0.8 压过顶层"）
- **要有依据**——原文里写着这东西才调；没依据就是基准值

**标尺表是你可见可改的一份东西**：改一行（"元婴该 0.65"），全世界同档一起变。
**填一次冻结**：书重读、换模型都不动已填的数；只有明确事件（突破/重伤/被灭）才改，且留痕。

### 3.3 数值的唯一用户是 LLM 自己

**引擎不拿数值算任何东西**（不裁胜负之后，它没有使用者了）。数值的作用只有一条：
**让 LLM 跨回合、跨实体保持判断一致**——不会这轮把"元婴"当顶尖、下轮当小角色。

## 4. 砍掉的东西（本棒明确删/停）

| # | 砍什么 | 为什么 |
|---|---|---|
| 1 | **四维属性浮点**（手拍的 0.5/0.8） | 手拍值比没有更坏：让"编的"看起来像"算的" |
| 2 | **全量名号抽取（872 条）** | 书里有条目的只有 77 条；795 条是字缝里读的，还带 48 例重复。**名录按需长** |
| 3 | **关系轮 / 属性轮 / 标签扫描** | 全部作用是"把书抄进账本"——书随时可查 |
| 4 | **引擎的胜负裁定与分量计算** | 用户定：引擎不裁胜负（能力不在战力维度上） |
| 5 | **"序"作为约束**（我上一轮的方案） | 用户指出：世界书不会给全角色排序，全局序本来就不存在 |
| 6 | **手动的"重新抽取设定"按钮** | 书变自动发现（指纹），不需要玩家点 |
| 7 | **默认值兜底**（0.25 那套） | 空着就标"无据"，不许填数冒充客观 |

**保留并升级的**：抽象设定（力量体系/法则/格局/世情）——抽一次、冻结、可复验（用户定的第一步）。

## 5. 这套设计里，哪句话是谁说的（如实记账）

**用户定的（本棒逐条拍板）**：
1. 世界书是**未加工的原料**；要最简模型
2. **先抽象设定**（每次抽象都没错）→ **再抽名号+类别** → **然后让 LLM 查世界书填数值**
3. "如果知道了力量体系（分段或分维度 LLM 都能理解），又知道了实体设定，**理论上只有 LLM 够聪明，什么数值都能填**"
4. **LLM 自问**：先定"每种力量体系里什么阶段/数值该填什么数"，再查实体、对应填入
5. **同档但某人某有神通 → 在区间内由 LLM 微调**
6. "**序设计是画蛇添足**——一般只有一个势力甚至一个部门才有序，没人给全角色排序"（否掉了我的序约束）
7. **理由可选**；**填一次冻结**
8. "**最好就是不让引擎裁定胜负**"（否掉了引擎裁定的整条路）
9. 位置：**粗粒度够，细的现场查**
10. "如果**要更新属性**怎么办，直接更新世界书？"→ 定：**书只读，增量入账**

**用户否掉我的（我错在哪）**：
- 我把"引擎裁定胜负 + 档位换算成数 + 维度合成"当主路 → 用户否掉裁定这一环
- 我拿"序"当约束 → 用户指出全局序不存在
- 我一度反对"LLM 填数值" → 用户论证成立，我撤回反对
- 我把标尺表做成一格一数 → 用户指出同档需按神通微调

**我做的（工程侧）**：
- 把上述定案落成字段与动作（§2.3/§2.4）
- 补三条防倒退的锁：空值不许填默认、微调不许越档、变更必留痕
- 把"矛盾拦截"与"胜负裁定"分开（引擎拦矛盾，但不裁定）

## 6. 待你确认的两处（只有这两处）

1. **账本的六项字段**（§2.3）——认不认？多了砍、少了加。
2. **分量（那个 0-1 的数）还要不要留在引擎里？**
   现状：它现在服务于"谁值得动"和"镜头谁先出场"。
   若不裁胜负，它只剩下"排序"这一个用途。
   我的建议：**砍掉分数，改按确定性的粗规则排**（谁刚动过、谁在飞盘算里、谁在镜头名单上），彻底不留"数值参与决策"的口子。
