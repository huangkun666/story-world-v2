## 1. ★"从一条线索回到往事"到底是哪条路（用户那一问的实测答案）

查清了四件事，其中一条是**用户直觉对了、我猜错了**：

| 路 | 机制 | 说明 |
|---|---|---|
| **① 靠号** | 事件拿 `ev_${tick}_${i+1}`（`settle.js:789`）；编年行的 `eventRef`/`chainRef` **指着同一个号** | 引擎自己写的键，**可靠** |
| **② 事件之间的来路** | `source.ref`（`ev_3 → ev_2 → ev_1`） | ★**这才是"回溯"**，`byCause` 就是一层层走它 |

★**所以"标题回溯"不是一条独立的路**：标题逐字出现在编年行里，是因为**落账模板把它裹进去了**；

## 2. 病：来路断在"大事纪"门口（本笔的要害）

### 2.1 病在哪（实读代码）

```
事件满 20 轮 + 整链结清  ⇒ settle.js 的 archiveClosedEvents 把它【从 ssot.events 删掉】、压成里程碑
                            （settle.js:724：world.events = world.events.filter(...)）
而本层只读 ssot.events    ⇒ ① 照因果上溯：走到归档边界就停，更老的来路一层都取不到
                            ② 照指针取：只能给你一行「事件「X」闭环（源盘算已结算）」——**取不到那件事本身**
```

### 2.2 ★但归档那件事**没丢**（这是本笔能修的前提）

`leg111` 已经把事件按**事件契约原样**留档了（`settle.js:711-717`）：

```js
m.rows.push({ id, title, source: { type, ref }, position, ripples })
```

⇒ **`source.ref` 就在 `milestones[].rows` 里躺着**，只是检索层从来没去看那个地方。

### 2.3 治法（两条，都是"换个地方找"，不是新机制）

| 落点 | 做什么 |
|---|---|
| `buildArchiveIndex(ssot)`（新，导出） | 把 `milestones[].rows` 收成一张 `id → 事件` 表；★**一批次只建一次**（不是每个事件扫一遍全账） |
| 取数"先热池、后归档" | `findEventAnywhere(q, id)`：热池没有就去归档里找，**归档来的带 `archivedIn`**（消费者据此知道它在哪个纪） |
| `modeByCause` | 沿 `source.ref` 上溯时**跨过归档边界继续走**（链顺序照旧，**不排序**——那是有向的） |
| `modeById` | 除编年行外，**把事件本体也取回来**（以前只回行 ⇒ "照指针取"名不副实） |

★判据 `L25`（跨归档上溯：`ev_3_1 → ev_2_1 → ev_1_1`，修之前走到 `ev_2_1` 就停）· `L26`（跨归档照指针：取回事件本体 + 标题 + `archivedIn`）。

## 3. ★★本笔踩的三个坑（都值得记，因为**都是"我以为"**）

### 3.1 第一次"收规则"：我把规则顺序排错，**真的改坏了产品**

我把"收场"那条规则排在最前（沿用旧注释"顺序要紧：先收场…"）。结果：
`RE_CAUSE_EVENT` 认的是 `事件「…」——沿「…」而来`，而 `RE_CLOSE_MODEL` 认的是 `事件「…」这一段收场了`——
**同一族行首**，我把后者放前面 ⇒ 带 `——` 的来路话被抢走，**真账那种行当场判成 `other`**。

★**抓出来的方式值一提**：不是靠读代码，是靠**先冻结合并前的输出、合并后逐行比对**（本仓老规矩：
"先打印实际输出，再写断言"）。**没有那把标准尺，这个回归会带着判据全绿出门。**

### 3.2 ★查下去的结论跟我的猜测**相反**：那条旧规则在真账上**从来没匹配上过**

我原以为"是我改坏 vs 旧的就对"。逐字符量下来：

```
真账那行：事件「万法阁商队集结」——由世界处境而生，…
          ↑ 破折号在 index 11（在「」之后）
旧正则：  /^(?:——)?(?:由世界处境而生|沿「|由盘算「)/   ← 要求**行首**就是 ——
⇒ 实测：真账三种来路写法，旧正则**一条都不匹配**
```

⇒ 旧规则只吃"省了 `事件「」` 前缀"的写法（**判据夹具**就是那种形状），真账那行是掉进
"**认不出就收**"的兜底、**碰巧**当上来路的——**结论对、理由是错的**：改一条规则就会翻车。

★治法：两条规则改成**两种形状都认**（真账模板 + 裸短语）。
★**并且证明它是零行为变化**：两种形状**都归"收"** ⇒ 出包那一栏**逐行相同**、冒烟 **8351 字节逐字节相同**。

### 3.3 一个只有跑判据才会发现的低级坑

我在判据里写了 `const本体 = ...`（**中文变量名与 `const` 之间漏了空格**）⇒ JS 把它读成一个标识符 ⇒
`ReferenceError: const本体 is not defined`。**语法检查（`node --check`）能过**，只有真跑才炸。
